What You Need

The minimum is a computer with a screen. OCTAVE runs on it and plays music from a folder. Every other part is optional and adds one thing. Add them in any order: OCTAVE finds each one by itself once it is wired up.

OBD adapter (ELM327)Live readings from the car, trouble codes, a record of every driveBluetooth or USBAll of them

This page is the build guide: what to buy, how to wire it, what to set up, how to check it. What each device does in the app, its settings and how its code works are on Hardware Managers.

The Computer

Any computer that runs OCTAVE will do. For a dashboard that means a small single-board computer: a Raspberry Pi or an Orange Pi with a 64-bit Linux. The two wired sensors need Linux; a Windows or macOS machine runs everything else.

  1. Install a 64-bit Linux with a desktop on the board.
  2. Download OCTAVE-<version>-linux-aarch64.AppImage from the releases page, make it executable (chmod +x) and run it. Building on the board instead is covered in Getting Started.
  3. Give your user access to serial ports and the I2C bus, then log out and back in: 
    sudo usermod -aG dialout,i2c $USER

Check: OCTAVE opens on Home. With nothing else connected it says "No vehicle connected".

The Screen

Any screen the computer can drive works, in landscape or portrait. A touchscreen is what OCTAVE is designed for; a mouse works too. OCTAVE needs no driver of its own: if the desktop shows a picture and the touch moves the pointer, OCTAVE has both.

  1. Connect the picture (HDMI on the reference box) and the touch cable (USB).
  2. Start OCTAVE and open Settings > Display > Layout > Screen Dimensions. Tap Fullscreen, or Maximize if your desktop keeps a bar on screen. Width and Height set an exact window size instead. OCTAVE remembers the choice.

Check: the bottom bar sits on the bottom edge of the screen and every button answers a tap.

Common mistake: the reference hyprland.conf names the board's second HDMI port (monitor=HDMI-A-2,...) and pins OCTAVE's window to it. Change both lines if your screen is on another port.

Power in a Car

OCTAVE does not manage power, and the repository holds no power-supply design. What follows is guidance, not something the software checks.

  • Use a supply made for a car. It must meet the board's voltage and current needs, with the screen's added if the screen is powered from the same supply. A car's electrical system is noisy and dips when the engine starts.
  • Do not just cut the power. A computer switched off mid-write can damage its system disk. Shut down first: Settings > Device > Device > Power > Shut Down powers the computer off (on Linux it runs systemctl poweroff). A supply that holds power for a few seconds after the key is turned, and tells the computer to shut down, does this for you.
  • A shutdown script may simply stop OCTAVE. On SIGTERM OCTAVE quits cleanly and closes its ports.
  • Sensors take their power from the computer's 3.3 V pin. The knob's receiver is powered by its USB port.
  • Heat and vibration. Fix every connector so it cannot work loose, and keep the electronics out of direct sun.

How the reference box recovers from a hang by itself is under Starting OCTAVE at Boot.

OBD Adapter

The OBD adapter is how OCTAVE reads the car. It plugs into the car's OBD-II port, usually under the dashboard, and there is nothing to wire.

StepWhat to do
BuyAny ELM327-compatible adapter. Bluetooth or USB for a Linux, Windows or macOS computer; Bluetooth LE for Android.
WirePlug it into the OBD-II port. A USB adapter's cable goes to the computer.
Set upLinux: your user must be in the dialout group (above). You do not need to pair a Bluetooth adapter in the system settings first: OCTAVE pairs it. Windows and macOS: pair it in the system's Bluetooth settings.
CheckTurn the ignition on. In OCTAVE open OBD and tap Connect, then tap your adapter in the Connect Vehicle sheet. The status becomes Connected and Live Data fills with readings.

The steps in the app, what each status means and what to do when it fails are on OBD Manager.

Common mistake: trying with the ignition off. Most adapters have power only with the ignition on, and the car does not answer until then.

hardware/obd-adapter/ holds the design of an adapter of OCTAVE's own. It has not been reviewed by a person or built. Do not order it; nothing in OCTAVE depends on it.

The I2C Bus (Both Sensors)

Linux only

I2C is a two-wire bus (data, called SDA, and clock, called SCL) that several chips can share. The motion sensor and the gesture sensor both use it, wired to the same four pins. Each chip has its own address on the bus.

OCTAVE only looks on bus 2, which Linux shows as /dev/i2c-2. There is no setting for the bus number. So the first job is to find out which header pins of your board are bus 2, or to make them so.

  1. Install the I2C tools and list the buses the system has: 
    sudo apt install i2c-tools
i2cdetect -l
ls /dev/i2c-2
  2. If /dev/i2c-2 does not exist, enable it in the board's boot configuration and reboot. Which setting does that, and which header pins it puts the bus on, depends on the board: look it up in the board's own documentation.
  3. Wire the sensors (motion, gesture) with the computer switched off.
  4. Scan the bus. Each chip that is wired and powered shows its address: 
    i2cdetect -y 2
AddressChipOn which board
1cLIS3MDL, compassBerryIMU v3
6aLSM6DSL, accelerometer and gyroscopeBerryIMU v3
77BMP388, barometerBerryIMU v3
73PAJ7620U2Gesture sensor

Common mistakes:

  • The sensors are on another bus. Many boards, the Raspberry Pi among them, put the header's usual I2C pins on bus 1. The scan of bus 2 is then empty and OCTAVE says Disconnected. Scan the other buses (i2cdetect -y 1) to see where the chips answer.
  • The reference Orange Pi has no I2C bus enabled. Its /boot/armbianEnv.txt has no overlays= line, so /dev/i2c-2 does not exist there. The repository does not record which overlay or which pins to use on that board.
  • You are not in the i2c group, or have not logged out and in since joining it. OCTAVE then gives up at once without retrying. After fixing it, switch the sensor off and on in Settings > Accessories.

Motion Sensor (BerryIMU v3)

Linux / Raspberry Pi / Orange Pi

The motion sensor tells OCTAVE how the vehicle leans, which way it points, how hard it corners and brakes, and how high it is.

Buy: a BerryIMU v3 from OzzMaker, and four jumper wires. OCTAVE talks to the three chips on that board by their addresses, so another version or another sensor board will not work without changing the code.

Wire it with the computer off. Check the names printed on the board against the maker's guide.

BerryIMU pinComputer pin
3V33.3 V
GNDGround
SDASDA of bus 2
SCLSCL of bus 2

Mount the board flat and fixed firmly to the vehicle, its Z axis pointing straight up or down. Keep the wires short and away from ignition wiring.

Set up: the I2C bus, nothing more. The sensor is on by default.

Check:

  1. i2cdetect -y 2 shows 1c, 6a and 77.
  2. Start OCTAVE with the vehicle standing still. It looks for the sensor one second after starting and measures the gyroscope's resting error during the second after that.
  3. Settings > Accessories > IMU Sensor: the line under Connection reads Connected.
  4. Tap the sensor button on the bottom bar, then Sensors. Tilt the board: Pitch and Roll follow. G-Force reads about 1 at rest.
  5. With the vehicle on level ground, tap ZERO on that page so pitch and roll read 0 as mounted. Level is not saved: set it after each start.

Common mistakes:

  • Disconnected: the bus could not be opened. OCTAVE tries five more times, after 5, 10, 15, 20 and 25 seconds, then stops. Fix the bus, then switch IMU Sensor off and on.
  • Error: the bus opened but a chip did not answer, or stopped answering. A loose wire does this. The same five tries follow.
  • The model drifts: the vehicle was moving during the first second. Switch IMU Sensor off and on while standing still.

Gesture Sensor (PAJ7620U2)

Linux / Raspberry Pi / Orange Pi

The gesture sensor sees a hand moving in front of it, so you can skip a track or change the volume without looking at the screen.

Buy: a PAJ7620U2 breakout board, for example the DFRobot SEN0315 or the Waveshare PAJ7620U2. The connectors of the two differ: wire by the names printed on yours.

Wire it with the computer off, to the same four pins as the motion sensor.

Sensor pinComputer pin
VCC3.3 V
GNDGround
SDASDA of bus 2
SCLSCL of bus 2

OCTAVE asks the sensor for gestures 50 times a second, so an interrupt pin, if your board has one, stays unconnected.

Mount it facing where the hand will be, with nothing in between, and out of direct sunlight: it works with infrared light.

Set up: the I2C bus, nothing more. The sensor is on by default.

Check:

  1. i2cdetect -y 2 shows 73.
  2. Settings > Accessories > Gesture Sensor: the line under Connection reads Connected.
  3. Play a song and swipe a hand to the right in front of the sensor. The next track starts.

Common mistakes:

  • Error with "expected chip ID 0x7620, got …" in the log: the sensor is not answering, or another chip is at its address. Check power and the two bus wires.
  • A swipe is read as a push, or the other way round: move the sensor nearer to or further from the hand. OCTAVE does not tune the sensor's range.
  • One movement counts twice: raise Pause Between Gestures in the sensor's settings.

The gestures and what each does are on Hardware Managers.

Volume Knob (ESP32)

Linux Windows macOS

A knob you can find without looking: turn it for the volume, press it to mute. It is two ESP32 boards. One holds the rotary encoder and sits within reach. The other, an ESP32-S3 "receiver", plugs into a USB port of the computer. The two talk by radio (ESP-NOW), so no cable runs to the knob. 

  knob: rotary encoder + ESP32  ~~~ ESP-NOW radio ~~~>  ESP32-S3 receiver  --- USB --->  computer
You write the firmware
No firmware for either board is in the OCTAVE repository, and no wiring for the encoder. OCTAVE only defines the text lines the receiver exchanges with it over USB; they are listed on Hardware Managers. Any pair of boards whose receiver speaks those lines works. hardware/pods/volume-knob/ is the design of a battery knob board; it has not been built and has no firmware either.
StepWhat to do
Buy / buildAn ESP32-S3 board for the receiver; an ESP32 board, a rotary encoder with a push switch and a power source for the knob.
WireThe receiver's own USB port to the computer. It is powered from there.
Serial settings115200 baud, 8 data bits, no parity, 1 stop bit, no flow control.
Set upLinux: your user must be in the dialout group (above). Plug the receiver in before starting OCTAVE.

Check:

  1. Open Settings > Accessories > Volume Knob. Under USB Serial Port the receiver's port has a star, and the line under Connection reads "Connected to ESP32 on <port>". OCTAVE picks an ESP32-S3 by itself three seconds after starting.
  2. Turn the knob: the volume in the bottom bar follows. Press it: the sound mutes.

Common mistakes:

  • The port is not an ESP32-S3's own USB port. OCTAVE never picks such a port by itself. Tap it under USB Serial Port, then turn the knob once when the page says "turn the knob to confirm". The reference Jeep is this case: its knob is on the board's serial port /dev/ttyS0.
  • The port is missing from the list. The port saved for the OBD adapter is never offered. Tap Refresh after plugging in.
  • "Connection failed" on Linux: usually the dialout group.

Phone

An Android phone shows on the dash and can be touched there. Nothing is installed on the phone; it needs USB debugging switched on. The steps on the phone and in the app are on Phone Mirror. This section is the head unit's side.

WayWhat the head unit needs
USB cableA free USB port and a data cable (not a charge-only one). On a Raspberry Pi or Orange Pi, install adb: sudo apt install adb.
Wi-FiThe phone and the head unit on the same network. OCTAVE does not create one, so in a car the head unit has to host an access point that the phone joins.
iPhoneAirPlay, on Linux only: see iPhone (AirPlay).

Check: plug the phone in and tap Connect Phone in the phone window on Home. Allow USB debugging on the phone when it asks.

The reference hotspot

The Jeep's access point is in deployment/orange-pi-5-plus/etc/. It runs beside the board's normal Wi-Fi connection, on a second, virtual interface named ap0, and needs hostapd, dnsmasq and iw installed.

FileWhat it does
systemd/system/ap0-iface.serviceCreates ap0 with a fixed MAC address and the address 10.42.0.1. The MAC must stay the same: Android trusts the network by it.
systemd/system/hostapd-ap0.service, hostapd/ap0.confThe OCTAVE-Jeep network: 5 GHz, WPA2. Set your own name and password.
systemd/system/dnsmasq-ap0.service, dnsmasq-ap0.confGives the phone an address and nothing else: no gateway, no DNS. The phone then sees a network without internet and keeps using mobile data, which is what you want.
udev/rules.d/85-ap0-nm-unmanaged.rulesKeeps NetworkManager off ap0.

Copy them to /etc, fill in the placeholders, then sudo systemctl enable --now ap0-iface hostapd-ap0 dnsmasq-ap0.

Common mistake: the wrong channel. That board's Wi-Fi chip can use one channel at a time, so the access point must be on the channel of the Wi-Fi the board joins at home (channel= in ap0.conf). The network interface name in ap0-iface.service is that board's too. Type the network's name and password into OCTAVE under Settings > Phone > Phone Mirror > Car Wi-Fi, and a phone on a cable joins it by itself. More under Without a Cable.

Starting OCTAVE at Boot

A head unit should come up in OCTAVE with no keyboard. That takes two things: the desktop logs in by itself, and the desktop starts OCTAVE. The reference box does it like this.

  1. Log in automatically. /etc/gdm3/custom.conf: 
    [daemon]
AutomaticLoginEnable = true
AutomaticLogin = <user>
  2. Install the start script. 
    mkdir -p ~/.local/bin
cp deployment/orange-pi-5-plus/home/.local/bin/octave-start.sh ~/.local/bin/
chmod +x ~/.local/bin/octave-start.sh
  3. Edit the top of the script. OCTAVE_CPP_DIR is where OCTAVE was built (the script runs build/octave inside it; point that line at the AppImage if you use one). ANALOG_SINK is the sound output to use: pactl list short sinks lists yours.
  4. Have the desktop run it. In Hyprland, one line in ~/.config/hypr/hyprland.conf: 
    exec-once = ~/.local/bin/octave-start.sh
    Any other desktop's autostart can run the same script.

Check: reboot. OCTAVE is on screen with no login prompt.

The two scripts

Both are in deployment/orange-pi-5-plus/home/.local/bin/.

ScriptWhat it doesIts log
octave-start.shStarts OCTAVE, once: a second run while OCTAVE is up does nothing. Sends sound to the chosen output and unmutes it. Starts OCTAVE again two seconds after a crash, and gives up after 5 crashes in 3 minutes. Quitting OCTAVE normally ends the script.~/.local/state/octave/console.log
octave-rebuild-start.shFor a box that builds OCTAVE from source in ~/octave-cpp. Builds what changed, then starts OCTAVE, or restarts it if the build produced a new program. If the build fails, the previous build keeps running and a notification says so. On the Jeep it is the menu entry "OCTAVE (Rebuild)". It is not used at boot, so a compile never holds up the start.~/.local/state/octave/rebuild.log

Common mistake: OCTAVE keeps crashing at start and the screen stays on the desktop. The script has given up; the reason is at the end of console.log.

Surviving a hang

These files under deployment/orange-pi-5-plus/etc/ are worth copying to any head unit:

FileWhat it does
systemd/system.conf.d/10-hw-watchdog.confHardware watchdog: the board resets itself if the kernel locks up for 30 seconds.
sysctl.d/90-panic-reboot.confA kernel fault becomes a reboot after 10 seconds instead of a frozen screen.
systemd/journald.conf.d/10-persistent.conf, default/armbian-ramlogKeep the system log on disk, so a freeze leaves evidence.
systemd/logind.conf.d/no-sleep.confNever suspend. Also run sudo systemctl mask sleep.target suspend.target.

When Something Goes Wrong

Look in this order:

  1. Outside OCTAVE. Is the device there at all? For a sensor, i2cdetect -y 2 must show its address. For the knob or a USB OBD adapter, dmesg shows a new serial port when you plug it in.
  2. Permissions. groups must list dialout and i2c. A change takes effect after you log out and in.
  3. Settings > Accessories. Each tile says Connected, Not found or Off.
  4. The log. Start OCTAVE with --debug for more detail and read octave-cpp.log in the logs folder of OCTAVE's configuration folder (~/.config/OCTAVE/logs/ on Linux). A healthy start has these lines:
    DeviceLine
    Knobdetected ESP32-S3 on …, then connected to …
    Motion sensorall sensors initialized successfully, then gyro calibrated - bias …
    Gesture sensorPAJ7620U2 initialized (chip ID: 0x7620)
    The lines that name a failure are listed on Hardware Managers.

More fixes, by symptom, are on the Troubleshooting page.

Why It Is Set Up This Way

  • A USB receiver, not a wired knob. The knob can sit anywhere in the cabin, and the computer needs nothing but a serial port. That is why the knob also works on Windows and macOS.
  • Bus 2 is fixed in the code. It was set for the reference board and has not needed to move. The price is the set-up step above. Another bus is a one-line change in each of src/managers/berryimumanager.cpp and gesturemanager.cpp (I2C_BUS).
  • Sensors retry, but not for ever. Five tries cover a bus that appears late at boot without hammering one that never will. A permission error is not retried, because waiting cannot fix it.
  • The hotspot gives no internet on purpose. The phone keeps its mobile data for maps and music while its screen travels over the car's own network.
