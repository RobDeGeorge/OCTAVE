ESP32 Wireless Volume Knob

All Platforms

The volume knob uses a two-ESP32 architecture with ESP-NOW for wireless communication. A remote encoder unit sends commands to a USB receiver dongle plugged into the computer running OCTAVE.

Architecture

  [Rotary Encoder]          ESP-NOW (2.4GHz)         [USB Serial]
  [  + Button    ] ----> [ESP32 Dev Board] ~~~~> [ESP32-S3 Dongle] ----> Computer
  [  + LED Ring  ]         "Encoder Unit"            "Receiver"          (OCTAVE)
                          Sends: +, -, M           Forwards to USB
                                                    at 115200 baud

Serial Protocol

The ESP32-S3 receiver forwards simple text commands over USB serial at 115200 baud:

CommandDirectionDescription
+ or +NESP32 -> OCTAVEVolume up (N ticks clockwise)
- or -NESP32 -> OCTAVEVolume down (N ticks counter-clockwise)
MESP32 -> OCTAVEMute toggle (encoder button press)
PESP32 -> OCTAVEPlay/pause (double-click, not yet implemented)
V##OCTAVE -> ESP32Current volume level (0-100) for LED display
M0 / M1OCTAVE -> ESP32Mute state (0=unmuted, 1=muted)
C###,###,###OCTAVE -> ESP32Theme RGB color for LED ring (e.g., C255,128,0)

ESP32-S3 Auto-Detection

OCTAVE automatically detects ESP32-S3 USB devices by checking for the Espressif VID 303A in USB hardware IDs. Platform-specific port scanning:

  • Windows: Scans COM ports, looks for VID 303A or "USB JTAG/serial debug unit" in description
  • macOS: Checks /dev/tty.usbserial*, /dev/cu.usbmodem*, etc.
  • Linux: Checks /dev/ttyUSB*, /dev/ttyACM*
Auto-Connect: On startup, OCTAVE waits 3 seconds, scans for devices, and auto-selects the ESP32-S3 port if no port is configured. The OBD port is filtered out to avoid conflicts.

Reconnection Behavior

  • Max 5 reconnect attempts with exponential backoff (3s, 6s, 9s... max 10s)
  • Background port scanning every 10 seconds when disconnected
  • Keepalive timer sends volume updates every 2 seconds to prevent ESP32 LED timeout (5s)
  • Volume updates rate-limited to 20/sec (50ms debounce) to prevent LED flickering

LED Modes

  • Theme mode: LED color follows album art extracted theme colors
  • Static mode: LED uses a fixed user-chosen color
  • Sleep mode: LEDs turn off after ESP32 timeout when OCTAVE stops sending keepalives

BerryIMU v3 IMU Sensor

Linux / Raspberry Pi

The BerryIMU v3 provides 10 degrees of freedom (accelerometer, gyroscope, magnetometer, barometer) over I2C. OCTAVE uses Madgwick 9DOF AHRS for sensor fusion, outputting a quaternion directly to the QML 3D model.

I2C Wiring

  BerryIMU v3                  Raspberry Pi / SBC
  +-----------+                +-----------------+
  |  VCC  (1) |----[ 3.3V ]---|  Pin 1 (3.3V)   |
  |  GND  (2) |----[ GND  ]---|  Pin 6 (GND)    |
  |  SDA  (3) |----[ SDA  ]---|  Pin 3 (GPIO2)  |   I2C Bus 2
  |  SCL  (4) |----[ SCL  ]---|  Pin 5 (GPIO3)  |
  +-----------+                +-----------------+

I2C Chip Addresses

ChipAddressFunctionInit Rate
LSM6DSL0x6AAccelerometer + Gyroscope416 Hz, +/-4g, 245 dps
LIS3MDL0x1CMagnetometer155 Hz, +/-8 gauss
BMP3880x77Barometer + TemperatureContinuous mode with 21-byte calibration

Madgwick AHRS Filter

The Madgwick filter fuses all 9 axes into a single quaternion, avoiding gimbal lock entirely. Key parameters:

  • Beta (gain): 0.03 (lower = smoother, higher = more responsive)
  • Gyro deadband: 0.4 deg/s (zeros out noise when stationary)
  • Sample interval: ~200 Hz (5ms read-loop period; sleeps out the remainder, never spins)
  • Emit interval: ~60 Hz (16ms between signal emissions)

Mounting Orientation

Tare Calibration: Mount the BerryIMU in any orientation, then use the "Calibrate Tare" button in the sensor page to set the current position as zero reference. The tare offset is stored as a quaternion and applied to all subsequent readings.
Enable I2C bus 2 first
OCTAVE opens the BerryIMU and PAJ7620 on I2C bus 2 (/dev/i2c-2), which is not exposed on the Raspberry Pi's GPIO header by default — pins 3/5 are i2c-1 out of the box. Expose bus 2 with a device-tree overlay in /boot/firmware/config.txt (e.g. an i2c-gpio overlay mapping SDA/SCL to your wired pins), reboot, and confirm ls /dev/i2c-2 succeeds before launching — otherwise the sensors fail with “device not found.”

Startup Sequence

  1. 1 second delay after app start (QTimer.singleShot)
  2. Open I2C bus 2 via smbus2
  3. Initialize LSM6DSL (accel 416Hz +/-4g, gyro 416Hz 245dps, BDU + auto-increment)
  4. Initialize LIS3MDL (ultra-high perf 155Hz, +/-8 gauss, continuous)
  5. Initialize BMP388 (read 21-byte calibration, enable continuous mode)
  6. Calibrate gyro bias (samples at rest)
  7. Start background read thread (daemon)

Reconnection

If initialization fails, OCTAVE retries up to 5 times with linear backoff (5s, 10s, 15s, 20s, 25s). Permission errors do not trigger retries (user must fix I2C permissions).

PAJ7620U2 Gesture Sensor

Linux / Raspberry Pi

The PAJ7620U2 is a 9-gesture recognition sensor that detects hand motions for touchless control. It communicates over I2C and is polled at ~50Hz.

I2C Wiring

  PAJ7620U2                    Raspberry Pi / SBC
  +-----------+                +-----------------+
  |  VCC  (1) |----[ 3.3V ]---|  Pin 1 (3.3V)   |
  |  GND  (2) |----[ GND  ]---|  Pin 6 (GND)    |
  |  SDA  (3) |----[ SDA  ]---|  Pin 3 (GPIO2)  |   I2C Bus 2
  |  SCL  (4) |----[ SCL  ]---|  Pin 5 (GPIO3)  |
  +-----------+                +-----------------+

  I2C Address: 0x73
  Chip ID: 0x7620 (verified on init)

Supported Gestures

GestureRegister FlagDefault Action
RIGHT0x01 (reg 0x43)next_track
LEFT0x02 (reg 0x43)previous_track
UP0x04 (reg 0x43)volume_up
DOWN0x08 (reg 0x43)volume_down
FORWARD0x10 (reg 0x43)play_pause
BACKWARD0x20 (reg 0x43)mute_toggle
CLOCKWISE0x40 (reg 0x43)volume_up
COUNTER-CLOCKWISE0x80 (reg 0x43)volume_down
WAVE0x01 (reg 0x44)play_pause

Two-Pass Gesture Disambiguation

Forward and backward gestures are compound motions that the sensor initially reports as directional. The driver uses a two-pass approach:

  1. Detect initial gesture flag
  2. If FORWARD: wait 300ms, re-read. If a directional gesture followed, use that instead.
  3. If BACKWARD: wait 400ms, re-read. Same disambiguation logic.
  4. For directional/rotation gestures: confirm with a second read after 20ms to reject glitches
  5. After confirming, flush sensor for 100ms to prevent echo/ghost detections

Timing Parameters

  • Poll interval: 20ms (~50Hz)
  • Cooldown between gestures: 300ms (configurable via settings)
  • Forward wait: 300ms
  • Backward wait: 400ms
  • Post-flush duration: 100ms

Initialization

The sensor requires writing 220 register pairs from the DFRobot reference initialization table. The driver verifies chip ID 0x7620 before proceeding. A wakeup sequence is used to bring the sensor out of sleep.

Mounting Position

Optimal Position: Mount the gesture sensor facing the driver, approximately 30-50cm away, at chest height. Ensure no obstructions in the sensor's field of view. The sensor works best with open-hand gestures at moderate speed.

Power Supply Considerations

  • Raspberry Pi: Use a regulated 5V supply rated for at least 3A. Vehicle 12V must be stepped down with a buck converter. Avoid powering from the vehicle's USB ports (insufficient current).
  • BerryIMU / PAJ7620U2: Both run on 3.3V from the Pi's GPIO header. Total I2C bus current is minimal (<50mA).
  • ESP32 Volume Knob: The receiver dongle is USB-powered from the host computer. The encoder unit needs its own 3.3V or 5V supply (battery or vehicle power).
  • Display: Ensure the display has a separate power feed or is rated for the current draw. HDMI displays for Pi typically need their own 5V supply.
Vehicle Power: Always use a proper voltage regulator and consider adding a capacitor to smooth out voltage spikes from the alternator. Sudden power loss can corrupt the SD card on a Raspberry Pi. Consider a UPS HAT or supercapacitor-based graceful shutdown circuit.

Vehicle Installation Tips

  1. I2C Cable Length: Keep I2C cables under 30cm for reliable communication. Use shielded cable if running near power wires.
  2. Vibration: Secure all connections with hot glue or cable ties. Vibration can cause intermittent I2C failures.
  3. Heat: Vehicle cabins can exceed 60C in summer. Use heat-rated filament for 3D prints and keep electronics out of direct sunlight.
  4. Grounding: Ensure a common ground between all components. Ground loops cause sensor noise.
  5. I2C Permissions: On Linux, add your user to the i2c group: sudo usermod -aG i2c $USER
  6. Serial Permissions: For ESP32 USB, add user to dialout group: sudo usermod -aG dialout $USER
  7. OBD-II: The Bluetooth OBD adapter connects via rfcomm. Pair the adapter first, then set the port in settings (default: /dev/rfcomm0).
