Overview

The SettingsManager class in backend/settings_manager.py is the central configuration store for all of OCTAVE. It inherits from QObject and exposes every user-configurable option to QML via Qt's Property, Signal, and Slot decorators. All state is persisted to a single JSON file (settingsConfigure.json) in an OS-specific data directory.

In addition to individual typed properties, SettingsManager provides a SETTINGS_REGISTRY metadata system that maps setting IDs to control types, labels, categories, and save slots. This registry powers the dynamic Quick Panel UI, allowing settings to be rendered as sliders, toggles, or chip selectors without any QML-side per-setting code.

All Platforms

File Location and Storage Paths

The settings file is stored at an OS-specific location determined by get_app_data_dir():

PlatformPath
Windows%APPDATA%\OCTAVE\settingsConfigure.json
macOS~/Library/Application Support/OCTAVE/settingsConfigure.json
Linux~/.config/OCTAVE/settingsConfigure.json (or $XDG_CONFIG_HOME/OCTAVE/)
Android<cwd>/OCTAVE/settingsConfigure.json (app-private internal storage)

The get_app_data_dir() function creates the directory if it does not exist:

def get_app_data_dir():
    from backend.platform_config import IS_ANDROID
    app_name = "OCTAVE"
    if IS_ANDROID:
        data_dir = os.path.join(os.getcwd(), app_name)
    elif sys.platform == 'win32':
        base = os.environ.get('APPDATA', os.path.expanduser('~'))
        data_dir = os.path.join(base, app_name)
    elif sys.platform == 'darwin':
        data_dir = os.path.join(os.path.expanduser('~'), 'Library', 'Application Support', app_name)
    else:
        base = os.environ.get('XDG_CONFIG_HOME', os.path.join(os.path.expanduser('~'), '.config'))
        data_dir = os.path.join(base, app_name)
    os.makedirs(data_dir, exist_ok=True)
    return data_dir

Property / Signal / Slot System

Every setting follows a consistent three-part pattern using PySide6 decorators:

  1. Signal declaration at the class level (e.g., themeSettingChanged = Signal(str))
  2. Property decorator that exposes the value to QML with a notify signal
  3. Slot method that QML calls to save the value, updates internal state, persists to JSON, and emits the signal

Here is a representative example for the themeSetting property:

# 1. Signal declaration (class level)
themeSettingChanged = Signal(str)

# 2. Property with notify signal
@Property(str, notify=themeSettingChanged)
def themeSetting(self):
    return self._theme_setting

# 3. Slot for QML to call
@Slot(str)
def save_theme_setting(self, theme):
    logger.debug(f"Saving theme setting: {theme}")
    self._theme_setting = theme
    self.update_setting("themeSetting", theme, self.themeSettingChanged)

The update_setting() helper loads the current JSON, updates the key, saves atomically, and optionally emits the signal: 

def update_setting(self, key, value, signal=None):
    settings = self.load_settings()
    settings[key] = value
    self.save_settings(settings)
    if signal:
        signal.emit(value)
Property Types Used
Settings use str, bool, int, float, and 'QVariantList' as Property types. Boolean properties must be checked before int in validation because bool is a subclass of int in Python.

JSON Persistence

Settings are stored in settingsConfigure.json and saved atomically with cross-platform file locking.

Atomic Save Strategy

The save_settings() method uses a write-to-temp-then-rename approach:

  1. Validate the settings dict against _default_settings
  2. Write to a temporary file in the same directory via tempfile.mkstemp()
  3. Acquire an exclusive file lock (platform-specific: fcntl on Unix, msvcrt on Windows)
  4. Write JSON with indent=4
  5. Set restrictive file permissions (chmod 600 on Unix)
  6. Atomic rename to the final path (on Windows, removes old file first since os.rename cannot overwrite)
  7. On any failure, falls back to direct write

Validation

The _validate_settings() method ensures type correctness by comparing each loaded value against the type of its default. Booleans are explicitly checked before int fields. Extra keys not in defaults are preserved for forward compatibility.

File Locking

def _lock_file(self, f, exclusive=True):
    if sys.platform == 'win32':
        msvcrt.locking(f.fileno(), msvcrt.LK_NBLCK, 1)
    else:
        fcntl.flock(f.fileno(), fcntl.LOCK_EX | fcntl.LOCK_NB)

Settings Registry Metadata System

The SETTINGS_REGISTRY is a module-level dictionary that maps setting IDs to metadata objects. This allows the QML Quick Panel to dynamically render controls without per-setting UI code.

Registry Entry Structure

FieldTypeDescription
keystrThe camelCase key in settingsConfigure.json and the QML property name
labelstrHuman-readable label displayed in the UI
categorystrSettings section (e.g., "mediaSettings", "displaySettings")
controlTypestrUI control: "toggle", "slider", or "chips"
saveSlotstrName of the Python @Slot method to call when the value changes
paramsdict(Optional) Control parameters like from, to, stepSize, options, logarithmic

Example Registry Entries

    "startup_volume": {
        "key": "startUpVolume", "label": "Startup Volume",
        "category": "mediaSettings",
        "controlType": "slider", "saveSlot": "save_start_volume",
        "params": {"from": 0, "to": 1, "stepSize": 0.01, "logarithmic": True}
    },
    "album_art_transition": {
        "key": "albumArtTransition", "label": "Album Art Transition",
        "category": "mediaSettings",
        "controlType": "chips", "saveSlot": "save_album_art_transition",
        "params": {"options": ["Crossfade", "Slide", "Vinyl Lift", "Dissolve", "Flip"]}
    },
    "obd_fast_mode": {
        "key": "obdFastMode", "label": "OBD Fast Mode",
        "category": "obdSettings",
        "controlType": "toggle", "saveSlot": "save_obd_fast_mode"
    },
}

@Slot(result=str)
def get_settings_registry(self):
    return json.dumps(SETTINGS_REGISTRY)

Section Visibility System

The settings menu sections can be shown or hidden. Visibility state is stored in the nested settingsMenuVisibility dictionary: 

"settingsMenuVisibility": {
    "deviceSettings": true,
    "mediaSettings": true,
    "displaySettings": true,
    "obdSettings": true,
    "volumeKnobSettings": false,  // Hidden by default
    "gestureSensorSettings": true,
    "about": true
}

Key methods:

  • is_settings_section_visible(section) - Returns bool for a specific section
  • save_settings_section_visibility(section, visible) - Saves and emits settingsMenuVisibilityChanged
  • get_settings_menu_visibility() - Returns full visibility dict as JSON string

Pinned Quick Settings

Users can pin frequently-used settings to a Quick Panel. Pinned setting IDs are stored in the pinnedSettings list. When QML requests pinned settings metadata, the manager resolves current values from internal attributes. 

@Slot(str)
def toggle_pin_setting(self, setting_id):
    if setting_id in self._pinned_settings:
        self._pinned_settings.remove(setting_id)
    else:
        if setting_id in SETTINGS_REGISTRY:
            self._pinned_settings.append(setting_id)
    # persist and emit...

get_pinned_settings_metadata() returns a JSON array where each entry includes the full registry metadata plus a currentValue field resolved via _key_to_attr() mapping from camelCase JSON keys to snake_case Python attributes.

Generic Setting Access

For settings that do not have dedicated properties (e.g., per-parameter OBD gauge configuration), SettingsManager provides generic get/set methods: 

@Slot(str, result='QVariant')
def get_setting(self, key, default_value=None):
    settings = self.load_settings()
    return settings.get(key, default_value)

@Slot(str, 'QVariant')
def save_setting(self, key, value):
    settings = self.load_settings()
    settings[key] = value
    self.save_settings(settings)
    self.genericSettingChanged.emit(key)

The genericSettingChanged signal emits the key name so QML listeners can filter for specific keys.

Album Art Colors

When the "Album Art Capture" theme is active, extracted color palettes are stored on SettingsManager as a JSON string property. This is the central distribution point: MediaManager and SpotifyManager both call set_album_art_colors() to push new colors, and QML reads the albumArtColors property. 

@Property(str, notify=albumArtColorsChanged)
def albumArtColors(self):
    return self._album_art_colors

@Slot(str)
def set_album_art_colors(self, colors_json):
    self._album_art_colors = colors_json
    self.albumArtColorsChanged.emit(colors_json)

Connection to QML

SettingsManager is registered as a QML context property in main.py: 

settings_manager = SettingsManager()
engine.rootContext().setContextProperty("settingsManager", settings_manager)

QML accesses settings directly:

// Read a property
text: settingsManager.deviceName

// Write via slot
settingsManager.save_device_name(newName)

// React to changes
Connections {
    target: settingsManager
    function onThemeSettingChanged(theme) { /* ... */ }
}

How to Add a New Setting

Follow these steps to add a new setting end-to-end:

  1. Add the default value to self._default_settings in __init__: 
    "myNewFeature": False,
  2. Declare the change signal at the class level: 
    myNewFeatureChanged = Signal(bool)
  3. Initialize the backing attribute from loaded settings in __init__: 
    self._my_new_feature = self._settings.get("myNewFeature", self._default_settings["myNewFeature"])
  4. Add the Property: 
    @Property(bool, notify=myNewFeatureChanged)
def myNewFeature(self):
    return self._my_new_feature
  5. Add the save Slot: 
    @Slot(bool)
def save_my_new_feature(self, enabled):
    self._my_new_feature = enabled
    self.update_setting("myNewFeature", enabled, self.myNewFeatureChanged)
  6. (Optional) Add to SETTINGS_REGISTRY if the setting should appear in Quick Panel: 
    "my_new_feature": {
    "key": "myNewFeature", "label": "My New Feature",
    "category": "mediaSettings",
    "controlType": "toggle", "saveSlot": "save_my_new_feature"
},
  7. (Optional) Add to _key_to_attr mapping if the setting will be pinnable: 
    "myNewFeature": "my_new_feature",
  8. (Optional) Add to reset_to_defaults() to ensure it resets properly.
Tip
If your setting does not need a dedicated Property (e.g., it is only used by one QML component), you can use the generic save_setting(key, value) and get_setting(key) methods instead. The genericSettingChanged signal will notify listeners.
