What This Page Covers

OCTAVE's built-in screen is written in QML, Qt's language for describing a user interface. A component is one QML file that draws one thing and can be used from any page: a card that shows a sensor reading, the "Connect Vehicle" button, the 3D vehicle. This page lists the components at the top of frontend/, for someone building or changing a screen.

Each entry says what the component is for, gives a snippet you can paste, lists the properties that matter and ends with anything that might surprise you. Three families of components have pages of their own:

  • Gauges and dashboard widgets (gauges/, dashboards/widgets/): Gauges & Dashboards.
  • Settings cards, toggles and sliders (settings/): Settings UI.
  • Colours, fonts and sizes (Style, Spacing): Theme System.

Whole screens (Home, the Media Room, the OBD pages) are on Pages.

Before You Use One

frontend/ is on the QML import path, so a page in that folder uses a component by its file name with no import. Most files also write import "." as App and then say App.SensorCard, App.Style, App.Spacing; a file in a sub-folder writes import ".." as App.

Sizes go through a small dp() function that each file defines for itself, so that everything grows and shrinks with the GUI scale setting. See GUI Scale for why each file carries its own copy.

Components reach the backend through context properties: the C++ managers, visible to all QML under fixed names such as obdManager or settingsManager. A component that uses one checks that it exists first, because the managers are destroyed before the QML at shutdown. Do the same in yours.

Readings and Sensors

OBDParameterModel

The one place QML gets readings from. It is a singleton (one shared object, no need to create it) that answers two questions about any reading id such as RPM, COOLANT_TEMP or PITCH: what is its value now, and how should it be shown (title, unit, range, decimals). Car readings and motion-sensor readings come through the same calls. 

Text {
    readonly property real rpm: App.OBDParameterModel.sample("RPM")
    text: isFinite(rpm) ? rpm.toFixed(0) : "--"
}
CallGives you
sample(id)The reading as a number, NaN until one has arrived. Use this for anything you bind a real to: "no reading yet" can never look like a real 0.
liveValue(id)The same reading, undefined until one has arrived.
rawValue(id)The reading in the parameter's own unit (speed in MPH, temperature in °C), whatever unit the user picked for gauges.
displayInfo(id)Title, unit, min, max, kind and decimals in the units the gauges show, or null for an unknown id.
decimalsFor(id)How many decimals a plain-text readout should print (0 for speed, RPM and counters, otherwise 1).
hasParameter(id)Whether the id exists at all. Use it to validate an id.
isSupported(id)Whether the connected car reports this reading. Always true for motion-sensor readings; false for every car reading until a car has been scanned (vehicleKnown).
vehicleParametersThe readings the connected car supports, in display units. Empty until a car has been scanned.
toDisplay(id, v), fromDisplay(id, v)Convert a value between the parameter's own unit and the gauges' unit.

Things to know:

  • A reading is only polled if something asks for it. A page tells the OBD manager which ids it shows with obdManager.setParameterDemand(consumer, ids) and clears the list when it is hidden. Without that the value stays empty. See Which Readings Get Polled.
  • Values arrive in the user's units. liveValue() and sample() follow the temperature, speed and altitude unit settings. Code that does arithmetic on a physical quantity (the 3D vehicle's wheel speed) wants rawValue().
  • A binding wakes up only for its own id. The values live in a C++ store that notifies per id, about 30 times a second at most, so a page with forty readouts does not redraw forty times when one changes.
  • getParamInfo(id) never fails: for an unknown id it returns the id as the title and a 0 to 100 range. It is handy for drawing and wrong for validating.
  • kind is one of percentage, temperature, voltage, pressure, bidirectional (a value that swings either side of zero) or numeric. Dashboard widgets use it to say which readings suit them.
  • simulationActive replaces every reading with a slow sweep between its min and max, for looking at a layout with no car. Nothing in the app turns it on; the tests do. For a car that behaves like one, start the simulated car instead (see OBD Manager).

The list of readings and their metadata is not in this file: it comes from the C++ parameter catalog, which is the same table every frontend reads. OBD Manager describes what can be read; the API reference lists parameterCatalog and paramStore.

ImuDemand

The motion sensor idles at a low rate until a page wants it. Drop one of these into any page or widget that shows pitch, roll, heading or G-force, and the sensor runs at full rate while wanted is true. 

App.ImuDemand { consumer: "myPage"; wanted: myPage.visible }

consumer is any name that stays the same for this page (its objectName is the habit). The request is withdrawn when the component is destroyed. With no consumer it does nothing.

SensorCard

A card for one reading: a small label with an icon, the value in large type, the unit, and an optional bar. The Sensors page is built from these. 

SensorCard {
    label: "PITCH"
    icon: "↕"
    value: pitch.toFixed(1)
    unit: "°"
    barValue: (pitch + 90) / 180
    connected: imuConnected
}
PropertyDefaultWhat it does
label, unitemptyThe texts above and below the value.
value"--"The text to show. You format the number.
iconemptyOne character from the symbol font, drawn in the accent colour.
barValue-10 to 1 fills the bar; -1 hides it.
connectedfalseWhile false the card shows "--" whatever value says.
globalFontemptyFont family for the texts.

The card is meant for a GridLayout or RowLayout: it asks to fill its cell and sets no size of its own. connected defaults to false, so a card you forget to connect shows "--" forever.

GForceDisplay

The same card shape with a plot inside: a dot that moves with cornering (sideways) and braking or accelerating (up and down), a short trail behind it, rings at 0.5 g and 1 g, and the total below. 

GForceDisplay {
    lateralG: currentLateralG
    longitudinalG: currentLongitudinalG
    magnitude: currentGForce
    connected: imuConnected
}
PropertyDefaultWhat it does
lateralG, longitudinalG0Where the dot is, in g. Positive longitudinalG is up.
magnitude0The number printed under the plot. The component does not work it out from the other two.
maxG1.5The g at the outer ring.
decimalPlaces2Decimals of the printed number.
connectedfalseWhile false the dot sits in the centre, the trail stops and the number reads "--".

This is the full-size version for a page. For a dashboard cell use the GForceGauge widget, which finds its own data (Gauges & Dashboards).

Connecting Things

OBDConnectButton

The outlined Connect Vehicle button. It opens the adapter sheet by itself and reads "Connecting…" while an attempt runs. Every screen that can show "No vehicle connected" uses it: the OBD pages, the Home dashboard, the classic Home and the hand-built Home screens. 

App.OBDConnectButton {
    anchors.horizontalCenter: parent.horizontalCenter
    mainWindow: page.mainWindow
}
PropertyWhat it does
mainWindowThe app window. The sheet's OBD Settings button uses it to open Settings > OBD. Leave it out and that button does nothing.
fontFamilyFont of the label. Defaults to the theme's.

The button sizes itself to its label. You decide when it is visible; it does not hide once a car is connected.

OBDAdapterSheet

The Connect Vehicle popup behind that button: it scans for OBD adapters, lists them, and pairs and connects the one the user taps. Use it directly only when you want your own button in front of it, as Settings > OBD does. 

App.OBDAdapterSheet { id: adapterSheet }
// from your button:
adapterSheet.open()

Opening it starts a scan and closing it stops the scan; a pairing that has started carries on. It closes itself a second and a half after the car connects. Set offerSettings: true and handle settingsRequested() if you want the OBD Settings button on devices where OCTAVE cannot scan and only lists the adapters the system already knows.

What the user sees in the sheet, and what each platform can do, is in OBD Manager; how scanning and pairing work is in Finding and Pairing an Adapter.

ConnectSheet and SheetRow

The look that the "connect something" popups share: a card in the middle of the window with a centred title and a column of choices. Connect Vehicle and Connect Music are both built from it. Use it for any short "pick one of these" popup so they all look alike. 

App.ConnectSheet {
    id: sheet
    title: "Connect Music"
    App.SheetRow {
        title: "Local Music"
        detail: "Songs in a folder on this device"
        onPicked: { sheet.close(); chooseFolder() }
    }
}
MemberDefaultWhat it does
ConnectSheet.titleemptyThe heading.
ConnectSheet.busyfalseA spinner beside the heading, for a scan under way.
ConnectSheet.bodyWidthread-onlyWidth of the column your children sit in.
SheetRow.title, detailemptyThe bold line and the smaller line under it (two lines at most).
SheetRow.trailingemptyA word on the right, such as "Working…".
SheetRow.bars-10 to 4 signal bars on the right; -1 for none.
SheetRow.activetrueFalse dims the row and makes it ignore taps.
SheetRow.highlightedfalseA stronger outline, for the row that is busy.
SheetRow.picked()signalThe row was tapped.

The sheet is a Popup: it is modal, attaches itself to the window, is as tall as its content (up to 92 % of the window) and closes on a tap outside or Esc. Children go into a column, so give them width: parent.width; a SheetRow does that itself. A row does not close the sheet when picked: that is yours to do.

PhoneQrPairingPanel

Connects an Android phone over Wi-Fi: a QR code on the left, the three steps to follow on the phone on the right, then the result. The phone page shows it when no phone is connected, and Settings shows it in a popup. 

App.PhoneQrPairingPanel {
    id: pairing
    anchors.centerIn: parent
    qrSize: Math.round(page.height * 0.55)
    Component.onCompleted: start()
    Component.onDestruction: cancel()
}
MemberWhat it does
qrSizeSide of the code, in pixels. Size it from the screen as above, not with dp(): the phone has to read it from arm's length.
showCancelShow a Cancel button while a code is up. Default true.
start()Ask for a code, unless one is already showing.
cancel()Withdraw the code.
cancelled()Signal: the user tapped Cancel.
activeRead-only: a code is showing.

The panel does not start by itself: until start() it shows a Show QR code button in the code's place. The code is always black on white, whatever the theme, so cameras lock on. A code expires after two minutes. How the pairing works is in Mirroring over Wi-Fi.

Notices, Logs and Icons

ErrorToast

The one app-wide notice: a red strip at the top centre of the window for errors the driver should hear about while on another page. There is exactly one, created at the end of Main.qml so that it draws over every page. You do not create another; you add a message to that one. 

// in Main.qml, beside the two that are there
Connections {
    target: typeof myManager !== "undefined" ? myManager : null
    function onSomethingFailed(message) { errorToast.show(message) }
}
MemberWhat it does
show(message)Show the message, or queue it behind the one showing.
dismiss()Remove the one showing and bring up the next.
durationMsHow long a message stays: 8 seconds. A tap removes it sooner.
currentMessage, queuedCountRead-only, for tests.

Two things use it today:

  • The OBD connection dropping: "OBD connection lost: <reason>". Not shown on a page that already shows the OBD status (the OBD pages, Trip History, Settings > OBD).
  • A Spotify control that did not work.

Be sparing. Everything else stays on its own page and in the logs, so that nothing chatty appears in the driver's view. A message equal to the one showing, or to the last one queued, is dropped, so a repeating failure does not stack up. Popups draw above the toast. There is one severity and no sound.

TerminalFeedback

A dark box of scrolling log lines with a title and a Clear button, for showing what a long job is doing. The library scan in Settings > Media uses it. 

App.TerminalFeedback {
    id: scanLog
    title: "Scan Log"
    Layout.fillWidth: true
    Layout.preferredHeight: dp(300)

    Connections {
        target: mediaManager
        function onScanProgress(message) { scanLog.appendLine(message) }
    }
}
MemberDefaultWhat it does
appendLine(text)Add a line, with the time in front. The colour follows the line's prefix (below).
appendLineWithColor(text, color)Add a line in a colour you choose.
clear()Empty the box.
title"Output"Text in the header.
showHeadertrueHide the header, and the Clear button with it.
maxLines50Older lines are dropped beyond this.
autoScrolltrueFollow new lines to the bottom.

A line that starts with one of these prefixes is coloured for you; anything else is terminal green:

PrefixColour
[ERROR]red
[WARN], [WARNING]amber
[DONE], [SUCCESS], [FOUND], [OK]bright green
[INFO], [SCAN], [CLEAR]blue
[PATH]grey

The colours are fixed and do not follow the theme. The box is 300 by 150 dp unless you size it. The OBD Trouble Codes page has a terminal of its own and does not use this component.

ThemedIcon

Draws a single-colour SVG icon in any colour. The icons in frontend/assets/ are drawn as flat white shapes so that they can be tinted this way. 

App.ThemedIcon {
    width: dp(28); height: dp(28)
    source: "assets/obd_button.svg"
    color: App.Style.accent
}
PropertyDefaultWhat it does
sourceemptyThe SVG file.
colorwhiteThe tint, applied to every pixel that is not transparent.
shadowtrueA dark copy of the icon behind it, offset by shadowOffsetX / shadowOffsetY (1, 2) in shadowColor.
fillRatio1.0How much of the item the icon fills. 0.7 matches the bottom bar's buttons.

source is resolved against the file that uses the icon, so a file in a sub-folder passes "../assets/…". The item is 24 by 24 unless you size it. A multi-colour picture comes out as a flat silhouette. The shadow is an offset copy, not a blur, so it costs nothing per frame. How theme colours reach an icon is in Theme System.

CornerBrackets

A pulsing accent-coloured bracket at each corner of its parent. It is switched off everywhere: the settings cards, the settings tiles and TerminalFeedback each carry one, bound to a style flag that is always false (see EnvironmentTheme). It fills its parent, you control visible, and its animation stops while hidden. Do not build on it.

Music

AlbumArtCarousel

The album art in the middle of the Media Room: the square cover or, in vinyl mode, a turning record, with the animation that plays when the track changes. It can also show the previous and next covers tilted at the sides. 

AlbumArtCarousel {
    id: art
    anchors.fill: parent
    artSource: currentArt
    direction: wentForward ? 1 : -1
    roundedArt: true; artRadius: dp(16)
    onArtClicked: picker.open()
    onArtLoadFailed: currentArt = "./assets/missing_art.png"
}
// when the track changes (true: the cover comes separately, as from a phone):
art.triggerSlide(false)
MemberDefaultWhat it does
artSourceemptyThe cover to show. Changing it plays the transition to the new cover.
direction11 brings the new cover in from the right (next track), -1 from the left.
triggerSlide(artMayFollow)The track changed. With false the transition plays now, also when the cover stays the same. With true the source sends its cover apart from the track (a phone, Spotify): the transition plays when artSource changes, and a track with the same cover moves nothing.
roundedArt, artRadiusfalse, 0Rounded corners and their radius.
vinylModefalseShow the cover as a record. It turns once per song, from playbackPosition / playbackDuration.
showShadowfalseA drop shadow under the cover.
artFill0.85Share of the shorter side the cover takes when there are no side cards.
previewEnabledfalseShow the neighbours' covers at the sides, from prevArtSource / nextArtSource, tilted by sideCardAngle (30) at sideCardOpacity (0.4). The cover then takes 0.75 of the shorter side.
showSideCards()Fade the side cards back in. Call it once you have given them the new neighbours.
animBusyfalseTrue from the start of a transition until settled().
animationFinished(), settled()signalsThe transition ended; a moment later, the component is at rest.
artClicked(), artLoadFailed()signalsA tap on the cover; the cover could not be loaded.
  • The component does not watch the player. You change artSource and call triggerSlide(), in either order.
  • The cover on screen never changes its picture. The component has two cards: the hidden one loads the new cover, comes in once its picture is ready, and the two change roles. A cover that arrives late, or two changes close together, therefore cannot show the wrong picture in the middle of a transition.
  • The transition moves a plain holder around each card, not the card. An Animator has no visible effect on an item with a layer effect (the cards have the corner mask and the shadow): the item stays still and jumps at the end.
  • The side cards hide themselves when a transition starts and stay hidden until you call showSideCards().
  • Start heavy work for the new track on settled(), not on the track change, so that it does not compete with the animation. The Media Room does its audio analysis there.
  • A cover that fails to load leaves a hole: put a fallback in on artLoadFailed().

Each cover is a CoverflowCard.qml: one image with the rounding or record mask, the tilt and the shadow. It has no animation of its own and is not meant to be used outside the carousel.

Music device components

The Media Room can show a 3D music player where the album art is: a record player, an MP3 player, a CD player, a cassette player or an iPod. Four pieces make that up. They need Qt Quick 3D, which not every build has.

ComponentWhat it is
MusicDevicePreferenceA singleton that holds the choice. mode is one of options ("Album art", "Record player", "MP3 player", "CD player", "Cassette player", "iPod"); select(value) saves it (setting musicDeviceModel); enabled is true for anything but "Album art"; isAvailable() says whether this build can draw the 3D players.
MusicDeviceSceneThe player itself. Give it device, playing, artSource, trackTitle, artist, hasTrack, and playbackPosition / playbackDuration in milliseconds. A drag turns it and it eases back; a tap emits clicked(). ready and error report the model load.
MusicDeviceCarouselThe picker: every choice on a ring, the front one large. Set options and artSource, call show(value) when it opens. It emits chosen(value) for a tap on the front item and missed() for a tap on none; focusValue is the one at the front and step(±1) moves the ring.
MusicDeviceCover, MusicDeviceArtSurfaceThe cover as an image that falls back to the "missing art" picture, and that image printed on a 3D surface (a record label, a CD). Used inside the two above.
 
Loader {
    id: deviceLoader
    active: App.MusicDevicePreference.enabled && App.MusicDevicePreference.isAvailable()
    source: active ? "MusicDeviceScene.qml" : ""
}
Binding { target: deviceLoader.item; property: "device"
          value: App.MusicDevicePreference.mode; when: deviceLoader.status === Loader.Ready }
  • Load the scene and the picker through a Loader with a file name, as above, never as a plain child. A page that names them directly fails to load at all on a build without Qt Quick 3D.
  • isAvailable() loads the 3D module the first time it is called. Call it only when the user has picked a player, so that the default (album art) never pays for it at startup.
  • The scene has no clock of its own. If you do not feed it the position, nothing moves.
  • The picker's list is the caller's. The Media Room adds "Vinyl" and, where phone mirroring can run, "Phone mirror" to options and handles those two itself.

The Vehicle

The user picks a vehicle in Settings: one that ships with OCTAVE or a 3D model of their own. Two components show it, a picture and a live 3D scene, and both follow that choice by themselves. Choosing and importing a vehicle is described in docs/VEHICLES.md.

VehiclePicture

The vehicle as an image, fitted inside whatever size you give it. Use it wherever the car only has to be seen: it costs almost nothing, where a 3D scene is the most expensive thing the app draws. 

App.VehiclePicture {
    id: picture
    anchors.fill: parent
    visible: hasPicture
}
PropertyWhat it does
specWhich vehicle. Defaults to the active one (vehicleManager.active); pass a row of vehicleManager.vehicles to show another, as the vehicle chooser's tiles do.
hasPictureRead-only. False when no vehicle is chosen, or when the user's own model has no picture yet.

Plan for hasPicture being false: there is nothing to draw then. A bundled vehicle's picture ships with the app (rendered once from the 3D model by tools/vehicle/render_preview.py; run it again after changing a model). A model the user added gets its picture the first time Settings shows it.

VehicleView

The vehicle in 3D: the scene, its lights and camera, and the gestures (drag to orbit, pinch or wheel to zoom, tap a door or the hood to open it, double-tap to put the view back). Your page gives it a size and draws whatever it wants around it. The 3D vehicle page is built on it. 

VehicleView {
    id: view
    anchors.fill: parent
    active: page.visible
    attitude: Quaternion.fromEulerAngles(pitch, 0, roll)
}
MemberDefaultWhat it does
activetrueWhether the view is on screen. Bind it to your page's visible: it stops the moving parts when false.
attitudelevelHow the vehicle is tilted, as a quaternion in the scene's frame (+Y up, +Z forward).
interactivetrueFalse for a picture that should take no touches.
showLevelRingtrueA ring on the ground that stays level while the vehicle tilts.
cameraYaw, cameraPitch-35, -25The orbit, in degrees.
cameraZoom11 fits the vehicle to the view; 0.4 to 3.
resetView()Glide back to the default orbit and zoom.
specthe active vehicleWhich vehicle to show.
hasVehicleread-onlyFalse while the user has chosen none. Nothing is loaded then.
ready, errorread-onlyThe model has loaded; or why it did not.
vehicleread-onlyThe loaded vehicle object (below), or null.
  • One at a time. On a machine without a GPU, building the scene stalls for seconds. Where the car does not have to move, use VehiclePicture.
  • It needs Qt Quick 3D. A page that uses it must be opened only where that module is installed (the hasQuick3D context property), or be loaded through a Loader with a file name.
  • vehicle is null for a moment while the user switches vehicles and while none is chosen. Guard every use, and show your own "Loading…" or error text from ready and error.
  • The background is transparent: the vehicle sits on whatever your page draws behind it.
  • A sideways drag turns the car, so the view opts out of the swipe that changes sections.

The vehicle inside the view

view.vehicle is one of three things, depending on the vehicle chosen. All three offer the same members, so your page does not need to know which it has.

ComponentForWhat moves
JeepVehicleThe built-in Jeep TJDoors, hood, tailgate, wheels, steering with its linkage, engine fan and driveshafts, lamps.
RigVehicleA bundled vehicle described by a rig.json (the BMW)Whatever the file lists: panels, wheels, steered wheels, lamps.
GenericVehicleA model the user importedNothing. The model is shown whole, centred and scaled to fit, whatever units its file uses.
Member (on all three)What it does
engineRpm, wheelSpeedKphSet wheelSpeedKph and a rig's wheels turn (shown up to 30 km/h). On the Jeep the driveshafts turn with them, and engineRpm turns the fan and crank pulley, 60 times slower than real so that it reads as motion.
toggle(key)Open or close a panel: driverDoorOpen, passengerDoorOpen, hoodOpen, tailgateOpen (and rearLeftDoorOpen, rearRightDoorOpen on a rig that has them). The same names are properties on the two rigs.
ready, errorLoad state.
closedRadius, sweptRadius, groundYThe size the camera frames, closed and with panels open, and where the ground is.
 
Binding { target: view.vehicle; property: "engineRpm"
          value: Number(App.OBDParameterModel.liveValue("RPM")) || 0; when: carConnected }

The two rigs also have openAll(), closeAll(), steeringInput (-1 to 1) and the lamp switches headlightsOn, fogLightsOn, brakeLightsOn, reverseLightsOn. The vehicle itself reads no backend manager: the page feeds it. On a GenericVehicle, toggle() and the speeds are accepted and do nothing.

A rig is a set of small parts, not one model: one .glb file per moving part, each with a pivot and an axis. JeepHinge loads one part and turns it; JeepLamp is a lens with a beam; JeepLink is a steel rod between two points; JeepSteering.js works out the two front wheel angles from the steering input. The Jeep's parts are in frontend/assets/jeep_tj/, with the pivots in Rig.js, both written by the Blender scripts in tools/vehicle/. To add a bundled vehicle, write a build script that produces a folder with a rig.json (the format is at the top of RigVehicle.qml; tools/vehicle/build_bmw_e46.py is the example) rather than new QML. tools/vehicle/README.md describes how the Jeep model was made.

VehicleRigPanel is a strip of test controls for a rig (every panel and lamp, steering, speeds, and pitch and roll by hand). The 3D vehicle page loads it only in a developer run. It takes the vehicle to drive.

Classic Home Panels

Home is normally a dashboard or a hand-built screen (see Pages). The Classic choice in Settings > Display > Home Screen is the older three-panel Home, and these are its panels. They are written for that one place. For a new Home, write a dashboard or a hand-built screen instead of reusing them.

ComponentWhat it showsInterface
HomeOBDViewUp to eight reading cards, the ones the user chose for Home, in two columns. Each has a short title, the value and a bar; "--" until the reading arrives. The RPM card carries the shift light lamp when that is on.None. It reads its list from settings and rebuilds when the list changes.
HomeVehicleCardThe vehicle's picture in a card. With no vehicle chosen: "No vehicle selected, tap to choose one". For a user's model with no picture yet: its name.clicked()
HomeSensorPanelThree tiles from the motion sensor: G-force, compass, and pitch and roll. "No sensors connected" when there is no sensor.clicked(); inRow puts the tiles side by side, for an upright window.

The two that emit clicked() open nothing themselves: Home decides where a tap goes. The full-window shift-light flash is separate from the lamp on the RPM card (Shift Light Overlays).

Why They Are Built This Way

  • One source for readings. A gauge needs only a reading id, because OBDParameterModel answers for both the value and how to show it. The motion sensor goes through the same store as the car, so a compass or a G-force gauge is not a special case.
  • Values notify per id, at a capped rate. The motion sensor alone sends about 440 values a second. The store folds them together about 30 times a second, which is plenty for a needle, and wakes only the readers of the ids that changed.
  • The album-art transition runs on the render thread. It moves a frozen copy of the old cover while the real image already shows the new one, so a busy interface thread cannot make it stutter.
  • No blur where a shape will do. The icon shadow is an offset copy. A blurred shadow costs a full pass every frame on a small GPU. The album-art shadow is the one real drop shadow, and it stops updating during the transition.
  • A picture where the car does not move. Home is on screen for most of a drive, so it shows VehiclePicture and leaves the 3D scene to the page made for it.
  • A rig of parts, not one model. With one file per moving part and the pivots as data, QML can open a door or spin a wheel with plain transforms, and a new vehicle is data from a build script, with no new QML.
  • One toast, few messages. A notice in the driver's view has to be rare to be read, so errors stay on their own pages unless the driver would otherwise miss them.
