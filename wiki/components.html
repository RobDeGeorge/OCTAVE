Scope and Conventions

This page covers the reusable QML types that live at the top of frontend/. The settings component library (settings/: cards, tiles, toggles, sliders, chips, hub widgets) is documented in Settings UI; the gauge primitives (gauges/) and the dashboard widgets (dashboards/widgets/) in Gauges & Dashboards; the design-token singletons (Style, Spacing, EnvironmentTheme) in Theme System. Full views are on the Pages page.

Because frontend/ is on the QML import path, every file here is usable by its type name without an import. Files that import "." as App reach the singletons as App.Style / App.Spacing / App.EnvironmentTheme. Almost every component carries the same two-line local dp() / dpMin() wrapper (see GUI Scale for why).

AlbumArtCarousel

frontend/AlbumArtCarousel.qml (938 lines) is the album-art display at the centre of MediaRoom. It owns three CoverflowCards (previous, centre, next), a frozen "exit snapshot" of the outgoing art, the dissolve shader, and ten selectable track-change animations. The header comment states the design: one unified transition list — transitionStyle picks any of the ten names, and each animation reads previewEnabled to decide whether the side cards take part (3D-flavoured animations animate them when the preview is on and no-op that part when it is off; 2D-flavoured animations never touch them).

Public API

// Inputs
property int direction: 1              // +1 next, -1 previous
property url artSource: ""
property url prevArtSource: ""
property url nextArtSource: ""
property string transitionStyle: "Crossfade"
property bool previewEnabled: false   // show 3D side cards
property bool roundedArt: false
property real artRadius: 0
property bool vinylMode: false
property real sideCardAngle: 30
property real sideCardOpacity: 0.4
property bool showShadow: false
property real playbackPosition: 0     // vinyl rotation
property real playbackDuration: 0

// Outputs
property bool animBusy: false
readonly property bool dissolveActive
readonly property real dissolveProgress
readonly property url  dissolveNewArt
readonly property real artSize          // min(w,h) * (previewEnabled ? 0.75 : 0.85)

signal animationFinished()
signal settled()          // 50 ms after animationFinished, animBusy is false again
signal artClicked()
signal artLoadFailed()

function triggerSlide()    // dispatch on transitionStyle
function showSideCards()   // re-bind side-card opacity after a 3D animation

MediaRoom binds the inputs straight to settings: show3DAlbumPreview, roundedAlbumArt, albumArtCornerRadius (through dp()), vinylRecordMode, sideCardAngle, sideCardOpacity, showAlbumArtShadow and albumArtTransition. There is no separate "3D style" setting; the same albumArtTransition string selects a 2D or 3D animation.

Transition styles and constants

StyleFlavourConstants (top of file)Notes
"Crossfade" (default and fallback)2DkCrossfadeDuration 250, kCrossfadeScale 0.97Old art fades out while the new art scales up from 0.97
"Slide"2DkSlideDuration 280, kSlideDistance 80 (passed through dp())Direction-aware horizontal slide
"Vinyl Lift"2DkLiftDuration 180, kLiftPause 60, kLiftScale 0.85Sequential: lift out, pause, drop in with OutBack overshoot 1.2 — 420 ms in total
"Dissolve"2DkDissolveDuration 900, kDissolveGridSize 20, kDissolveSmoothness 0.1GPU shader, see below
"Flip"2DkFlipDuration 350 (half per side)Y-axis flip: exit snapshot turns away, new art turns in
"Coverflow", "Conveyor", "Stack", "Depth", "Swing"3Dk3dDuration 350, k3dSideOffsetFactor 0.42, k3dSideScale 0.72, k3dFarScale 0.5Side cards move into the centre slot; a few per-style numbers are inline (Coverflow fast-fade 220 ms, Swing ±70° exit / ±60° side, Depth 0.5 exit / 0.4 far scale)

Every animation sets animBusy = true on start and calls animationFinished() on finish; a 50 ms settleTimer then clears animBusy and emits settled(). MediaRoom does its heavy work (FFT analysis of the new file) only on settled, so it never competes with animation frames. A _anyAnimRunning property ORs the ten animation running flags and gates the live-ness of the exit-snapshot texture and the drop-shadow layer.

Structure

  • Shared masks — two hidden Rectangles with layer.enabled: true: artRoundedMask (radius = artRadius when roundedArt) and vinylMaskRect (a circle with a black centre hole at 12 % of the width). They are handed to every card and to the dissolve effect as OpacityMask.maskSource so the GPU holds one mask texture, not one per card.
  • Side cards — prevCard / nextCard, visible only when previewEnabled and a source is set, at artSize * 0.9, with image.layer.live: !animBusy.
  • Exit snapshot — an Item holding a ShaderEffectSource of centerCard.image (live: !_anyAnimRunning, hideSource: false) with its own translate/rotation. Animations move this frozen copy of the outgoing art while the centre card already shows the new one.
  • Centre card — carries showShadow / shadowLive, the vinyl angle, emits artLoadFailed() on Image.Error (MediaRoom then substitutes assets/missing_art.png) and hosts the full-size MouseArea that emits artClicked().
  • Vinyl rotation — a Binding active only in vinylMode maps playbackPosition / playbackDuration to 0–360° (one revolution per track), smoothed by a 200 ms linear Behavior that is disabled while animating; the angle resets to 0 whenever artSource changes.
  • Render-thread animators — the comments on the 2D animations note that they are built from Animator types only ("entire group runs on the render thread") so a busy QML thread cannot stutter them.

The Dissolve shader

The file comment reads: "GPU shader replaces the old 400-item grid. A single ShaderEffect with one draw call dissolves the new art in over the old art (visible via centerCard underneath)." The ShaderEffect takes the hidden dissolveNewArtImage as source plus progress, gridSize and smoothness uniforms, is clipped by the same shared mask through OpacityMask, and points at a pre-compiled bundle:

// On Android, QML is bundled under assets:/ which Qt RHI's ShaderEffect
// rejects (only qrc:/ or local files). Embed the .qsb via qrc for Android.
fragmentShader: Qt.platform.os === "android"
    ? "qrc:/shaders/dissolve_squares.frag.qsb"
    : "shaders/dissolve_squares.frag.qsb"

What the shader does and how the .qsb is produced is covered in Frontend Overview → Shaders. The three dissolve* readonly properties let MediaRoom keep its blurred background in step with the dissolve.

CoverflowCard

frontend/CoverflowCard.qml (84 lines) is "one album art image with 3D perspective transform, rounded-corner or vinyl masking, and animated coverflow properties". The carousel animates the four cf* properties; the card itself contains no animation.

// Animated by the carousel
property real cfOffset: 0      // Translate.x
property real cfAngle: 0       // Rotation about the Y axis, origin = centre
property real cfScale: 1.0     // bound to scale
property real cfOpacity: 1.0   // bound to opacity

// Image
property url artSource: ""
property real artSize: width   // sourceSize = 2 * artSize (supersampled)
property bool asynchronous: true
property bool animating: false // smooth: !animating

// Masking (shared textures passed in by the carousel)
property bool roundedArt: false
property bool vinylMode: false
property real artRadius: 0
property Item roundedMask: null
property Item vinylMask: null
property real vinylAngle: 0    // image.rotation in vinyl mode

// Shadow (centre card only)
property bool showShadow: false
property bool shadowLive: true

readonly property alias image: artImage
readonly property alias imageStatus: artImage.status

transform: [
    Translate { x: root.cfOffset },
    Rotation { axis { x: 0; y: 1; z: 0 }; angle: root.cfAngle
               origin.x: root.width / 2; origin.y: root.height / 2 }
]

Two layers are involved. The Image's own layer is enabled only when roundedArt || vinylMode and applies OpacityMask with whichever shared mask applies. The card's root layer is enabled only when showShadow, with layer.live: shadowLive, and its effect is a DropShadow { transparentBorder: true; horizontalOffset: 8; verticalOffset: 8; radius: 16; samples: 33; color: "#E0000000" } — the single user-toggleable drop shadow in the app.

Why the masks are passed in
The comment on roundedMask / vinylMask says it directly: "External mask items — shared across all cards to avoid duplicating GPU textures." Three cards plus the dissolve effect would otherwise allocate four identical mask textures per resize.

ThemedIcon

frontend/ThemedIcon.qml (71 lines) is a theme-tinted SVG icon. The header comment explains its purpose: it "wraps the Image + ColorOverlay pair that the rest of the app hand-rolls at every call site (BottomBar.qml alone repeats it ~20 times)", and the assets in frontend/assets/ "are authored as flat white fills precisely so they can be recoloured this way".

property url source: ""          // relative to the *importing* file; subdirectories pass "../assets/…"
property color color: "#FFFFFF"   // tint for every non-transparent pixel
property bool shadow: true
property color shadowColor: Qt.rgba(0, 0, 0, 0.40)
property real shadowOffsetX: 1
property real shadowOffsetY: 2
property real fillRatio: 1.0      // 0.7 matches the bottom-bar buttons
implicitWidth: 24; implicitHeight: 24

Internally: a hidden Image (sourceSize = 2× the rendered size — "2x supersample keeps SVG edges crisp when the tile scales up" — smooth, antialiasing, mipmap) feeds two ColorOverlays from Qt5Compat.GraphicalEffects: one offset by the shadow vector and tinted shadowColor, one tinted color. The comment stresses that the shadow "is a second ColorOverlay, not a blur, so there is no per-frame cost"; it reproduces the offset-glyph trick the settings tiles used when their icons were Unicode characters. See Theme System → ThemedIcon for how the tint follows the active theme.

TerminalFeedback

frontend/TerminalFeedback.qml (331 lines) is a "reusable terminal-style feedback component for displaying backend progress" — a dark Rectangle with a header bar, a touch-friendly Flickable log and a custom scroll indicator. Its two consumers are both in settings/MediaSettingsPage.qml: "Library Scan Terminal Output" and "Spotify Connection Terminal Output". OBDDiagnostics does not use it — that page carries an older inline QtObject terminal with the same appendLine() / clear() API and prefix colouring, plus a blinking cursor and a scanline canvas.

property int maxLines: 50
property bool autoScroll: true
property string title: "Output"
property bool showHeader: true
property color terminalBackground: "#1a1a1a"
property color terminalBorder: "#333333"
property color textColor: "#00ff00"     // classic terminal green
property color errorColor: "#ff4444"
property color infoColor: "#4a9eff"
property color successColor: "#44ff44"
property color warningColor: "#ffaa00"
property real fontSize: App.Spacing.overallText * 0.85
implicitWidth: dp(300); implicitHeight: dp(150)

function appendLine(text)                 // colour from [PREFIX], timestamp prepended
function appendLineWithColor(text, color)
function clear()

appendLine() picks the colour from the line's prefix — [ERROR] → error; [DONE], [SUCCESS], [FOUND], [OK] → success; [INFO], [SCAN], [CLEAR] → info; [WARN], [WARNING] → warning; [PATH] → grey — prepends a hh:mm:ss timestamp, and replaces the lines array (trimmed to maxLines) so the Repeater rebinds. Lines render in "Consolas, Monaco, monospace" with lineHeight: 1.3 and wrap anywhere. When autoScroll is on, a 150 ms OutQuad animation on contentY follows new content. The header holds the title and a "Clear" button; the Flickable uses pressDelay: 0, flickDeceleration: 1500 and maximumFlickVelocity: 4000 for touch, and a 4 dp scroll indicator appears only when the content overflows (opacity 0.8 while moving, 0.3 at rest).

Dormant environment styling

The component reads several App.EnvironmentTheme.active.* flags — terminalCornerBrackets (a CornerBrackets child), terminalScanlines (a Canvas that strokes a white line every 3 px at 4 % opacity), terminalAccentBorder (accent border at 40 % and a 1 px top highlight at 25 %), terminalHeaderAccent ("// TITLE" header, a pulsing status dot, "CLR" button) and terminalAccentScroll (a 2 dp accent scrollbar). Since commit 484bc76 EnvironmentTheme exposes one fixed active object in which every one of these flags is false and terminalRadius is 4, so the terminal always renders in its plain form: #333333 border, #2d2d2d header, grey "Clear" button, grey scrollbar. The branches remain in the file so the bindings keep working if environments are ever revived (see Theme System → EnvironmentTheme).

}

CornerBrackets

frontend/CornerBrackets.qml (43 lines) draws eight 1 px Rectangles — a horizontal and a vertical arm of length bracketLength = dp(12) at each corner, offset by −1 so they sit on the parent's border — tinted with App.Style.accent at an alpha that pulses 0.5 → 0.8 → 0.3 in two 2000 ms InOutSine legs, looping forever. It anchors itself to fill the parent; the caller controls visible, and the SequentialAnimation has running: brackets.visible, so a hidden instance costs nothing per frame.

It is instantiated in six places (TerminalFeedback, SettingsCard, SettingsTile, SettingsDashboardCard, SettingsHubCard, SettingsHubGridCard), every one bound to App.EnvironmentTheme.active.cornerBrackets or .terminalCornerBrackets. Both flags are permanently false in the single remaining environment (the file's own comment still calls it the "spacecraft theme" overlay), so the brackets are never shown in a shipped build. The component is retained because the ~40 EnvironmentTheme.active.X bindings were deliberately left intact when the presets were removed.

SensorCard

frontend/SensorCard.qml (101 lines) is the generic reading card in SensorMenu: a headerBackgroundColor Rectangle (radius: dp(10), Layout.minimumHeight: dp(100)) with a ColumnLayout of a centred label row (accent-coloured icon glyph + upper-case label in secondary text with 1.5 dp letter spacing), a spacer, the value in dp(36) bold, the unit in dp(14), and an optional 4 dp accent progress bar.

property string label: ""
property string value: "--"
property string unit: ""
property string icon: ""          // Unicode glyph
property real barValue: -1        // 0..1 fills the bar, -1 hides it
property string globalFont: ""
property bool connected: false    // shows "--" when false

The value Text has Behavior on text { enabled: false } so rapid IMU updates never queue text animations; the bar width has a 100 ms OutQuad Behavior. SensorMenu feeds pitch/roll as (value + 90) / 180 and heading as value / 360, and hides the bar for altitude and temperature.

GForceDisplay

frontend/GForceDisplay.qml (208 lines) is the G-force card in SensorMenu. Same shell as SensorCard; the body is a 2-D "friction circle" plot.

property real lateralG: 0        // X axis
property real longitudinalG: 0   // Y axis (up = positive)
property real magnitude: 0       // printed below the plot
property bool connected: false
property string globalFont: ""
property int decimalPlaces: 2
property real maxG: 1.5          // radius of the outer ring
  • Rings — the outer ring at maxG, a 1 g accent ring (only if maxG > 1) and a 0.5 g ring, plus a crosshair, all 1 px at low alpha; the circle is 92 % of the smaller card dimension and gScale = circleSize / 2 / maxG pixels per g.
  • Trail — while connected, a 50 ms Timer appends {gx, gy} to a ListModel capped at 30 entries; a Repeater draws them as 3 dp accent dots whose opacity ramps to 0.3 with age.
  • Marker — a 22 dp accent glow at 20 % alpha behind a 10 dp dot; the position properties have 50 ms OutQuad Behaviors and snap to the centre when disconnected.
  • Readout — magnitude.toFixed(decimalPlaces) + " g" in dp(20) bold, or "--".

HomeOBDView

frontend/HomeOBDView.qml (317 lines) is the OBD panel embedded in the right two-thirds of MainMenu. It has no objectName and no required properties; it is a plain child, and the tap that opens OBDMenu.qml is a MouseArea in MainMenu, not in this file.

  • Which parameters — settingsManager.get_home_obd_parameters(), falling back to ["SPEED", "RPM", "COOLANT_TEMP", "CONTROL_MODULE_VOLTAGE"], cut to at most 8 ("Limit to maximum 8 cards"). Any of the 92 ids works, IMU ones included, because titles/units come from App.OBDParameterModel.parameterInfo (short titles such as CLT) and values from paramValues.
  • Layout — a GridLayout of stacked cards: "1 column for up to 5 cards, 2 columns for 6-8 cards"; with an odd count in two-column mode the first card spans both columns. Each card is a backgroundColor rectangle with a 1 px accent border, an upper-case title (Spacing.mainMenuOBDTextSize), the value as toFixed(1) + unit (Spacing.mainMenuOBDDataSize) and a 4 dp progress strip along the bottom (200 ms width Behavior). displayValue has the same 50 ms linear Behavior as the OBDMenu cards ("fast rolling effect").
  • Shift light on the RPM card — a circular lamp anchored right-middle, visible when param === "RPM" && rpm_shift_light_enabled && rpm_show_on_home_card. It parses rpm_flags itself (tolerating the legacy single rpm field), picks the active flag by scanning from the last flag to the first ("highest priority (last) to lowest (first)"), and drives a flashTimer at the flag's flashSpeed, an 800 ms pulse (scale 1.0 → 1.15 → 1.0) when rpm_pulse_enabled, an inner glow sized by rpm_glow_size / rpm_glow_intensity, a colour Behavior of rpm_color_transition_speed ms, and a dark #1a1a1a silhouette when no flag is active. Every rpm_* setting is re-read on settingsManager.genericSettingChanged.
  • Rebuild on change — onHomeOBDParametersChanged sets the Repeater model to [] and re-assigns it via Qt.callLater "to force re-creation of all delegates".

The window-wide full-screen and aura flashes for the same flags live in Main.qml (see Shift Light Overlays); the flags are edited in the RPM popup on OBDMenu.

OBDParameterModel

frontend/OBDParameterModel.qml (376 lines) is a pragma Singleton QtObject registered in qmldir. It is the single definition of every displayable parameter and the single live-value store that all OBD views, gauges and dashboards read.

Parameter definitions

{ id: "SPEED", title: "Speed", unit: "MPH", min: 0, max: 160, kind: "numeric" }

allParameters holds 92 entries: 84 OBD-II PIDs plus 8 BerryIMU readings. The kind field ("percentage", "temperature", "voltage", "pressure", "bidirectional", "numeric") is what gauge widgets match against their octaveSupportedKinds array, and what the dashboard editor's PID picker filters on.

Live values and write coalescing

property var paramValues: ({})       // { "SPEED": 65, "RPM": 3200, ... }
property var _pendingValues: ({})

function updateParamValue(paramId, value) {
    if (simulationActive) return;         // demo mode owns paramValues
    _pendingValues[paramId] = value;
    if (!_flushTimer.running) _flushTimer.start();   // 33 ms, single-shot
}
function _flushPendingValues() {
    paramValues = Object.assign({}, paramValues, _pendingValues);  // fresh object → bindings re-evaluate
    _pendingValues = ({});
}

The comment gives the reason: replacing paramValues re-evaluates every gauge binding that reads it, and the IMU alone fires ~440 updates/s (7 signals at 60 Hz). Copying the dict on each write "pegged the QML thread at 100% CPU while idle on the Orange Pi (V4 string-alloc + GC churn), so the per-write path must stay allocation-free". Writes now land in _pendingValues and are folded in at most ~30×/s by a single-shot 33 ms timer that is re-armed by the next write and idle otherwise.

Signal wiring

Two Connections objects held as properties do the feeding. _obdConnections targets obdManager with one handler per PID (onRpmChanged, onCoolantTempChanged, … onElmVoltageChanged), so the signal names on both backends are part of the contract (see OBD Manager → Signals). _imuConnections targets berryIMU only if it exists (typeof berryIMU !== "undefined", ignoreUnknownSignals: true) and maps onPitchChanged → PITCH, … onBaroTempChanged → BARO_TEMP. The comment on the IMU block explains why the sensor values are modelled as parameters at all: "They flow through paramValues like any OBD PID, so every gauge, the PID picker, and the editor's demo mode all work with them unchanged."

Demo mode

simulationActive switches the singleton to "pure-QML fake data so dashboards can be built/tested without a live OBD connection": every parameter sweeps a sine between its min and max with a 4–16 s period and a per-parameter phase (so the screen "doesn't pulse in lockstep"), driven by a 100 ms timer; big-range values are rounded to integers. While active, real backend updates are dropped; on deactivation paramValues is reset so stale fake readings never linger in the real OBD views. The dashboard editor toggles this (see Gauges & Dashboards → Editor).

The Jeep TJ Rig

The 3D vehicle shown on CarMenu is not one mesh but a small rig of Quick3D components at the top of frontend/, assembled from part-local GLB files in frontend/assets/jeep_tj/. Every file uses unversioned Qt 6 imports (import QtQuick, import QtQuick3D), so they only load when the optional QtQuick3D module is installed — SensorHome probes CarMenu.qml for exactly this reason.

JeepHinge

JeepHinge.qml (25 lines) is a Node that loads one part with RuntimeLoader from QtQuick3D.AssetUtils (source: "./assets/jeep_tj/" + part.file) and positions it at the part's pivot. open: true drives animatedAngle to part.openAngle about the part's axis, through a 450 ms InOutCubic Behavior that can be disabled with animate: false (wheels are driven directly). It exposes moving, closed, opened (within 0.1°), ready (RuntimeLoader.Success) and error (errorString on failure, also logged with console.warn).

JeepVehicle

JeepVehicle.qml (205 lines, pragma ComponentBehavior: Bound, objectName: "jeepVehicle") is the assembly. Its public state is plain booleans and reals that CarMenu's buttons and sliders toggle:

property bool driverDoorOpen, passengerDoorOpen, rearGlassOpen, tailgateOpen, hoodOpen
property bool headlightsOn, fogLightsOn, brakeLightsOn, reverseLightsOn
property real steeringInput: 0     // -1 .. 1, smoothed by a 180 ms Behavior
property real wheelSpeedKph: 0     // clamped to ±30
readonly property bool ready       // every RuntimeLoader succeeded
readonly property string error     // first loader error, or ""
readonly property real radius      // closedRadius, or sweptRadius while anything is open
function openAll(); function closeAll()
  • Hinged panels — six JeepHinges (body, driverHinge, passengerHinge, glassHinge, gateHinge, hoodHinge). The tailgate and rear glass are sequenced: the glass opens only once the gate reports opened, the gate stays open while the glass is not closed, setting tailgateOpen mirrors into rearGlassOpen and raising the glass forces the gate open ("Open the swing gate fully before raising the glass; reverse this on closing"). The third brake light is a child of the gate hinge so it swings with the spare carrier.
  • Steering — driverWheel / passengerWheel are hinges with animate: false whose angle comes from steeringPose.driverAngle / passengerAngle; the front spin parts are nested inside them (relativeWheelPart() re-bases the pivot) "so their spin axis turns with the steering knuckle".
  • Wheel spin — a 16 ms Timer, running only while ready && visible && wheelSpeedKph !== 0, integrates wheelDegreesPerSecond (speed in m/s over a 0.3937 m tyre radius) into wheelSpinAngle, which all four spin hinges read.
  • Linkage — a Node of JeepLinks (pitman arm, drag link, three tie-rod segments with objectNames, two clamp sleeves, and a two-piece telescoping steering damper: "The steering damper telescopes; the steering rods remain rigid").
  • Lamps — a Repeater3D over [-1, 1] places a fog, brake and reverse JeepLamp on each side; a second Repeater3D places the two headlights as an emissive #Sphere (headlightGlow) plus a SpotLight (headlightBeam, 48° cone, brightness 8).

JeepSteering.js

JeepSteering.js (51 lines, .pragma library) is a small kinematics solver. solve(input, g) rotates the pitman arm by input × pitmanTravel in twelve steps and, at each step, Newton-iterates the two knuckle angles so that the drag link (pitman end → passenger knuckle) and the tie rod (driver knuckle → a pickup point pickupFraction along the drag link) keep their neutral lengths — "two fixed-length constraints, following the neutral assembly branch". It returns both wheel angles in degrees, the world points of every joint, and the residual errors. tiePoints() bends the tie rod by tieBend so it clears the differential. All coordinates are the metre-scale rig space the meshes use.

JeepLink and JeepLamp

JeepLink.qml (40 lines) draws a steel rod between two points: a #Cylinder scaled to the segment length and radius, rotated into place by a quaternion computed from the direction vector, with optional #Sphere joints at both ends (joints: true) and a PrincipledMaterial (metalness 0.65, roughness 0.42, tint #424b52 by default). JeepLamp.qml (40 lines) is an emissive lens (#Cube or #Sphere when round, lensSize in metres, NoLighting with an emission factor) plus a SpotLight (beamBrightness, beamAngle, beamInnerAngle, no shadows), both shown only while on. Each names its children <objectName>Glow / <objectName>Beam for scripts.

IMU drives the whole body only
CarMenu applies the BerryIMU quaternion to the parent carModel node (scaled 30×, "metre-scale TJ, +Z forward / +Y up, pivot at chassis centre"); doors, hood, tailgate, lights, steering and wheel spin are manual controls on the page. Nothing in the rig reads a sensor.

Design Decisions

Each item is taken from a comment in the file or from the commit that introduced it.

One carousel, ten animations, one setting

The carousel header explains the shape of the API: rather than separate 2D and 3D pickers, every animation reads previewEnabled and adapts, so the settings UI exposes a single albumArtTransition list and the Now Playing Studio can preview any of them with previewTrackTransition(). The exit-snapshot / centre-card split means the incoming art is always the real Image and only the outgoing art is a frozen texture.

GPU work over scene-graph work

The dissolve moved from a 400-item grid of rectangles to one ShaderEffect draw call; masks are shared textures; the album-art shadow is a layer whose live flag is dropped during animation; the 2D animations use Animators so they run on the render thread. All of these are documented in-line as ways to keep a busy QML thread (IMU signals, backend calls) from stuttering the visuals on the single-board head unit.

No blur where a shape will do

ThemedIcon's shadow is a second ColorOverlay and MediaPlayer's row shadow is a translucent Rectangle; both comments say so explicitly, because a DropShadow blur costs a full-screen pass per frame on Pi-class GPUs. CornerBrackets and the environment features in TerminalFeedback stop their animations when hidden for the same reason.

A singleton as the data bus for gauges

OBDParameterModel centralises definitions and values so that a gauge only needs a parameter id. Feeding the IMU through the same paramValues dictionary (rather than a second binding API) is what lets the compass, G-force and pitch/roll gauges, the PID picker and the demo mode work with no special cases; the 33 ms coalescing timer is the price of that single shared object, and the comment records the CPU measurement that made it necessary.

A rigged vehicle instead of one GLB

Splitting the model into per-part GLBs with generated pivot metadata lets QML own the articulation with public Qt APIs (RuntimeLoader + Node transforms) instead of reaching into an imported scene's internals, as tools/vehicle/README.md notes. It also keeps the steering solver, the lamp lights and the wheel spin as plain QML/JS that a script can drive by objectName, which is how the README captures are produced.
