OCTAVE Wiki

Guides and reference for the Open-source Cross-platform Telematics for Augmented Vehicle Experience, as implemented by its Python / PySide6 backend and the QML frontend it drives.

Frozen snapshot
This wiki describes the python-final branch: the last state (2026-10-18, version 0.9.5) of OCTAVE's Python backend. It is a frozen snapshot and is not maintained; current OCTAVE development happens in C++ on the main branch.

What is OCTAVE?

OCTAVE is an open-source (GPLv3) car head unit / infotainment system you run on your own hardware. On this branch it is a Python / PySide6 backend (backend/ and main.py) driving a QML frontend (frontend/). It plays local music, reads live data from the car over OBD-II, mirrors an Android phone over USB or Wi-Fi, shows a live 3D model of the vehicle from an IMU, and recolours its interface to match the album art. The Python backend runs from a source checkout on Linux, Raspberry Pi / Orange Pi class boards, Windows and macOS; it is not packaged and does not run on Android or iOS.

The typical installation is a single-board computer behind the dash, a touchscreen, a power source and a 3D-printed mount. Development and testing can happen on any desktop OS.

This reference describes the checked-out source. Optional hardware, optional Python packages and the Qt modules in your PySide6 install affect which features are available; the detailed pages call out the platform limits.

Core Features

♫
Local Media Player
MP3, M4A, MP4, FLAC, OGG, Opus and WAV playback with album art carousel, shuffle/repeat, playlists, a persistent metadata store, and album-art colour extraction.
>_
OBD-II Diagnostics
Live vehicle data from an ELM327 adapter over USB or Bluetooth serial through python-obd, DTC read and clear, freeze frame, a full-screen shift light, and a protocol transcript in the debug log.
◔
Gauges & Dashboards
Seven gauge primitives plus G-force and compass widgets, JSON-defined dashboards (five built-in presets plus your own), a chooser with live miniatures, and an in-app drag-and-drop dashboard editor.
☏
Phone Mirror & Android Auto
Mirror an Android phone over USB or Wi-Fi with the built-in scrcpy-protocol client (PyAV decode). Android Auto uses Google's Desktop Head Unit, embedded into OCTAVE's window on Windows only.
↧
Music Download
Search YouTube Music and download tracks through the vendored music_dl package (yt-dlp, ytmusicapi). Finished downloads trigger a library rescan.
⚙
Hardware Integrations
ESP32 wireless volume knob (ESP-NOW pair, USB dongle, LED ring), BerryIMU v3 attitude and heading readings, and PAJ7620U2 gesture recognition (I²C sensors on Linux).
⛟
Live 3D Vehicle
A rigged Jeep TJ in Qt Quick 3D with working doors, hood, tailgate, lights, steering and wheels, rolled and pitched in real time by the IMU.
◆
Dynamic Theming
UI colours adapt in real time to album art. Accent, background and text colours are extracted and applied across every view (and to the ESP32 LED ring).
∿
Waveform Visualizer
FFT visualisation with 96 frequency bars for local tracks or live mirrored phone audio, rendered in QML.
✎
Diagnostics & Logs
Rotating log files, crash tracebacks and faulthandler dumps, a UI-thread watchdog, and a Diagnostics card that copies or exports the logs straight from the dash.
↻
Network & Updates
WiFi status, GitHub update checks and git-based self-update with in-app restart for checkout installs.

Platform Support

Every platform runs the same way: from a checkout, in a venv, with python setup.py or python main.py (see Running from Source).

Platform Notes
Linux (Debian/Ubuntu, Arch, Fedora families) setup.py installs the Qt runtime libraries with the distro package manager (sudo). I²C sensors need an accessible bus and smbus2 (installed on Linux only). The Bluetooth OBD adapter finder (BlueZ over D-Bus) is Linux-only. Android Auto cannot be embedded (window lookup is Win32-only).
Raspberry Pi / Orange Pi (Linux aarch64) The in-vehicle target; setup.py recognises a Raspberry Pi from the device-tree model and treats it as Linux. Google publishes no aarch64 adb, so phone mirroring needs an adb installed separately.
Windows 10+ No system packages are installed by setup.py. I²C hardware (BerryIMU, gesture sensor) is unavailable. Android Auto's DHU window is embedded with Win32 calls and works only here.
macOS (Intel and Apple Silicon) No system packages are installed by setup.py. I²C hardware and Android Auto embedding are unavailable.

Tech Stack

Component Implementation
Language / runtime Python ≥ 3.10 (pyproject.toml; CI tests 3.11), PySide6 ≥ 6.8 (requirements.txt), venv created by setup.py
Frontend QML (Qt Quick, Qt Quick Controls "Basic" style, Qt5Compat.GraphicalEffects, QtQuick.Effects, Qt Quick 3D for the vehicle view) loaded from frontend/ at runtime
Audio playback / tags QMediaPlayer + mutagen
Waveform FFT PyAV (av) decode + numpy FFT on a single-worker thread pool
OBD-II python-obd (obd.Async) over pyserial; an rfcomm:// pyserial URL handler for direct Bluetooth RFCOMM sockets on Linux (backend/obd_transports/)
Music download vendored backend/music_dl package: yt-dlp, ytmusicapi, rapidfuzz
I²C sensors smbus2 (Linux only)
ESP32 serial pyserial
Phone mirror sockets + PyAV H.264 decode → QVideoSink; PCM audio → QAudioSink
Phone side phone_server/ — OCTAVE's fork of the scrcpy server (v3.3.4, Apache-2.0), prebuilt jar in tools/phone-server/; Google platform-tools (adb) fetched by scripts/fetch_platform_tools.py
Logging logging hierarchy under octave.*, rotating files, faulthandler
Lint, tests & CI ruff (pyproject.toml) and a headless pytest suite in tests/, run by the lint and test GitHub Actions jobs; never packaged
