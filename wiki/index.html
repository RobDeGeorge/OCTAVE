OCTAVE Wiki

The complete reference for the Open-source Cross-platform Telematics for Augmented Vehicle Experience. Everything you need to understand, use, modify, and extend OCTAVE — both backends and the shared frontend.

What is OCTAVE?

OCTAVE is an open-source (MIT) car head unit / infotainment system you run on your own hardware. It pairs a C++ / Qt 6 backend — the shipped binary on every platform — with a parallel Python / PySide6 backend for desktop development and tinkering, both driving a single shared QML frontend. It plays local music and Spotify, reads live data from the car over OBD-II, mirrors an Android phone over USB, shows a live 3D model of the vehicle from an IMU, and recolours its interface to match the album art. It runs on Windows, macOS, Linux, Raspberry Pi / Orange Pi class boards, and Android (iOS is planned but not built yet).

The typical installation is a single-board computer behind the dash, a touchscreen, a power source and a 3D-printed mount (the author daily-drives it in a 2003 Jeep TJ on an Orange Pi 5 with a 2560×1080 display). Development and testing can happen on any desktop OS.

Core Features

♫
Local Media Player
MP3, M4A, FLAC, OGG, Opus and WAV playback with album art carousel, shuffle/repeat, playlists, a persistent metadata store, and album-art colour extraction.
♬
Spotify Integration
Spotify Web API with OAuth2 (local callback on port 8888), device switching, playback control and a cached token (OS keyring on Python, file on C++). Desktop only.
>_
OBD-II Diagnostics
92 vehicle parameters via an ELM327 adapter (USB / Bluetooth serial; BLE on Android), DTC read and clear, freeze frame, a full-screen shift light, and a protocol transcript in the logs.
◔
Gauges & Dashboards
Nine gauge primitives, JSON-defined dashboards (five built-in presets plus your own), a chooser with live miniatures, and an in-app drag-and-drop dashboard editor.
☏
Phone Mirror & Android Auto
Mirror an Android phone over USB with a built-in scrcpy-protocol client and bundled adb — nothing to install on the phone — or run Android Auto through Google's Desktop Head Unit.
↧
Music Download
Search and download music with Spotify metadata matching and YouTube audio extraction (yt-dlp). Auto-adds to your library. Compiled out for app-store builds.
⚙
Hardware Integrations
ESP32 wireless volume knob (ESP-NOW pair, USB dongle, LED ring), BerryIMU v3 9DOF sensor fusion (Madgwick AHRS), PAJ7620U2 gesture recognition.
⛟
Live 3D Vehicle
A rigged Jeep TJ in Qt Quick 3D with working doors, hood, tailgate, lights, steering and wheels, rolled and pitched in real time by the IMU.
◆
Dynamic Theming
UI colours adapt in real time to album art. Accent, background and text colours are extracted and applied across every view (and to the ESP32 LED ring).
∿
Waveform Visualizer
FFT waveform visualisation with 96 frequency bars, pre-computed off the UI thread and rendered directly in QML.
✎
Diagnostics & Logs
Rotating logs from both backends, crash backtraces, a UI-thread watchdog, and a Diagnostics page that copies or exports the logs straight from the dash.
↻
Network & Updates
WiFi status, GitHub update checks and git-based self-update with in-app restart for checkout installs.

Platform Support

Platform Status Shipped artefact Notes
Linux (Debian/Ubuntu/Arch/Fedora) Full support OCTAVE-<v>-linux-x86_64.AppImage Primary development target. All features. Both backends.
Raspberry Pi / Orange Pi (Linux aarch64) Full support OCTAVE-<v>-linux-aarch64.AppImage The in-vehicle target. I²C sensors and the ESP32 knob supported. Google ships no aarch64 adb, so the distro adb is used for phone mirroring.
Windows 10+ Full support OCTAVE-<v>-windows-x86_64.exe (Inno Setup) All features except I²C hardware (BerryIMU, gesture sensor). Python-backend Android Auto capture is Windows-only.
macOS (Intel and Apple Silicon) Full support OCTAVE-<v>-macos.dmg All features except I²C hardware. CI builds on macOS 14 against Qt 6.7.3.
Android (arm64-v8a, Android 11+) Sideload OCTAVE-<v>-android-arm64-v8a.apk C++ only. Local media, OBD over BLE, YouTube Music search and download, dashboards, IMU view from the device's own sensors. Spotify, phone mirror, Android Auto, ESP32 and I²C sensors are excluded. The release APK is signed with a per-build keystore, so updates require an uninstall.
iOS Planned, not built — No CMake toolchain wiring and no CI job yet (see BUILD.md, "iOS build").

Tech Stack

Component C++ backend (shipped) Python backend (developer)
Language / toolchain C++17, Qt 6.7.3, CMake 3.21+ (Ninja recommended) Python ≥ 3.10 (pyproject.toml; CI tests 3.11), PySide6 ≥ 6.8 (requirements.txt), venv via setup.py
Frontend QML (Qt Quick, Qt Quick Controls "Basic" style, Qt5Compat.GraphicalEffects, QtQuick.Effects, Qt Quick 3D for the vehicle view) loaded from frontend/ at runtime
Audio playback / tags QMediaPlayer + TagLib QMediaPlayer + mutagen
Waveform FFT QAudioDecoder + in-house radix-2 FFT on QtConcurrent PyAV (av) decode + numpy FFT on a thread pool
Spotify QNetworkAccessManager + QTcpServer OAuth callback; token file in the app data dir spotipy + keyring (OS keychain)
OBD-II QSerialPort + own ELM327 protocol (elm327protocol.cpp); Android: native BluetoothGatt via JNI (OctaveOBDBridge.java) python-obd (obd.Async) over pyserial
Music download yt-dlp via QProcess; Android: youtubedl-android AAR + bundled ytmusic Python vendored music_dl package: yt-dlp, ytmusicapi, rapidfuzz
I²C sensors /dev/i2c-N + ioctl; Android: QtSensors (accelerometer, compass, pressure) smbus2 (Linux only)
ESP32 serial QSerialPort pyserial
Phone mirror QTcpSocket + libavcodec (FFmpeg, optional at build) → QVideoSink; QAudioSink sockets + PyAV → QVideoSink; QAudioSink
Phone side phone_server/ — OCTAVE's fork of the scrcpy server (v3.3.4, Apache-2.0), prebuilt jar in tools/phone-server/; bundled Google platform-tools (adb)
Logging QLoggingCategory + src/util/logger.cpp rotating files, signal crash handlers logging hierarchy under octave.*, rotating files, faulthandler
Build & CI GitHub Actions: compile check + qmllint on every push; Windows / macOS / Linux x86_64 / Linux aarch64 / Android on tags ruff lint + headless pytest smoke and boot tests on every push; never packaged
