System Requirements

RequirementMinimumNotes
Python 3.8+ Desktop developer backend only — not used for Android (C++/Qt) builds
OS Windows 10+, macOS 10.14+, Linux Raspberry Pi OS fully supported
Display Any resolution Auto-scales based on screen height (720p baseline). Scale factor clamped to 0.4–3.0.
Audio PulseAudio / ALSA / CoreAudio / DirectSound Required for media playback. Qt uses the platform's native audio.
Network Optional Required for Spotify, music download, and update checking. Local playback works offline.

Quick Start

The fastest path from zero to running:

# Clone the repository
git clone https://github.com/waybettersolutions/octave.git
cd octave

# Setup and run (creates venv, installs deps, launches app)
python setup.py

That's it. The setup.py script handles everything automatically. If you only want to install without launching:

python setup.py --no-run

To run manually after setup:

# Linux / macOS
source venv/bin/activate
python main.py

# Windows
venv\Scripts\activate
python main.py

What setup.py Does

setup.py

The setup script performs these steps in order:

  1. Detects your platform — Identifies Windows, macOS, Linux, or Raspberry Pi. On Linux, detects the distro family (Arch, Debian, Fedora) by reading /etc/os-release or falling back to package manager detection (pacman, apt, dnf).
  2. Checks Python version — Ensures Python 3.8 or higher is available. Exits with a clear error if not.
  3. Installs system dependencies (Linux only) — Uses the appropriate package manager to install required system libraries: audio (PulseAudio/ALSA), OpenGL/EGL, XCB platform plugins, X11 libs, fonts, D-Bus, and Qt6 base packages.
  4. Creates a virtual environment — Uses Python's built-in venv module to create an isolated environment at ./venv/. If an existing venv is incompatible (wrong platform or broken pip), it is automatically recreated.
  5. Installs Python dependencies — Upgrades pip, then installs everything from requirements.txt into the venv.
  6. Launches the application — Unless --no-run is passed, replaces the setup process with the OCTAVE app via os.execv().

Linux Installation

Linux is the primary development and deployment platform. The setup script automatically installs system-level dependencies via your distro's package manager.

  libxcb xcb-util xcb-util-cursor xcb-util-image xcb-util-keysyms \

Raspberry Pi

Raspberry Pi OS (Debian-based) uses the same apt packages as Debian. The setup script automatically detects Raspberry Pi by reading /sys/firmware/devicetree/base/model.

OBD-II Bluetooth
To use OBD-II via Bluetooth on Linux, add your user to the dialout group: 
sudo usermod -a -G dialout $USER
Log out and back in for the change to take effect.

Windows Installation

  1. Install Python 3.8+ from python.org. Check "Add Python to PATH" during installation.
  2. Clone and run setup: 
    git clone https://github.com/waybettersolutions/octave.git
cd octave
python setup.py

No system dependencies are needed on Windows. PySide6 bundles everything required. The venv activation command on Windows is venv\Scripts\activate.

macOS Installation

  1. Install Python 3.8+ via Homebrew (brew install python) or from python.org.
  2. Clone and run setup: 
    git clone https://github.com/waybettersolutions/octave.git
cd octave
python3 setup.py

macOS system dependencies are typically pre-installed. If you encounter OpenGL issues, ensure you're running macOS 10.14+.

Android Build

The Android app is built from the C++ / Qt 6 tree in src/ as a native .apk — not from Python. The Python backend in backend/ is a desktop-only developer backend and is never packaged for mobile. (The old Buildozer / python-for-android path has been removed and will not be reintroduced.)

Full toolchain lives in BUILD.md
The complete step-by-step Android setup — Qt for Android 6.7.3, OpenJDK 17, the Android SDK + NDK 26.1.10909125, environment variables, and APK signing — is documented in BUILD.md under Android build. The summary here is orientation only.

Prerequisites

  • Linux host — with roughly 40–60 GB free on the $HOME disk
  • Qt for Android 6.7.3 (android_arm64_v8a) plus the matching host Qt
  • OpenJDK 17 — required by Android Gradle Plugin 8.x (not 11, not 21)
  • Android SDK (platform android-34) and NDK 26.1.10909125

Build the APK

With the toolchain environment variables set (see BUILD.md), configure and build with Qt's qt-cmake cross-compile wrapper. OpenSSL for Android is wired in at build time via the KDAB android_openssl CMake project — no separate install step: 

# arm64-v8a, Android 11+ (see BUILD.md for the full flag set incl. signing)
qt-cmake -S . -B build-android \
    -DCMAKE_BUILD_TYPE=Release \
    -DANDROID_PLATFORM=android-30

cmake --build build-android -j
# androiddeployqt produces the .apk under build-android/

Android Feature Differences

On Android everything runs through the C++ backend; platform-specific behavior is gated behind #ifdef Q_OS_ANDROID in the relevant managers (there is no Python mirror for mobile). The desktop ↔ Android feature split:

FeatureDesktopAndroid
OBD-II USB / Bluetooth ELM327 Bluetooth & BLE ELM327 (C++)
Spotify Full Web API integration Excluded from the build (simpler OAuth, smaller footprint)
IMU / Gesture Sensors BerryIMU + PAJ7620U2 via I2C (smbus2) Not applicable (desktop/Pi hardware)
Volume Knob ESP32 via USB serial Not applicable (desktop/Pi hardware)
Phone Mirror scrcpy-based screen mirroring Not applicable
Android Auto Google DHU capture Not applicable

WSL Notes

OCTAVE can run under WSL (Windows Subsystem for Linux) but requires a display server. The setup script detects WSL by checking for "microsoft" in /proc/version.

  • WSLg (Windows 11) — Should work automatically. Run wsl --update to ensure it's current.
  • X Server (Windows 10) — Install VcXsrv or X410, then set export DISPLAY=:0.

If no display is detected (DISPLAY and WAYLAND_DISPLAY both unset), the setup script will install dependencies but skip launching.

Running OCTAVE

Standard Mode

source venv/bin/activate
python main.py

Debug Mode

Enables DEBUG-level logging and creates octave-debug.log:

python main.py --debug

Performance Profiling

Enables the performance monitor with CSV and log export to dev/perf/logs/:

python main.py --profile

Profiling also starts a Command Server (TCP) for remote control via MCP, and instruments hot paths across all managers.

Developer Mode

dev/main_dev.py

Developer mode provides simulated OBD data and keyboard controls for testing without hardware or a vehicle connection. The dev/ directory is fully isolated from production code and is gitignored. 

source venv/bin/activate
python -m dev.main_dev
Dev Mode Features
  • Mock OBD data with simulated RPM, speed, and temperature
  • Development tools panel for testing
  • Keyboard shortcuts for media control
  • No hardware required

First Steps After Install

  1. Set your music directory — Open Settings and point the media library to a folder containing MP3, M4A, or FLAC files. OCTAVE will scan and index them automatically.
  2. Configure Spotify (optional) — Go to Settings > Spotify and enter your Spotify API credentials (Client ID and Client Secret from the Spotify Developer Dashboard). Tokens are stored securely in your OS keychain.
  3. Connect OBD-II (optional) — Plug in an ELM327 adapter (USB or Bluetooth) and OCTAVE will auto-detect it. On Linux, ensure your user is in the dialout group.
  4. Explore Settings — OCTAVE has 100+ configurable settings across display, media, OBD, hardware, and more. The settings pages are organized by category with sliders, toggles, and dropdowns.
