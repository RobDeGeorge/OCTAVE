Which Path Do I Want?

Whichever backend you run, the QML frontend in frontend/ is the same and the settings file is shared, so you can switch between them on one machine.

Installing a Pre-built Release

Every release on the GitHub Releases page is built from the C++ tree by CI. No toolchain, no Python.

macOSOCTAVE-<version>-macos.dmgOpen, drag to Applications. adb is inside the bundle.

Python Quick Start

The fastest development loop, from zero to a running app:

# Clone the repository
git clone https://github.com/waybettersolutions/octave.git
cd octave

# Setup and run (creates venv, installs deps, launches app)
python setup.py

If you only want to install without launching:

python setup.py --no-run

To run manually after setup:

# Linux / macOS
source venv/bin/activate
python main.py

# Windows
venv\Scripts\activate
python main.py
Python is desktop-only
The Python backend runs on Linux, Windows, macOS and Raspberry Pi / Orange Pi. It is never packaged (there is no PyInstaller pipeline) and never runs on Android or iOS — mobile is C++-only.

What setup.py Does

setup.py

The setup script performs these steps in order:

  1. Detects your platform — Windows, macOS, Linux, or Raspberry Pi (by reading /sys/firmware/devicetree/base/model). On Linux it detects the distro family (Arch, Debian, Fedora) from /etc/os-release, falling back to whichever of pacman, apt, dnf/yum is on PATH. It also notes WSL ("microsoft" in /proc/version).
  2. Checks the Python version — exits with "Python 3.10+ required" if below 3.10 (the same floor pyproject.toml declares; see requirements above).
  3. Installs system dependencies (Linux only, via sudo) — audio (PulseAudio/ALSA), OpenGL/EGL, the XCB platform-plugin libraries, X11, fonts, D-Bus, and on Arch/Fedora the Qt 6 base + multimedia packages. Missing packages are ignored rather than fatal.
  4. Creates a virtual environment at ./venv/ with the built-in venv module. An existing venv from the other OS family (a Dropbox-synced Windows venv on Linux, say) or one whose pip no longer runs is removed and recreated.
  5. Installs Python dependencies — upgrades pip, then pip install -r requirements.txt.
  6. Launches the application — unless --no-run is passed (or WSL has no display), it replaces itself with venv/bin/python main.py via os.execv().

Raspberry Pi / Orange Pi

Raspberry Pi OS (Debian-based) uses the same apt packages as Debian. The setup script detects a Raspberry Pi from the device-tree model string. For an Orange Pi or any other aarch64 board the same Debian path applies; the author's Jeep runs an Orange Pi 5 Plus. smbus2 (I²C for BerryIMU and the gesture sensor) is installed automatically on Linux.

Serial devices (OBD adapters, ESP32 knob)
On Linux, add your user to the dialout group so USB serial and Bluetooth rfcomm devices are accessible without root: 
sudo usermod -a -G dialout $USER
Log out and back in for the change to take effect.

Windows (Python backend)

  1. Install Python 3.10 or newer from python.org. Check "Add Python to PATH" during installation.
  2. Clone and run setup: 
    git clone https://github.com/waybettersolutions/octave.git
cd octave
python setup.py

No system dependencies are needed on Windows — the PySide6 wheel bundles Qt. The venv activation command is venv\Scripts\activate. smbus2 is skipped (no I²C on Windows).

macOS (Python backend)

  1. Install Python 3.10 or newer via Homebrew (brew install python) or from python.org.
  2. Clone and run setup: 
    git clone https://github.com/waybettersolutions/octave.git
cd octave
python3 setup.py

macOS needs no extra system packages for the Python backend; setup.py only prints a note and proceeds to the venv.

WSL Notes

OCTAVE can run under WSL (Windows Subsystem for Linux) but requires a display server. The setup script detects WSL by checking for "microsoft" in /proc/version.

  • WSLg (Windows 11) — Should work automatically. Run wsl --update to ensure it's current.
  • X Server (Windows 10) — Install VcXsrv or X410, then set export DISPLAY=:0.

If no display is detected (DISPLAY and WAYLAND_DISPLAY both unset), the setup script installs dependencies but skips launching.

Building the C++ Backend

The C++ tree is what ships. A desktop build needs CMake 3.21+, Qt 6.7.3 (the CI-pinned version; other 6.7.x / 6.8.x will likely work but are untested) with the Multimedia, NetworkAuth, SerialPort, Connectivity, Qt5Compat and ShaderTools modules, TagLib, and optionally FFmpeg (libavcodec/libavutil, for the built-in phone-mirror decoder) and Qt Quick 3D (for the 3D vehicle view). 

# Configure + build (Debug, current platform)
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j

# Run — the binary finds frontend/ one directory up from build/
./build/octave            # Linux / macOS
./build/Debug/octave.exe  # Windows (MSVC multi-config)

# App-store variant: music download feature compiled out
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DOCTAVE_ENABLE_DOWNLOADS=OFF
cmake --build build -j

CMake reports Built-in phone mirror decoder (libavcodec): ON/OFF and whether QtQuick3D was found at configure time; both are optional and the app degrades gracefully without them (external scrcpy for mirroring, greyed-out "3D View" card). Per-platform package lists, the AppImage / DMG / Inno Setup packaging that CI runs, and the pinned tool versions are in BUILD.md and on the Building & CI/CD page.

The C++ binary also runs the Python backend's QML
Both backends load frontend/Main.qml from disk at runtime rather than compiling it in, so a QML change is visible on the next launch of either without a rebuild. On Android the directory is bundled as assets:/frontend.

Android Build

The Android app is built from the C++ / Qt 6 tree in src/ as a native .apk for arm64-v8a (Android 11+, minSdk 30, package org.octave.app) — not from Python. The old Buildozer / python-for-android path has been removed and will not be reintroduced.

Full toolchain lives in BUILD.md
The complete step-by-step Android setup — Qt for Android 6.7.3 via aqtinstall, OpenJDK 17, the Android SDK + NDK 26.1.10909125, environment variables (QT_HOST_PATH is required), and APK signing — is documented in BUILD.md under Android build. The summary here is orientation only.

Prerequisites

  • Linux host with roughly 40–60 GB free on the $HOME disk
  • Qt for Android 6.7.3 (android_arm64_v8a) plus the matching host Qt (gcc_64) for androiddeployqt
  • OpenJDK 17 — required by Android Gradle Plugin 8.x (not 11, not 21)
  • Android SDK (platform android-34, Build-Tools 35.0.0) and NDK 26.1.10909125

Build the APK

With the toolchain environment variables set (see BUILD.md), configure with Qt's qt-cmake cross-compile wrapper and build the apk target. OpenSSL for Android is wired in at build time via the KDAB android_openssl CMake project: 

qt-cmake -S . -B build-android \
    -DCMAKE_BUILD_TYPE=Debug \
    -DANDROID_ABI=arm64-v8a \
    -DANDROID_PLATFORM=android-30 \
    -DOCTAVE_ENABLE_DOWNLOADS=OFF \
    -DQT_ANDROID_SIGN_APK=OFF

cmake --build build-android --target apk -j
adb install build-android/android-build/build/outputs/apk/debug/android-build-debug.apk

CI builds Release with downloads left on (the default for sideload APKs; the youtubedl-android AAR bundles Python, yt-dlp and ffmpeg) and signs with a throw-away keystore. If adb install reports INSTALL_FAILED_UPDATE_INCOMPATIBLE, a differently-signed build is already installed — uninstall it first.

Android Feature Differences

On Android everything runs through the C++ backend; desktop-only managers are compiled as stub classes behind Q_OS_MOBILE so the QML keeps working, and Android-specific code sits behind #ifdef Q_OS_ANDROID. The desktop ↔ Android split:

FeatureDesktopAndroid
OBD-II USB or Bluetooth-SPP ELM327 through a serial port (/dev/ttyUSB*, /dev/rfcomm0, COMn) BLE ELM327 through a native BluetoothGatt JNI bridge (android/src/org/octave/app/OctaveOBDBridge.java)
Spotify Full Web API integration Excluded (stub) — simpler OAuth, smaller footprint for store review
IMU BerryIMU v3 over I²C Device's own sensors via QtSensors (accelerometer, compass, pressure)
Gesture sensor, ESP32 knob PAJ7620U2 over I²C; ESP32 over USB serial Not applicable (stubs)
Phone mirror, Android Auto Built-in scrcpy-protocol client; Google DHU capture Not applicable (stubs)
Music download yt-dlp as a subprocess youtubedl-android AAR + bundled ytmusic script; off with OCTAVE_ENABLE_DOWNLOADS=OFF
Local media, dashboards, theming, diagnostics Same on both (runtime permissions READ_MEDIA_AUDIO / BLUETOOTH_* are requested at first launch on Android)

Running OCTAVE

Standard Mode

# Python
source venv/bin/activate
python main.py

# C++
./build/octave

Debug Logging

Both backends accept --debug. It enables DEBUG-level output and creates the extra rotating debug log (octave-debug.log / octave-cpp-debug.log) in the config directory's logs/ folder; without it, debug messages are filtered at the source.

python main.py --debug
./build/octave --debug

Performance Profiling (Python, developer machines only)

python main.py --profile

Starts the PerfMonitor (CSV + log under dev/perf/logs/, exposed to QML as perfMonitor), a command server on 127.0.0.1:9876 for remote control and the MCP tools, and instruments hot paths. The modules behind it (backend/perf_monitor.py, backend/command_server.py, backend/perf_patches.py) are gitignored developer files, so --profile only does something on a machine that has them: on a checkout without them setup_perf_profiling() logs a warning for each missing module (--profile: backend/perf_monitor.py not present (gitignored dev tooling), skipping ...) and the app starts normally instead of raising ImportError.

Developer Mode

dev/main_dev.py

Developer mode provides simulated OBD data and keyboard controls for testing without hardware or a vehicle. It imports main.py, installs a MockOBDManager through install_obd_manager() before the QML loads, and adds a dev overlay. The dev/ directory is gitignored — it exists on the maintainers' machines and is fully isolated from production code, but is not part of a fresh clone. 

source venv/bin/activate
python -m dev.main_dev
python -m dev.main_dev --profile   # + command server, used by the screenshot / MCP tooling
Dev Mode Features
  • Mock OBD data with simulated RPM, speed, temperatures and throttle
  • Development tools panel and overlay
  • Keyboard shortcuts for media control
  • Screenshot and story-driven clip recording (python -m dev.screenshots), MCP server for agents
See Development.

First Steps After Install

  1. Set your music directory — Open Settings and point the media library at a folder of MP3 / M4A / FLAC / OGG / Opus / WAV files. OCTAVE scans it, extracts album art and caches tags in metadata_cache.json so later launches are instant.
  2. Configure Spotify (optional, desktop) — Settings > Spotify, enter a Client ID and Client Secret from the Spotify Developer Dashboard with http://127.0.0.1:8888/callback as the redirect URI. The token is cached in your OS keychain (Python) or in the OCTAVE config directory (C++).
  3. Connect OBD-II (optional) — Plug in an ELM327 adapter (USB, or pair a Bluetooth one and select its port in Settings > OBD). On Linux make sure you are in the dialout group. Then open the OBD page, pick a dashboard from the chooser, or build your own in the editor.
  4. Try the 3D view — Sensors > 3D View shows the Jeep model; with a BerryIMU attached it follows the vehicle's attitude (use ZERO on level ground).
  5. Explore Settings — OCTAVE has 100+ configurable settings across display, media, OBD, accessories and device, all persisted to settingsConfigure.json. Settings > About > Diagnostics shows the running backend, its version, and lets you export the logs.
