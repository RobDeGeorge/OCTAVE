System Requirements

RequirementMinimumNotes
OS Linux, Windows, macOS Desktop only. setup.py recognises Raspberry Pi from the device-tree model string; other Debian-based boards (e.g. Orange Pi) take the normal Linux path.
Python 3.10+ pyproject.toml declares requires-python = ">=3.10" with no upper bound and setup.py exits below 3.10; CI tests Python 3.11.
Qt PySide6 6.8.0+ Installed from PyPI by requirements.txt; the wheel brings its own Qt libraries.
Display Any size main.py divides the shorter edge of the primary screen's available size by 720 and clamps the result to 0.4–3.0 (screenAutoScale); the user's UI scale setting is applied on top. Without a primary screen it uses 1.0.
Audio Working system audio output Playback uses Qt Multimedia from PySide6; available codecs depend on that build.
Network Optional Needed for music search / download and update checks. Local playback, OBD and USB phone mirroring work offline.

Quick Start

From zero to a running app:

# Clone the repository
git clone https://github.com/RobDeGeorge/OCTAVE.git
cd OCTAVE

# Setup and run (creates venv, installs deps, launches app)
python setup.py

To install without launching:

python setup.py --no-run

To run manually after setup:

# Linux / macOS
source venv/bin/activate
python main.py

# Windows
venv\Scripts\activate
python main.py
Runs from a checkout
The Python backend is not packaged: there is no installer or frozen executable. It always runs as python main.py inside the checkout's virtual environment, and it reads the QML from frontend/ on disk, so a QML change shows on the next launch.

What setup.py Does

setup.py

The script changes to its own directory and performs these steps in order:

  1. Detects your platform — Windows, macOS, Linux, or Raspberry Pi (if /sys/firmware/devicetree/base/model contains "raspberry"), and WSL ("microsoft" in /proc/version).
  2. Checks the Python version — exits with "Python 3.10+ required" below 3.10.
  3. Installs system dependencies (Linux and Raspberry Pi only, via sudo) — the distro family (Arch, Debian, Fedora) comes from /etc/os-release, falling back to whichever of pacman, apt, dnf/yum is on PATH; anything unrecognised takes the Debian list. The packages are audio (PulseAudio/ALSA), OpenGL/EGL, the XCB platform-plugin libraries, X11 and input, fonts, D-Bus, and on Arch/Fedora the Qt 6 base + multimedia packages. Package-manager failures do not stop the script, so read its output if something is still missing. On macOS and Windows this step only prints a note.
  4. Creates a virtual environment at ./venv/ with the built-in venv module. An existing venv is kept if its pyvenv.cfg matches the OS family (a C:\ path marks a Windows venv) and its pip --version runs; otherwise it is deleted and recreated. If the deletion fails it is renamed to venv_old_<timestamp> (the deletion passes shutil.rmtree(onexc=...), which needs Python 3.12, so on 3.10 and 3.11 the rename is what happens).
  5. Installs Python dependencies — upgrades pip, then pip install -r requirements.txt; a failure exits the script.
  6. Launches the application — unless --no-run is passed (it then prints the activate-and-run commands) or WSL has no display, it replaces itself with the venv's python main.py via os.execv().

Linux

Linux is the main development platform. The setup script installs the system-level dependencies below through your distro's package manager; they are what PySide6's xcb platform plugin and Qt Multimedia need at runtime.

Arch Linux / Manjaro / EndeavourOS

System packages installed via pacman:

sudo pacman -S --needed --noconfirm python python-pip libpulse alsa-lib mesa libglvnd \
  libxcb xcb-util xcb-util-cursor xcb-util-image xcb-util-keysyms \
  xcb-util-renderutil xcb-util-wm libx11 libxkbcommon libxkbcommon-x11 \
  libxi libsm libice fontconfig freetype2 harfbuzz dbus libxrender \
  libxext libxrandr libxfixes libxcomposite libxdamage libxtst libxss \
  qt6-base qt6-multimedia
Note
On Arch, venv is part of the python package. No separate install needed.

Debian / Ubuntu / Mint / Pop!_OS

System packages installed via apt (after sudo apt update):

sudo apt install -y python3 python3-venv python3-pip libpulse0 libasound2 \
  libegl1 libgl1 libopengl0 libglx-mesa0 libgl1-mesa-dri libegl1-mesa \
  libgles2 libxcb1 libxcb-cursor0 libxcb-icccm4 libxcb-image0 \

  libxcb-xkb1 libxcb-util1 libx11-6 libx11-xcb1 libxkbcommon0 \
  libxkbcommon-x11-0 libxi6 libsm6 libice6 libfontconfig1 libfreetype6 \
  libharfbuzz0b libdbus-1-3 libxrender1 libxext6 libxrandr2 libxfixes3 \

The list is installed in one apt install; a package name that a release does not have makes apt refuse the whole command, and the script carries on regardless, so check the output and install the rest by hand if needed.

Raspberry Pi / Orange Pi

Raspberry Pi OS is Debian-based, so the script installs the Debian list above. An Orange Pi or another aarch64 board is detected as plain Linux and takes the same path through its distro. smbus2 (I²C for the BerryIMU and the gesture sensor) has the marker sys_platform == "linux" in requirements.txt, so it is installed on every Linux machine. PySide6 must have a wheel for the board's architecture and Python version; see Hardware Setup for the sensors.

Serial devices (OBD adapters, ESP32 knob)
On Linux, add your user to the dialout group so USB serial and Bluetooth rfcomm devices are accessible without root: 
sudo usermod -a -G dialout $USER
Log out and back in for the change to take effect.

Windows

  1. Install Python 3.10 or newer from python.org. Check "Add Python to PATH" during installation.
  2. Clone and run setup: 
    git clone https://github.com/RobDeGeorge/OCTAVE.git
cd OCTAVE
python setup.py

setup.py installs no system packages on Windows; the PySide6 wheel bundles Qt. It reconfigures stdout to UTF-8 when the console encoding is not, so its check marks print. The venv activation command is venv\Scripts\activate. smbus2 is skipped (Linux only). Optional features need their own tools, such as adb for phone mirroring.

macOS

  1. Install Python 3.10 or newer via Homebrew (brew install python) or from python.org.
  2. Clone and run setup: 
    git clone https://github.com/RobDeGeorge/OCTAVE.git
cd OCTAVE
python3 setup.py

On macOS setup.py prints "system dependencies should be available" and proceeds to the venv. Optional integrations can still require tools such as adb.

WSL Notes

OCTAVE can run under WSL (Windows Subsystem for Linux) but needs a display server. The setup script detects WSL from "microsoft" in /proc/version and treats it as Linux for the package install.

  • WSLg — follow Microsoft's GUI-app setup guide; the script suggests wsl --update.
  • External X server — if you use one instead of WSLg, set DISPLAY for that server and the WSL network mode (the script's hint mentions export DISPLAY=:0, which is not right for every setup).

If DISPLAY and WAYLAND_DISPLAY are both unset, the script installs everything, prints these options, and skips launching.

Running OCTAVE

Standard Mode

source venv/bin/activate
python main.py

main.py forces the Qt Quick Controls style to Basic, sets up logging, creates the QApplication and every manager, registers them as QML context properties, adds frontend/ to the QML import path and loads frontend/Main.qml. If PySide6.QtWebEngineQuick imports, it is initialised for the in-app wiki browser (wikiViewerAvailable), and on Linux --disable-gpu is appended to QTWEBENGINE_CHROMIUM_FLAGS for that browser only. SIGTERM and SIGINT quit the app through Qt (a 500 ms no-op timer lets Python see the signal inside app.exec()), so cleanup_on_quit() still stops child processes and flushes the settings.

Command-line flags

Parsed with argparse.parse_known_args(), so unknown arguments are ignored.

FlagEffect
--debugDEBUG-level console and file logging, plus the extra rotating octave-debug.log (10 MB, 2 backups). Without it the level is INFO.
--profileAfter the QML loads, runs setup_perf_profiling(): the perf monitor (perfMonitor, CSV + log under dev/perf/logs/), the command server on 127.0.0.1:9876 and method timing. These modules are gitignored developer files; on a fresh clone each missing one is logged as a warning (--profile: backend/perf_monitor.py not present (gitignored dev tooling), skipping ...) and the app starts normally. See Development.
--smokeLoads Main.qml, then exits with code 0 after 5 s (a launch check)

Logs

backend/logging_config.py writes rotating logs to the logs/ folder of the app-data directory (Linux ~/.config/OCTAVE/logs/, macOS ~/Library/Application Support/OCTAVE/logs/, Windows %APPDATA%\OCTAVE\logs\): octave.log (INFO and above, 5 MB, 3 backups), octave-error.log (ERROR and above, 2 MB, 5 backups) and, with --debug, octave-debug.log.

Developer Mode

Developer mode adds a simulated car and keyboard controls for testing without hardware or a vehicle. dev/main_dev.py imports main, installs a MockOBDManager through install_obd_manager() before the QML loads, and adds the dev overlay. The dev/ directory (dev mode and the screenshot / MCP / perf clients) and the --profile modules in backend/ are gitignored: they exist on the maintainers' machines but are not part of a fresh clone. 

source venv/bin/activate
python -m dev.main_dev
python -m dev.main_dev --profile     # + command server: what the screenshot / MCP tooling drives

The tools in dev/ that launch the app start the Python backend when OCTAVE_BACKEND=python is set (the screenshot and story tools also take --backend python).

Dev Mode Features
  • Simulated OBD data: RPM, speed, temperatures, throttle, load, trouble codes, VIN; optional simulated IMU motion
  • Dev overlay with a HUD and the DevToolsPanel
  • Keyboard driving (W/S throttle and brake, Q/R shift, F1–F4 scenarios, Tab for the HUD)
  • Screenshot sweeps and story clips (python -m dev.screenshots), MCP servers for agents
See Development.

First Steps After Install

  1. Set your music directory — the default library is ~/Music. Point the media folder setting at a folder of MP3 / M4A / MP4 / FLAC / OGG / Opus / WAV files; each sub-folder becomes a playlist. OCTAVE scans it, extracts album art and caches tags in metadata_cache.json so later launches do not re-read every file.
  2. Connect OBD-II (optional) — plug in a USB ELM327 adapter or pair a Bluetooth one and select its port in Settings > OBD. On Linux make sure you are in the dialout group. Then open the OBD page and pick a dashboard from the chooser, or build your own in the editor.
  3. Try the 3D view — Sensors > 3D View shows the Jeep model; with a BerryIMU attached it follows the vehicle's attitude.
  4. Explore Settings — display, media, OBD, accessories and device settings are all persisted to settingsConfigure.json in the app-data directory, with a backup copy that is used if the file is found damaged. Settings > Device > Diagnostics shows the version and the backend ("Python") and can export the logs.
