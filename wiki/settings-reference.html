Overview

Settings are owned by SettingsManager (src/managers/settingsmanager.{h,cpp} in the shipped C++ build, backend/settings_manager.py in the Python developer backend) and persisted to settingsConfigure.json in the OS-specific config directory:

  • Windows: %APPDATA%/OCTAVE/settingsConfigure.json
  • macOS: ~/Library/Application Support/OCTAVE/settingsConfigure.json
  • Linux / Raspberry Pi / Orange Pi: ~/.config/OCTAVE/settingsConfigure.json (or $XDG_CONFIG_HOME/OCTAVE/)
  • Android / iOS (C++ only): the Linux rule applied to QDir::homePath()

Both backends define the same 92 top-level default keys with identical literal defaults (verified key by key against both sources on 2026-09-10). Settings are read once at startup, validated against the defaults, served from memory, and written back atomically 500 ms after the last change. The mechanics are on the Settings Manager page; this page is the key catalogue.

How to read the tables:

  • Property: the QML-visible property name (same as the JSON key) or how QML reaches a key that has no property.
  • Type: JSON type; the C++ property type is noted where it differs from the Python one.
  • Default: the literal in both backends' default dicts.
  • Range / Values: what the save slot enforces (clamp or whitelist), and in parentheses the range the UI control offers when it is narrower. A dash means the slot stores whatever it is given.
  • UI: the page under frontend/settings/ (Display, Media, OBD, Accessories, Device, About) or the other QML file that writes the key. See Settings UI.
Pinnable settings
25 of these keys are also registered in SETTINGS_REGISTRY and can be pinned to the Quick Panel. They are marked pinnable in the description; the registry itself is documented on the Settings Manager page.

Persistence and File Format

One JSON object, 4-space indented, containing the 92 default keys (nested dicts for obdParameters, gestureMapping, customThemes, settingsMenuVisibility, expandedCards) plus any QML-only keys. Writes are:

  1. Validated once into the in-memory copy (types checked against the defaults; unknown keys kept)
  2. Coalesced behind a 500 ms single-shot timer, flushed at quit
  3. Written to a temp file in the same directory under an exclusive advisory lock (fcntl / msvcrt in Python, flock / LockFileEx in C++)
  4. chmod 600 on Unix
  5. Renamed over the real file (Windows: old file deleted first); direct write as the fallback

On load, a missing file is created from the defaults, a corrupt file is logged and replaced by defaults in memory, and wrong-typed values are replaced individually. Full detail: Settings Manager: JSON Persistence and Validation.

C++ / Python Parity Check

Result of comparing buildDefaultSettings() with _default_settings and both slot sets on 2026-09-10:

  • Keys: 92 in both; no key exists in only one backend.
  • Default values: identical for every key, including all 86 PID flags and the nine gesture bindings.
  • Properties / signals / slots: identical names. The shutdown flush is flushPendingSave() on both sides; Python keeps a flush_pending_save() alias for older callers.
Differences that affect stored values
  • mediaFolder resolves an empty value to QStandardPaths::MusicLocation in C++ and to ~/Music in Python. Identical on Linux and macOS; may differ on Windows and Android.
