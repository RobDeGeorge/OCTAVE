What This Page Is

OCTAVE keeps your settings in one file, settingsConfigure.json, in its configuration folder: ~/.config/OCTAVE/ on Linux, the Raspberry Pi and the Orange Pi, %APPDATA%/OCTAVE/ on Windows and ~/Library/Application Support/OCTAVE/ on macOS. This page lists every key that file can hold. How the file is loaded, checked and saved is on the Settings Manager page.

Each row is one key. Key is its name in the file, and the name a program uses for it. Name on screen is the label of its control; it is blank when the key has none. Type is bool (true or false), int (a whole number), number, text, list or object. Default is what a fresh install has. Range or allowed values is what OCTAVE accepts: "clamped" means a value outside the range is brought to the nearest end, "refused" means it is ignored and the old value stays, and "not checked" means any value of the right type is stored.

You can change almost everything here on screen, in Settings, and the tables follow the sections and cards you see there. The file is the fallback: for the few keys with no control (listed after the sections), or for repairing a setup that will not start. Close OCTAVE before you edit it, because OCTAVE writes the file again when a setting changes. A value of the wrong type is replaced by its default at the next start, and a key OCTAVE does not know is left alone. Values typed into the file are checked a little differently from values set on screen: a number marked "clamped" is still clamped, a text value that is not one of the allowed ones becomes the default, and a number marked "refused" is kept as you wrote it.

The settings registry. settingsManager also carries a list of 30 settings with a label, a kind of control and a range each, and pinnedSettings holds the ones a user has pinned from it. OCTAVE's own screen uses neither. They are there for other frontends that want to build a quick-settings panel; the API reference has the calls.

What Is Not in the File

The volume you are listening at is not saved: OCTAVE starts at Startup Volume every time, and settingsManager.currentVolume exists only while it runs. Keys of features that have been removed are deleted from the file at startup. Everything else about the file (the backup copy, what happens to a damaged file, when changes are written) is on the Settings Manager page.
