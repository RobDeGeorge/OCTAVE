Overview

Settings are owned by SettingsManager (backend/settings_manager.py, QML context property settingsManager) and persisted to settingsConfigure.json in the directory returned by get_app_data_dir() (created if missing):

  • Windows: %APPDATA%/OCTAVE/settingsConfigure.json
  • macOS: ~/Library/Application Support/OCTAVE/settingsConfigure.json
  • Linux / Raspberry Pi / Orange Pi: $XDG_CONFIG_HOME/OCTAVE/settingsConfigure.json, which is ~/.config/OCTAVE/ when XDG_CONFIG_HOME is unset

_default_settings defines 96 top-level keys (95 in the dict literal plus directoryHistory, added right after it). Settings are read once at startup, validated against the defaults, served from memory, and written back atomically 500 ms after the last change. The mechanics are on the Settings Manager page; this page is the key catalogue.

How to read the tables:

  • Property: the QML-visible property name (same as the JSON key) or how QML reaches a key that has no property.
  • Type: the Python type of the default, which is what the loader validates against (see Persistence).
  • Default: the literal in _default_settings.
  • Range / Values: what the save slot enforces (clamp or whitelist), and in parentheses the range the UI control offers when it is narrower. A dash means the slot stores whatever it is given.
  • UI: the page under frontend/settings/ (Display, Media, OBD, Accessories, Device, About) or the other QML file that writes the key. See Settings UI.
Pinnable settings
25 of these keys are also registered in SETTINGS_REGISTRY and can be pinned to the Quick Panel. They are marked pinnable in the description; the registry itself is documented on the Settings Manager page.

Persistence and File Format

One JSON object, 4-space indented (json.dumps(settings, indent=4)), containing the 96 default keys (nested dicts for obdParameters, gestureMapping, customThemes, settingsMenuVisibility, expandedCards) plus any QML-only keys. Writes are:

  1. Validated into the in-memory copy by _validate_settings() (types checked against the defaults; unknown keys kept)
  2. Coalesced behind a 500 ms single-shot timer; flushPendingSave() writes at quit
  3. Written to a temp file in the same directory (tempfile.mkstemp, under a non-blocking advisory lock: fcntl.flock on Unix, msvcrt.locking on Windows) and fsynced
  4. chmod 600 on Unix
  5. Replaced over the real file in one step (os.replace), then the directory is fsynced on Unix; on failure the temp file is removed, the existing file is left untouched and the error is logged

On load, a missing file is created from the defaults, a corrupt file is moved to settingsConfigure.json.corrupt and restored from the last known-good settingsConfigure.json.bak (defaults only if that fails too), and wrong-typed values are replaced individually. Keys of removed features (spotifyClientId, spotifyClientSecret, mediaSource, scrcpyAudioEnabled) are deleted from the file at startup, together with the old Spotify login token (.spotify_token_cache files and the OCTAVE_Spotify keyring entry). The .bak copy is refreshed once per session from a file that parsed cleanly. Two more load-time migrations: uiScale 0.6 → 1.0 and lastSettingsSection "clockSettings" → "displaySettings" (the latter in memory only).
