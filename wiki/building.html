Quick Start

Every shipped binary (Windows .exe, macOS .dmg, Linux AppImages, Android .apk) is built from the C++ / Qt 6 tree in src/ with CMake. There is no PyInstaller pipeline — the Python backend is never packaged (see below).

# Configure + build (Debug, current platform)
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j

# Run
./build/octave            # Linux/macOS
./build/Debug/octave.exe  # Windows MSVC multi-config

# App store build (downloads feature stripped out)
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DOCTAVE_ENABLE_DOWNLOADS=OFF
cmake --build build -j
Requirements (all desktops): CMake 3.21+, Qt 6.7.3 (the CI-pinned version; other 6.7.x / 6.8.x will likely work but are untested), a C++17 compiler (GCC 11+ / Clang 14+ / MSVC 2022), and Ninja recommended on Linux/macOS (cmake -G Ninja). Qt Quick 3D is optional at build time — without it the app still builds and the "3D View" card on the Sensors hub greys itself out. Full per-platform package lists live in BUILD.md.

CMake Options

OptionDefaultEffect
OCTAVE_ENABLE_DOWNLOADSONCompiles in DownloadManager (yt-dlp music download). Pass -DOCTAVE_ENABLE_DOWNLOADS=OFF for app-store / Android builds.
OCTAVE_HAVE_FFMPEGauto-detectedSet by CMake when libavcodec / libavutil are found (pkg-config or vcpkg). Provides the H.264 decoder for the built-in phone-mirror client; without it OCTAVE still builds but phoneMirrorManager.nativeAvailable is false. CMake prints Built-in phone mirror decoder (libavcodec): ON/OFF at configure time.

Qt components linked: Core, Gui, Qml, Quick, QuickControls2, Multimedia, Network, Concurrent, NetworkAuth, SerialPort, Bluetooth (+ Sensors on mobile); Quick3D is probed with find_package(Qt6 QUIET COMPONENTS Quick3D). The QML frontend additionally needs QtQuick.Effects (Qt ≥ 6.5) and Qt5Compat.GraphicalEffects at runtime — distro Qt 6.2 (Ubuntu 22.04) links fine and then fails at Main.qml load.

Windows Build

Windows

Requirements

  • Visual Studio 2022 with the "Desktop development with C++" workload
  • Qt 6.7.3 (msvc2019_64 or msvc2022_64) via the Qt online installer
  • vcpkg for taglib and ffmpeg[core,avcodec]
  • (CI only) Inno Setup 6 for the installer
cmake -S . -B build `
  -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_INSTALLATION_ROOT/scripts/buildsystems/vcpkg.cmake" `
  -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j

Output

  • build\Release\octave.exe — the built executable
  • dist\OCTAVE-<version>-windows-x86_64.exe — Inno Setup installer produced by CI (windeployqt then iscc.exe build_scripts/installer_windows.iss)

build_scripts/installer_windows.iss is the only file left in build_scripts/; it creates the Start Menu shortcuts and uninstaller.

macOS Build

macOS

Requirements

  • Xcode Command Line Tools (xcode-select --install)
  • Qt 6.7.3 (Apple Silicon and Intel), e.g. via aqt install-qt mac desktop 6.7.3 -O ~/Qt -m qtmultimedia qtnetworkauth qtserialport qtconnectivity qtsensors qtquick3d qt5compat qtshadertools qtquicktimeline
  • TagLib and FFmpeg (Homebrew) for tag reading and the phone-mirror decoder
export PATH="$HOME/Qt/6.7.3/macos/bin:$PATH"
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

Output

  • build/octave.app — application bundle
  • dist/OCTAVE-<version>-macos.dmg — produced by CI with macdeployqt + hdiutil; bundled adb lands in Contents/Resources/platform-tools/
Code Signing: Unsigned macOS apps trigger Gatekeeper warnings. Users can bypass with xattr -cr /Applications/OCTAVE.app. For distribution, sign with a Developer ID certificate.

Linux Build

Linux

Requirements

  • Build essentials, CMake, Ninja, pkg-config, and the X11/XCB dev libraries listed in BUILD.md
  • Qt 6.7.3 via the Qt online installer or aqtinstall (distro Qt 6.2 cannot run OCTAVE — see CMake Options)
  • For a local AppImage on Ubuntu 22.04: libtag1-dev libavcodec-dev libavutil-dev libfuse2 wget file
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Optional: portable AppImage (same layout CI ships, linked against your distro's glibc)
bash packaging/linux/build-appimage.sh
# -> dist/OCTAVE-<version>-linux-x86_64.AppImage (or -linux-aarch64 on an ARM host)

Output

  • build/octave — the built executable; QML and assets load from the checkout's frontend/
  • dist/OCTAVE-<version>-linux-x86_64.AppImage / -linux-aarch64.AppImage — portable single-file AppImages (the aarch64 one is built by the cpp-build-linux-arm64 job for Orange Pi / Raspberry Pi class hardware; Google ships no aarch64 adb, so that build uses the distro's adb on PATH)

AppImage Structure

packaging/linux/build-appimage.sh runs a Release CMake build, then linuxdeploy + linuxdeploy-plugin-qt (both vendored under packaging/linux/tools/). The layout must match the binary's runtime asset lookup in src/main.cpp:

AppDir/
  usr/bin/octave            # applicationDirPath()
  usr/frontend/             # ../frontend relative to the binary -- the QML tree
  usr/lib/, usr/plugins/, usr/qml/   # Qt runtime deployed by linuxdeploy-plugin-qt

Putting the QML tree anywhere else breaks the lookup and the app exits silently with no window. On Arch the bundled strip rejects modern .relr.dyn sections — pass NO_STRIP=1. AppImages built on Arch will not run on Ubuntu/Debian (newer glibc); let CI on ubuntu-22.04 produce distributable ones.

Desktop launcher (development machines)

scripts/octave-desktop.sh installs a ~/.local/share/applications/octave-dropbox.desktop entry that incrementally builds the checkout into build-desktop-<hostname>/ and runs it, so a Dropbox-synced tree can be launched from the desktop menu without clobbering another machine's CMake cache. Build failures raise a desktop notification; the log is in ~/.local/state/octave/desktop-launch.log.

Linux System Dependencies

The compile-check job installs these packages before configuring (the AppImage jobs add the Qt dev packages listed in the header of packaging/linux/build-appimage.sh):

sudo apt-get install -y \
  libtag1-dev libavcodec-dev libavutil-dev libgl1-mesa-dev libegl1-mesa-dev \
  libxcb-xinerama0 libxcb-cursor0 libxkbcommon-dev \
  libpulse-dev libssl-dev

Release Job

The release job runs only on version tags, after all five build jobs. It downloads their artifacts and creates a GitHub Release with auto-generated release notes using softprops/action-gh-release@v2, attaching the Windows installer, macOS DMG, both AppImages and the APK.

Phone mirror bundling

No scrcpy binary is bundled or required. The C++ binary embeds OCTAVE's phone server jar (tools/phone-server/, built from phone_server/) as a Qt resource and CI ships Google's adb next to the executable (python scripts/fetch_platform_tools.py, pinned and SHA-256 verified). libavcodec is an optional build dependency for the H.264 decoder; without it phoneMirrorManager.nativeAvailable is false. After editing phone_server/src, rebuild the jar with phone_server/build_without_gradle.sh and commit it with the source — the phone-server job fails when they differ, and SCRCPY_VERSION_NAME must equal both clients' server version (3.3.4-octave).

Android APK Build

Android

The Android .apk is built from the C++ / Qt 6 tree in src/ using Qt's qt-cmake cross-compile wrapper — not from Python. The Python backend is desktop-only and is never packaged for mobile; platform-specific behavior is gated behind #ifdef Q_OS_ANDROID in the C++ managers. (The former Buildozer / python-for-android path has been removed.)

qt-cmake -S . -B build-android \
    -DCMAKE_BUILD_TYPE=Debug \
    -DANDROID_ABI=arm64-v8a \
    -DANDROID_PLATFORM=android-30 \
    -DOCTAVE_ENABLE_DOWNLOADS=OFF \
    -DQT_ANDROID_SIGN_APK=OFF

cmake --build build-android --target apk -j
adb install build-android/android-build/build/outputs/apk/debug/android-build-debug.apk
Full toolchain: See BUILD.md (Android build) for the complete setup — Qt for Android 6.7.3, OpenJDK 17, Android SDK + NDK 26.1.10909125, and APK signing. A condensed walkthrough is on the Getting Started page. iOS is not yet wired (no toolchain in CMake, no CI job).

Python Developer Backend

The Python tree (backend/ + main.py) is a peer backend for tinkering on desktop and Raspberry Pi / Orange Pi. It has no build pipeline: run it from a checkout.

python setup.py              # create venv, install requirements.txt, launch
python setup.py --no-run     # setup only
python main.py               # run (venv activated); --debug / --profile
python -m dev.main_dev       # dev mode: simulated OBD + keyboard controls

Do not reintroduce build_scripts/build.py, octave.spec, requirements-build.txt, per-platform build_*.{sh,bat} wrappers, or the Buildozer spec — they were removed deliberately.

Build Troubleshooting

"DLL not found" on Windows

Install the Visual C++ Redistributable: Download link

"App is damaged" on macOS

xattr -cr /Applications/OCTAVE.app

App links but exits at Main.qml load

The Qt you built against lacks QtQuick.Effects or Qt5Compat.GraphicalEffects (both imported by frontend/MainMenu.qml). Use the pinned Qt 6.7.3 with the qt5compat module rather than distro Qt 6.2.

3D vehicle model does not load

Failed to load asset import plugin with key: "assimp" means Qt Quick 3D is present but its assimp import plugin is not — on Arch, qt6-quick3d additionally needs the assimp package.

AppImage Won't Run

# Make executable
chmod +x OCTAVE-<version>-linux-x86_64.AppImage

# If FUSE unavailable, extract and run
./OCTAVE-<version>-linux-x86_64.AppImage --appimage-extract
./squashfs-root/AppRun

Dropbox Sync Interference

CMake caches are machine-specific. If the checkout is Dropbox-synced between machines, build into a per-host directory (as scripts/octave-desktop.sh does with build-desktop-<hostname>/) rather than sharing build/.
