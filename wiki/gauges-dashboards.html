Overview

A dashboard is a JSON spec that places gauge primitives on a grid, drawn by frontend/dashboards/DashboardRenderer.qml. Home shows one: the built-in home (frontend/dashboards/presets/) or a file of the user's own from the dashboards directory, picked in Settings > Display > Home Screen. Dashboards are not made in the app; they are written as files (or in the browser editor the service serves). DashboardManager (src/managers/dashboardmanager.{h,cpp}) enumerates both sources, watches the user directory, and exposes save / delete / duplicate plus export / import. The OBD page (frontend/OBDMenu.qml) is the Parameter Cards grid: every PID the connected vehicle supports. A vehicle gate keeps dashboards from showing PIDs that vehicle doesn't report.

Every gauge binds to the OBDParameterModel singleton by paramId ("RPM", "SPEED", "LATERAL_G"...) -- title, unit, min and max are auto-populated from the model and the live value updates reactively. No gauge touches obdManager directly, so the same widgets work unchanged with the live OBD manager, the dev-mode simulated car, a test fake, or the model's demo data.

The step-by-step authoring spec is docs/GAUGE_AUTHORING.md; this page documents how the pieces are built and why. Where the two disagree, the code wins and both should be updated.

Shared Binding API

The seven value gauges (Circular, Arc, Bar, Segmented, Linear, DigitalReadout, Sparkline) are each a frontend/gauges/ValueGaugeBase.qml that only draws: the base holds the paramId string, the _pInfo row (one map lookup, App.OBDParameterModel.displayInfo(paramId), not a scan), the properties defaulted from it, the reading and the alert rule below. WarningLight binds the same way without the alert properties. The self-binding widgets (below) skip paramId and read their ids directly. 

ValueGaugeBase {
    id: root
    // from the base, all overridable per widget:
    //   paramId, title, unit, min, max, value (NaN = no reading), hasValue, decimals,
    //   warnAbove / warnBelow / critAbove / critBelow, alertFlash, alertHysteresis,
    //   warnColor, critColor, alertLevel (read-only)
}
PropertyTypeDefaultNotes
paramIdstring""Any id from allParameters. Drives title/unit/min/max/value.
title, unitstringfrom paramIdOverride the label / suffix (a preset can set "title" in props).
min, maxrealfrom paramId (0 / 100 when unbound)Range used for normalisation. Presets override them freely (the TJ preset rescales RPM to 0-6000, coolant to 60-115). DigitalReadout draws no scale and uses them only for the alert hold.
valuerealliveOverride for previews and demos.
decimalsint0Digits after the point in numeric readouts; WarningLight has no decimals property.
labelColor, valueColorcolorApp.Style.obdLabelColor, App.Style.obdValueColorNumeric readout colors; WarningLight has its own label colors. Other default colors come from App.Style (obdBarColor, obdBoxBackground, statusDanger, accent).
octaveSupportedKindsvar (readonly)per widgetKinds the widget accepts, ["*"] = any, [] = self-binding. Must mirror WidgetCatalog.supportedKinds.

Normalisation and animation are also shared: _normalized = clamp((value - min) / (max - min), 0, 1) and a _animNorm property with a Behavior { NumberAnimation { duration: 120-140; easing: OutCubic } }. The raw value is never animated (readouts show the true number; only the geometry eases).

No reading is not zero. Every PID-bound primitive binds value: App.OBDParameterModel.sample(paramId), which is NaN until there is a finite reading, and exposes hasValue. Without one the readout shows --, no fill, needle or marker is drawn, _normalized is 0 and no threshold (redline, warnAbove, triggerAbove / triggerBelow) is evaluated, so a missing fuel level never lights a low-fuel warning. A real 0 is a value. SparklineGauge records a missing sample as a gap in the trace; GForceGauge and CompassGauge hide the dot / keep the card still and show -- g / --°.

Alerts. The value gauges (Circular, Arc, Bar, Segmented, Linear, DigitalReadout, Sparkline) share one rule, frontend/gauges/AlertLevel.js: warnAbove / warnBelow (level 1, warnColor = the theme's statusWarning, amber) and critAbove / critBelow (level 2, critColor = statusDanger, red), inclusive, critical winning; alertLevel is 0 without a reading. At a level the value text and the fill take its colour, and alertFlash blinks the value while critical. A level is entered at its limit and left only once the value is back inside it by a hold (alertHysteresis, display unit on the gauge and the PID's own unit in a spec, where it is converted as a difference; default 1 % of the range, whatever the range is; Alerts.levelHeld(); the dashboard's banner computes the same hold), so a reading sitting on a limit does not flicker the colour, restart the flash or pop the dashboard's alert banner in and out. WarningLight holds its lamp the same way. Circular and Arc draw each band as a thin arc on the inner edge of the scale (Alerts.bands(); a warning band stops where a critical one starts); redlineStart stays a separate red zone. All four limits are stored in the PID's own unit (paramUnit). Until 2026-10-30 Bar and Segmented had only warnAbove, drawn red; the presets moved those limits to critAbove.

Text stays inside the cell. Header rows give the value its width and elide the title in what is left; ArcGauge and DigitalReadout scale their readout block by its measured height against the space they have; values use fontSizeMode: Text.HorizontalFit. BarGauge and LinearGauge lay out with explicit geometry per orientation, so switching orientation after creation lays out as creating it so, and a bar's fill is the track's own shape revealed by a clip (exactly proportional, never outside the track). tst_dashboardwidgets checks every widget's text bounds with a long title and a wide value at 160×50, 80×32, 320×100, 164×103 and 100×240. The renderer additionally clips every cell.

SegmentedGauge

A horizontal discrete level strip for any numeric PID. segmentCount defaults to 20 (2–40); the shared alert limits default off. Each lit segment past warnAbove / critAbove takes that level's colour, like a shift-light strip, the readout takes the value's level, and unlit segments past a limit keep a dim outline. showLabel and showValue default on. Decimals default to 0 and can be set to 0–4. Range and threshold overrides are stored in native units and follow display-unit preferences. Missing/non-finite samples show --, with no lit segments or warning; a real zero remains zero. Invalid ranges fill no segments. Values outside a valid range clamp the strip, while the numeric readout stays truthful. Default span: 6 × 2.

SparklineGauge

Rolling history drawn on a Canvas. ["*"]. A Timer (running only while visible, triggeredOnStart) pushes value into _samples every sampleIntervalMs and drops the oldest past maxSamples; the x step is width / (maxSamples - 1) and samples are right-aligned so the newest sits at the right edge. It samples on its own clock rather than on value changes so the x-axis means time regardless of the OBD poll rate (and is unaffected by the model's 33 ms coalescing).

PropertyTypeDefaultNotes

sampleIntervalMsint50060 × 500 ms = 30 s window by default.
fillBelowbooltrueArea fill at 22 % alpha of obdBarColor.
showHeaderbooltrue"Title Value Unit" strip.
autoScaleboolfalseY-range from the visible window's min/max instead of the PID range -- for fuel trim, timing and other small-swing values.
lineColor, fillColor, backgroundColorcolorthemefillColor defaults to lineColor at 22 % alpha, so the editor's single Color pick (which writes lineColor) recolors line and area together.

Angle and Needle Math

PathAngleArc measures degrees from 3 o'clock, clockwise. A QML Item with rotation: 0 points straight up, so an item rotated to sit on arc angle a needs rotation: a + 90. Both dials use: 

// tick i of N (N = (majorTickCount - 1) * minorTicksPerMajor + 1)
_t        = i / (N - 1)
_angleDeg = startAngle + sweepAngle * _t
x         = cx + tickR * cos(_angleRad) - width / 2
y         = cy + tickR * sin(_angleRad) - height / 2
rotation  = _angleDeg + 90              // long axis radial

// needle (transformOrigin: Item.Bottom, drawn pointing up from the centre)
rotation  = (startAngle + sweepAngle * _animNorm) + 90

// redline arc
_t         = (redlineStart - min) / (max - min)
startAngle = startAngle + sweepAngle * _t
sweepAngle = sweepAngle * (1 - _t)

With the CircularGauge defaults (135° start, 270° sweep) the minimum sits at item rotation 225° (down-left) and the maximum at 135° (down-right); a redline equal to max has zero width and looks like a missing end, so keep redlineStart < max.

Dashboard JSON Schema (schema 1 and 2)

{
  "id":          "my-board",        // required, unique across presets + user files, file-safe slug
  "label":       "My Board",        // required, shown in the chooser and the OBD header
  "schema":      1,                 // 1, or 2 with "layouts" (every built-in)
  "gridColumns": 12,                // optional, default 12
  "gridRows":    8,                 // optional, default 6 (presets use 8; tj-wrangler 12)
  "margins":     20,                // optional dp, outer padding, default 20
  "spacing":     16,                // optional dp, gap between cells, default 16
  "cells": [
    {
      "type":    "CircularGauge",   // a WidgetCatalog type (== the .qml file name)
      "paramId": "RPM",             // an OBDParameterModel id; omit or "" for self-binding widgets
      "col": 6, "row": 0,             // 0-based grid position, default 0/0
      "colSpan": 6, "rowSpan": 7,     // default 1/1
      "props": { "showNeedle": true, "redlineStart": 5500,   // any QML property of the widget
                 "title": "Revs", "max": 6000,          // per-widget overrides (Label & Range)
                 "fillColor": "#2ECC71", "needleColor": "#2ECC71" }  // Color row
    }
  ],
  "layouts": {                       // schema 2, optional
    "portrait": {                    // a portrait screen: one placement per cell, same order
      "gridColumns": 8, "gridRows": 12,  // default: the grid turned
      "cells": [ { "col": 0, "row": 0, "colSpan": 8, "rowSpan": 6 } ]
    }
  }
}
FieldRequiredRead byRules
idyesDashboardManager, OBDMenuMissing id: file skipped (logged). Duplicate of a built-in: user file skipped. "grid" is reserved for the Parameter Cards entry (DashboardManager::kParameterCardsId): uniqueIdForLabel never returns it, saveDashboard refuses it, and a user file carrying it is skipped on scan (logged). saveDashboard writes <id>.json and refuses an id that isn't file-safe ([A-Za-z0-9_-], ≤ 64 chars).
labelyes (for save)DashboardManager, OBDMenuWhitespace collapsed, capped at 80 chars. saveDashboard rejects an empty label; a file with none loads named after its id.
schemaby conventionDashboardManagerWritten by the editor and every preset. Save and the import sanitizer refuse a spec newer than kSupportedSchema (2) with "This dashboard needs a newer version of OCTAVE"; a newer file dropped into the folder by hand is listed, and DashboardRenderer shows that message instead of its cells (and demands no PIDs). It reads the limit from dashboardManager.supportedSchema, or 1 with no manager; loadDashboard passes such a file through untouched and the editor won't open it. A missing schema is 1.
gridColumns, gridRowsnoRenderer, EditorNot a positive JSON number (0, missing, a string) = 12 / 6; capped at 48.
margins, spacingnoRenderer and editorApplied through App.Spacing.dp(); 0..200, null = absent. The editor keeps a loaded spec's values (specMargins / specSpacing), renders its canvas with them and writes them back into saves and drafts (_withGridGeometry()), but only when the spec had them — a dashboard without the keys keeps relying on the 20 / 16 defaults and its JSON stays minimal.
cells[].typeyesRenderer, Editor, WidgetCatalogKept in the file whatever it is (a newer build's widget survives a save). Unknown type: renderer logs and skips the cell (its area stays empty); editor shows it inert as "needs a newer OCTAVE", and Delete works.
cells[].paramIdnoRenderer, EditorKept in the file. Unknown id: renderer logs and leaves the widget unbound; the editor canvas doesn't bind it either. Ignored for widgets without a paramId property.
cells[].col/row/colSpan/rowSpannoRenderer, EditorNormalised on save and load (DashboardManager::normalizeSpec): a cell off the grid keeps its size and moves back in, shrinking only if wider than the grid; cells never overlap (the earlier cell in file order wins, a later one shrinks toward 1×1 and is dropped only if its corner is taken). The editor's tap / drag / resize use the same placement code (canPlace, fitAt, src/util/dashboardgrid.{h,cpp}).
cells[].propsnoRenderer, EditorScalars only (bool, number, string ≤ 200 chars); nested objects and arrays are dropped on save and load. Applied after paramId so overrides win over model defaults. This is also where the editor's per-widget overrides live: title, unit, min, max and the color keys from the catalog's colorProps; omit a key to follow the PID metadata / live theme. Keys the widget does not declare are silently skipped. The string "NaN" is coerced to NaN (JSON cannot encode it; used to un-set thresholds).
layouts.portraitno (schema 2)Renderer, EditorWhere each cell goes on a portrait screen, {gridColumns, gridRows, cells: [{col, row, colSpan, rowSpan}]}, one placement per cell in cells order (a cell the rules drop takes its placement with it). Normalised like the cells; a missing or colliding placement goes to the nearest free spot of its size, then 1×1, and if even that fails the layout is dropped. A spec with one is saved as schema 2, one without as 1. DashboardRenderer uses it when taller than wide (orientedSpec(spec, true)); without one it derives a layout by fixed rules (derivePortrait: the grid turned, every widget its on-screen shape on a 16:9 screen, reading order, made smaller in steps until all fit), the same on every run. Every built-in has one (TJ Wrangler's and Sport's hand-tuned). JSON Schema: docs/api/dashboard-spec.schema.json.

Built-in Presets

One built-in ships since 2026-11-24: home (frontend/dashboards/presets/home.json, 12 × 12, portrait 12 × 20), the dashboard Home shows until another is chosen. It is read-only; editing it from Home makes a copy.   • Scanning: every *.json is fully parsed (there is no lightweight header read; readHeader calls readFullSpec). Non-object roots, parse errors, missing ids, duplicate preset ids and user ids colliding with a built-in are logged (octave.dashboards category) and skipped.
  • Atomic writes: pretty-printed JSON is written through QSaveFile (a temporary file committed over the target). This prevents readers from seeing a partially written JSON file; it is not a guarantee against every power-loss failure.
  • Id generation: slugify lowercases, replaces runs of [^a-z0-9] with -, trims dashes, and falls back to "dashboard"; uniqueIdForLabel appends -2, -3, ... up to 999 (then a millisecond timestamp), skipping hidden built-ins and "grid". The editor calls it before saving a new dashboard, so there is one rule (tests/cpp/tst_dashboardmanager.cpp).
  • Hot reload (c754f3d): a QFileSystemWatcher on the user dir, a 300 ms single-shot debounce, and a signature name:mtime:size|... of the JSON files. A directory event only triggers a rescan when the signature differs from the one recorded at the last scan -- the manager's own saves already rescanned, so they do not double-fire. If the directory was recreated the watch is re-armed.
Synchronous rescans
Specs are parsed with QJsonDocument and the hot-reload signature uses QFileInfo::lastModified().toSecsSinceEpoch(). Headers carry the user file's absolute path, and dashboardsChanged is emitted synchronously at the end of every rescan -- which is why the chooser's delete button must not run code after deleteDashboard() in its own delegate (see below).

Sharing: Export and Import

DashboardManager exports and imports dashboards as text or files (exportDashboard, copyDashboardToClipboard, importDashboard, importDashboardFromText). The buttons for them were in the OBD page's chooser, removed on 2026-11-24; the calls remain for the browser editor and the service API, and a file copied into <config>/dashboards/ needs no import at all.

Imports never overwrite. The incoming id is discarded and a new one is generated from the label with the same uniqueIdForLabel rule as Duplicate, so importing the same file twice gives name and name-2. The spec rules every save and load apply (DashboardManager::normalizeSpec, see the field table above) run first, plus the import-only refusals:

  • Root must be a JSON object with a cells array; schema (default 1) must be 1 or 2 -- newer is refused with "This dashboard needs a newer version of OCTAVE".
  • Only schema, label, gridColumns, gridRows, margins, spacing, cells survive; per cell only type, paramId, col, row, colSpan, rowSpan, props. Anything else -- an id, a source field, unknown keys -- is dropped.
  • props keeps scalar values only (bool, number, string ≤ 200 chars); nested objects and arrays are dropped.
  • Numbers must be JSON numbers (no bools, no numeric strings); geometry is moved into the grid and overlaps resolved as for any save, grid size 1..48, margins/spacing 0..200. Label is whitespace-collapsed, capped at 80 chars, default "Imported dashboard".
  • Caps: 512 KB of text, 256 cells. Cells with an empty or over-long type are skipped; unknown types are kept (the renderer skips them, so a newer catalog's widgets survive a round trip).

Shared dashboards are pure data -- no QML or script is ever loaded from an import. Covered by tests/cpp/tst_dashboardmanager.cpp (spec rules on save, load and import, the presets already satisfying them, rejections, export/import round trip, grid placement).

DashboardRenderer: Spec to QML

frontend/dashboards/DashboardRenderer.qml is an Item with one input, spec. It positions cells absolutely instead of using GridLayout: GridLayout's fillHeight + rowSpan interaction does not give proportional sizes (a rowSpan: 4 cell came out the same height as a rowSpan: 1 peer), and deterministic cells are exactly the snap model the editor needs. 

_cols    = spec.gridColumns || 12
_rows    = spec.gridRows    || 6
_margin  = dp(spec.margins  !== undefined ? spec.margins : 20)
_spacing = dp(spec.spacing  !== undefined ? spec.spacing : 16)
_cellW   = max(1, (width  - 2 * _margin - _spacing * (_cols - 1)) / _cols)
_cellH   = max(1, (height - 2 * _margin - _spacing * (_rows - 1)) / _rows)

cell.x      = _margin + col * (_cellW + _spacing)
cell.y      = _margin + row * (_cellH + _spacing)
cell.width  = colSpan * _cellW + (colSpan - 1) * _spacing
cell.height = rowSpan * _cellH + (rowSpan - 1) * _spacing

A Repeater over spec.cells creates, per cell, a clipped Item containing an asynchronous Loader:

  1. _knownType = WidgetCatalog.isKnownType(type) and _knownParam = !paramId || OBDParameterModel.hasParameter(paramId); Component.onCompleted emits one console.warn per failure, naming the dashboard id.
  2. The Loader is active only for known types; its source is WidgetCatalog.urlFor(type).
  3. onLoaded binds item.width/height to the Loader (Loader auto-sizing is unreliable when the loaded root has no implicit size), sets item.paramId first (only if the widget has that property and the id is known), then walks props applying every key the item already declares, through _coerce() for the "NaN" sentinel. Range props (WidgetCatalog.paramUnitProps(type): min / max where rangeProps, and editable props flagged "paramUnit": true such as warnAbove, redlineStart, triggerAbove / triggerBelow) are written in the PID's own unit and bound through OBDParameterModel.toDisplay(paramId, v), so they follow the gauge unit settings (gaugeTempUnit, gaugeSpeedUnit, sensorAltitudeUnit); the editor canvas does the same and the properties panel shows and stores them converted.
  4. Loader.Error is logged with the source URL; it never throws into the page.
  5. Vehicle gate: _unsupported is true when the cell has a known paramId, OBDParameterModel.vehicleKnown and !isSupported(paramId); the Loader is hidden and a placeholder (dashUnsupported_<index>) shows the title (or the title override) and "Not supported by this vehicle".

The renderer also exposes paramIds (distinct paramIds in the spec), which OBDMenu registers as the "dashboard" polling demand.

Cells without a paramId are still placed -- a WarningLight with an explicit value can be decorative. The renderer is instantiated in two places: full-size in OBDMenu for the active dashboard, and once per chooser card as a live miniature (same spec, scaled).

WidgetCatalog

The catalog's data lives in frontend/dashboards/widget-catalog.json ({schema, widgets, colorSwatches}), read by DashboardManager and served as dashboardManager.widgetCatalog, so every frontend gets the same widget list, and published as docs/api/widget-catalog.json. normalizeSpec uses it to hold a known widget's editableProps to their kind (a wrong type is dropped; numbers clamped to min / max, ints rounded). frontend/dashboards/WidgetCatalog.qml is a singleton that adds each type's QML url (its urls map: Qt.resolvedUrl("../gauges/X.qml") or "widgets/X.qml") and offers the ordered widgets array (a type needs both an entry and a url), colorSwatches, metaFor(type), urlFor(type) and isKnownType(type). It is the single whitelist the renderer, the palette, the PID picker and the properties panel all consult, so "what can render" and "what can be placed" cannot drift.

Each entry declares, besides type / url / displayName / glyph / default span (for a 12 × 6 grid; the editor scales it) / supportedKinds:

Authoring New Gauges and Dashboards

docs/GAUGE_AUTHORING.md is the source of truth for the API and carries the step-by-step recipes; update it in the same commit as any gauge or schema change. In short:

  • New dashboard: write a schema-1 JSON by hand and drop it into frontend/dashboards/presets/ (ships as a read-only built-in, picked up at the next start) or the user dashboards directory (picked up live).
  • New primitive: create frontend/gauges/MyGauge.qml, paste the shared binding preamble verbatim, animate _animNorm (not value), use Shape/PathAngleArc for curves and rotated Rectangles for marks, declare octaveSupportedKinds, scale typography with the cell, and register it in WidgetCatalog with a url, display name, glyph, default span, matching supportedKinds and curated editableProps with honest defaults. Without the catalog entry it will neither render nor be placeable. Then document it in §3 of the authoring guide and on this page.
  • New backend parameter: add the decoder to elm327protocol.cpp (and the signal to OBDManager), and the row with a kind to parametercatalog.cpp (tst_parametercatalog fails without it); its values reach paramStore through parameterSampled, so gauges pick it up with no further work.

Design Decisions

  • A singleton aggregator between the backend and the gauges. OBDParameterModel was introduced (42bbf5f, "centralized OBD parameter definitions into a singleton") so that parameter metadata lives in one QML table and gauges bind by string id. That is what lets the same gauge run against the live manager, the dev-mode simulated car, a test fake or pure-QML demo data, and what let the IMU parameters join later with zero gauge changes.
  • Coalesced model writes, then a per-key store. Replacing a whole paramValues map per signal was correct but cost a full core on the Pi with nothing connected (486a809); a 33 ms flush kept bindings reactive without allocating per write. Open-backend #8 moved the values into the C++ paramStore (same 33 ms fold, one notifying key per id), so a value now re-evaluates only its own readers. The sparkline samples on its own timer, so the change did not alter any time axis.
  • Grid over free placement. Every dashboard anyone had written was grid-shaped, grids are far easier to edit on a touchscreen, and a 12-column grid maps cleanly onto the spans people actually want (TODO/dashboards-roadmap.md, "Key design decisions already made").
  • JSON before editor. Phase 2 (data-driven dashboards) was declared the hinge: an editor that emitted QML source would have been a mess, while an editor that emits a JSON object is a GUI over a data format. Hand-written dashboard QML files were retired once all built-ins were JSON.
  • Absolute positioning in the renderer. GridLayout could not give proportional row spans; explicit cell math also gives the editor a deterministic snap grid and makes the miniature previews pixel-consistent with the full view.
  • Built-ins read-only, "Copy" to derive. Presets are authoritative and their ids are reserved (even while hidden by Delete); a user file that reuses one is rejected at load rather than shadowing it, so an update to a preset can never be masked by a stale copy.
  • One catalog for every consumer. The type -> url map used to live inline in the renderer; with the data in widget-catalog.json and the map in WidgetCatalog, the app, the browser editor and any other frontend agree on which widgets exist and which props a spec may set.
  • No editor in the app (2026-11-24). A touch editor was built twice (a toolbar-and-sheet one, then a tiled one in the manner of a tiling window manager) and both were taken out: designing a dashboard at the head unit took more interface than the result was worth. A dashboard is a JSON file, written at a desk or in the browser editor, and the app only shows it. The editor's last form is in the history before that date.
  • Validation logs and degrades, never throws. A typo in one cell of a hand-written spec must not take down the OBD page in a moving vehicle.
  • Hot reload with a signature, not just an event. Directory events fire for the manager's own atomic saves; comparing a name/mtime/size signature makes the external-edit path and the in-app path share one rescan without double work.
