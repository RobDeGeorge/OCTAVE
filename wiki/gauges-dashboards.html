Overview

OCTAVE's OBD view has two presentations: the built-in Parameter Cards grid inside frontend/OBDMenu.qml, and dashboards -- JSON specs that place gauge primitives on a grid. Five presets ship in frontend/dashboards/presets/; users build their own in an in-app editor, or drop a JSON file into the user dashboards directory. DashboardManager (src/managers/dashboardmanager.{h,cpp}) enumerates both sources, watches the user directory, and exposes save / delete / duplicate plus export / import for sharing. frontend/dashboards/DashboardRenderer.qml turns a spec into live widgets; the chooser popup shows every dashboard as a scaled live miniature; the selection persists as the activeDashboard setting, and a horizontal swipe on the OBD page cycles through Parameter Cards and every dashboard. Parameter Cards lists every PID the connected vehicle supports, and a vehicle gate keeps dashboards from showing PIDs that vehicle doesn't report.

Every gauge binds to the OBDParameterModel singleton by paramId ("RPM", "SPEED", "LATERAL_G"...) -- title, unit, min and max are auto-populated from the model and the live value updates reactively. No gauge touches obdManager directly, so the same widgets work unchanged with the live OBD manager, the dev-mode simulated car, a test fake, or the editor's demo data.

The step-by-step authoring spec is docs/GAUGE_AUTHORING.md; this page documents how the pieces are built and why. Where the two disagree, the code wins and both should be updated.

Shared Binding API

Every PID-bound primitive pastes the same ~15-line preamble: a paramId string, a _pInfo lookup that scans allParameters, and properties defaulted from it. The self-binding widgets (below) skip paramId and read their ids directly. 

property string paramId: ""
readonly property var _pInfo: {
    if (!paramId) return null
    var all = App.OBDParameterModel.allParameters
    for (var i = 0; i < all.length; i++)
        if (all[i].id === paramId) return all[i]
    return null
}
property string title: _pInfo ? _pInfo.title : ""
property string unit:  _pInfo ? _pInfo.unit  : ""
property real   min:   _pInfo ? _pInfo.min   : 0
property real   max:   _pInfo ? _pInfo.max   : 100
property real   value: paramId ? (App.OBDParameterModel.liveValue(paramId) || 0) : 0

title, unitstringfrom paramIdOverride the label / suffix (a preset can set "title" in props).
min, maxrealfrom paramId (0 / 100 when unbound)Range used for normalisation. Presets override them freely (the TJ preset rescales RPM to 0-6000, coolant to 60-115). DigitalReadout has no min/max.
valuerealliveOverride for previews and demos.

Normalisation and animation are also shared: _normalized = clamp((value - min) / (max - min), 0, 1) and a _animNorm property with a Behavior { NumberAnimation { duration: 120-140; easing: OutCubic } }. The raw value is never animated (readouts show the true number; only the geometry eases).

No reading is not zero. Every PID-bound primitive binds value: App.OBDParameterModel.sample(paramId), which is NaN until there is a finite reading, and exposes hasValue. Without one the readout shows --, no fill, needle or marker is drawn, _normalized is 0 and no threshold (redline, warnAbove, triggerAbove / triggerBelow) is evaluated, so a missing fuel level never lights a low-fuel warning. A real 0 is a value. SparklineGauge records a missing sample as a gap in the trace; GForceGauge and CompassGauge hide the dot / keep the card still and show -- g / --°.

Alerts. The value gauges (Circular, Arc, Bar, Segmented, Linear, DigitalReadout, Sparkline) share one rule, frontend/gauges/AlertLevel.js: warnAbove / warnBelow (level 1, warnColor = the theme's statusWarning, amber) and critAbove / critBelow (level 2, critColor = statusDanger, red), inclusive, critical winning; alertLevel is 0 without a reading. At a level the value text and the fill take its colour, and alertFlash blinks the value while critical. Circular and Arc draw each band as a thin arc on the inner edge of the scale (Alerts.bands(); a warning band stops where a critical one starts); redlineStart stays a separate red zone. All four limits are stored in the PID's own unit (paramUnit). Until 2026-10-30 Bar and Segmented had only warnAbove, drawn red; the presets moved those limits to critAbove.

Text stays inside the cell. Header rows give the value its width and elide the title in what is left; ArcGauge and DigitalReadout scale their readout block by its measured height against the space they have; values use fontSizeMode: Text.HorizontalFit. BarGauge and LinearGauge lay out with explicit geometry per orientation, so switching orientation after creation lays out as creating it so, and a bar's fill is the track's own shape revealed by a clip (exactly proportional, never outside the track). tst_dashboardwidgets checks every widget's text bounds with a long title and a wide value at 160×50, 80×32, 320×100, 164×103 and 100×240. The renderer additionally clips every cell.

SegmentedGauge

A horizontal discrete level strip for any numeric PID. segmentCount defaults to 20 (2–40); the shared alert limits default off. Each lit segment past warnAbove / critAbove takes that level's colour, like a shift-light strip, the readout takes the value's level, and unlit segments past a limit keep a dim outline. showLabel and showValue default on. Decimals default to 0 and can be set to 0–4. Range and threshold overrides are stored in native units and follow display-unit preferences. Missing/non-finite samples show --, with no lit segments or warning; a real zero remains zero. Invalid ranges fill no segments. Values outside a valid range clamp the strip, while the numeric readout stays truthful. Default span: 6 × 2.

SparklineGauge

Rolling history drawn on a Canvas. ["*"]. A Timer (running only while visible, triggeredOnStart) pushes value into _samples every sampleIntervalMs and drops the oldest past maxSamples; the x step is width / (maxSamples - 1) and samples are right-aligned so the newest sits at the right edge. It samples on its own clock rather than on value changes so the x-axis means time regardless of the OBD poll rate (and is unaffected by the model's 33 ms coalescing).

Angle and Needle Math

PathAngleArc measures degrees from 3 o'clock, clockwise. A QML Item with rotation: 0 points straight up, so an item rotated to sit on arc angle a needs rotation: a + 90. Both dials use: 

// tick i of N (N = (majorTickCount - 1) * minorTicksPerMajor + 1)
_t        = i / (N - 1)
_angleDeg = startAngle + sweepAngle * _t
x         = cx + tickR * cos(_angleRad) - width / 2
y         = cy + tickR * sin(_angleRad) - height / 2
rotation  = _angleDeg + 90              // long axis radial

// needle (transformOrigin: Item.Bottom, drawn pointing up from the centre)
rotation  = (startAngle + sweepAngle * _animNorm) + 90

// redline arc
_t         = (redlineStart - min) / (max - min)
startAngle = startAngle + sweepAngle * _t
sweepAngle = sweepAngle * (1 - _t)

With the CircularGauge defaults (135° start, 270° sweep) the minimum sits at item rotation 225° (down-left) and the maximum at 135° (down-right); a redline equal to max has zero width and looks like a missing end, so keep redlineStart < max.

Dashboard JSON Schema (schema 1 and 2)

{
  "id":          "my-board",        // required, unique across presets + user files, file-safe slug
  "label":       "My Board",        // required, shown in the chooser and the OBD header
  "schema":      1,                 // 1, or 2 with "layouts" (every built-in)
  "gridColumns": 12,                // optional, default 12
  "gridRows":    8,                 // optional, default 6 (presets use 8; tj-wrangler 12)
  "margins":     20,                // optional dp, outer padding, default 20
  "spacing":     16,                // optional dp, gap between cells, default 16
  "cells": [
    {
      "type":    "CircularGauge",   // a WidgetCatalog type (== the .qml file name)
      "paramId": "RPM",             // an OBDParameterModel id; omit or "" for self-binding widgets
      "col": 6, "row": 0,             // 0-based grid position, default 0/0
      "colSpan": 6, "rowSpan": 7,     // default 1/1
      "props": { "showNeedle": true, "redlineStart": 5500,   // any QML property of the widget
                 "title": "Revs", "max": 6000,          // per-widget overrides (Label & Range)
                 "fillColor": "#2ECC71", "needleColor": "#2ECC71" }  // Color row
    }
  ],
  "layouts": {                       // schema 2, optional
    "portrait": {                    // a portrait screen: one placement per cell, same order
      "gridColumns": 8, "gridRows": 12,  // default: the grid turned
      "cells": [ { "col": 0, "row": 0, "colSpan": 8, "rowSpan": 6 } ]
    }
  }
}

Sharing: Export and Import

In the chooser, every JSON dashboard card has a Share action (a menu: Save to Downloads -> exportDashboard, Copy as text -> copyDashboardToClipboard), and the header has an Import button (From file… opens a FileDialog filtered to *.json; Paste from clipboard). Results show in a status banner at the bottom of the chooser for 4.5 s (accent on success, statusDanger with lastShareError on failure).

Imports never overwrite. The incoming id is discarded and a new one is generated from the label with the same uniqueIdForLabel rule as Duplicate, so importing the same file twice gives name and name-2. The spec rules every save and load apply (DashboardManager::normalizeSpec, see the field table above) run first, plus the import-only refusals:

  • Root must be a JSON object with a cells array; schema (default 1) must be 1 or 2 -- newer is refused with "This dashboard needs a newer version of OCTAVE".
  • Only schema, label, gridColumns, gridRows, margins, spacing, cells survive; per cell only type, paramId, col, row, colSpan, rowSpan, props. Anything else -- an id, a source field, unknown keys -- is dropped.
  • props keeps scalar values only (bool, number, string ≤ 200 chars); nested objects and arrays are dropped.
  • Numbers must be JSON numbers (no bools, no numeric strings); geometry is moved into the grid and overlaps resolved as for any save, grid size 1..48, margins/spacing 0..200. Label is whitespace-collapsed, capped at 80 chars, default "Imported dashboard".
  • Caps: 512 KB of text, 256 cells. Cells with an empty or over-long type are skipped; unknown types are kept (the renderer skips them, so a newer catalog's widgets survive a round trip).

Shared dashboards are pure data -- no QML or script is ever loaded from an import. Covered by tests/cpp/tst_dashboardmanager.cpp (spec rules on save, load and import, the presets already satisfying them, rejections, export/import round trip, grid placement).

DashboardRenderer: Spec to QML

frontend/dashboards/DashboardRenderer.qml is an Item with one input, spec. It positions cells absolutely instead of using GridLayout: GridLayout's fillHeight + rowSpan interaction does not give proportional sizes (a rowSpan: 4 cell came out the same height as a rowSpan: 1 peer), and deterministic cells are exactly the snap model the editor needs. 

_cols    = spec.gridColumns || 12
_rows    = spec.gridRows    || 6
_margin  = dp(spec.margins  !== undefined ? spec.margins : 20)
_spacing = dp(spec.spacing  !== undefined ? spec.spacing : 16)
_cellW   = max(1, (width  - 2 * _margin - _spacing * (_cols - 1)) / _cols)
_cellH   = max(1, (height - 2 * _margin - _spacing * (_rows - 1)) / _rows)

cell.x      = _margin + col * (_cellW + _spacing)
cell.y      = _margin + row * (_cellH + _spacing)
cell.width  = colSpan * _cellW + (colSpan - 1) * _spacing
cell.height = rowSpan * _cellH + (rowSpan - 1) * _spacing

A Repeater over spec.cells creates, per cell, a clipped Item containing an asynchronous Loader:

  1. _knownType = WidgetCatalog.isKnownType(type) and _knownParam = !paramId || OBDParameterModel.hasParameter(paramId); Component.onCompleted emits one console.warn per failure, naming the dashboard id.
  2. The Loader is active only for known types; its source is WidgetCatalog.urlFor(type).
  3. onLoaded binds item.width/height to the Loader (Loader auto-sizing is unreliable when the loaded root has no implicit size), sets item.paramId first (only if the widget has that property and the id is known), then walks props applying every key the item already declares, through _coerce() for the "NaN" sentinel. Range props (WidgetCatalog.paramUnitProps(type): min / max where rangeProps, and editable props flagged "paramUnit": true such as warnAbove, redlineStart, triggerAbove / triggerBelow) are written in the PID's own unit and bound through OBDParameterModel.toDisplay(paramId, v), so they follow the gauge unit settings (gaugeTempUnit, gaugeSpeedUnit, sensorAltitudeUnit); the editor canvas does the same and the properties panel shows and stores them converted.
  4. Loader.Error is logged with the source URL; it never throws into the page.
  5. Vehicle gate: _unsupported is true when the cell has a known paramId, OBDParameterModel.vehicleKnown and !isSupported(paramId); the Loader is hidden and a placeholder (dashUnsupported_<index>) shows the title (or the title override) and "Not supported by this vehicle".

The renderer also exposes paramIds (distinct paramIds in the spec), which OBDMenu registers as the "dashboard" polling demand.

Cells without a paramId are still placed -- a WarningLight with an explicit value can be decorative. The renderer is instantiated in two places: full-size in OBDMenu for the active dashboard, and once per chooser card as a live miniature (same spec, scaled).

Dashboard Editor Internals

The editor is QML over DashboardManager's save / placement API. It is a full-screen page: it declares hidesNavigation: true, and while it is the StackView's current item Main.qml (navigationHidden) hides the nav bar and gives the page the whole window, so it is left only through Done or Close. Interaction model (touch first, select then manipulate; design and rationale in docs/DASHBOARD_EDITOR_REVIEW.md §4.2):

  • Tap a widget to select it: it lifts (scale 1.02 and a shadow) and a floating toolbar appears above it, or below when there is no room (Data · Settings · S / M / L · Duplicate · Delete).
  • Drag the selected widget to move it (after 8 dp). An unselected widget never moves under a passing finger; press and hold selects one and drags it in the same gesture. While dragging the widget follows the finger (scale 1.05), a ghost shows the drop cell and the neighbours slide to where the drop would put them; the ghost turns red with the reason when the drop won't go.
  • Tap-tap: with a widget selected, tapping another one offers Swap / Select, and tapping free space offers Move here / Add here. With nothing selected, tapping free space offers Add here; + Add (bottom right) finds room by itself.
  • Resize with the size chips (S / M / L from dashboardManager.sizeOptions) or the corner grip, which snaps to the grid, shows "4 × 2" in the ghost, and never goes below the widget's readable minimum (minSpan) unless the widget is already smaller.
  • Settings opens the properties panel as a side sheet (a bottom sheet on a portrait screen). The canvas keeps its full-size layout and is zoomed to fit what the sheet leaves (canvasFrame.zoom), so nothing reflows while it is open; drags and resizes are off meanwhile, taps still select another widget.
  • Delete shows "<widget> removed · Undo" in the snackbar; every edit is undoable.
  • Keyboard: Ctrl+Z / Ctrl+Y (or Ctrl+Shift+Z), Delete, Ctrl+D (duplicate), arrow keys (nudge), Escape (close a chooser, then the sheet, then the selection).

Controls are at least touchSize: 9 mm where the screen reports its size (Screen.pixelDensity), never under 44 dp. While open, the editor registers its cells' PIDs as the "editor" polling demand so gauges preview live values from a connected car.

Component.onDestruction first forces OBDParameterModel.simulationActive = false (demo data must never leak into the real OBD views), then, if dirty, writes { editingId, label, gridColumns, gridRows, cells } (plus margins / spacing when the loaded spec had them) as JSON to the dashboardEditorDraft setting; restoring a draft reads them back the same way. Only a session that resumed a draft may clear it, so opening and closing a fresh editor cannot wipe an earlier draft. Demo data is the checkable item in the top bar's Grid · Demo menu, bound to simulationActive.

Settings sheet: the properties panel was first docked beside the canvas (it resized the canvas on every selection change, rescaling the dashboard mid-edit) and then floated over it (it covered the widget being edited). The sheet takes its own strip and the canvas is scaled, not re-laid out, to fit the rest, with drags off while it is open, which avoids both.

EditorCanvas.qml

  • Geometry mirrors the renderer exactly: the canvas takes the spec's optional margins / spacing (undefined keeps the 20 dp / 16 dp defaults) and uses the same cell formulas, so the layout you edit is the layout that renders.
  • canPlace(col, row, colSpan, rowSpan, exceptIndex): inside the grid and no rectangle overlap with any other cell; it calls dashboardManager.canPlace(), the rule save and load use too. arrangement(index, col, row, colSpan, rowSpan) asks dashboardManager.arrange() where everything would go for a drop or resize (swapping or pushing), caching the last answer (canArrange() is its ok); it drives the ghost and the live preview.
  • The grid is a dot at every gutter crossing (one Canvas), brighter while a drag snaps to it. A background MouseArea turns a tap into emptyCellTapped(col, row) on a free cell (cellAt(), isFree() over the _occupied map) or backgroundTapped() outside the grid.
  • Placed cells: a Repeater over the editor's cellModel. Each delegate has a synchronous Loader with the same bind/props logic as the renderer, reloaded only when its own type / paramId / propsJson change; a "Choose data" badge on unbound PID widgets; a selection frame and shadow; and a MouseArea whose drag.target is set only for the selected cell (or one held down; drag.threshold 8 dp). onClicked emits cellTapped, onPressAndHold cellHeld; while dragging, _updateDragCandidate() rounds the item position to the nearest cell and sets the drag state (dragIndex, dragCol / dragRow, dragValid, dragReason); the other cells bind their position to _previewCells (the arrangement's cells) and animate there in 110 ms; onReleased re-binds the delegate's x / y to its cell and emits cellMoveRequested.
  • Drop ghost (editorDropGhost): accent when the drop or resize would go through, statusDanger with the reason (editorDropGhostText) when not; shows the span while resizing.
  • Resize grip (editorResizeGrip_<index>): on the selected cell only, while interactive; a 24 dp accent dot centred on the bottom-right corner with a touchSize hit area. Its MouseArea (preventStealing) maps the pointer into canvas coordinates, snaps the far corner to the cell under it (never below minSpanFor(index), which the editor supplies) and drives the ghost and preview; release emits cellResizeRequested.
  • selectedRect, rectOf(cell): canvas rectangles the editor places its toolbar and choosers by. cellWidthDp / cellHeightDp / spacingDp feed minSpan / sizeOptions.
  • Signals: emptyCellTapped(col, row), cellTapped(index), cellHeld(index), cellMoveRequested(index, col, row), cellResizeRequested(index, colSpan, rowSpan), backgroundTapped(). The canvas never mutates cells.

Authoring New Gauges and Dashboards

docs/GAUGE_AUTHORING.md is the source of truth for the API and carries the step-by-step recipes; update it in the same commit as any gauge or schema change. In short:

  • New dashboard: build it in the editor, or write a schema-1 JSON by hand and drop it into frontend/dashboards/presets/ (ships as a read-only built-in, picked up at the next start) or the user dashboards directory (picked up live).
  • New primitive: create frontend/gauges/MyGauge.qml, paste the shared binding preamble verbatim, animate _animNorm (not value), use Shape/PathAngleArc for curves and rotated Rectangles for marks, declare octaveSupportedKinds, scale typography with the cell, and register it in WidgetCatalog with a url, display name, glyph, default span, matching supportedKinds and curated editableProps with honest defaults. Without the catalog entry it will neither render nor be placeable. Then document it in §3 of the authoring guide and on this page.
  • New backend parameter: add the decoder to elm327protocol.cpp (and the signal to OBDManager), and the row with a kind to parametercatalog.cpp (tst_parametercatalog fails without it); its values reach paramStore through parameterSampled, so gauges pick it up with no further work.

Design Decisions

  • A singleton aggregator between the backend and the gauges. OBDParameterModel was introduced (42bbf5f, "centralized OBD parameter definitions into a singleton") so that parameter metadata lives in one QML table and gauges bind by string id. That is what lets the same gauge run against the live manager, the dev-mode simulated car, a test fake or pure-QML demo data, and what let the IMU parameters join later with zero gauge changes.
  • Coalesced model writes, then a per-key store. Replacing a whole paramValues map per signal was correct but cost a full core on the Pi with nothing connected (486a809); a 33 ms flush kept bindings reactive without allocating per write. Open-backend #8 moved the values into the C++ paramStore (same 33 ms fold, one notifying key per id), so a value now re-evaluates only its own readers. The sparkline samples on its own timer, so the change did not alter any time axis.
  • Grid over free placement. Every dashboard anyone had written was grid-shaped, grids are far easier to edit on a touchscreen, and a 12-column grid maps cleanly onto the spans people actually want (TODO/dashboards-roadmap.md, "Key design decisions already made").
  • JSON before editor. Phase 2 (data-driven dashboards) was declared the hinge: an editor that emitted QML source would have been a mess, while an editor that emits a JSON object is a GUI over a data format. Hand-written dashboard QML files were retired once all built-ins were JSON.
  • Absolute positioning in the renderer. GridLayout could not give proportional row spans; explicit cell math also gives the editor a deterministic snap grid and makes the miniature previews pixel-consistent with the full view.
  • Built-ins read-only, "Copy" to derive. Presets are authoritative and their ids are reserved (even while hidden by Delete); a user file that reuses one is rejected at load rather than shadowing it, so an update to a preset can never be masked by a stale copy.
  • The editor is pure QML. The backend already had everything the editor needed; the only missing piece, "unique id from a label", was duplicated in QML rather than adding a slot. No CMake or main.cpp churn.
  • One catalog, three consumers. The type -> url map used to live inline in the renderer; lifting it into WidgetCatalog means the palette cannot offer a type the renderer cannot draw, and the panel cannot expose a prop the gauge does not declare.
  • Curated, honest editable props. The panel shows a deliberately small set of scalar props with the gauge's real defaults so the in-car UI stays simple; the JSON stays fully expressive for power users (the TJ preset uses min/max and sample-interval overrides, which the current panel also offers).
  • Hybrid tap-and-drag. The original plan was tap-to-place only, because drag fights the chooser's Flickable; the editor canvas is a full-screen non-scrolling page, so drag is safe there and was added for placement. Tap-to-place stays for new widgets, steppers stay for precision.
  • Visible action buttons, two-tap destructive actions. Long-press is hidden; a Delete or Discard that fires on one tap is dangerous at 60 mph. Both confirmations time out after 3 s.
  • Draft rescue on destruction. Home and Settings can pop and destroy the editor without going through its Cancel action; stashing the working spec in a setting and offering it back was the smallest fix that loses no work.
  • Demo data lives in the model and is forced off on editor destruction. A sine sweep in QML needs no backend and no mock; the destruction hook turns it off when the editor is destroyed. Because the model is global, other views can observe demo values while an editor remains alive underneath a cached page.
  • Validation logs and degrades, never throws. A typo in one cell of a hand-written spec must not take down the OBD page in a moving vehicle.
  • Hot reload with a signature, not just an event. Directory events fire for the manager's own atomic saves; comparing a name/mtime/size signature makes the external-edit path and the in-app path share one rescan without double work.
