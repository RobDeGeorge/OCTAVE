Overview

OCTAVE's OBD view has two presentations: the built-in Parameter Cards grid inside frontend/OBDMenu.qml, and dashboards -- JSON specs that place gauge primitives on a grid. Five presets ship in frontend/dashboards/presets/; users build their own in an in-app editor, or drop a JSON file into the user dashboards directory. DashboardManager (C++ src/managers/dashboardmanager.{h,cpp}, Python backend/dashboard_manager.py, full parity) enumerates both sources, watches the user directory, and exposes save / delete / duplicate. frontend/dashboards/DashboardRenderer.qml turns a spec into live widgets; the chooser popup shows every dashboard as a scaled live miniature; the selection persists as the activeDashboard setting.

Every gauge binds to the OBDParameterModel singleton by paramId ("RPM", "SPEED", "LATERAL_G"...) -- title, unit, min and max are auto-populated from the model and the live value updates reactively. No gauge touches obdManager directly, so the whole system is backend-agnostic and works unchanged with the Python or C++ OBD manager, the dev-mode mock, or the editor's demo data.

The step-by-step authoring spec is docs/GAUGE_AUTHORING.md; this page documents how the pieces are built and why. Where the two disagree, the code wins and both should be updated.

frontend/OBDParameterModel.qml (registered as a singleton in frontend/qmldir) declares:

MemberDescription

Shared Binding API

Every PID-bound primitive pastes the same ~15-line preamble: a paramId string, a _pInfo lookup that scans allParameters, and properties defaulted from it. The self-binding widgets (below) skip paramId and read their ids directly. 

property string paramId: ""
readonly property var _pInfo: {
    if (!paramId) return null
    var all = App.OBDParameterModel.allParameters
    for (var i = 0; i < all.length; i++)
        if (all[i].id === paramId) return all[i]
    return null
}
property string title: _pInfo ? _pInfo.title : ""
property string unit:  _pInfo ? _pInfo.unit  : ""
property real   min:   _pInfo ? _pInfo.min   : 0
property real   max:   _pInfo ? _pInfo.max   : 100
property real   value: paramId ? (App.OBDParameterModel.paramValues[paramId] || 0) : 0
PropertyTypeDefaultNotes
paramIdstring""Any id from allParameters. Drives title/unit/min/max/value.
title, unitstringfrom paramIdOverride the label / suffix (a preset can set "title" in props).
min, maxrealfrom paramId (0 / 100 when unbound)Range used for normalisation. Presets override them freely (the TJ preset rescales RPM to 0-6000, coolant to 60-115). DigitalReadout has no min/max.
valuerealliveOverride for previews (the Primitives Gallery does this).
decimalsint0Digits after the point in the readout.
labelColor, valueColorcolorApp.Style.obdLabelColor, App.Style.obdValueColorTheme tokens; all other colours also come from App.Style (obdBarColor, obdBoxBackground, statusDanger, accent).
octaveSupportedKindsvar (readonly)per widgetKinds the widget accepts, ["*"] = any, [] = self-binding. Must mirror WidgetCatalog.supportedKinds.
octaveEditablePropsvar (readonly)per widgetManifest of editable props declared in the gauge itself. Not read by the current editor -- the properties panel uses the curated editableProps list in WidgetCatalog instead (see WidgetCatalog).

Normalisation and animation are also shared: _normalized = clamp((value - min) / (max - min), 0, 1) and a _animNorm property with a Behavior { NumberAnimation { duration: 120-140; easing: OutCubic } }. The raw value is never animated (readouts show the true number; only the geometry eases). Typography scales down with the cell through a _fontFit / _vfit factor or an arc-radius cap, so an editor cell of any size keeps its text inside the widget; the renderer additionally clips every cell.

Gauge Primitives

Defaults below are read from the QML property declarations, not from the manifests.

CircularGauge

Arc-sweep dial built from three Shape { ShapePath { PathAngleArc } } layers (track, static redline zone, animated fill), a Repeater of tick rectangles, an optional needle + hub, and a centre readout. octaveSupportedKinds: ["*"]. Fills its own bounding box; the arc radius is min(width, height) / 2 - 4 dp, arc width max(6 dp, 12 % of radius).

BarGauge

Filled pill. octaveSupportedKinds: ["percentage", "temperature", "numeric", "pressure", "voltage"] -- deliberately not bidirectional, because the bar grows from one end and does not represent signed ranges well (use LinearGauge). SparklineGauge

Rolling history drawn on a Canvas. ["*"]. A Timer (running only while visible, triggeredOnStart) pushes value into _samples every sampleIntervalMs and drops the oldest past maxSamples; the x step is width / (maxSamples - 1) and samples are right-aligned so the newest sits at the right edge. It samples on its own clock rather than on value changes so the x-axis means time regardless of the OBD poll rate (and is unaffected by the model's 33 ms coalescing).

Angle and Needle Math

PathAngleArc measures degrees from 3 o'clock, clockwise. A QML Item with rotation: 0 points straight up, so an item rotated to sit on arc angle a needs rotation: a + 90. Both dials use: 

// tick i of N (N = (majorTickCount - 1) * minorTicksPerMajor + 1)
_t        = i / (N - 1)
_angleDeg = startAngle + sweepAngle * _t
x         = cx + tickR * cos(_angleRad) - width / 2
y         = cy + tickR * sin(_angleRad) - height / 2
rotation  = _angleDeg + 90              // long axis radial

// needle (transformOrigin: Item.Bottom, drawn pointing up from the centre)
rotation  = (startAngle + sweepAngle * _animNorm) + 90

// redline arc
_t         = (redlineStart - min) / (max - min)
startAngle = startAngle + sweepAngle * _t
sweepAngle = sweepAngle * (1 - _t)

With the CircularGauge defaults (135° start, 270° sweep) the minimum sits at item rotation 225° (down-left) and the maximum at 135° (down-right); a redline equal to max has zero width and looks like a missing end, so keep redlineStart < max.

Dashboard JSON Schema (schema 1)

{
  "id":          "my-board",        // required, unique across presets + user files, file-safe slug
  "label":       "My Board",        // required, shown in the chooser and the OBD header
  "schema":      1,                 // format version; every shipped spec carries 1
  "gridColumns": 12,                // optional, default 12
  "gridRows":    8,                 // optional, default 6 (presets use 8; tj-wrangler 12)
  "margins":     20,                // optional dp, outer padding, default 20
  "spacing":     16,                // optional dp, gap between cells, default 16
  "cells": [
    {
      "type":    "CircularGauge",   // a WidgetCatalog type (== the .qml file name)
      "paramId": "RPM",             // an OBDParameterModel id; omit or "" for self-binding widgets
      "col": 6, "row": 0,             // 0-based grid position, default 0/0
      "colSpan": 6, "rowSpan": 7,     // default 1/1
      "props": { "showNeedle": true, "redlineStart": 6500 }   // any QML property of the widget
    }
  ]
}
FieldRequiredRead byRules
idyesDashboardManager, OBDMenuMissing id: file skipped (logged). Duplicate of a built-in: user file skipped. "grid" is reserved for the Parameter Cards sentinel (the editor's id generator excludes it; the manager does not). saveDashboard writes <id>.json.
labelyes (for save)DashboardManager, OBDMenusaveDashboard rejects an empty label; a preset with an empty label loads with a blank name.
schemaby conventionnobody yetWritten by the editor and every preset; no reader checks it today. It exists so a future format can degrade gracefully instead of stranding files.
gridColumns, gridRowsnoRenderer, EditorFalsy values (0, missing) fall back to 12 / 6.
margins, spacingnoRenderer onlyApplied through App.Spacing.dp(). The editor canvas always uses 20 / 16 and does not persist these, so a hand-edited spacing survives editing only if you never save from the editor.
cells[].typeyesRenderer, Editor, WidgetCatalogUnknown type: renderer logs and skips the cell; editor drops it on load.
cells[].paramIdnoRenderer, EditorUnknown id: renderer logs and leaves the widget unbound; editor clears it to "". Ignored for widgets without a paramId property.
cells[].col/row/colSpan/rowSpannoRenderer, EditorRenderer trusts them; editor clamps into the grid on load.
cells[].propsnoRenderer, EditorApplied after paramId so overrides win over model defaults. Keys the widget does not declare are silently skipped. The string "NaN" is coerced to NaN (JSON cannot encode it; used to un-set thresholds).

DashboardManager (C++ and Python)

Context property dashboardManager, registered before the QML engine loads. main.cpp / main.py call setPresetsDir(<frontend>/dashboards/presets) then setUserDir(<app data dir>/dashboards); the second call performs the initial scan and starts the directory watch. The user dir is ~/.config/OCTAVE/dashboards/ on Linux, ~/Library/Application Support/OCTAVE/dashboards/ on macOS, %APPDATA%/OCTAVE/dashboards/ on Windows (via SettingsManager::getAppDataDir() / get_app_data_dir()), and is created on demand.

MemberKindBehaviour (identical in both backends)
dashboardsProperty (list), notify dashboardsChangedHeaders { id, label, builtIn, path }: presets first in file-name order, then user files in file-name order.
loadDashboard(id)Invokable -> mapFull parsed spec, or an empty map for an unknown id / unreadable file (logged).
isBuiltIn(id)Invokable -> bool
saveDashboard(spec)Slot -> id or ""Requires non-empty id and label and a configured user dir; refuses an id that belongs to a built-in; otherwise writes <userDir>/<id>.json (overwriting an existing user file with that id) and rescans.
deleteDashboard(id)Slot -> boolRemoves the user file; false for unknown or built-in ids.
duplicateDashboard(sourceId, newLabel)Slot -> id or ""Reads the source spec (built-in or user), sets label to newLabel or "<source label> (Copy)", generates a unique id, and calls saveDashboard.
refresh()SlotFull rescan of both directories.
  • Scanning: every *.json is fully parsed (there is no lightweight header read; readHeader calls readFullSpec). Non-object roots, parse errors, missing ids, duplicate preset ids and user ids colliding with a built-in are logged (octave.dashboards category / module logger) and skipped.
  • Atomic writes: pretty-printed JSON goes to a .dashboard_tmp_*.json temp file in the same directory, then rename / os.replace. C++ removes the destination first on Windows and falls back to a direct write if the rename fails.
  • Id generation: slugify lowercases, replaces runs of [^a-z0-9] with -, trims dashes, and falls back to "dashboard"; uniqueUserIdFromLabel appends -2, -3, ... up to 999 (then a millisecond timestamp). The editor reimplements the same rule in QML so it can pick an id before calling save.
  • Hot reload (c754f3d): a QFileSystemWatcher on the user dir, a 300 ms single-shot debounce, and a signature name:mtime:size|... of the JSON files. A directory event only triggers a rescan when the signature differs from the one recorded at the last scan -- the manager's own saves already rescanned, so they do not double-fire. If the directory was recreated the watch is re-armed.
Differences between the two implementations
There are none in behaviour. The C++ side uses QJsonDocument, QTemporaryFile, and QFileInfo::lastModified().toSecsSinceEpoch(); Python uses json, tempfile.mkstemp and int(st.st_mtime). Both return the user file's absolute path in the header, and both emit dashboardsChanged synchronously at the end of every rescan -- which is why the chooser's delete button must not run code after deleteDashboard() in its own delegate (see below).

DashboardRenderer: Spec to QML

frontend/dashboards/DashboardRenderer.qml is an Item with one input, spec. It positions cells absolutely instead of using GridLayout: GridLayout's fillHeight + rowSpan interaction does not give proportional sizes (a rowSpan: 4 cell came out the same height as a rowSpan: 1 peer), and deterministic cells are exactly the snap model the editor needs. 

_cols    = spec.gridColumns || 12
_rows    = spec.gridRows    || 6
_margin  = dp(spec.margins  !== undefined ? spec.margins : 20)
_spacing = dp(spec.spacing  !== undefined ? spec.spacing : 16)
_cellW   = max(1, (width  - 2 * _margin - _spacing * (_cols - 1)) / _cols)
_cellH   = max(1, (height - 2 * _margin - _spacing * (_rows - 1)) / _rows)

cell.x      = _margin + col * (_cellW + _spacing)
cell.y      = _margin + row * (_cellH + _spacing)
cell.width  = colSpan * _cellW + (colSpan - 1) * _spacing
cell.height = rowSpan * _cellH + (rowSpan - 1) * _spacing

A Repeater over spec.cells creates, per cell, a clipped Item containing an asynchronous Loader:

  1. _knownType = WidgetCatalog.isKnownType(type) and _knownParam = !paramId || OBDParameterModel.hasParameter(paramId); Component.onCompleted emits one console.warn per failure, naming the dashboard id.
  2. The Loader is active only for known types; its source is WidgetCatalog.urlFor(type).
  3. onLoaded binds item.width/height to the Loader (Loader auto-sizing is unreliable when the loaded root has no implicit size), sets item.paramId first (only if the widget has that property and the id is known), then walks props applying every key the item already declares, through _coerce() for the "NaN" sentinel.
  4. Loader.Error is logged with the source URL; it never throws into the page.

Cells without a paramId are still placed -- a WarningLight with an explicit value can be decorative. The renderer is instantiated in two places: full-size in OBDMenu for the active dashboard, and once per chooser card as a live miniature (same spec, scaled).

WidgetCatalog

frontend/dashboards/WidgetCatalog.qml is a singleton holding the ordered widgets array plus metaFor(type), urlFor(type) and isKnownType(type). It is the single whitelist the renderer, the palette, the PID picker and the properties panel all consult, so "what can render" and "what can be placed" cannot drift. URLs are Qt.resolvedUrl("../gauges/X.qml") or "widgets/X.qml", resolved relative to the catalog's own location.

OBDMenu Integration: Active Dashboard and Chooser

  • Registry: dashboardRegistry = [ { id: "grid", label: "Parameter Cards", builtIn: true } ].concat(dashboardManager.dashboards), rebuilt in a Connections handler on dashboardsChanged (guarded with typeof dashboardManager so the page loads without the manager).
  • Active dashboard: activeDashboardId is read from the generic setting activeDashboard (default "grid") and written by setActiveDashboard(id). The header shows the registry label; the DashboardRenderer is visible and loads dashboardManager.loadDashboard(activeDashboardId) only when the id is not "grid", otherwise the GridLayout of parameter cards (3 columns, one card per parameter passing get_obd_parameter_enabled, square or circular per obdCardStyleCircular) is shown.
  • Fallback: if the active id is no longer in the registry after a rescan (deleted in-app or externally), the handler calls setActiveDashboard("grid"). Delete goes through the page-level deleteUserDashboard(id) because dashboardsChanged is emitted synchronously inside deleteDashboard(), which destroys the card delegate that tapped Delete -- any code after the call in the delegate threw "obdPage is not defined" (c754f3d).
  • Chooser popup (square Dashboards button top-right, openDashboardChooser() / closeDashboardChooser() are also callable from the command server): a modal Popup up to 960 dp wide with a 2-column grid of cards. Each card renders a live miniature -- a second DashboardRenderer laid out at the page's full size and scaled down with transformOrigin: Item.Center. The miniature Loaders activate at aboutToShow (preloadMinis) so instantiation overlaps the popup's enter animation, and the stage fades in 180 ms after the spec lands so the gauges' 140 ms zero-to-value animation is never visible. The "grid" card uses a schematic 3 × 3 placeholder instead.
  • Card actions: always-visible buttons, no long-press ("discoverability-hostile in a glance-and-go in-car UI"). Copy on every JSON dashboard (calls duplicateDashboard(id, "")), Edit and Delete only when builtIn === false; Delete is two-tap ("Delete" -> "Sure?" with a 3 s timer). The grid sentinel has no actions.
  • + New pushes dashboards/editor/DashboardEditor.qml onto the page's StackView with { stackView, callerPage }; Edit adds editingId. ▲ Draft appears when the dashboardEditorDraft setting is non-empty (re-read on every aboutToShow) and pushes the editor with draftJson.
  • Primitives Gallery: a second popup with eight GalleryTiles showing every gauge with hard-coded values -- a dev/showcase screen the source marks for removal now that the editor exists.

Dashboard Editor Internals

The editor is pure QML -- it needed nothing new from either backend because DashboardManager already exposed save/delete/duplicate with parity. Interaction model (decided 2026-06-10, "hybrid"): tap an empty cell to place, drag a placed widget to move, tap to select and edit in a floating panel.

DashboardEditor.qml -- owner of the working spec

StateMeaning
cellsThe working cell array. Every mutation reassigns the whole array (_patchCell builds a shallow-merged copy); nothing mutates in place. This keeps the canvas Repeater and every binding honest, and it is what makes a rejected drag snap back for free.
gridColumns, gridRows12 × 6 for a new dashboard, or the loaded spec's values.
editingIdNon-empty when editing an existing user dashboard (the id is kept on save).
selectedIndex / selectedCellDrives the properties panel and the PID picker.
dirtySet by every mutation; gates the two-tap Cancel and the draft rescue.
draftJsonInjected by the chooser's Draft button; restored in Component.onCompleted before any editingId load.

Mutation API called by the canvas and panel:

FunctionBehaviour
addCellAt(type, col, row)Starts from the catalog's default span, clamps to the grid, then shrinks toward 1 × 1 (wider side first) until canPlace() succeeds; the tapped cell itself is guaranteed free. Selects the new cell and opens the PID picker unless the widget is self-binding.
moveCell(index, col, row)Clamps, checks canPlace excluding the cell itself, patches -- or, on a rejected drop, reassigns cells = cells.slice() so the dragged delegate is rebuilt at its origin.
nudgeCell, resizeCellStepper helpers (±1 column/row/span) built on the same checks.
removeCell, setCellParam, setCellProp, clearCellPropPatch helpers; clearing a prop removes the key so the gauge default applies again.
save()Label defaults to "Untitled"; id = editingId or _uniqueId(label) (slugify + uniquify against dashboardManager.dashboards and the reserved "grid"); builds { schema: 1, id, label, gridColumns, gridRows, cells }; on success clears dirty, clears the stored draft if this session resumed one, calls callerPage.setActiveDashboard(savedId) and pops. Failure shows a 3 s error banner.
cancel()First tap with unsaved work arms "Discard?" for 3 s; the second tap clears dirty, clears a resumed draft and pops. "Editing in a car -- accidental data loss hurts."
_sanitizeCells(raw)Applied to every spec arriving from disk or a draft: drops unknown types, clamps col/row/span into the grid, clears unknown paramIds (the panel then shows "Choose PID…").

Draft stash: switching menus mid-build pops the whole StackView, destroying the page. Component.onDestruction first forces OBDParameterModel.simulationActive = false (demo data must never leak into the real OBD views), then, if dirty, writes { editingId, label, gridColumns, gridRows, cells } as JSON to the dashboardEditorDraft setting. Only a session that resumed a draft may clear it, so opening and cancelling a fresh editor cannot wipe an earlier draft. Demo data is the checkable button in the top bar bound to simulationActive.

Properties panel placement: it floats over the canvas (300 dp wide, z: 20) and docks to the side away from the selected widget's centre column, sliding 150 ms. A docked panel was tried first and rejected because it resized the canvas on every selection change, rescaling the dashboard mid-edit and making drag snapping unstable.

EditorCanvas.qml

  • Geometry mirrors the renderer's defaults exactly (20 dp margin, 16 dp spacing, same cell formulas) so the layout you edit is the layout that renders.
  • canPlace(col, row, colSpan, rowSpan, exceptIndex): inside the grid and no rectangle overlap with any other cell.
  • _occupied: a flat row * cols + col boolean map recomputed whenever cells is reassigned; a Repeater over gridColumns * gridRows shows a [+] target on every free index (dimmed while dragging).
  • Placed cells: a synchronous Loader (synchronous so panel tweaks, which rebuild the Repeater, do not flicker) with the same bind/props logic as the renderer, a "no PID" hint for unbound PID widgets, a selection frame, and a MouseArea with drag.target: cellRoot. onPressed selects; while dragging, _updateDragCandidate() rounds the item position to the nearest cell, clamps, and sets dragCol/dragRow/dragValid for the highlight rectangle (accent when valid, statusDanger when not); onReleased emits cellMoveRequested.
  • Signals: emptyCellTapped(col, row), cellTapped(index), cellMoveRequested(index, col, row), backgroundTapped(). The canvas never mutates cells.

PalettePopup, PIDPicker, PropertiesPanel

  • PalettePopup: modal, 4-column grid of cards from WidgetCatalog.widgets (glyph + display name); tapping emits widgetPicked(type) and closes.
  • PIDPicker: modal, 85 % of the window height, a search field focused on open, and a flat row model built from allParameters filtered by supportedKinds ("*" passes all) and by the query against title or id, grouped under headers in the order numeric, percentage, temperature, pressure, voltage, bidirectional. The current PID is highlighted; empty results show "No matching PIDs".
  • PropertiesPanel: header (glyph, name, deselect ✕); PID button (red border while unbound; hidden for self-binding widgets); Column / Row / Width / Height ◄ value ► steppers calling nudgeCell / resizeCell; an OPTIONS repeater over the catalog's editableProps rendering a Switch for bools and a numeric TextField otherwise (empty = unset = gauge default; parsed with parseInt / parseFloat on editingFinished); "Remove widget". Because Repeater delegates survive selection changes between same-type cells and user input breaks bindings, each control re-syncs from the cell on a _cellRef change. The panel never mutates the cell; every control calls back into the editor page.

Every interactive control carries an objectName (newDashboardButton, dashCard_<id>_edit, editorEmptyCell_<c>_<r>, paletteCard_<type>, pidRow_<id>, stepper_Width_inc, panelOpt_<key>, ...) for the command-server test driver.

Authoring New Gauges and Dashboards

docs/GAUGE_AUTHORING.md is the source of truth for the API and carries the step-by-step recipes; update it in the same commit as any gauge or schema change. In short:

  • New dashboard: build it in the editor, or write a schema-1 JSON by hand and drop it into frontend/dashboards/presets/ (ships as a read-only built-in, picked up at the next start) or the user dashboards directory (picked up live).
  • New primitive: create frontend/gauges/MyGauge.qml, paste the shared binding preamble verbatim, animate _animNorm (not value), use Shape/PathAngleArc for curves and rotated Rectangles for marks, declare octaveSupportedKinds, scale typography with the cell, and register it in WidgetCatalog with a url, display name, glyph, default span, matching supportedKinds and curated editableProps with honest defaults. Without the catalog entry it will neither render nor be placeable. Then document it in §3 of the authoring guide and on this page.
  • New backend parameter: add the signal to both OBDManagers, the handler in OBDParameterModel._obdConnections, and the allParameters entry with a kind; gauges pick it up with no further work.

Design Decisions

  • A singleton aggregator between the backend and the gauges. OBDParameterModel was introduced (42bbf5f, "centralized OBD parameter definitions into a singleton") so that parameter metadata lives in one QML table and gauges bind by string id. That is what lets the same gauge run against the C++ manager, the Python manager, the dev-mode mock or pure-QML demo data, and what let the IMU parameters join later with zero gauge changes.
  • Coalesced model writes. Replacing paramValues per signal was correct but cost a full core on the Pi with nothing connected (486a809); a 33 ms flush keeps bindings reactive without allocating per write. The sparkline samples on its own timer, so the change did not alter any time axis.
  • Grid over free placement. Every dashboard anyone had written was grid-shaped, grids are far easier to edit on a touchscreen, and a 12-column grid maps cleanly onto the spans people actually want (TODO/dashboards-roadmap.md, "Key design decisions already made").
  • JSON before editor. Phase 2 (data-driven dashboards) was declared the hinge: an editor that emitted QML source would have been a mess, while an editor that emits a JSON object is a GUI over a data format. Hand-written dashboard QML files were retired once all built-ins were JSON.
  • Absolute positioning in the renderer. GridLayout could not give proportional row spans; explicit cell math also gives the editor a deterministic snap grid and makes the miniature previews pixel-consistent with the full view.
  • Built-ins read-only, "Copy" to derive. Presets are authoritative and their ids are reserved; a user file that reuses one is rejected at load rather than shadowing it, so an update to a preset can never be masked by a stale copy.
  • The editor is pure QML. The backend already had everything the editor needed; the only missing piece, "unique id from a label", was duplicated in QML rather than adding a slot to two backends. No CMake / main.py churn, no parity work.
  • One catalog, three consumers. The type -> url map used to live inline in the renderer; lifting it into WidgetCatalog means the palette cannot offer a type the renderer cannot draw, and the panel cannot expose a prop the gauge does not declare.
  • Curated, honest editable props. The panel shows a deliberately small set of scalar props with the gauge's real defaults so the in-car UI stays simple; the JSON stays fully expressive for power users (the TJ preset overrides min/max and sample intervals that the panel never offers).
  • Hybrid tap-and-drag. The original plan was tap-to-place only, because drag fights the chooser's Flickable; the editor canvas is a full-screen non-scrolling page, so drag is safe there and was added for placement. Tap-to-place stays for new widgets, steppers stay for precision.
  • Visible action buttons, two-tap destructive actions. Long-press is hidden; a Delete or Discard that fires on one tap is dangerous at 60 mph. Both confirmations time out after 3 s.
  • Draft rescue on destruction. The bottom bar pops the whole StackView when the user changes menus, which destroys the editor with no chance to ask; stashing the working spec in a setting and offering it back was the smallest fix that loses no work.
  • Demo data lives in the model, is forced off on exit. A sine sweep in QML needs no backend and no mock; the destruction hook guarantees the real OBD views can never show fake readings.
  • Validation logs and degrades, never throws. A typo in one cell of a hand-written spec must not take down the OBD page in a moving vehicle.
  • Hot reload with a signature, not just an event. Directory events fire for the manager's own atomic saves; comparing a name/mtime/size signature makes the external-edit path and the in-app path share one rescan without double work.
