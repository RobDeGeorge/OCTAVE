MainMenu.qml

frontend/MainMenu.qml is the home screen and the initialItem of the StackView. It presents a two-column dashboard with media controls on the left and OBD telemetry on the right.

Layout

RowLayout {
    anchors.fill: parent
    spacing: App.Spacing.dp(10)

    // LEFT: Media section (33% width)
    Rectangle { Layout.preferredWidth: parent.width * 0.33 }

    // RIGHT: OBD section (fills remaining 67%)
    Rectangle { Layout.fillWidth: true }
}

Media Section Features

  • Blurred album art background — Uses GaussianBlur on the current album art with a dark overlay for readability
  • Album art image with DropShadow effect
  • Auto-scrolling text — Song title and artist/album use a Flickable with a Timer-driven NumberAnimation that scrolls horizontally when text overflows
  • Seek slider — Custom-styled Slider with accent-colored fill and a circular handle
  • Dual media source — The useSpotify flag determines whether properties come from mediaManager or spotifyManager

OBD Section

Embeds the HomeOBDView component which displays a configurable subset of OBD parameters in a compact stacked layout. Clicking either section navigates to the relevant full page.

Backend Managers Used

mediaManager, spotifyManager, settingsManager, obdManager

MediaRoom.qml

frontend/MediaRoom.qml is the full-screen "now playing" view with large album art, playback controls, and optional waveform visualizer.

Key Features

  • AlbumArtCarousel — The centerpiece uses the reusable AlbumArtCarousel component with configurable transitions (Crossfade, Slide, Vinyl Lift, Dissolve, Flip, and 3D modes like Coverflow, Conveyor, Stack)
  • Blurred background — Full-screen album art blur behind all content, with configurable blur radius
  • Scrolling metadata — Song title, artist, and album with auto-scroll for long text
  • Seek bar with position/duration display
  • Transport controls — Previous, Play/Pause, Next, Shuffle buttons with press animations
  • Empty playlist detection — When no local songs exist, shows a download button instead of controls
  • Cached DownloadPage navigation — The openDownloadPage() function reuses a cached page instance stored on the StackView

Spotify Integration

The useSpotify property switches all track info, playback commands, and progress between local and Spotify sources. Spotify track info is cached in dedicated properties updated via Connections signals.

Side Card Preloading

MediaRoom pre-fetches album art for adjacent tracks to ensure instant coverflow transitions:

// Hidden preloaders decode next/prev art at full resolution
Image {
    id: prevArtPreloader
    visible: false; width: 1; height: 1
    sourceSize: Qt.size(albumArtStack.artSize * 2, ...)
    asynchronous: true; cache: true
}
Image {
    id: nextArtPreloader
    visible: false; width: 1; height: 1
    sourceSize: Qt.size(albumArtStack.artSize * 2, ...)
    asynchronous: true; cache: true
}

A sideCardRefreshTimer fires on the next event-loop tick after track changes, using a batched backend call (get_neighbor_album_arts()) to minimize PySide6 bridge crossings.

Animation and Performance

Track change animations are carefully sequenced to avoid frame stuttering:

  1. Kill the visualizer instantly (snap bars to zero before animation)
  2. Trigger the carousel slide animation
  3. Defer FFT analysis until after the settled signal fires
  4. Fade the visualizer back in after a brief delay
function animateTrackChange() {
    vizFadeInTimer.stop()
    _cardAnimBusy = true
    waveformContainer._vizFadedOut = true
    waveformContainer.dropBars()
    albumArtStack.triggerSlide()
}

Backend Managers Used

mediaManager, spotifyManager, settingsManager, audioAnalyzer, downloadManager

MediaPlayer.qml

frontend/MediaPlayer.qml is the playlist/library browser view showing all songs in a scrollable list.

Key Features

  • Playlist management — Local and Spotify playlists are listed and switchable. Properties track both playlistNames and spotifyPlaylistNames
  • Song list — Each row shows index, album art thumbnail (via LazyImage), title, artist, and album
  • Playback state highlighting — Currently playing song is highlighted with playingHighlightColor; paused songs use pausedHighlightColor
  • Initial scroll position — On page load, the list scrolls to the currently playing song
  • Cached DownloadPage — Uses the same caching pattern as MediaRoom, stored on stackView._cachedDownloadPage
  • Force model refresh — A playlistRefreshCounter is incremented when switching between local and Spotify playlists to force delegate rebinding

Backend Managers Used

mediaManager, spotifyManager, settingsManager, downloadManager

OBDMenu.qml

frontend/OBDMenu.qml displays live OBD-II vehicle data in a responsive grid of parameter cards.

Layout

GridLayout {
    id: parametersGrid
    columns: 3  // Adapts: 2 for ≤4 params, 3 for ≤9, 4 for more
    rowSpacing: App.Spacing.dp(10)
    columnSpacing: App.Spacing.dp(10)

    Repeater {
        model: allParameters  // From OBDParameterModel singleton
    }
}

Key Features

  • OBDParameterModel singleton — All 93 OBD parameters with display metadata (title, unit, min, max) are defined in the OBDParameterModel singleton
  • Configurable visibility — Each parameter can be enabled/disabled via settings; the grid column count auto-adjusts
  • Animated values — A Behavior on displayValue with 50ms linear animation creates a smooth rolling number effect
  • Dual card styles — The useCircularCards setting switches between square progress bar cards and circular gauge cards
  • OBD-specific theming — Uses Style.obdBoxBackground, Style.obdBarColor, Style.obdValueColor, and Style.obdLabelColor

Backend Managers Used

obdManager, settingsManager

OBDDiagnostics.qml

frontend/OBDDiagnostics.qml is the diagnostic trouble code (DTC) reader and clearer.

Key Features

  • DTC scanning — Reads trouble codes via obdManager and displays code + description
  • MIL status — Shows whether the Check Engine Light is on or off
  • DTC clearing — Sends a clear command and reports success/failure
  • Freeze frame data — Displays snapshot data captured when a DTC was set
  • Terminal output — Uses the TerminalFeedback component to show a real-time log of all diagnostic operations in a retro terminal style

Signal Handling

Connections {
    target: obdManager
    function onDtcCodesChanged(codes) {
        dtcCodes = codes
        for (var i = 0; i < codes.length; i++) {
            terminalOutput.appendLine(
                "[DTC] " + codes[i].code + " - " + codes[i].description)
        }
    }
    function onMilStatusChanged(status) { ... }
    function onDtcClearResult(success, message) { ... }
}

Backend Managers Used

obdManager

CarMenu.qml

frontend/CarMenu.qml renders a 3D vehicle model that rotates in real time based on IMU sensor data.

Key Features

  • QtQuick3D integration — Imports QtQuick3D and QtQuick3D.AssetUtils for real-time 3D rendering
  • Quaternion-based rotation — The 3D car model uses quaternion orientation directly from the BerryIMU, avoiding gimbal lock. The sensor frame (Z-up) is remapped to Qt3D's frame (Y-up): (w,x,y,z) → (w,y,z,x)
  • Camera orbit — Properties cameraYaw, cameraPitch, and cameraDistance allow interactive camera control
  • Simulation fallback — When no IMU is connected, a timer generates sinusoidal pitch and roll values for demonstration
  • Gauge overlays — Heading (with cardinal direction), altitude, G-force, and barometric temperature are displayed around the 3D viewport

IMU Connection

Connections {
    target: berryIMU
    // Quaternion for 3D model (no gimbal lock)
    function onOrientationChanged(w, x, y, z) {
        carModel.rotation = Qt.quaternion(w, y, z, x)
    }
    // Euler angles for gauge displays only
    function onPitchChanged(val) { currentPitch = val }
    function onRollChanged(val) { currentRoll = val }
    function onHeadingChanged(val) { currentHeading = val }
}

Backend Managers Used

berryIMU, settingsManager

SensorMenu.qml

frontend/SensorMenu.qml is a dashboard for all BerryIMU sensor readings.

Key Features

  • SensorCard components — Each reading (pitch, roll, heading, altitude, temperature) is displayed in a dedicated SensorCard
  • GForceDisplay — A specialized G-force visualization with lateral/longitudinal components and a trail history
  • Configurable units — Temperature (Celsius/Fahrenheit) and altitude (meters/feet) are switchable via settings
  • Configurable visibility — Each sensor card can be shown/hidden independently
  • Decimal precision — Configurable decimal places for all numeric displays
  • Emit rate control — The sensor polling rate is adjustable and applied on page load via berryIMU.setEmitRate(emitRate)

Backend Managers Used

berryIMU, settingsManager

ClockMenu.qml

frontend/ClockMenu.qml is a full-screen clock with both digital and analog displays.

Key Features

  • Digital clock — Large text display using dp(72) font size, respecting the 24-hour format setting
  • Date display below the digital clock
  • Analog clock face — Built entirely from QML Rectangle primitives:
    • Hour hand: width: dp(4), height: parent.height * 0.3
    • Minute hand: width: dp(2), height: parent.height * 0.4
    • Second hand and center dot
    • All hands use transformOrigin: Item.Bottom and rotate around the clock center
  • Timer-driven updates — A 1-second timer updates all hand rotations and text

Backend Managers Used

settingsManager (for clock format preference)

PhoneMirrorView.qml

frontend/PhoneMirrorView.qml displays a mirrored phone screen using OCTAVE's built-in scrcpy-protocol client. A VideoOutput binds its videoSink to phoneMirrorManager.videoSink and decoded frames land on it directly; a MultiPointTouchArea forwards every touch point through phoneMirrorManager.injectTouch(id, action, relX, relY) (real multitouch); Back/Home/Recents buttons overlay the bottom edge. The manager reports specific errors (unauthorized, offline, unplugged) and the view polls getDeviceState() every 2 s on a phone-side error and restarts on its own.

Backend Managers Used

phoneMirrorManager

AndroidAutoView.qml

frontend/AndroidAutoView.qml embeds the Google Desktop Head Unit (DHU) directly into OCTAVE's window.

Key Features

  • Custom QML type — Imports OCTAVE.AndroidAuto 1.0 for the EmbeddedDhuItem component
  • Seamless embedding — The DHU window becomes a child widget of the QML item, rendering natively within the OCTAVE window
  • Stream signals — onStreamStarted and onStreamStopped track the DHU connection state
  • Close button overlay — A semi-transparent "X" button at the top-right corner allows stopping the DHU
  • Error display — Connection failures show an error message with a retry button
EmbeddedDhuItem {
    id: embeddedDhu
    anchors.fill: parent

    Component.onCompleted: {
        if (androidAutoManager)
            connectToManager(androidAutoManager)
    }
}

Backend Managers Used

androidAutoManager

DownloadPage.qml

frontend/DownloadPage.qml provides a YouTube music search and download interface.

Key Features

  • Search interface — Text input with results displayed as cards showing title, artist, and duration
  • Download queue — Active downloads tracked by song_id with progress bars (0.0 to 1.0)
  • Playlist targeting — A playlist selector lets users choose which local playlist to download songs into
  • Page caching — The DownloadPage is created once and cached on stackView._cachedDownloadPage so navigating away and back is instant
  • On-screen keyboard — A showKeyboard flag for touch environments
  • Pagination — hasMoreResults enables loading additional search results

Download Manager Connections

Connections {
    target: downloadManager

    function onSearchResults(jsonStr) {
        var results = JSON.parse(jsonStr)
        downloadPage.searchResults = results
        // If we got a full page (20), there are probably more
        downloadPage.hasMoreResults =
            (results.length % 20 === 0) && results.length > 0
    }
}

Backend Managers Used

downloadManager, mediaManager
