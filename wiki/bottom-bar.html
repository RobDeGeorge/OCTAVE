Overview

frontend/BottomBar.qml (about 3100 lines) is the persistent control surface that is visible on every page. It is a Rectangle with a themed gradient background whose contents are provided by a Loader that swaps between two complete layout components: a horizontal bar docked at the bottom of the window and a vertical bar docked at the left. Both layouts carry the same three logical sections — media transport controls, navigation buttons, and the clock.

It is instantiated once in frontend/Main.qml with z: 0; the page StackView sits above it (z: 1) and anchors to bottomBar.top (horizontal) or bottomBar.right (vertical). A 12 px gradient Rectangle (bottomBarShadow / sideBarShadow) in Main.qml draws a soft shadow along the bar's inner edge.

Layout and Structure

The root is a Rectangle whose gradient direction follows the orientation. Note the unusual stop positions — the "start" colour is placed at 1.5, beyond the end of the gradient, so the visible bar is dominated by bottomBarGradientEnd (the theme's baseAlt) fading toward base:

Rectangle {
    id: bottomBar
    gradient: Gradient {
        orientation: isVertical ? Gradient.Horizontal : Gradient.Vertical
        GradientStop { position: 1.5; color: App.Style.bottomBarGradientStart }
        GradientStop { position: 0.0; color: App.Style.bottomBarGradientEnd }
    }

    required property StackView stackView
    required property Window mainWindow

    Loader {
        anchors.fill: parent
        sourceComponent: isVertical ? verticalLayoutComponent : horizontalLayoutComponent
    }
}

Like every other QML file in the project, the bar defines local dp() / dpMin() wrappers (Math.round(size * (App.Spacing.effectiveScale || 1.0))) instead of calling App.Spacing.dp(). The comment at the top of the file explains why: calling functions on a QML singleton is unreliable on Android, so every file re-implements the two-line helper locally.

Section 1: Media Controls

In the horizontal layout this Item takes parent.width * 0.4 when settingsManager.showBottomBarMediaControls is true. When the user hides the media controls the item stays in the layout but its width is bound to clockSection.width, so the navigation row still sits at the true horizontal centre. The vertical layout uses the same trick with heights (40 % shown, 10 % hidden).

Section 2: Navigation

Uses Layout.fillWidth: true (or fillHeight when vertical) and centres a RowLayout / ColumnLayout of nav buttons. The horizontal row has z: 1 so that, with many buttons enabled, its outer buttons (Phone Mirror in particular) still receive clicks when the row is wider than its section. Its spacing is computed by fitSpacing:

readonly property real preferredSpacing: App.Spacing.bottomBarBetweenButtonMargin * 6
readonly property real fitSpacing: {
    var n = 0, w = 0
    for (var i = 0; i < children.length; ++i) {
        var c = children[i]
        if (c.visible && c.implicitWidth > 0) { n++; w += c.implicitWidth }
    }
    if (n < 2) return preferredSpacing
    var avail = parent.width - w
    return Math.max(dp(4), Math.min(preferredSpacing, avail / (n - 1)))
}

The gap between buttons shrinks (down to dp(4)) instead of letting the row overflow under the clock or the media controls.

Section 3: Clock

Horizontal: parent.width * 0.2 when settingsManager.showClock is true, otherwise 0 so the navigation row re-centres. Vertical: a fixed 10 % of the bar height at the bottom.

Dual Orientation

The isVertical property is bound to the persisted setting (Display → Layout → "Nav Bar Position", a SettingsSegmentedControl with the options "bottom" and "side"):

property bool isVertical: settingsManager &&
    settingsManager.bottomBarOrientation === "side"

updateLayout() re-anchors the bar. Anchors are released (set to undefined) before the new ones are assigned, which avoids a transient state where conflicting anchors are active at the same time:

function updateLayout() {
    if (isVertical) {
        anchors.bottom = undefined
        anchors.right = undefined
        anchors.left = parent.left
        anchors.top = parent.top
        width = parent.width * 0.1
        height = parent.height
    } else {
        anchors.top = undefined
        anchors.right = undefined
        anchors.left = parent.left
        anchors.bottom = parent.bottom
        width = parent.width
        height = parent.height * App.Spacing.bottomBarHeightPercent   // 0.125
    }
}

It runs from Component.onCompleted, from onIsVerticalChanged, and from a Connections on settingsManager.bottomBarOrientationChanged. A second Connections on the parent's widthChanged / heightChanged keeps the explicit width/height current after a window resize.

Main.qml reacts to the same signal: it flips isVerticalLayout, re-asserts the z-order (stackView.z = 1, bottomBar.z = 0) and, if the Settings page is open, restarts navReloadTimer (150 ms) which replaces the current SettingsMenu with a fresh instance on the same section so the settings layout re-measures against the new content area.

Media Transport Controls

Section 1 contains, in order: Previous, Play/Pause, Next, Shuffle, Mute and the volume percentage. Each transport button is a Control with a transparent background, an SVG rendered through the hidden-Image-plus-ColorOverlay pattern (see SVG Icon Pattern), and the press animation described under Button Animation Pattern:

Control {
    id: previousButtonControl
    implicitWidth: App.Spacing.bottomBarPreviousButtonWidth
    implicitHeight: App.Spacing.bottomBarPreviousButtonHeight
    scale: mouseAreaPrev.pressed ? 0.8 : 1.0
    opacity: mouseAreaPrev.pressed ? 0.7 : 1.0
    background: Rectangle { color: "transparent" }

    contentItem: Item {
        Image { id: previousButtonImage; source: "./assets/previous_button.svg"; visible: false }
        ColorOverlay { source: previousButtonImage; color: App.Style.bottomBarPreviousButton }
    }
    Item {   // enlarged hit area
        anchors.centerIn: parent
        width: parent.width * 2.5
        height: parent.height * 3.0
        MouseArea {
            id: mouseAreaPrev
            anchors.fill: parent
            onClicked: useSpotify ? spotifyManager.previous_track() : mediaManager.previous_track()
        }
    }
}

Every button wraps its MouseArea in an invisible Item larger than the drawn icon so it is easy to hit on a car touchscreen. The multipliers differ per button:

Play/Pause Button

The play/pause image picks its source from the active backend's is_playing(). Because that is a method call and not a property, the binding does not re-evaluate on its own; two Connections blocks (one on mediaManager, one on spotifyManager) listen for playStateChanged(playing) and assign the source of both the horizontal and the vertical image explicitly. The mediaManager handler only acts when !useSpotify, the Spotify handler only when useSpotify:

source: {
    var isPlaying = useSpotify ?
        (spotifyManager && spotifyManager.is_playing()) :
        (mediaManager && mediaManager.is_playing())
    return isPlaying ? "./assets/pause_button.svg" : "./assets/play_button.svg"
}

Volume Slider and Mute

Volume Label and Popup

The bar itself only shows the percentage as bold text (volumeControl.currentValue + "%", primaryTextColor, size bottomBarVolumeText). Tapping it opens popupSlider, a modal Popup as wide as the window and dp(140) tall, centred in Overlay.overlay, closed by Escape or by pressing outside. Its background is backgroundColor with a 1 px accent border. Inside: a dp(32) accent-coloured percentage label and a Slider:

Slider {
    id: volumeSlider
    width: parent.width * 0.95
    height: dp(50)
    from: 0; to: 100; stepSize: 1
    value: volumeControl.currentValue

    background: Rectangle {      // dp(16) tall track, hoverColor, volumeSliderColor fill
        ...
    }
    handle: Rectangle {          // dp(40) circle in accent
        ...
    }

    onValueChanged: {
        volumeControl.currentValue = value
        // Single dispatch to settings + every audio output.
        volumeController.applyVolume(Math.round(value))

        if (value > 0 && muteButton.isMuted) {
            muteButton.isMuted = false
            mediaManager.toggle_mute()
        }
        updateMuteButtonImage()
    }
}

Volume Routing: VolumeController

The bar never computes the volume curve and never calls mediaManager.setVolume() directly (except for a fallback when settingsManager is missing). Every change goes through volumeController.applyVolume(percent), a QML context property registered by both backends. The curve is quadratic: linear = (percent / 100)².

BackendImplementationWhat applyVolume(percent) does
C++ src/managers/volumecontroller.{h,cpp} Clamps to 0–100, calls SettingsManager::setCurrentVolume(percent), then emits volumeApplied(percent, linear). src/main.cpp connects that signal to mediaManager.setVolume(linear), a 300 ms trailing-debounced spotifyManager.set_volume(percent), phoneMirrorManager.setVolume(linear) and (desktop builds) esp32VolumeManager.send_volume_update(percent) — the same fan-out as the Python controller.
Python backend/volume_utils.py Clamps, calls settings_manager.setCurrentVolume(percent), media_manager.setVolume(linear), spotify_manager.set_volume(percent) (if connected, through the same 300 ms trailing debounce as C++), phone_mirror_manager.setVolume(linear), esp32_manager.send_volume_update(percent).

At startup volumeControl.Component.onCompleted reads settingsManager.currentVolume and calls volumeController.applyVolume(currentValue) so every output starts at the persisted level (both entry points also apply it once before QML loads). The reverse direction is handled by a Connections on mediaManager.volumeChanged(volume), which converts the linear value back to a percent with the inverse curve — Math.round(Math.sqrt(volume) * 100) — and updates the label and slider, but only while the slider is not being dragged (!volumeSlider.pressed). The vertical layout's handler does the same for volumeControlVertical / volumeSliderVertical, guarded by !volumeSliderVertical.pressed.

One Curve, One Entry Point
The docstring in backend/volume_utils.py records why this exists: the curve used to be hard-coded in about nine call sites across main.py and QML, so any change had to be made everywhere in lockstep. See the Frontend Overview and Media Manager pages for the consumers.

Touch-Friendly Slider

Nine dp(80) square MouseAreas are laid along the track at index * (volumeSlider.width / 8), each mapping its press position back to a slider value. preventStealing: false lets the slider itself still receive the events. This turns a thin 16 px track into a band of large targets:

Repeater {
    model: 9
    MouseArea {
        x: (index * (volumeSlider.width / 8)) - width/2 + volumeSlider.x
        y: volumeSlider.y + volumeSlider.height/2 - height/2
        width: dp(80); height: dp(80)
        onMouseXChanged: {
            if (pressed) {
                var globalX = mapToItem(volumeSlider, mouseX, mouseY).x
                var newPosition = Math.max(0, Math.min(1,
                    (globalX - volumeSlider.leftPadding) / volumeSlider.availableWidth))
                volumeSlider.value = newPosition * 100
            }
        }
        preventStealing: false
    }
}

Mute Button

Tapping Mute normally calls mediaManager.toggle_mute(). If the volume is already 0 the tap instead restores the persisted startup volume (Math.round(settingsManager.startUpVolume * 100)) by assigning the slider, which routes through applyVolume. Mute state comes back from mediaManager.muteChanged(muted):

onClicked: {
    if (volumeControl.currentValue === 0 && settingsManager) {
        volumeSlider.value = Math.round(settingsManager.startUpVolume * 100)
    } else {
        mediaManager.toggle_mute()
    }
}

Update Notification

The Settings button carries a dp(8) orange dot (#FF9800) anchored to its top-right corner, visible while networkManager.updateStatus === "update-available". The pulse animation is bound to the same condition through running, so it costs nothing while hidden:

Rectangle {
    width: dp(8); height: dp(8); radius: width / 2
    color: "#FF9800"
    z: 10
    visible: networkManager && networkManager.updateStatus === "update-available"

    SequentialAnimation on opacity {
        running: networkManager && networkManager.updateStatus === "update-available"
        loops: Animation.Infinite
        NumberAnimation { from: 1.0; to: 0.3; duration: 1200 }
        NumberAnimation { from: 0.3; to: 1.0; duration: 1200 }
    }
}

The same dot, with the same colour and 1200 ms cadence, is repeated inside the settings UI on the "About" entry of every layout (sidebar row, carousel tab, hub card, dashboard card) and on the About page's "Check for Updates" button, so the user can follow it all the way to the update controls. updateStatus is produced by NetworkManager in both backends (see Network Manager); the other values it can take are "checking", "up-to-date", "ahead", "diverged" and "error", none of which show the dot.

Clock Section

The clock is a Text fed by the clock context property (Clock in both backends emits timeChanged(QString); the format and seconds options live in Display → Clock). It uses clockTextColor (the theme accent), the global font, and font.pixelSize: settingsManager.clockSize (default 18, slider 10–85). Tapping the clock pushes SensorHome.qml. A press highlight uses hoverColor.

Both layouts bind their clock Text to one bar-level property, bottomBar.clockTimeText, which a single Connections on clock.timeChanged (also at bar level, outside both layout components) keeps current:

property string clockTimeText: ""

Connections {
    target: clock
    function onTimeChanged(time) { bottomBar.clockTimeText = time }
}

The comment explains why the value is held on the bar rather than written into each layout's Text by its own handler: the layout that the Loader instantiates on an orientation switch shows the current time immediately instead of staying blank until the clock next emits — up to a minute when seconds are hidden.

Shuffle State

isShuffleEnabled on the bar root is the single source of truth for both layouts' shuffle buttons. It is initialised from spotifyManager.is_shuffled() or mediaManager.is_shuffled() depending on useSpotify, and kept current by shuffleStateChanged(enabled) from whichever manager is active, plus a Connections on settingsManager.mediaSourceChanged that re-reads the correct source when the user switches between local and Spotify playback.

When active, the button background becomes bottomBarToggleShade (radius 4) and the icon is tinted bottomBarActiveToggleButton (the accent). When inactive the icon uses bottomBarShuffleButton, the per-theme bottombar.shuffle colour.

External Volume Sources

Volume can change without the slider being touched. All of these end in volumeController.applyVolume() in one of the backends, so the bar simply reacts to mediaManager.volumeChanged:

SourcePath
ESP32 rotary encoderesp32VolumeManager.volumeChangeRequested(delta) → applyVolume(currentVolume + change) (wired in src/main.cpp / main.py). The knob's mute button toggles mediaManager mute and the bar's icon follows via muteChanged.
PAJ7620U2 gesture sensorUp/down gestures call applyVolume(currentVolume ± step) with gestureVolumeStep.
StartupPersisted currentVolume is applied by the entry point and again by the bar's Component.onCompleted.
Spotify connectspotifyManager.connectionStateChanged(true) → the bar calls spotifyManager.set_volume(settingsManager.currentVolume) so a freshly connected device matches OCTAVE's level.

Manager Communication

Every media action is dispatched by the useSpotify flag:

property bool useSpotify: settingsManager &&
    settingsManager.mediaSource === "spotify" &&
    spotifyManager && spotifyManager.is_connected()
  • useSpotify ? spotifyManager.previous_track() : mediaManager.previous_track()
  • useSpotify ? spotifyManager.toggle_play() : mediaManager.toggle_play()
  • useSpotify ? spotifyManager.next_track() : mediaManager.next_track()
  • useSpotify ? spotifyManager.toggle_shuffle() : mediaManager.toggle_shuffle()

Mute and volume feedback always come from mediaManager (the local player is the audio device that is actually muted). The context properties the bar depends on — settingsManager, mediaManager, spotifyManager, volumeController, networkManager, clock, and the optional isAndroid flag — are registered under the same names by src/main.cpp and main.py.

Toggle View Popup

At the bottom of the file, outside both layout components, a modal Popup named settingsVisibilityPopup ("Toggle View") lists six settings sections (Device, Media, Display, OBD, Accessories, About) with animated switches bound to settingsManager.is_settings_section_visible(section) and writing save_settings_section_visibility(section, state). It is defined at bar level "so both horizontal and vertical layouts can access it": the Settings nav button's MouseArea in each layout calls settingsVisibilityPopup.open() from onPressAndHold, while a plain tap keeps the navigate / navigateToHub() behaviour described above. The visibility map is honoured by SettingsMenu.buildHubModel() (see Settings UI → Section Visibility).

Button Animation Pattern

Every interactive button follows the same press feedback: scale to 0.8 with an Easing.OutBack overshoot of 1.1 over 200 ms, and opacity to 0.7 over 150 ms. Transport buttons animate the Control; navigation buttons animate both the bordered background and the contentItem separately so the border and icon shrink together:

scale: mouseArea.pressed ? 0.8 : 1.0
Behavior on scale {
    NumberAnimation { duration: 200; easing.type: Easing.OutBack; easing.overshoot: 1.1 }
}
opacity: mouseArea.pressed ? 0.7 : 1.0
Behavior on opacity { NumberAnimation { duration: 150 } }

SVG Icon Pattern

All icons are flat single-fill SVGs from frontend/assets/. The Image is hidden and used only as the source of a ColorOverlay (Qt5Compat.GraphicalEffects), which recolours every opaque pixel with a theme token:

Image {
    id: iconImage
    source: "./assets/home_button.svg"
    sourceSize: Qt.size(width * 2, height * 2)   // 2x supersample
    fillMode: Image.PreserveAspectFit
    smooth: true; antialiasing: true; mipmap: true
    visible: false
}
ColorOverlay {
    anchors.fill: iconImage
    source: iconImage
    color: App.Style.bottomBarHomeButton
}

Because every token in Style.qml has a Behavior on colour animation, the icons cross-fade when the theme changes (see Theme System → Colour Transitions). The bar repeats this pair by hand about twenty times; the newer frontend/ThemedIcon.qml wraps the same pattern for the settings UI but the bar has not been migrated to it.

Design Decisions

DecisionRationale (from code comments and commit history)
Two complete layout Components instead of one reflowing layout The horizontal and vertical bars differ in more than direction (section proportions, button widths, hit areas, popup ids), so each is written out in full and a Loader swaps them. The cost is duplication: helper functions, most Connections and the mute/volume logic exist twice (suffixed Vertical); only the clock text (clockTimeText) and the shuffle flag are shared at bar level.
Release anchors before re-anchoring Comment in updateLayout(): "Release anchors first to prevent binding loops". Setting bottom and top at the same time would over-constrain the item.
Local dp()/dpMin() wrappers "Work around Qt Android singleton-function bug" — singleton functions are unreliable on Android, so only singleton properties (App.Spacing.effectiveScale) are read across the boundary.
All volume changes go through volumeController.applyVolume() Commit d2b047b ("volume curve de-duplication") replaced the per-site Math.pow(value/100, 2) and the four manual setVolume calls with one dispatcher. Changing the curve is now a one-line edit in toLinear() and every output stays in sync.
Hidden media section keeps the clock's width Comment: "When hidden, mirror the clock section's width so nav buttons sit at the true horizontal center". Collapsing it to zero would shift the nav row left.
Nav row shrinks its spacing and sits at z: 1 Comments: "Shrink the gap between buttons when they would not fit, instead of overflowing under the clock / media controls" and "keep it above the neighbouring sections so the outermost buttons (e.g. Phone Mirror) still receive clicks". Enabling Android Auto and Phone Mirror adds two buttons to a row sized for five.
Nine circular touch areas on the popup slider A 16 px track is impractical to grab while driving; the overlapping dp(80) areas turn the whole band into a target while leaving the Slider functional.
Mute at 0 % restores the startup volume Comment: "If volume is 0, restore to startup volume instead of toggling mute". Toggling mute on a silent output would do nothing visible.
Sensor button remembers and validates the last subpage Comments and commit 0c29e64 ("Fix sensor menu dead-end"): a stored lastSensorPage that no longer loads (CarMenu needs the optional QtQuick3D module) used to make the button appear dead. The failure is now logged, the preference cleared, and Sensor Home shown.
Second tap on Settings returns to the hub The Hub and Dashboard layouts have a card-grid landing state; navigateToHub() gives the nav button a purpose while already in Settings. The section-visibility popup moved to press-and-hold on the same button (see above), so a tap never opens a modal by surprise.
Phone Mirror pops back to an existing view Comment: "Check if PhoneMirrorView is already on the stack - if so, pop back to it". Pushing a second view would start a second mirroring session over the live one.
playStateChanged handlers instead of relying on the binding is_playing() is a method, so the image source binding is evaluated once; the signal handlers are what actually flip the icon.
Inverse curve on volumeChanged The bar stores percent, the player reports linear; Math.sqrt(volume) * 100 is the exact inverse of the quadratic in VolumeController, so external changes display the same number the user would have set.
StackView transitions disabled in Main.qml Comment: "Disable transitions for better performance" — every push from the bar is instant, which matters on the Raspberry Pi / Orange Pi head units.
