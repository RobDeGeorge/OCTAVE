Where to Look First

Most failures do not pop up a message. The reason is written in one of three places. Look in this order:

  1. The status line of the part that is failing. The car: Settings > OBD > Connection, with its Connection Log. A phone: Settings > Phone > Phone Mirror, Android Auto or iPhone. Music: the Scan Log in Settings > Media > Library & Playback. A sensor or the knob: its card in Settings > Accessories. These say what is missing in plain words.
  2. Settings > Device > Developer > Diagnostics. It shows the last 200 lines of the log on the screen, so you can read them in the car. The buttons are in the table below.
  3. The log files, described in the next section. A crash, a frozen screen and a dropped adapter all leave a line there even when the screen showed nothing.
Diagnostics buttonWhat it does
RefreshReads the last 200 log lines again.
CopyPuts the last 400 lines and the device information on the clipboard.
Export logsCopies every log file to a new folder OCTAVE-logs-<date>-<time> in your Downloads folder, with a device-info.txt. This is how you get logs off a phone or a tablet.
Open folderOpens the log folder in the file manager. Not on Android.

The card also shows the OCTAVE version and the path of the log folder. Include both when you report a problem.

The Log Files

The logs are in a logs folder inside OCTAVE's config folder:

SystemFolder
Windows%APPDATA%\OCTAVE\logs\
macOS~/Library/Application Support/OCTAVE/logs/
Linux, Raspberry Pi~/.config/OCTAVE/logs/ (under $XDG_CONFIG_HOME if that is set)
AndroidInside the app's private storage, which a file manager cannot open. Use Export logs. The same lines also go to adb logcat.
FileWhat is in it
octave-cpp.logEverything of note: connections made and lost, songs skipped, sensors found. Start here.
octave-cpp-error.logOnly warnings and errors, and the trace of a crash. Shorter, so a problem is easier to find.
octave-cpp-debug.logEvery detail, including each line sent to and received from the OBD adapter. Written only when OCTAVE is started with --debug.
hang-<date>-<time>.txtLinux only: what every thread was doing when the screen froze for 15 seconds. Needs gdb installed.

Old logs are replaced by new ones, so the folder stays small: about 30 MB at most without --debug.

To get the detailed log, start OCTAVE from a terminal with --debug, make the problem happen, then export the logs:

octave --debug                                  # an installed or built binary
./OCTAVE-<version>-linux-x86_64.AppImage --debug # the AppImage

Architecture explains how logging and the crash trace work.

Installing and Starting

These are problems with a downloaded package. Problems building from source are on the Building page.

Windows: "DLL not found" when starting

Files are missing from the install folder. The installer puts every DLL OCTAVE needs, including the Visual C++ runtime, next to OCTAVE.exe.

  1. Run the installer (OCTAVE-<version>-windows-x86_64.exe) again.
  2. If you copied the program folder by hand, copy all of it, not only the .exe.

macOS: "App is damaged" or "cannot be opened"

The .dmg is not signed with an Apple Developer ID and not notarized, so macOS blocks a downloaded copy.

  1. Try to open OCTAVE once, then go to System Settings > Privacy & Security and choose Open Anyway.
  2. If macOS still says "damaged", remove the download mark in Terminal: xattr -dr com.apple.quarantine /Applications/OCTAVE.app
  3. If that does not help, the download itself may be broken: download it again.

Linux: AppImage won't run

The file is not marked as a program, or the system has no FUSE 2, which an AppImage uses to open itself.

  1. chmod +x OCTAVE-<version>-linux-x86_64.AppImage
  2. Install FUSE 2: sudo apt install libfuse2 on Debian and Ubuntu, sudo pacman -S fuse2 on Arch.
  3. Or run it without FUSE: ./OCTAVE-<version>-linux-x86_64.AppImage --appimage-extract-and-run
  4. An error that names GLIBC means the system is older than Ubuntu 22.04, which the release is built on. Build OCTAVE on that machine instead: see Building.

On a Raspberry Pi or another ARM board, use the aarch64 AppImage.

Android: the update will not install

The new APK is signed with a different key from the installed one. This happens between a release and a build you made yourself, and with releases older than 0.9.4.

  1. Uninstall OCTAVE (this deletes its settings on the phone).
  2. Install the new APK.

The app will not start, or closes at once

Start it from a terminal so you can read what it says.

  1. Run it with --debug and read the last lines printed, or octave-cpp-error.log.
  2. Could not load the Qt platform plugin "xcb": see Screen and Display.
  3. Could not locate frontend/ directory: the program was moved away from its frontend folder. The folder must be next to the program or one level above it. Reinstall, or move both together.
  4. To rule out your own settings, start once on an empty config folder: octave --config /tmp/octave-test. If that works, the problem is in your config folder; nothing in it was changed by the test.
  5. To check the app without any hardware: octave --sim starts with a simulated car on a throwaway config.

Screen and Display

Linux: Could not load the Qt platform plugin "xcb"

Libraries that Qt needs to open a window under X11 are missing, or there is no display to open it on. This happens with a binary you built, on a minimal system.

  1. Install the libraries (Debian and Ubuntu names): 
    sudo apt install libxcb1 libxcb-cursor0 libxcb-icccm4 libxcb-image0 libxcb-keysyms1 \
  libxcb-randr0 libxcb-render0 libxcb-render-util0 libxcb-shape0 libxcb-shm0 \
  libxcb-sync1 libxcb-xfixes0 libxcb-xinerama0 libxcb-xkb1 libxcb-util1 \
  libxkbcommon0 libxkbcommon-x11-0 libgl1 libegl1
  2. Check that echo $DISPLAY $WAYLAND_DISPLAY prints something. Over SSH it usually prints nothing: start OCTAVE from the desktop session.
  3. Run with QT_DEBUG_PLUGINS=1 to see which library is still missing.
  4. On Wayland, try QT_QPA_PLATFORM=wayland; to force X11, QT_QPA_PLATFORM=xcb.

A black window, or icons and album art missing

The icons, the album art and the 3D vehicle are drawn by the graphics card, so a broken graphics driver shows as a black or half-empty window.

  1. Start with QT_QUICK_BACKEND=software. If the window appears, the graphics driver is the problem. This mode is slow and shows no shader effects and no 3D view, so use it only to find the cause.
  2. Look in the log for module "..." is not installed. It means the Qt you built against lacks a module; see Building.

Everything is too big or too small

OCTAVE sizes itself from the screen's shorter side, and you can scale it on top of that.

  1. Settings > Display > UI Scaling, from 0.5 to 2.0.
  2. If the screen is too small to reach the setting, close OCTAVE and set "uiScale": 1.0 in settingsConfigure.json in the config folder.

Windows Subsystem for Linux: no window

OCTAVE needs a display, and WSL only has one with WSLg (WSL 2 on Windows 10 build 19044 or later, or Windows 11).

  1. Set up WSLg with Microsoft's guide to Linux GUI apps.
  2. If the window is black, start with QT_QUICK_BACKEND=software LIBGL_ALWAYS_SOFTWARE=1.

Sound and Music

No sound

Most often OCTAVE is muted, or it is playing on another output than the one you are listening to.

  1. Check the volume on the bottom bar. Its icon shows when OCTAVE is muted; turning the volume up unmutes.
  2. Settings > Media > Library & Playback > Audio Output says where OCTAVE plays. If it reads "The picked output is not connected", OCTAVE is on the system default until that output is back: pick the right one.
  3. Check the system's own volume and output. On Linux, pactl list short sinks lists the outputs and pactl info shows the default one.

Very quiet at low volume

This is intended. The slider follows a curve that matches how hearing works: 50 % on the slider is a quarter of full power, 10 % is a hundredth. Turn it up.

The music gets quiet while a phone is mirrored

OCTAVE turns its own music down while the phone makes a sound, and back up a moment after it stops.

  1. To stop this: Settings > Phone > Phone Mirror > Duck Local Music.

"No Music Loaded", or songs are missing

The library folder is not set, or the files are of a type OCTAVE does not read.

  1. Settings > Media > Library & Playback: check Library Folder, tap Scan and read the Scan Log.
  2. OCTAVE reads .mp3, .m4a, .mp4 (sound only), .flac, .ogg, .opus and .wav.
  3. For which folders are read, see Media Manager.

A song is skipped, or playback stops by itself

The file is damaged or uses a codec the system cannot play. OCTAVE tries a file twice, then skips it. After 10 unplayable songs in a row it stops instead of running through the whole library.

  1. Find the file in the log: "Giving up on ..." names it.
  2. Play that file in another player. If it fails there too, replace it.
  3. If many files fail, the folder may be gone (an unplugged drive): check the Library Folder.

Spotify problems are shown in red on the Spotify card in Settings > Media; see Media Manager.

The Car (OBD)

Read the status in Settings > OBD > Connection first. OBD Manager has a table of what each status means; the entries here are the common cases.

The adapter is not found

The Connect Vehicle sheet lists nothing, or the status is Device Not Found. Usually the adapter has no power, or the system has not paired with it.

  1. Turn the ignition on. Most adapters only have power with the ignition on. Check that the adapter's light is on.
  2. Scan again, and tap Show All Devices: the sheet normally lists only devices whose name looks like an OBD adapter.
  3. On Windows and macOS, pair the adapter in the system's Bluetooth settings first. On Linux, Pick Bluetooth Adapter pairs it for you.
  4. A USB adapter on Linux: your user must be allowed to open serial ports. sudo usermod -aG dialout $USER (the group is uucp on Arch), then log out and in.
  5. If you know the address, type it: Settings > OBD > Connection > Enter Address Manually.

The status is "No Vehicle"

The adapter answers but the car does not. This is nearly always the ignition.

  1. Turn the ignition on. OCTAVE tries again every 10 seconds; you do not need to tap anything.
  2. Push the adapter firmly into the port.
  3. Look at the "Vehicle check" line in the Connection Log.

The status is "Connection Failed", or the connection keeps dropping

The adapter was found but stopped answering. Cheap adapters lock up, and another app may be holding the adapter.

  1. Unplug the adapter, wait a few seconds and plug it back in.
  2. Close any other OBD app, on this device and on your phone: an adapter talks to one program at a time.
  3. If readings drop out while connected, turn Fast Polling off in Settings > OBD: not every adapter and car keep up.
  4. Stale Connection needs nothing: after 30 seconds without a reading OCTAVE connects again by itself.

The status is "Error" (Linux)

OCTAVE could not set up the Bluetooth link. The Connection Log says why.

  1. Use Pick Bluetooth Adapter in the Connect Vehicle sheet. It connects directly and needs no system tool.
  2. "rfcomm bind failed: rfcomm binary not found" appears when a Bluetooth address was typed by hand and the rfcomm tool is not installed. Install it (bluez-utils on Arch), or bind the adapter once yourself and enter the port: 
    sudo rfcomm bind 0 AA:BB:CC:DD:EE:FF    # your adapter's address
# then enter /dev/rfcomm0 under Enter Address Manually

A reading is missing or shows "--"

The car does not report it. After connecting, OCTAVE asks the car which readings it supports and shows only those.

  1. Start the engine: many readings exist only while it runs.
  2. If the car has the sensor but reports it in its own way, see Custom PIDs in OBD Manager.

Trip History is empty, or says "Black box unavailable"

Either recording is off, no drive has been made yet, or OCTAVE could not open its database.

  1. Settings > OBD > Black Box: Record every drive must be on. A drive starts at the first reading with the engine running, so a connection with the engine off records nothing.
  2. "Black box unavailable" means the database could not be opened, and nothing is recorded until it can. The Status line on the Black Box card gives the reason, and octave-cpp.log has it too.
  3. The usual reasons are a full disk or a config folder that cannot be written. Free some space or fix the folder's permissions, then restart OCTAVE.

See OBD Manager: Black Box.

The Car, on Android

Android

"Requesting Bluetooth permission — tap Allow, then tap Connect again"

Android has to ask you once before OCTAVE may use Bluetooth.

  1. Tap Allow on Android's question.
  2. Tap Connect again.
  3. If Android no longer asks, give the permission by hand in Android's settings, under the OCTAVE app's permissions.

The adapter is not in the list

On Android OCTAVE does not scan. It lists the devices the phone is already paired with.

  1. Turn Bluetooth on and pair the adapter in Android's Bluetooth settings.
  2. Tap Connect once so that the permission is asked for (above); the list fills after that.
  3. The adapter must be a Bluetooth LE one. An older "Bluetooth classic" ELM327 does not work on Android.

The adapter's Bluetooth events are written to the Connection Log and to octave-cpp.log as lines starting with [BLE]. Trouble codes, custom PIDs and the bus monitor are not on Android yet.

Phone Mirror

The first line of Settings > Phone > Phone Mirror says what is missing. The Phone Mirror page has a table of every message; these are the ones met most often.

The phone does not appear

OCTAVE reaches an Android phone through adb, Android's debugging tool, and the phone must allow it.

  1. On the phone, turn on USB debugging (Settings > Developer options) and plug it in with a cable that carries data.
  2. "USB debugging is not authorized": unlock the phone and tap Allow on its prompt. If no prompt comes, unplug and plug in again.
  3. "adb not found": on Linux install it (sudo apt install adb, or sudo pacman -S android-tools on Arch) and restart OCTAVE. On Windows and macOS the release includes it: reinstall OCTAVE.
  4. An iPhone is not shown here: use AirPlay.

"adb is too old for wireless pairing"

Pairing over Wi-Fi needs adb from platform-tools 30 or newer, and some systems ship an older one (Ubuntu 22.04 does).

  1. Install Google's current Android platform-tools, with adb at ~/Android/Sdk/platform-tools/adb, and restart OCTAVE. It uses the first adb it finds that is new enough.
  2. Or use the cable: mirroring over USB works with the old adb.

Wi-Fi: the phone scans the QR code and nothing happens

The phone and OCTAVE cannot see each other on the network. After 120 seconds OCTAVE says "The phone did not scan the code".

  1. Put both on the same Wi-Fi network. A guest network usually keeps devices apart and will not work.
  2. The phone's own hotspot does not work for pairing. See Without a Cable: Wi-Fi for what does.
  3. Tap Show QR code for a new code and scan again.

Wi-Fi: the phone does not come back after a drive or a restart

Android switches Wireless debugging off when the phone leaves the network or restarts.

  1. Switch Wireless debugging on again on the phone. OCTAVE finds it by itself.
  2. Or plug the phone in once.

Android Auto

These are for OCTAVE's built-in head unit (Settings > Phone > Android Auto > Head Unit: Built-in). Setting it up is described under The Built-in Head Unit. While the Android Auto page is open OCTAVE keeps trying by itself, every few seconds, so after you fix the cause there is nothing to restart. The line under the page title gives the exact reason.

There is no Head Unit choice in the settings

This build has no built-in head unit: it was built without OpenSSL or FFmpeg, or it is not a desktop build.

  1. Rebuild with both present: see Building.

"Connect your phone with USB debugging on"

OCTAVE does not see a phone. Android Auto reaches the phone the same way Phone Mirror does.

  1. Follow The phone does not appear above.
  2. "adb was not found" has the same fix as "adb not found" there.

"Waiting for the phone's head unit server"

The phone is connected, but Android Auto on it is not listening. The server has to be started on the phone by hand.

  1. On the phone: Android Auto settings > ⋮ > Start head unit server.
  2. No ⋮ menu? Developer mode is off. Tap Version in Android Auto's settings 10 times, then look again.

"the phone's head unit server did not answer"

The server on the phone accepted the connection and then said nothing for 10 seconds. It gets stuck like this after a session was cut off.

  1. On the phone: ⋮ > Stop head unit server, then Start head unit server.
  2. Wait a few seconds; OCTAVE connects again by itself.

"Android Auto needs a certificate"

Android Auto only talks to a head unit that shows a certificate, and OCTAVE does not come with one.

  1. Put headunit.crt and headunit.key in the folder the message names. See The Head-Unit Certificate.
  2. "No private key next to the head-unit certificate": the .key file is missing. It must have the same name as the certificate.
  3. "The head-unit certificate can't be used", followed by the reason: the certificate is not in PEM format, the key belongs to another certificate, or the key is protected by a passphrase (not supported). Convert a DER certificate with openssl x509 -inform der -in headunit.der -out headunit.crt.

"TLS handshake failed", or "the phone closed the connection"

The phone refused the certificate. Android Auto accepts only a certificate issued under Google's head-unit authority; one you signed yourself is refused.

  1. Use a certificate the phone accepts: see The Head-Unit Certificate.
  2. To see the phone's side: adb logcat | grep -i CAR.GAL

"the phone stopped answering", or "Android Auto ended"

The link dropped, the phone went to sleep, or the phone ended the session.

  1. Nothing: OCTAVE reconnects while the page is open.
  2. If it keeps happening on Wi-Fi, use the cable.

There is a picture but no sound, or the Assistant does not hear you

Android Auto plays through OCTAVE's output and listens through the system's default microphone. The phone's own volume is not used.

  1. Check OCTAVE's volume and mute, and Settings > Media > Audio Output.
  2. For the Assistant, the device needs a microphone set as the system's default input. The log says "the phone asked for the microphone, but there is no audio input" when there is none.

"the phone refused protocol version 1.6"

The phone's Android Auto is a version OCTAVE's head unit does not work with. Report it with the Android Auto version from the phone's app information.

Sensors and the Volume Knob

Wiring and first set-up are on the Hardware Setup page.

The IMU or the gesture sensor is not found

Linux only

Both sensors must be on I2C bus 2, and your user must be allowed to use it. The bus number cannot be changed in the settings.

  1. Check that the bus exists: ls /dev/i2c-2. If not, enable it on your board (on a Raspberry Pi, sudo raspi-config > Interface Options > I2C turns I2C on; the board decides which bus number the pins get).
  2. Check that the sensors answer: i2cdetect -y 2 should show 1c, 6a and 77 for the BerryIMU and 73 for the gesture sensor. A missing address is a wiring or power problem.
  3. The log says "permission denied on /dev/i2c-2": sudo usermod -aG i2c $USER, then log out and in.
  4. OCTAVE tries five times, waiting longer each time (5 to 25 seconds), then gives up; after a permission error it does not retry at all. Once the cause is fixed, restart OCTAVE.

The volume knob does nothing

OCTAVE has not found the knob's USB dongle, or is listening on the wrong port.

  1. Plug the dongle in and open Settings > Accessories > Volume Knob > Connection.
  2. An ESP32-S3 dongle is picked by itself. Any other has to be picked from the list there.
  3. "Port ... open: turn the knob to confirm": turn or press the knob once. OCTAVE waits for that before it trusts the port.
  4. "Max retries reached. Check connection.": the dongle disappeared and five attempts to get it back failed. Unplug it and plug it back in; OCTAVE looks for it every 10 seconds and connects when it appears.
  5. On Linux your user must be allowed to open serial ports: sudo usermod -aG dialout $USER (uucp on Arch), then log out and in.

Slow or Frozen

The screen froze

OCTAVE watches its own screen thread. When it has not answered for 5 seconds, the log gets "UI thread blocked for N s and counting", and "UI thread responsive again" when it recovers. On Linux, after 15 seconds it writes a hang-*.txt file, and after 30 seconds it closes itself so that a launcher script can start it again (the one for the reference install does).

  1. Find the "UI thread blocked" line in octave-cpp-error.log and read the lines just before it in octave-cpp.log: they show what OCTAVE was doing.
  2. Report it with the exported logs, including the hang-*.txt file.

The app freezes for a while when it reads a big music library

The library scan is done in one go and the screen waits for it. With a very large library the first one can take a while. Let it finish.

The screen stutters

The device is short of graphics or processor power for what is on screen.

  1. Check that OCTAVE is not running in software mode: unset QT_QUICK_BACKEND if you set it.
  2. Look at what else is using the processor: top.
  3. If one core is busy while the OBD adapter is unplugged or out of range, report it with the logs.
  4. To measure it, a development build has a profiler: see Performance Profiling.

Developer Tools

For people working on OCTAVE itself. The tools are described on the Development page.

"--dev / --profile need a build with -DOCTAVE_DEV_TOOLS=ON"

The developer tools are only compiled into Debug builds.

  1. Build a Debug tree: cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug && cmake --build build -j8
  2. For only the simulated car, --sim works in every build.

"command server could not listen on 127.0.0.1:9876"

Another OCTAVE is already running with --profile or --service and holds the port.

  1. Close the other one. A test that was interrupted often leaves one behind: pgrep -a octave.
  2. Or use another port: ./build/octave --dev --profile --service=9933, and give the tool the same port.

The MCP servers or the screenshot tools cannot reach the app

They are Python programs in the dev/ folder that drive a running OCTAVE through the command server.

  1. The app must be a Debug build. The tools start it through dev/app_launch.py; set OCTAVE_BIN if you have more than one build.
  2. Check the Python path in .mcp.json: it is different on every machine. Install what the tools need with venv/bin/pip install -r requirements.txt.
  3. A screenshot tool that asks for an unknown page gets "Unknown page: ..." with the list of valid names.

A test hangs or will not start

The tests that draw a screen need a display.

  1. Run them without one, as CI does: QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure
  2. Run one test with its full output: ctest --test-dir build --output-on-failure -V -R <name>

See Tests and Linting.
