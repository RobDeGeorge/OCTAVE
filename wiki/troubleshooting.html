Display & Rendering Issues

XCB Plugin Errors (Linux)

Error: qt.qpa.plugin: Could not load the Qt platform plugin "xcb"

Install required X11 libraries:

sudo apt install libxcb-xinerama0 libxcb-cursor0 libxkbcommon-x11-0 \
  libxcb-icccm4 libxcb-image0 libxcb-keysyms1 libxcb-randr0 \
  libxcb-render-util0 libxcb-shape0

Wayland vs X11

OCTAVE uses Qt Quick which works on both Wayland and X11. If you experience issues on Wayland:

# Force X11 backend
export QT_QPA_PLATFORM=xcb
python main.py

# Or force Wayland
export QT_QPA_PLATFORM=wayland
python main.py

OpenGL / Software Rendering

If the UI is black or has rendering artifacts:

# Force software rendering (slow but reliable)
export QT_QUICK_BACKEND=software
python main.py

# Or specify OpenGL ES (for Raspberry Pi)
export QT_OPENGL=es2
python main.py

Black Screen on Startup

  • Check QML import path: OCTAVE adds frontend/ to the QML import path. If running from a different directory, QML files won't be found.
  • Check Qt Quick Controls style: OCTAVE forces QT_QUICK_CONTROLS_STYLE=Basic. If this env var is overridden, slider customization breaks.
  • Run with --debug and check logs for QML errors.

UI Scaling Issues

If the UI is too small or too large, adjust the uiScale setting (0.5 - 2.0) in Settings > Display, or set it in settingsConfigure.json.

Audio Issues

No Audio Output

  • Check volume: OCTAVE uses a logarithmic curve (volume/100)^2.0. Low slider values produce very quiet output.
  • Check mute state: mediaManager.is_muted() in QML or check the mute toggle guard (_mute_toggle_locked).
  • Verify audio output device in system settings.

PulseAudio Issues (Linux)

# Check PulseAudio is running
pulseaudio --check

# Restart PulseAudio
pulseaudio --kill && pulseaudio --start

# List audio sinks
pactl list short sinks

ALSA Errors (Linux)

# Install ALSA plugins
sudo apt install libasound2-plugins

# If "ALSA lib pcm_dmix.c" errors appear, set:
export QT_MULTIMEDIA_PREFERRED_PLUGINS=gstreamer

Audio Playback Stalls

The media manager has automatic recovery for stalled/invalid media. If a file consistently fails, check the file format. Supported: MP3, M4A, FLAC, OGG, OPUS, WAV.

OBD Connection Issues

Serial Port Permissions (Linux)

# Add user to dialout group for serial port access
sudo usermod -aG dialout $USER

# Log out and back in, then verify
groups | grep dialout

Bluetooth OBD Pairing (Linux)

# Pair the OBD adapter
bluetoothctl
  scan on
  pair XX:XX:XX:XX:XX:XX
  trust XX:XX:XX:XX:XX:XX
  quit

# Bind to rfcomm
sudo rfcomm bind 0 XX:XX:XX:XX:XX:XX

# Verify
ls -la /dev/rfcomm0

Connection Timeouts

  • Default timeout is 5 seconds. The OBD manager uses a dedicated QThread worker to avoid blocking the UI.
  • If connection is slow, check if obdFastMode is enabled (it should be by default).
  • The manager caches the last successful protocol to skip auto-detection on reconnect (saves 1-3 seconds).
  • Set obdAutoReconnectAttempts to 1-10 for automatic reconnection after drops.

"No Data" from Vehicle

  • Run a vehicle scan (OBD Settings > Scan Vehicle) to discover which PIDs your vehicle supports.
  • Not all vehicles support all 87+ parameters. Enable only supported ones to avoid polling errors.
  • Some parameters only report data when the engine is running.

Data Watchdog

The OBD manager includes a data watchdog that detects stale connections (no data for 30 seconds while parameters are watched). If triggered, it automatically reconnects.

Spotify Authentication Issues

OAuth Flow

  1. Enter Client ID and Client Secret in Spotify Settings
  2. Click "Connect" - OCTAVE starts a local HTTP server on port 8888
  3. Browser opens to Spotify's auth page
  4. After authorizing, Spotify redirects to http://127.0.0.1:8888/callback
  5. OCTAVE captures the auth code and exchanges it for tokens

Common Issues

ProblemSolution
Redirect URI mismatchAdd http://127.0.0.1:8888/callback to your Spotify Developer Dashboard redirect URIs
Token expiredOCTAVE auto-refreshes tokens via spotipy. If it fails, disconnect and re-authenticate.
Keyring errorsInstall keyring and the appropriate backend. Falls back to file cache at backend/.spotify_token_cache
No devices foundEnsure Spotify is running on at least one device (phone, desktop). OCTAVE controls playback remotely.
Rate limitingOCTAVE polls every 3 seconds and uses max 2 concurrent API threads. If rate-limited, reduce polling interval.

Token Storage

Tokens are stored securely in the OS keychain via the keyring library (service: "OCTAVE_Spotify", username: "spotify_token"). Fallback: backend/.spotify_token_cache file.

Hardware Sensor Issues

I2C Permissions

# Add user to i2c group
sudo usermod -aG i2c $USER

# Enable I2C on Raspberry Pi
sudo raspi-config  # Interface Options > I2C > Enable

# Verify I2C devices are detected
i2cdetect -y 2
# Should show: 0x6A (LSM6DSL), 0x1C (LIS3MDL), 0x77 (BMP388), 0x73 (PAJ7620)

Reconnection Behavior

Both BerryIMU and gesture sensor managers retry up to 5 times with linear backoff (5s, 10s, 15s, 20s, 25s). Permission errors do not trigger retries (permanent failure). After max retries, the sensor is marked as unavailable.

ESP32 Volume Knob Not Connecting

  • Check that the ESP32-S3 dongle appears in dmesg output after plugging in
  • Verify serial port permissions: sudo usermod -aG dialout $USER
  • Check that the OBD port and ESP32 port are different (OCTAVE filters out the OBD port)
  • Try manual port selection in Volume Knob settings if auto-detection fails
  • Check baud rate: must be 115200

Enabling Debug Mode

python main.py --debug

Creates the octave-debug.log file with verbose output from all modules. Useful for diagnosing:

  • I2C communication issues (every register read/write logged)
  • Serial port data (ESP32 commands logged)
  • Settings load/save operations
  • Media file scanning and metadata extraction
  • Spotify API calls and token refresh

Reading Logs

Module names are mapped to clean hierarchical names:

octave.obd        - OBD manager
octave.media      - Media manager
octave.spotify    - Spotify manager
octave.settings   - Settings manager
octave.clock      - Clock
octave.app        - Main application

Performance Issues

UI Stuttering

  1. Run with --profile to see event-loop latency. Healthy is <5ms avg.
  2. Check GIL jitter. High values indicate a Python thread is holding the GIL too long.
  3. Look for slow slots in the perf output (>2ms p95).
  4. Check CPU usage. If near 100%, identify which thread is busy.

High Memory Usage

  • Album art cache: Limited to 500 files. LRU eviction when full.
  • Metadata cache: Limited to 1000 entries.
  • FFT data: Pre-computed for entire track. Large FLAC files may use significant memory.
  • Spotify queue cache: Stores track metadata for side-card art.

Slow Media Library Scan

Large libraries (>10,000 files) may take time on first scan. The scan runs on the main thread but uses lazy metadata loading. Pre-caching of neighboring tracks runs on a background thread after each track change.

WSL Display Issues

WSL2 with GUI

WSL2 supports GUI apps natively on Windows 11. If the display doesn't work:

# Check WSLg is working
echo $DISPLAY  # Should show :0 or similar

# If blank, try setting it
export DISPLAY=:0

# For WSL2 with X server (VcXsrv, etc.)
export DISPLAY=$(cat /etc/resolv.conf | grep nameserver | awk '{print $2}'):0
export LIBGL_ALWAYS_INDIRECT=1

WSL1 (No Native GUI)

WSL1 requires an external X server (VcXsrv, Xming). Install and run the X server first, then set DISPLAY.

OpenGL in WSL

# If OpenGL errors, force software rendering
export QT_QUICK_BACKEND=software
export LIBGL_ALWAYS_SOFTWARE=1
python main.py
