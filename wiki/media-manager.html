Overview

The MediaManager class in backend/media_manager.py handles all local audio playback. It wraps Qt's QMediaPlayer and QAudioOutput, turns the sub-folders of the music folder into playlists, keeps a metadata and album-art cache backed by a persistent tag store on disk, extracts dominant colors from album art for the "Album Art Capture" theme, and provides shuffle, skip, playback resume and automatic recovery from unplayable files.

main.py creates one instance, calls media_manager.connect_settings_manager(settings_manager) and registers it as the QML context property mediaManager. Playback controls are Slots and state changes are Signals; the QML that uses them is frontend/MediaRoom.qml, MediaPlayer.qml, BottomBar.qml, MainMenu.qml, DownloadPage.qml, settings/MediaSettingsPage.qml and Main.qml.

Supported Audio Formats

The library scanner only picks up files whose extension is in AUDIO_EXTENSIONS:

# backend/media_manager.py
AUDIO_EXTENSIONS = ('.mp3', '.m4a', '.mp4', '.flac', '.ogg', '.opus', '.wav')

.mp4 is listed because YouTube serves audio-only streams in an MP4 container that yt-dlp names with a literal .mp4 extension. strip_audio_extension(filename) removes any of these extensions (and only these) and is what the display-name and metadata fallbacks use.

Tags are read by _read_tags(file_path, base_name), which never raises, and covers by _extract_art_for(file_path, album_id). Both dispatch on the lower-cased extension. Both also accept .aac in the MP4 branch, but .aac is not in AUDIO_EXTENSIONS, so the scanner never lists such a file. A file that fails to open yields the file-name title with "Unknown Artist" / "Unknown Album" and duration 0. Whether a file actually plays depends on the codecs available to Qt Multimedia in the installed PySide6.

QMediaPlayer Integration

The constructor creates one QMediaPlayer and one QAudioOutput and sets the output to volume 0.5 (the saved volume is applied moments later by VolumeController in main.py, see Volume). It also sets the dynamic properties probe-size (10 MB) and analyzeduration (5 s) on the player; the code does not check whether the active Qt multimedia backend reads them.

Output device. A QAudioOutput stays bound to the device that was the system default when it was created. The constructor therefore creates a QMediaDevices and connects audioOutputsChanged to _follow_default_output(), which switches the output to QMediaDevices.defaultAudioOutput() whenever that differs from the current device (a null device is ignored) and logs "Audio output changed, now using: ...". The comment names the cases: HDMI audio across a display sleep, a USB DAC. 

# backend/media_manager.py — __init__ (abridged)
self._player = QMediaPlayer()
self._audio_output = QAudioOutput()
self._player.setAudioOutput(self._audio_output)
self._media_devices = QMediaDevices(self)
self._media_devices.audioOutputsChanged.connect(self._follow_default_output)
self._audio_output.setVolume(0.5)

self._player.durationChanged.connect(self.durationChanged.emit)
self._player.positionChanged.connect(self.positionChanged.emit)
self._player.mediaStatusChanged.connect(self._handle_media_status)
self._player.errorOccurred.connect(self._handle_player_error)
self._player.playbackStateChanged.connect(
    lambda state: self.playbackStateChanged.emit(int(state.value)))

# 100 ms safety-net position timer, only while playing
self._position_timer = QTimer()
self._position_timer.setInterval(100)
self._position_timer.timeout.connect(self._update_position)
self.playStateChanged.connect(
    lambda playing: self._position_timer.start() if playing else self._position_timer.stop())

Connected signals from QMediaPlayer:

  • durationChanged / positionChanged - forwarded to QML as the manager's own signals of the same name
  • mediaStatusChanged - _handle_media_status(): EndOfMedia calls next_track(); LoadedMedia / BufferedMedia apply a pending seek left by _reseat_source() (only if the player's source is still that file) and reset the recovery counters; StalledMedia / InvalidMedia trigger recovery while playing
  • errorOccurred - _handle_player_error(): logs the error and triggers recovery, or only logs at debug level while nothing is playing
  • playbackStateChanged - forwarded as playbackStateChanged(int) with the raw QMediaPlayer.PlaybackState value (0 stopped, 1 playing, 2 paused); the manager's own playStateChanged(bool) is what the QML binds

_update_position() re-emits positionChanged(position) when the player's playbackState() is PlayingState, as a safety net for backends whose native positionChanged is coarse. The timer is started and stopped from playStateChanged so an idle app does not wake ten times a second.

Library Scanning

The library root is SettingsManager's mediaFolder. Its stored default is the empty string, which SettingsManager resolves to ~/Music when it loads. The manager's own backend/media/ directory (created by _ensure_directories()) is only the initial value of media_dir before settings are wired, and is what get_default_media_dir() reports.

Wiring happens in connect_settings_manager(settings_manager). main.py calls it at start-up and Main.qml calls it again from Component.onCompleted; the second call returns immediately because the manager is already set. It calls set_library_root(mediaFolder), connects mediaFolderChanged to set_library_root, schedules _restore_playback_state() 500 ms later, connects themeSettingChanged, and if the theme is already "Album Art Capture" schedules a colour extraction 1 s later. set_library_root(path) resolves the path with os.path.realpath, ignores it if it is not an existing directory, scans, and selects the first playlist.

scan_library(reset_display_names=True) runs synchronously on the GUI thread, is guarded by a _scan_in_progress flag (a re-entrant call logs and returns), and emits scanProgress lines ([SCAN], [PATH], [CLEAR], [INFO], [FOUND], [ERROR], [DONE]) that the Media settings page shows terminal-style. If the root is unset or missing it emits [ERROR] Library path not set or doesn't exist and returns. Otherwise:

  1. Clear the playlists, the in-memory metadata and album-art maps, the access counts, the All Music path map and the stats cache. With reset_display_names true the display names are also cleared and saved; every internal caller passes False, while the settings page's "Rescan" button calls scan_library() with the default
  2. Audio files directly in the root become the "Unsorted" playlist (only if there are any)
  3. Every immediate sub-folder whose name does not start with . becomes a playlist named after the folder, including empty folders, so a user-created playlist survives a rescan after its last song was moved out
  4. Every file is also appended to the combined "All Music" playlist (is_combined: True), created only if at least one file was found. A file name already seen is renamed "<folder> - <file>" for that playlist, and _all_music_file_paths maps each name to its directory
  5. Playlist names are ordered "All Music", "Unsorted", then the rest case-insensitively
  6. _auto_strip_display_names() cleans the file names that do not yet have a display name
  7. If a playlist was active before the rescan it is re-selected and the index of the previously current song restored; then playlistsChanged is emitted once, after all state is settled

main.py also rescans with reset_display_names=False on every downloadManager.downloadComplete.

get_media_files(emit_signal=True) is the older flat listing of the current media_dir; MediaPlayer.qml still calls it on load, and shuffle and sorting fall back to it when no playlist is selected. Both it and scan_library carry two @Slot decorators (@Slot(result=list) + @Slot(bool, result=list); @Slot() + @Slot(bool)) so QML can call them with or without the boolean.

Path Safety
_get_file_path() rejects names that contain os.sep + '..', start with '..' + os.sep, equal .., or start with / or \ (a name such as still feel..mp3 is allowed), resolves All Music names through _all_music_file_paths, and then requires the result to be inside the library root via is_safe_path(), which compares realpath-normalised paths. It returns None for a rejected name. create_playlist() additionally rejects names containing a separator or .. or starting with .; move_song_to_playlist() and delete_playlist() check every path they touch with is_safe_path(). "All Music" and "Unsorted" cannot be deleted.

Metadata Caching and the Tag Store

Every lookup (get_band, get_album, get_formatted_duration, the now-playing metadata, library statistics, display-name stripping) goes through _cache_metadata(filename), which fills the in-memory dict _metadata_cache (filename → title, artist, album, duration in seconds), capped at 1000 entries; at the cap the oldest insertion is dropped. The dict is cleared by every select_playlist() and scan_library().

Behind it sits the persistent tag store <app data>/metadata_cache.json (e.g. ~/.config/OCTAVE/metadata_cache.json on Linux): 

{
  "version": 1,
  "files": {
    "Artist - Song.mp3": {
      "title": "Song", "artist": "Artist", "album": "Album",
      "duration": 245,             // seconds
      "size": 6021384, "mtime": 1757000000   // validation: bytes, integer seconds since epoch
    }
  }
}

How the store is used:

  • _load_meta_store() reads it in the constructor; a file without "version": 1 and a files object is ignored, and an unreadable one logs a warning and starts empty.
  • _cache_metadata() first asks _meta_from_store(). An entry is served without opening the audio file if os.stat succeeds and both the size and int(st_mtime) match.
  • An entry that fails that check (deleted, renamed or rewritten file) is removed from the store when that filename is looked up. There is no separate pruning pass, so entries for files that are never looked up again stay on disk.
  • Only on a miss does _cache_metadata_from_file() read the tags; _meta_to_store() writes the result back with the current size and mtime.
  • Writes are coalesced: every change emits the internal _metaStoreChanged signal, connected with Qt.QueuedConnection to a 2 s single-shot timer, and _save_meta_store() writes compact JSON once with atomic_write_text(). Because the timer is started through a queued signal, _meta_to_store() is safe to call from any thread. The dirty flag is cleared only after a successful write, so a failed write is retried on the next change or at shutdown.
  • Shutdown flushes it: cleanup_on_quit() in main.py calls flush_metadata_store(), and __del__ also calls _save_meta_store().

Tag strings pass through sanitize_metadata(): non-printable characters become spaces, whitespace runs collapse to one space, and text longer than 200 characters is cut to 197 plus .... ID3 frames go through _extract_id3_text(), MP4 atoms and Vorbis comments through _extract_list_text(). Missing tags fall back to the file's base name for the title and to "Unknown Artist" / "Unknown Album".

Album Art Extraction

get_album_art(filename) returns a file:// URL to a cover image in backend/temp/ (next to the module; the directory is gitignored), or an empty string. Cover files are named from the album identifier, cover_<sha256(album_id + "_0")[:16]>.<ext>, where _write_cover() picks the extension from the MIME type: jpg for image/jpeg / image/jpg, png, gif, otherwise img. Only the first embedded picture is used.

Album ID

_get_album_id() keys covers by "{album}_{artist}" so every track of an album shares one file. When the album tag is "Unknown Album" the key becomes "Unknown Album_{artist}_{filename}": the code comment notes that YouTube downloads usually carry a different cover per track and must not all share the first one. If the metadata lookup raises, a 16-hex-digit SHA-256 of the file name is used.

Lookup Order

  1. Increment the album's access count (_access_count)
  2. Return the URL from _album_art_cache (album id → URL) if present
  3. _manage_cache(): when the map already holds 500 entries (_max_cache_files), the album with the lowest access count (other than the one being added) is removed from the map and its file deleted
  4. _cached_art_url_for(album_id): if a non-empty cover_<hash>.{jpg,png,gif,img} already exists from any earlier run, use it without opening the audio file
  5. Otherwise _extract_art_for() opens the audio file, extracts the first picture and writes it with atomic_write_bytes() unless a non-empty file of that name already exists. A zero-byte cover (which a power cut during an older, non-atomic write could leave) counts as missing and is rewritten
  6. Store the URL in the map and return it (empty string if the file has no picture)

Covers Survive Restarts

The temp directory is not wiped at start-up or quit, so step 4 finds a previous run's cover by hash. Because the in-memory map starts empty on every launch, _manage_cache() only bounds the covers the current run has seen; _prune_cover_dir() runs once in the constructor, deletes leftover .tmp-* files (interrupted atomic writes), and deletes the cover_* files with the oldest st_atime beyond 500. _clear_temp_files() still exists as a slot (it deletes every file in the temp dir) but nothing calls it.

Populate Tags and Covers Together

When _cache_metadata_from_file() has to read a file's tags it also fills the cover cache for that album in the same call (_cached_art_url_for(), else _extract_art_for(); the two may open the file separately), skipping it when the album's URL is already in the map. The get_album_art() call that a QML binding makes next is then a map hit. Entries served from the tag store skip this step; their cover is found by the hash fast path.

Color Extraction and Theming

When the "Album Art Capture" theme is active, MediaManager extracts dominant colors from the current cover and generates a complete theme palette using QImage and colorsys. The triggers are the manager's own currentMediaChanged (handled by _on_media_changed_for_theme), SettingsManager's themeSettingChanged switching to "Album Art Capture", the 1 s start-up timer when the theme is already active, and explicit calls to extract_colors_from_album_art(filename) from Main.qml, MediaRoom.qml and settings/DisplaySettingsPage.qml. extract_colors_from_image(path_or_url) runs the same pipeline on an image file or file: URL; the QML uses it for the mirrored phone's album art (phoneMirrorManager.mediaArtUrl).

Extraction Pipeline

  1. extract_colors_from_album_art() resolves the cover through get_album_art() and returns if there is none or the file is missing. A repeat request for the same file within 2 s is dropped (restoring playback and the 1 s start-up timer both ask for the same file). extract_colors_from_image() has no such dedupe and clears the remembered file, so the next local-track request is extracted again
  2. The image work runs on a daemon threading.Thread named album-colors. Each request increments _color_job; the worker posts its result through the internal signal _colorsReady(theme_json, filename, job), connected with Qt.QueuedConnection to _apply_album_colors() on the GUI thread, which ignores any job that is not the newest, so a fast skip through tracks applies only the last theme
  3. _extract_album_colors() converts the cover to Format_RGBA8888 and scales it to 50×50 with Qt.SmoothTransformation (2500 pixels)
  4. _kmeans_colors() finds k=5 centroids in pure Python with at most 10 iterations, stopping early when no centroid channel moves by more than 1. Initial centroids are drawn with a local random.Random(42), so the same cover always yields the same palette; the comment explains that seeding the global random module made every later random.shuffle() in the process deterministic
  5. Centroids are sorted by vibrancy (HSV saturation × value, most vibrant first)
  6. The image is classed dark when the average luminance (0.299R + 0.587G + 0.114B) of the first 1000 pixels is below 0.5
  7. _generate_theme_from_colors() returns the theme as a JSON string. _apply_album_colors() passes it to settings_manager.set_album_art_colors(json), which updates the albumArtColors property; Main.qml feeds that to Style.updateAlbumArtTheme(), and main.py forwards its accent to the ESP32 LEDs when their colour mode is "theme". The albumColorsExtracted signal is only emitted when no SettingsManager is wired

Theme Generation

_generate_theme_from_colors() takes the sorted palette (primary, secondary, tertiary, quaternary; missing entries repeat the previous one) and derives:

  • base, baseAlt - dark images: primary at 15% / 22% brightness; light images: primary at 250% brightness desaturated to 30%, then 92% of that
  • accent - primary with saturation ×1.4 and brightness ×1.2; three further accents from the other centroids with smaller boosts (×1.3 / 1.15, ×1.25 / 1.1, ×1.2 / 1.05), and two dimmer "nav" variants (70% / 75% brightness of the first two accents)
  • text.primary, text.secondary - (245,245,245) / (210,210,210) on a base whose WCAG relative luminance is below 0.3, otherwise (25,25,25) / (60,60,60)
  • states.hover, states.paused, states.playing - brightness steps of the primary (dark) or the base (light)
  • sliders.volume, sliders.media, sliders.settings - accents 1-3
  • bottombar.* - 14 keys (previous, play, pause, next, volume, shuffle, toggleShade, homeButton, obdButton, mediaButton, settingsButton, sensorButton, androidAutoButton, phoneMirrorButton)
  • mediaroom.* - previous, play, pause, next, left, right, shuffle, toggleShade (play/pause use the accent at 110% brightness)
  • mainmenu.mediaContainer - second accent at 60% brightness
  • obd.boxBackground, obd.barColor, obd.labelColor, obd.valueColor - gauge colors against baseAlt

Every icon/accent color is passed through ensure_icon_contrast(), which targets a contrast ratio of 3.0 against the background. Against a background with luminance below 0.5 it tries brightness factors 1.3 to 3.0 and falls back to a muted gold (200, 180, 130); against a light one it tries 0.7 down to 0.2 and falls back to (50, 40, 30). Colors that already pass, and brightened ones that reach the target, go through cap_brightness() (value capped at 0.85, saturation ×1.1 when capped). The capped or fallback colour is not rechecked, so this is a heuristic rather than a guaranteed minimum contrast.

Playback Control

Playing a File

play_file(filename):

  1. If no playlist order exists yet, build one: shuffled when shuffle is on, otherwise alphabetical by the sort key (lower-cased, then [^\w\s]|_ removed)
  2. Locate the file in the order and set _current_index; if it is not there and shuffle is off, rebuild the alphabetical list, and if it is still missing play the first entry instead
  3. Resolve the path with _get_file_path(); a missing file (deleted, moved, unmounted USB stick) is logged and handled by _skip_bad_track(advance=True), the same path as an unplayable track
  4. setSource() + play(), set the playing flags, set the output to 0 again if muted (setting a source can reset the output volume), emit playStateChanged(True)
  5. Fill the metadata and cover caches and emit metadataChanged (_emit_metadata) before currentMediaChanged, so the QML bindings that run on the latter are cache hits instead of tag I/O during the render phase
  6. Emit durationFormatChanged via get_formatted_duration(), then start the 80 ms pre-cache timer

Shuffle Logic

Shuffle is a toggle (_shuffle); there is no repeat mode, playback wraps around the playlist. toggle_shuffle() works on the selected playlist's file list (_get_current_playlist_files()), not on a directory scan, so shuffling "All Music" shuffles every folder:

  • On: the files are shuffled with random.shuffle, the current song is swapped to position 0 and the index set to 0, so playback continues from the current song into a random order
  • Off: the alphabetical order is rebuilt and the index set to the current song's position in it (0 if it is not there)
  • Then shuffleStateChanged, the save through settings_manager.save_last_shuffle_state(), and mediaListChanged(new_order), in that order

select_playlist() keeps shuffle on: it builds a fresh shuffled order with the loaded song first if that song is in the new list. On start-up _restore_playback_state() re-enables shuffle only when the persistShuffleState setting is on (default off) and lastShuffleState was true, then shuffles the restored playlist with the last played song at the front (see Settings Reference).

Playlist Management

Playlists are folders. The manager keeps:

  • _playlists - name → {name, path, files, song_count}, plus is_combined: True for "All Music"
  • _playlist_names - ordered names ("All Music", "Unsorted", then case-insensitive alphabetical)
  • _current_playlist_name, _current_playlist (the ordered or shuffled list actually played), _current_index
  • _library_root - the resolved mediaFolder; media_dir - the selected playlist's folder (the root for All Music)

select_playlist(name) sets media_dir, builds the order (alphabetical, or shuffled with the current song first when shuffle is on), resets the index to 0, clears the in-memory metadata map, recalculates the statistics with _calculate_all_stats() (total duration from cached durations, distinct non-"Unknown" albums and artists; emits totalDurationChanged, albumCountChanged, artistCountChanged), and emits currentPlaylistChanged and mediaListChanged. Computing the statistics reads the metadata of every file in the playlist, from the tag store where possible.

"All Music" Playlist

The combined playlist spans every folder, so _get_file_path() checks _all_music_file_paths first. A duplicate renamed "<folder> - <file>" during the scan is mapped back to the text after the first " - " when the prefixed name does not exist on disk; _get_original_filename() does the same for titles and moves when the unprefixed name is also in the map.

Display Names

get_display_name(filename) returns a cleaned title for lists and the now-playing views, or the file name without its audio extension when there is no entry. The map _display_names is persisted as <app data>/display_names.json (indented UTF-8 JSON, written with atomic_write_text()). _strip_single_filename() removes the audio extension, each artist name from the tags (split on / and ;, case-insensitive), underscores (to spaces), a leading track number (^\d{1,3}\s*[-._)\s]\s*), YouTube-style junk from _JUNK_PATTERNS such as (Official Audio), (Lyrics), [HD], [4K], (feat. ...), and leftover separators and empty brackets; it returns None if nothing changed. _auto_strip_display_names() runs at the end of every scan for files that have no entry yet. The settings page's "Strip filenames" button calls strip_filenames(), which re-strips every file, reports each change as a [STRIP] "old" → "new" line on scanProgress, saves, and emits mediaListChanged.

Volume, Mute and Ducking

The Volume Curve and VolumeController

The UI works in percent (0-100); QAudioOutput takes a linear 0.0-1.0. OCTAVE maps between them with a quadratic curve, linear = (percent / 100)², implemented once as to_linear() in backend/volume_utils.py. The VolumeController QObject in the same module, registered as volumeController, is the entry point for changing the volume: the QML sliders, the gesture handler and the ESP32 knob handler in main.py call applyVolume(percent), which clamps to 0-100, calls settings_manager.setCurrentVolume(percent), then media_manager.setVolume(linear), phone_mirror_manager.setVolume(linear) and esp32_manager.send_volume_update(percent) (each skipped if that reference is None). toLinear(percent) exposes the math to QML. 

# backend/volume_utils.py
def to_linear(percent) -> float:
    pct = max(0.0, min(100.0, float(percent)))
    return (pct / 100.0) ** 2.0

main.py calls volume_controller.applyVolume(settings_manager.currentVolume) once after every manager exists, which replaces the constructor's 0.5 placeholder.

Volume State Inside MediaManager

The user's volume (_volume), the mute flag and a ducking factor (_duck_current) are kept separately; _apply_output_volume() computes what the QAudioOutput actually gets: 0 while muted, otherwise volume × duck. getVolume() reports the user's volume, never the ducked or muted output level. 

# backend/media_manager.py
@Slot(float)
def setVolume(self, volume):
    volume = max(0.0, min(1.0, float(volume)))
    self._volume = volume
    if self._is_muted:
        self._previous_volume = volume      # slider moved while muted: remember it for unmute
    self._apply_output_volume()
    self.volumeChanged.emit(volume)

def _apply_output_volume(self):
    self._audio_output.setVolume(0.0 if self._is_muted else self._volume * self._duck_current)

Ducking

setDucking(factor) temporarily attenuates the output while the mirrored phone is producing sound (a navigation prompt, a call). The phone mirror client decides "producing sound" from its audio level with a 1.5 s release hold (AUDIO_HOLD_MS in backend/phone_mirror/scrcpy_client.py); PhoneMirrorManager then emits duckingChanged(factor), which is the scrcpyAudioDuckLevel setting (default 0.1, -20 dB) while the phone is producing sound and scrcpyAudioDuckEnabled is on, and 1.0 otherwise. main.py connects it to media_manager.setDucking. The factor is clamped to 0-1 and ramped with a QVariantAnimation (OutCubic): 80 ms when ducking so a prompt is not stepped on, 500 ms on release so music does not jump back up between sentences. A request equal to the current target is ignored. Volume changes and mute keep working while ducked. main.py also forwards muteChanged to phone_mirror_manager.setMuted, so OCTAVE's mute silences the phone audio too.

Mute Toggle with Guard

toggle_mute() uses a lock flag with a 150 ms single-shot unlock so a bouncing hardware button or a double tap cannot flip the state twice and lose the remembered volume: 

# backend/media_manager.py
@Slot()
def toggle_mute(self):
    if self._mute_toggle_locked:
        return
    self._mute_toggle_locked = True
    try:
        if self._is_muted:
            # Unmuting: _volume tracked the slider while muted; fall back if it is 0
            if self._volume <= 0.0:
                self._volume = self._previous_volume if self._previous_volume > 0.0 else 0.5
        elif self._volume > 0.0:
            self._previous_volume = self._volume     # muting: remember the meaningful volume

        self._is_muted = not self._is_muted
        self._apply_output_volume()
        self.muteChanged.emit(self._is_muted)
    finally:
        QTimer.singleShot(150, self._unlock_mute_toggle)

Because mute is applied by _apply_output_volume() rather than by overwriting the volume, a slider move while muted updates _volume silently and unmute uses it when positive; a zero value falls back to the previous positive volume or 0.5. play_file(), toggle_play() and recovery set the output to 0 again after setSource() when muted.

Playback State Resume

The current song, position (ms) and playlist name are saved through settings_manager.save_playback_state(). To avoid a disk write on every rapid track change, saves go through a 1 s single-shot debounce timer (_save_state_timer, connected to _save_playback_state_now()): next_track, previous_track, pause and toggle_play restart it, so only the last change in a burst is written. The _save_playback_state() slot only restarts the timer. 

# backend/media_manager.py — __init__
self._save_state_timer = QTimer()
self._save_state_timer.setInterval(1000)
self._save_state_timer.setSingleShot(True)
self._save_state_timer.timeout.connect(self._save_playback_state_now)

At shutdown: Main.qml's onClosing calls mediaManager._save_playback_state() (which only restarts the timer), cleanup_on_quit() in main.py calls _save_playback_state_now() directly before settings_manager.flush_pending_save(), and __del__ runs a still-pending debounced save.

_restore_playback_state() runs 500 ms after the settings manager is wired: it restores shuffle if persisted, selects the last playlist if it exists, returns if the song is not in it, shuffles with the song first when shuffle is on, returns if the file is missing, sets the source without playing, emits currentMediaChanged, the metadata and the formatted duration so the UI shows the track, seeks to the saved position after 100 ms, and only if autoPlayOnStartup is on (default off) calls play() and sets the playing state 500 ms later (the comment: the delay lets the audio system initialize and avoids crackling).

Neighbor Pre-caching

80 ms after play_file() (_precache_timer, single-shot), _precache_neighbors_start() warms the metadata and cover caches for the tracks at offsets -3 to +3 around the current index, so the carousel's side cards and the next skip are cache hits. Indices wrap with Python's %; the current track and repeats (a playlist shorter than the window) are skipped, and the function returns on an index outside the playlist.

The work has three phases, and the GUI thread is the only one that touches the caches:

  1. GUI thread: neighbors already in _metadata_cache are skipped and those valid in the tag store are inserted directly. The rest go to a daemon threading.Thread that only calls _read_tags() and posts the results through the internal queued signal _precacheTagsReady(neighbors, [(filename, path, meta)])
  2. GUI thread, _apply_precached_tags(): inserts the tags and writes them to the store, then for each neighbor's album id not already known takes a cover found by hash or queues the file for a second daemon thread that only calls _extract_art_for() and posts _precacheArtReady([(album_id, url)])
  3. GUI thread, _apply_precached_art(): records the URLs (running _manage_cache() first)

Error Recovery

  • EndOfMedia - calls next_track()
  • StalledMedia / InvalidMedia and player errors - call _attempt_playback_recovery(), but only while something is playing; a stopped player keeps reporting its last failure, so those events are ignored
  • LoadedMedia / BufferedMedia - the file decodes, which is what "recovered" means here: a pending seek from _reseat_source() is applied, the attempt counters are reset and, if there were attempts, "Playback recovered for: ..." is logged
# backend/media_manager.py (abridged)
MAX_RECOVERY_ATTEMPTS = 2          # per file, then skip it
LONG_PAUSE_SECONDS = 30
MAX_CONSECUTIVE_BAD_TRACKS = 10    # then stop instead of looping the library

def _attempt_playback_recovery(self, force: bool = False):
    if not self._is_playing and not force:
        return
    current_file = self.get_current_file()
    # ... reset the attempt counter when the file changed ...
    self._recovery_attempts += 1
    if self._recovery_attempts > self.MAX_RECOVERY_ATTEMPTS:
        self._skip_bad_track()
        return
    position = self._player.position()
    # ... missing file: _skip_bad_track() ...
    self._reseat_source(file_path, position)   # seek deferred to LoadedMedia
    if was_playing:
        self._player.play()
    if self._is_muted:
        self._audio_output.setVolume(0.0)
    self.playStateChanged.emit(self._is_playing)

After 2 attempts on the same file the track is skipped (_skip_bad_track() → next_track()): a tag-only stub or a truncated file never becomes playable. A missing file skips immediately and counts toward the same limit. After 10 unplayable tracks in a row (or the playlist length, if shorter) playback stops, the source is cleared so no further status events arrive, and playStateChanged(False) is emitted instead of looping the library. toggle_play() passes force=True so pressing play on a bad state still gets a recovery attempt.

Reseating the source

_reseat_source(file_path, position) reloads a track at a position, which gives the player a fresh audio sink. It clears the source first (Qt does not reload a source identical to the current one), then sets it again. The seek is deferred: the code comment notes that a setPosition() straight after setSource() is dropped and playback restarts at 0. The pending (file_path, ms) is stored in _pending_seek before the second setSource(), because LoadedMedia can arrive during that call; a position of 0 sets no pending seek.

Both recovery and the long-pause resume in toggle_play() use it. The long-pause path exists because, per the comment on LONG_PAUSE_SECONDS, after a long pause the audio sink can come back silent while the player reports PlayingState (seen on the Orange Pi; only a skip brought the sound back). pause() and toggle_play() record time.monotonic() in _paused_at.

Threading

MediaManager lives on the GUI thread and its slots are normally called there. Work that leaves the thread:

  • Neighbor pre-cache - daemon threading.Threads that only read tags or write cover files; results come back through queued signals and the caches are written on the GUI thread (above)
  • Colour extraction - a daemon thread named album-colors per request, result through the queued _colorsReady; only the newest job is applied
  • Library scanning and on-demand tag reads stay synchronous on the GUI thread; the tag store makes a warm scan cheap

The pure-Python k-means and tag parsing on worker threads hold the GIL while they run, so they can still delay the GUI thread; the perf monitor's GIL probe (Development) measures that. The QMediaPlayer backend decodes on its own threads and reports back through the signals listed under QMediaPlayer Integration.

Design Decisions

ChoiceWhy (from code comments)
QMediaPlayer + QAudioOutput rather than a custom decoderQt Multimedia provides playback through PySide6; codecs depend on the Qt build. The manager only adds what Qt lacks: the position timer as a safety net for coarse positionChanged, following the default output device, and the recovery logic for files Qt cannot decode.
Folders as playlistsThe music folder's sub-folders are the only source of truth: there is no playlist database to keep in sync, every edit is a filesystem operation followed by a rescan, and "All Music" is the union. Empty folders are kept "so user-created playlists survive a rescan (e.g. after moving the last song out)".
Persistent tag store on disk (metadata_cache.json)Tags are read from a file once and then served from the store on every later run as long as size and mtime are unchanged, instead of opening every file with mutagen when a list scrolls or the media page opens.
Content-addressed covers kept across runs"wiping them here made every cover a fresh ID3 read + JPEG write on each boot". Hashing the album id makes the file name derivable without opening the audio file; the start-up prune bounds the directory, since _manage_cache() only sees the current run.
Atomic writesThe head unit loses power with the ignition (backend/atomic_io.py); a truncated cover would be served by the hash fast path on every later boot, so covers, the tag store and display names are replaced in one step.
Colour extraction off the GUI threadk-means over the cover takes "~0.3 s here, closer to a second on the Pi"; a newer request supersedes the running one so a fast skip applies only the last theme, and the 2 s dedupe removes the start-up double request.
Local k-means seedThe same cover produces the same theme every time, and a private random.Random(42) leaves the global generator alone, because seeding it "made every later random.shuffle() / getrandbits() in the process deterministic".
Caches populated before currentMediaChanged"moves the ID3/disk I/O out of the QML binding evaluation (render phase) so the animation can start without blocking the scene graph."
GUI thread as sole owner of the cachesThe pre-cache workers "only read files; results are applied to the caches here on the GUI thread", so no lock is needed around lookups made by list delegates.
Quadratic volume curve in one placePer volume_utils.py, (percent/100)² "gives a more natural perceptual response than linear at low volumes", and "every audio output in the app must use this same curve or they will drift out of sync". Before the module existed the curve was hard-coded in about nine call sites across main.py and QML.
Volume, mute and ducking as separate stateThe output level is computed from three independent values in one function, so a ducked or muted output level is never mistaken for the user's volume.
Recovery cap, skip, then stopQt does not reload or re-report an error for a source identical to the current one, so recovery clears and re-sets the source; a tag-only stub or truncated file "never becomes playable" and is skipped after two attempts, and "a library of stubs must not loop", so playback stops after ten bad tracks in a row. "Recovered" is only logged when the player reaches LoadedMedia.
Debounced state and store writesSpamming next/previous or scrolling a list must not turn into a disk write per event; the 1 s (playback state) and 2 s (tag store) single-shot timers coalesce bursts, and shutdown flushes both.
Position timer only while playing"It only runs while playing so an idle app does not wake ten times a second for nothing."

How to Modify / Extend

Adding a New Audio Format

  1. Add the extension to AUDIO_EXTENSIONS in backend/media_manager.py
  2. Add a branch in _read_tags() for its tags and, if the container embeds art, an _extract_album_art_*() reader dispatched from _extract_art_for() that hands the bytes and MIME type to _write_cover()
  3. Update the format table above

Adding a New Playback Feature

  1. Add the Signal, state variable and @Slot to MediaManager
  2. Emit the signal when the state changes; grep the QML for the new symbol
  3. If the feature should persist, add a setting to SettingsManager (see Development)
  4. Update Signals & Slots Reference and this page
