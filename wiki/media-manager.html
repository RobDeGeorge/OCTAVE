Overview

The MediaManager class (src/managers/mediamanager.{h,cpp} in the C++ backend, backend/media_manager.py in the Python backend) handles all local audio file playback for OCTAVE. It wraps Qt's QMediaPlayer and QAudioOutput, turns the sub-folders of the music folder into playlists, keeps a metadata and album-art cache backed by a persistent tag store on disk, extracts dominant colors from album art for the "Album Art Capture" theme, and provides shuffle, skip, playback resume and automatic recovery from unplayable files.

It is registered as a QML context property named mediaManager in both src/main.cpp and main.py. All playback controls are Slots and every state change is broadcast with a Signal, so the QML in frontend/MediaRoom.qml, MediaPlayer.qml, BottomBar.qml, MainMenu.qml and the dashboards/widgets/NowPlayingWidget.qml works identically against either backend.

Supported Audio Formats

The following file extensions are recognized during library scanning (MediaManager::s_audioExtensions in C++, AUDIO_EXTENSIONS in Python):

// C++ (src/managers/mediamanager.cpp)
".mp3", ".m4a", ".mp4", ".flac", ".ogg", ".opus", ".wav"

# Python (backend/media_manager.py)
AUDIO_EXTENSIONS = ('.mp3', '.m4a', '.mp4', '.flac', '.ogg', '.opus', '.wav')

Both lists accept .mp4: YouTube serves audio-only streams in an MP4 container that yt-dlp names with a literal .mp4 extension, and those files are the same format as .m4a. The Python module also exposes strip_audio_extension(filename), which removes any of these extensions (and only these) and is what the display-name and metadata fallbacks use.

Which tags and embedded covers each backend can read is the same for every format except WAV art, which neither backend extracts. Python's dispatch lives in _read_tags(file_path, base_name) (tags, never raises) and _extract_art_for(file_path, album_id) (cover, mirrors the C++ function of the same name); a file that fails to open yields the file-name title with "Unknown Artist" / "Unknown Album" in both backends:

QMediaPlayer Integration

The constructor creates one QMediaPlayer with one QAudioOutput and starts it at volume 0.5 (the real startup volume is applied a moment later by VolumeController, see Volume). The Python constructor additionally sets the probe-size (10 MB) and analyzeduration (5 s) dynamic properties on the player for more reliable format probing; the C++ constructor does not. 

// src/managers/mediamanager.cpp — constructor
m_player = new QMediaPlayer(this);
m_audioOutput = new QAudioOutput(this);
m_player->setAudioOutput(m_audioOutput);
m_audioOutput->setVolume(0.5f);

connect(m_player, &QMediaPlayer::durationChanged,    this, &MediaManager::durationChanged);
connect(m_player, &QMediaPlayer::positionChanged,    this, &MediaManager::positionChanged);
connect(m_player, &QMediaPlayer::mediaStatusChanged, this, &MediaManager::_handle_media_status);
connect(m_player, &QMediaPlayer::errorOccurred,      this, &MediaManager::_handle_player_error);
connect(m_player, &QMediaPlayer::playbackStateChanged, this,
        [this](QMediaPlayer::PlaybackState state) { emit playbackStateChanged(static_cast<int>(state)); });

// Position timer (100 ms) as a safety net for backends whose
// QMediaPlayer::positionChanged is coarse. It only runs while playing.
m_positionTimer.setInterval(100);
connect(&m_positionTimer, &QTimer::timeout, this, &MediaManager::_update_position);
connect(this, &MediaManager::playStateChanged, this, [this](bool playing) {
    if (playing) m_positionTimer.start(); else m_positionTimer.stop();
});

Connected signals from QMediaPlayer:

  • durationChanged / positionChanged - forwarded directly to QML as the manager's own signals of the same name
  • mediaStatusChanged - routed to _handle_media_status(): EndOfMedia advances to the next track, LoadedMedia / BufferedMedia reset the recovery counters, StalledMedia / InvalidMedia trigger recovery
  • errorOccurred - also triggers recovery (ignored while nothing is playing)
  • playbackStateChanged - forwarded as playbackStateChanged(int) with the raw QMediaPlayer::PlaybackState value (0 stopped, 1 playing, 2 paused); the manager's own playStateChanged(bool) remains the signal the QML actually binds

The 100 ms QTimer re-emits positionChanged(position) while the player's playbackState() is PlayingState, as a safety net for multimedia backends whose native positionChanged is coarse. It is started and stopped from playStateChanged, so a paused or idle app does not wake ten times a second (commit ee5a23e).

Library Scanning

The library root comes from SettingsManager's mediaFolder setting. The stored default is the empty string, which both backends resolve to the user's Music folder (QStandardPaths::MusicLocation in C++, ~/Music in Python; on Android /storage/emulated/0/Music) and create if missing. The manager's own built-in <app dir>/media (C++) / backend/media/ (Python) directory is therefore only the initial value of m_mediaDir before settings are wired, and what get_default_media_dir() reports. Wiring happens in setSettingsManager() (C++, called from main.cpp) / connect_settings_manager() (Python, called from main.py; the C++ slot of the same name is a no-op kept for Main.qml), which calls set_library_root(), connects mediaFolderChanged to it, and schedules _restore_playback_state() 500 ms later.

scan_library(resetDisplayNames) is synchronous on the GUI thread, guarded by a re-entrancy flag, and emits scanProgress lines ([SCAN], [PATH], [FOUND], [DONE], ...) that the Media settings page shows terminal-style. The algorithm:

  1. Clear the playlists, the in-memory metadata and album-art maps, the All Music path map and the stats cache (and the display names if resetDisplayNames is true; internal callers pass false, while the settings-page "Rescan" button and the C++ Android scan that runs once the READ_MEDIA_AUDIO permission is granted use true)
  2. Audio files directly in the root become the "Unsorted" playlist
  3. Every immediate, non-hidden sub-folder becomes a playlist named after the folder, including empty folders, so a user-created playlist survives a rescan after its last song was moved out
  4. Every file is also appended to the combined "All Music" playlist (isCombined / is_combined). A file name already seen in another folder is renamed "<folder> - <file>" for that playlist, and m_allMusicFilePaths remembers which directory each name lives in
  5. Playlist names are ordered "All Music", "Unsorted", then the rest case-insensitively
  6. _auto_strip_display_names() cleans the file names that do not yet have a display name
  7. If a playlist was active before the rescan it is re-selected and the playing index restored, then playlistsChanged is emitted once, after all state is settled

Android (C++ only): after the root scan the manager also walks the app's own external-files Music directory (OctaveAndroid::getDownloadsDir()), where the downloader must write under scoped storage, and merges each of its sub-folders into the playlist of the same name (or adds it as a new one). _get_file_path() accepts that directory as a second valid root, and play_file_at_path() has a filename-only fallback for the same reason.

get_media_files(emitSignal) is the older flat listing of the current m_mediaDir; it is still called by MediaPlayer.qml on load and used as a fallback by shuffle and sorting when no playlist is selected. Both it and scan_library(resetDisplayNames) can be called from QML with or without their boolean in either backend: the C++ methods have default arguments, the Python methods carry two @Slot decorators (@Slot(result=list) and @Slot(bool, result=list); @Slot() and @Slot(bool)).

Path Safety
_get_file_path() rejects names containing a .. path component or starting with a separator, resolves All Music names through m_allMusicFilePaths, and then requires the result to be inside the library root (_is_safe_path() / is_safe_path(), which compare canonical paths). create_playlist(), move_song_to_playlist(), delete_song() and delete_playlist() apply the same check to every path they touch, and the two special playlists "All Music" and "Unsorted" cannot be deleted.

Metadata Caching and the Tag Store

Every lookup (get_band, get_album, get_formatted_duration, the "now playing" metadata, library statistics) goes through _cache_metadata(filename), which fills an in-memory map (m_metadataCache / _metadata_cache, filename → title, artist, album, duration in seconds) capped at 1000 entries. When the cap is hit the Python map drops its oldest insertion; the C++ QHash drops whichever entry begin() points at. The map is cleared on every select_playlist() and scan_library().

Behind it sits the persistent tag store <app data>/metadata_cache.json (the app-data directory from SettingsManager::getAppDataDir() / get_app_data_dir(), e.g. ~/.config/OCTAVE/ on Linux), introduced in commit 1232538 and written by both backends in the same format: 

{
  "version": 1,
  "files": {
    "Artist - Song.mp3": {
      "title": "Song", "artist": "Artist", "album": "Album",
      "duration": 245,             // seconds
      "size": 6021384, "mtime": 1757000000   // validation: bytes, seconds since epoch
    }
  }
}

How the store is used:

  • _cache_metadata() first asks _meta_from_store(). An entry is served without opening the audio file if the file still exists and its size and integer mtime match. After the first run, scrolling a list or opening the media page therefore no longer opens every file with TagLib / mutagen.
  • A stale entry (file deleted, renamed or rewritten) is removed on lookup, so the store stays bounded by the current library rather than by everything ever seen.
  • Only on a miss does _cache_metadata_from_file() read the tags; the result is written back with _meta_to_store().
  • Writes are coalesced: a single-shot 2 s timer is restarted on every change and _save_meta_store() writes the compact JSON once. The dirty flag is only cleared when the write succeeded, so a failed write is retried on the next change or at shutdown.
  • Shutdown flushes it explicitly: flush_metadata_store() is called from the aboutToQuit handler in main.cpp and from cleanup_on_quit() in main.py (the C++ destructor also saves).
  • Python detail: the save timer is armed through the internal _metaStoreChanged signal with a QueuedConnection, so _meta_to_store() is safe to call from any thread (a QTimer must not be started from another thread).

Tag strings are sanitized (control characters replaced by spaces, whitespace collapsed, truncated to 200 characters with "...") by _sanitize_metadata() / sanitize_metadata(). Both _read_tags() implementations sanitize every format (Python through _extract_id3_text() for ID3 frames and _extract_list_text() for MP4 atoms and Vorbis comments). Missing tags fall back to the file's base name for the title and to "Unknown Artist" / "Unknown Album".

Album Art Extraction

get_album_art(filename) returns a file:// URL to a cover image written into the temp directory: <app dir>/temp in the C++ desktop build, backend/temp/ in Python, the app-data temp/ folder on Android. Covers are content-addressed by album: cover_<sha256(albumId + "_0")[:16]>.<jpg|png|gif|img>. The extension follows the picture's MIME type; only the first embedded picture is used.

Album ID

_get_album_id() keys covers by "{album}_{artist}" so every track of an album shares one file. When the album tag is missing the key becomes "Unknown Album_{artist}_{filename}", because a folder of YouTube downloads usually has a different cover per track and they must not all share the first one. If metadata cannot be read at all, a 16-hex-digit SHA-256 of the file name is used.

Lookup Order

  1. Bump the album's access count (m_accessCount)
  2. Return the URL from the in-memory map m_albumArtCache (albumId → URL) if present
  3. Run _manage_cache(): when the map already holds 500 entries (m_maxCacheFiles), the entry with the lowest access count (other than the one being added) is removed from the map and its file deleted
  4. _cached_art_url_for(albumId): if a cover file with that hash already exists in the temp dir from any earlier run, use it without opening the audio file
  5. Otherwise open the audio file and extract the first picture (_extract_art_for() in both backends dispatches on extension: TagLib readers in C++, the mutagen readers in the format table in Python, whose _write_cover() names the file by MIME type) and write it if the file does not exist yet
  6. Store the URL in the map and return it (empty string if the file has no picture)

Covers Survive Restarts

Until commit 1232538 the temp directory was wiped at startup and at quit, so every cover was a fresh tag read plus JPEG write on each boot. Now the directory is kept and step 4 above finds a previous run's cover by hash. Because the in-memory map starts empty on every launch, _manage_cache() can only bound the covers the current run has seen; commit 43432c3 therefore added _prune_cover_dir(), which runs once in the constructor and deletes the least recently read cover_* files beyond the 500 limit (QFileInfo::lastRead() in C++, st_atime in Python), so covers of removed tracks do not accumulate forever. _clear_temp_files() still exists as a slot but nothing calls it any more.

Single-Read Population

When _cache_metadata_from_file() has to open a file for its tags it also extracts the cover in the same pass (_extract_art_for() after _read_tags() in both backends, skipped when the album's cover is already known or found by hash), so the get_album_art() call that follows in a QML binding is an instant map hit. Entries served from the tag store skip this step on purpose; their cover is found by the hash fast path.

Color Extraction and Theming

When the "Album Art Capture" theme is active, MediaManager extracts dominant colors from the current cover and generates a complete theme palette. It uses Qt's QImage only (no Pillow in Python). The triggers are the manager's own currentMediaChanged, SettingsManager's themeSettingChanged switching to "Album Art Capture", a 1 s startup timer when the theme is already active, and explicit calls to the extract_colors_from_album_art(filename) slot from Main.qml.

Extraction Pipeline

  1. extract_colors_from_album_art() resolves the cover through get_album_art(). A repeat request for the same file within 2 s is dropped: restoring playback and the 1 s startup timer both ask for the same file and one extraction is enough
  2. The image work runs on a worker: QtConcurrent::run() with a QFutureWatcher<QString> in C++, a daemon threading.Thread named album-colors in Python (result posted back through the internal queued signal _colorsReady). Each request increments a job counter; when a job finishes it is applied only if no newer job was started, so a fast skip through tracks applies only the last theme
  3. _extract_album_colors() converts the cover to RGBA8888 and scales it to 50×50 pixels with a smooth transformation (2500 pixels)
  4. _kmeans_colors() finds k=5 centroids with at most 10 iterations, seeded with a fixed generator (std::mt19937(42) / random.Random(42)) so the same cover always yields the same palette. The Python version uses a local generator on purpose: seeding the global random module made every later random.shuffle() in the process deterministic
  5. Centroids are sorted by vibrancy (HSV saturation × value, most vibrant first)
  6. The image is classed dark when the average luminance (0.299R + 0.587G + 0.114B) of the first 1000 pixels is below 0.5
  7. _generate_theme_from_colors() builds the theme JSON and _apply_album_colors() (GUI thread) hands it to settingsManager.set_album_art_colors(json). That updates the albumArtColors property, and Main.qml feeds it to Style.updateAlbumArtTheme(). The albumColorsExtracted signal is only emitted when no SettingsManager is wired

Theme Generation

_generate_theme_from_colors() takes the sorted palette (primary, secondary, tertiary, quaternary; missing entries repeat the previous one) and derives:

  • base, baseAlt - dark images: primary at 15% / 22% brightness; light images: primary at 250% brightness desaturated to 30%, then 92% of that
  • accent - primary with saturation ×1.4 and brightness ×1.2; three further accents from the other centroids with progressively smaller boosts, and two dimmer "nav" variants (70% / 75%)
  • text.primary, text.secondary - near-white (245 / 210) on backgrounds whose WCAG relative luminance is below 0.3, otherwise near-black (25 / 60)
  • states.hover, states.paused, states.playing - brightness steps of the base
  • sliders.volume, sliders.media, sliders.settings - accents 1-3
  • bottombar.* - 14 keys (previous, play, pause, next, volume, shuffle, toggleShade, homeButton, obdButton, mediaButton, settingsButton, sensorButton, androidAutoButton, phoneMirrorButton)
  • mediaroom.* - player control colors (play/pause use the accent at 110% brightness)
  • mainmenu.mediaContainer - second accent at 60% brightness
  • obd.boxBackground, obd.barColor, obd.labelColor, obd.valueColor - gauge colors against baseAlt

Every icon/accent color is passed through ensureIconContrast(), which requires a WCAG contrast ratio of at least 3.0 against the background, trying brightness factors 1.3 to 3.0 (dark base) or 0.7 to 0.2 (light base) and falling back to a muted gold (200, 180, 130) or a dark brown (50, 40, 30). Colors that already pass are capped at 85% brightness by capBrightness() (with saturation nudged ×1.1) to avoid washed-out pastels.

Playback Control

Playing a File

play_file(filename) does the following (both backends):

  1. If no playlist order exists yet, build one: shuffled when shuffle is on, otherwise alphabetical by the sort key (lower-cased, punctuation and underscores stripped: [^\w\s]|_)
  2. Locate the file in the playlist and set m_currentIndex; if it is not there and shuffle is off, rebuild the alphabetical list; if it is still missing, play the first entry instead
  3. Resolve the path with _get_file_path() (All Music aware), refuse to play a missing file
  4. setSource() + play(), set the playing flags, re-apply mute (setting a source can reset the output volume), emit playStateChanged(true)
  5. Pre-populate the metadata and cover caches and emit metadataChanged before currentMediaChanged, so the QML bindings that fire on the latter get instant cache hits instead of doing tag I/O during the render phase
  6. Emit durationFormatChanged via get_formatted_duration(), then start the 80 ms pre-cache timer

Shuffle Logic

Shuffle is a toggle (m_shuffle / _shuffle); there is no repeat mode, playback simply wraps around the playlist. toggle_shuffle() works on the selected playlist's file list (_get_current_playlist_files()), not on a directory scan, so shuffling "All Music" shuffles every folder:

  • On: the files are shuffled (std::shuffle with a std::random_device-seeded mt19937 / random.shuffle), the currently playing song is swapped to position 0 and the index reset to 0, so playback continues from the current song into a random order
  • Off: the alphabetical order is rebuilt and the index set to the current song's position in it
  • Afterwards shuffleStateChanged and mediaListChanged(newOrder) are emitted, in that order, so QML reads the new order

Every toggle is saved through settingsManager.save_last_shuffle_state(). On startup _restore_playback_state() re-enables shuffle only when the persistShuffleState setting is on and lastShuffleState was true; it then shuffles the restored playlist with the last played song at the front (see Settings Reference).

Playlist Management

Playlists are folders. The manager keeps:

  • m_playlists / _playlists - name → {name, path, files, songCount, isCombined}
  • m_playlistNames - ordered names ("All Music", "Unsorted", then alphabetical)
  • m_currentPlaylistName, m_currentPlaylist (the ordered or shuffled file list actually played), m_currentIndex
  • m_libraryRoot - the resolved mediaFolder

select_playlist(name) switches m_mediaDir to the folder (or the root for All Music), sorts the files alphabetically, resets the index, clears the in-memory metadata map, recalculates the library statistics (totalDurationChanged, albumCountChanged, artistCountChanged, computed from cached durations and distinct non-"Unknown" album / artist tags) and emits currentPlaylistChanged and mediaListChanged.

"All Music" Playlist

The combined playlist spans every folder, so _get_file_path() looks the directory up in m_allMusicFilePaths first. A duplicate that was renamed "<folder> - <file>" during the scan is mapped back to its real name when the prefixed file does not exist on disk; _get_original_filename() does the same for display purposes and for moves.

Display Names

get_display_name(filename) returns a cleaned title for lists and the now-playing views. The map m_displayNames is persisted as <app data>/display_names.json so cleaned names survive restarts. _strip_single_filename() removes the extension, the artist name(s) from the tags (split on / and ;), leading track numbers (^\d{1,3}\s*[-._)\s]\s*), a list of YouTube-style junk such as (Official Audio), [HD], (feat. ...), and leftover separators. _auto_strip_display_names() runs at the end of every scan for files that have no entry yet; the settings page's "Strip filenames" button (strip_filenames()) re-strips every file and reports each change through scanProgress. Without an entry, both fallbacks strip any recognised audio extension (Python: strip_audio_extension(), also used for the metadataChanged title fallback and the strip log lines).

Volume, Mute and Ducking

The Volume Curve and VolumeController

The UI works in percent (0-100); QAudioOutput takes a linear 0.0-1.0. OCTAVE maps between them with a quadratic curve, linear = (percent / 100)², implemented once in src/managers/volumecontroller.{h,cpp} (VolumeController::toLinearStatic()) and backend/volume_utils.py (to_linear()). The VolumeController QObject, registered as the QML context property volumeController, is the single entry point for changing the volume: the BottomBar and MediaRoom sliders, the gesture sensor and the ESP32 knob all call volumeController.applyVolume(percent), which clamps, persists the percent as the currentVolume setting, computes the linear value and fans it out. toLinear(percent) exposes the pure math to QML. 

// src/managers/volumecontroller.cpp
float VolumeController::toLinearStatic(float percent)
{
    const float pct = std::clamp(percent, 0.0f, 100.0f);
    const float normalized = pct / 100.0f;
    return normalized * normalized;   // (pct / 100)^2.0
}

The fan-out differs between the backends:

  • C++: applyVolume() emits volumeApplied(percent, linear) and knows no manager; main.cpp connects it to mediaManager.setVolume(linear), phoneMirrorManager.setVolume(linear), esp32VolumeManager.send_volume_update(percent) (desktop builds) and a 300 ms debounced spotifyManager.set_volume(percent).
  • Python: the VolumeController holds references and calls media_manager.setVolume(linear), phone_mirror_manager.setVolume(linear) and esp32_manager.send_volume_update(percent) directly; the Spotify leg goes through the same 300 ms trailing debounce (_flush_spotify_volume(), only when connected).

Both mains call applyVolume(settingsManager.currentVolume) once at startup after every manager exists, which is what replaces the constructor's 0.5 placeholder.

Volume State Inside MediaManager

The user's volume (m_volume / _volume), the mute flag and a ducking factor are kept separately; one helper (applyOutputVolume() / _apply_output_volume()) computes what the QAudioOutput actually gets: 0 while muted, otherwise volume × duck. getVolume() reports the user's volume, never the ducked or muted output level. 

// src/managers/mediamanager.cpp
void MediaManager::setVolume(float volume)
{
    volume = qBound(0.0f, volume, 1.0f);
    m_volume = volume;
    if (m_isMuted)
        m_previousVolume = volume;      // slider moved while muted: remember it for unmute
    applyOutputVolume();
    emit volumeChanged(volume);
}

void MediaManager::applyOutputVolume()
{
    m_audioOutput->setVolume(m_isMuted ? 0.0f : m_volume * m_duckCurrent);
}

Ducking

setDucking(factor) (both backends, commit 5834d9d) temporarily attenuates the output while another source needs to be heard: today the mirrored phone's audio (a navigation prompt, a call). The PhoneMirrorManager measures each PCM chunk's peak, sets audioPlaying with a 1.5 s release hold, and emits duckingChanged(factor) (the scrcpyAudioDuckLevel setting, default 0.1 = -20 dB, or 1.0 when the phone is silent or scrcpyAudioDuckEnabled is off); both mains connect that signal to mediaManager.setDucking. The factor is ramped with a QVariantAnimation (OutCubic): 80 ms attack so a prompt is not stepped on, 500 ms release so music does not jump back up between sentences. Volume changes and mute keep working while ducked. Spotify is deliberately not ducked: it plays on its own Spotify Connect device, usually the mirrored phone, so its sound already arrives through the mirror stream.

Mute Toggle with Guard

toggle_mute() uses a lock flag with a 150 ms single-shot unlock so a bouncing hardware button or a double tap cannot flip the state twice and lose the remembered volume: 

# backend/media_manager.py
@Slot()
def toggle_mute(self):
    if self._mute_toggle_locked:
        return
    self._mute_toggle_locked = True
    try:
        if self._is_muted:
            # Unmuting: _volume tracked the slider while muted; fall back if it is 0
            if self._volume <= 0.0:
                self._volume = self._previous_volume if self._previous_volume > 0.0 else 0.5
        elif self._volume > 0.0:
            self._previous_volume = self._volume     # muting: remember the meaningful volume

        self._is_muted = not self._is_muted
        self._apply_output_volume()
        self.muteChanged.emit(self._is_muted)
    finally:
        QTimer.singleShot(150, self._unlock_mute_toggle)

Because mute is applied by applyOutputVolume() rather than by overwriting the volume, a slider move while muted updates m_volume silently and unmute restores exactly that. play_file(), toggle_play() and recovery re-apply setVolume(0) on the output after setSource(), which can reset the output level.

Playback State Resume

The current song, position (ms) and playlist name are saved through settingsManager.save_playback_state(). To avoid a disk write on every rapid track change, saves go through a 1 s single-shot debounce timer (m_saveStateTimer): next / previous restart it, pause and play-toggle restart it, only the last call wins. 

// src/managers/mediamanager.cpp — constructor
m_saveStateTimer.setInterval(1000);
m_saveStateTimer.setSingleShot(true);
connect(&m_saveStateTimer, &QTimer::timeout, this, &MediaManager::_save_playback_state_now);

At shutdown the state is flushed immediately: Main.qml calls mediaManager._save_playback_state() on close, main.cpp's aboutToQuit handler calls it again before settingsManager.flushPendingSave(), main.py's cleanup_on_quit() calls _save_playback_state_now(), and both destructors flush a pending debounced save. In C++ _save_playback_state() is a Q_INVOKABLE alias that saves immediately; in Python it restarts the debounce timer.

_restore_playback_state() runs 500 ms after the settings manager is wired: it restores shuffle if persisted, selects the last playlist, checks the song is still in it, sets the source without playing, emits currentMediaChanged and the metadata so the UI shows the track, seeks to the saved position after 100 ms, and only if the autoPlayOnStartup setting is on starts playback after a further 500 ms (the delay lets the audio system initialize and avoids crackling).

Neighbor Pre-caching

80 ms after a track change (m_precacheTimer, single-shot), _precache_neighbors_start() warms the metadata and cover caches for the tracks at offsets -3 to +3 around the current index, so the carousel's side cards and the next skip are instant. The index uses Euclidean modulo, skips the current track and de-duplicates: commit aa2dacb fixed a crash when spamming "next" on a two-track playlist, where C++'s truncating % produced a negative index (-1 % 2 == -1) and QList::at() asserted; a playlist shorter than the window now queues each neighbor once instead of six redundant jobs. Both backends also bail on the "no current track" sentinel (-1) or an index that outlived a playlist shrink.

Both desktop backends use the same three-phase, race-free model (C++ since commit 1232538, Python since the mutagen rework): phase 1 on a worker reads tags (_read_tags()) for neighbors not already in the map or the tag store; phase 2 on the GUI thread inserts them (and writes them to the store), then hands the neighbors still lacking a cover to a second worker that only writes cover files (_extract_art_for()); phase 3 on the GUI thread records the URLs. The GUI thread is therefore the sole owner of the metadata and album-art maps, and the workers never touch them. What differs is the plumbing:

  • C++ desktop: QtConcurrent workers, results delivered through QFutureWatcher. The earlier version mutated the hashes from the worker while list delegates were reading them.
  • C++ mobile: _precache_tracks() runs synchronously on the GUI thread, since the platform tag reader is cheap.
  • Python: daemon threading.Threads, results delivered through the internal queued signals _precacheTagsReady(neighbors, [(filename, path, meta)]) → _apply_precached_tags() and _precacheArtReady([(album_id, url)]) → _apply_precached_art(). The earlier _precache_tracks() thread called _cache_metadata() / get_album_art() directly and wrote the dicts from the worker.

Error Recovery

MediaManager recovers automatically from playback failures:

  • EndOfMedia - calls next_track()
  • StalledMedia / InvalidMedia and player errors - call _attempt_playback_recovery(), but only while something is playing; a stopped player keeps reporting its last failure, so those events are ignored (commits 2884c65, 1e5f585)
  • LoadedMedia / BufferedMedia - the file decodes, which is what "recovered" actually means: the attempt counters are reset and, if there were attempts, "Playback recovered" is logged
// src/managers/mediamanager.cpp
static constexpr int kMaxRecoveryAttempts = 2;        // per file, then skip it
static constexpr int kMaxConsecutiveBadTracks = 10;   // then stop instead of looping the library

void MediaManager::_attempt_playback_recovery(bool force)
{
    if (!m_isPlaying && !force)
        return;
    const QString currentFile = get_current_file();
    // ... reset the attempt counter when the file changed ...
    if (++m_recoveryAttempts > kMaxRecoveryAttempts) {
        _skip_bad_track();
        return;
    }
    const qint64 position = m_player->position();
    // Clear then re-set the source: Qt does not reload (or re-report an
    // error for) a source identical to the current one.
    m_player->setSource(QUrl());
    m_player->setSource(QUrl::fromLocalFile(filePath));
    if (position > 0)
        m_player->setPosition(position);
    if (wasPlaying)
        m_player->play();
    if (m_isMuted)
        m_audioOutput->setVolume(0.0f);
    emit playStateChanged(m_isPlaying);
}

Recovery is capped (commit 2884c65, seen on the Pi with 14 tag-only MP3 stubs). After 2 attempts on the same file the track is skipped (_skip_bad_track() → next_track()): a tag-only stub or a truncated MP3 never becomes playable. A missing file skips immediately. After 10 unplayable tracks in a row (or the whole playlist, if shorter) playback stops, the source is cleared so no further status events arrive, and playStateChanged(false) is emitted instead of looping the library. toggle_play() passes force so a user pressing play on a bad state still gets a recovery attempt. The Python constants are MAX_RECOVERY_ATTEMPTS / MAX_CONSECUTIVE_BAD_TRACKS with the same values.

Threading

MediaManager lives on the GUI thread and all of its slots are called there. Work that leaves the thread:

  • Neighbor pre-cache - QtConcurrent workers (C++, results marshalled back through QFutureWatcher) / daemon threads with queued signals back (Python); the caches are written only on the GUI thread, see above
  • Colour extraction - QtConcurrent + QFutureWatcher<QString> (C++) / a daemon thread with a queued signal back (Python); only the newest job is applied
  • Library scanning and tag reads on demand stay synchronous on the GUI thread; the tag store makes a warm scan cheap

The QMediaPlayer backend decodes on its own threads and reports back through the signals listed under QMediaPlayer Integration.

Design Decisions

ChoiceWhy (from code comments and commit history)
QMediaPlayer + QAudioOutput rather than a custom decoderQt Multimedia provides a native decoder on every target (the analyzer's decoder comment lists them: MediaCodec on Android, GStreamer/FFmpeg on Linux, Media Foundation on Windows, AVFoundation on macOS), so one class serves every build target and both backends with the same signals. The manager only adds what Qt lacks: the position timer as a safety net for backends whose positionChanged is coarse, and the recovery logic for files Qt cannot decode.
Folders as playlistsThe music folder's sub-folders are the only source of truth: there is no playlist database to keep in sync, every edit (create_playlist, move_song_to_playlist, delete_*) is a plain filesystem operation followed by a rescan, and "All Music" is the union. The scanner keeps empty folders on purpose "so user-created playlists survive a rescan (e.g. after moving the last song out)".
Persistent tag store on disk (metadata_cache.json)Reading tags is file I/O per track; on the Pi's SD card, scrolling a list or opening the media page opened every file with TagLib/mutagen on every run. Tags rarely change, and size + mtime is a cheap, sufficient validity check. The format is shared so the two backends can run against the same app-data directory (commit 1232538).
Content-addressed covers kept across runsThe cover of an album is the same bytes every time; wiping the temp dir at start and quit made every cover a fresh tag read + JPEG write on each boot. Hashing the album id makes the file name derivable without opening the audio file, and the startup prune bounds the directory once the in-memory LRU can no longer see earlier runs (43432c3).
Colour extraction off the GUI threadk-means over a 50×50 cover takes ~0.3 s on a desktop and closer to a second on the Pi; doing it in the currentMediaChanged handler froze the track-change animation. A job counter makes a fast skip through tracks apply only the last theme, and the 2 s dedupe removes the startup double-fire (restore + the 1 s timer).
Fixed k-means seedThe same cover must produce the same theme every time it is played; and the Python version uses a private random.Random(42) because seeding the global module made every later random.shuffle() deterministic (visible as identical shuffle orders).
Caches populated before currentMediaChangedQML bindings on the now-playing track run during the render phase; pre-filling the metadata and cover caches moves the disk I/O out of binding evaluation so the carousel animation starts without blocking the scene graph.
GUI thread as sole owner of the cachesThe first QtConcurrent pre-cache mutated QHashes from the worker while list delegates were reading them, and the Python thread relied on the GIL for the same dict writes. Splitting the work into "read files on the worker, insert on the GUI thread" keeps the speed without a mutex around every lookup; both backends now do it.
Quadratic volume curve in one placePer the VolumeController header, (percent/100)² "gives a more natural perceptual response than linear at low volumes", and "every audio output in the app must use this same curve or they will drift out of sync when the user moves the slider". Before VolumeController existed the curve was hard-coded in about nine call sites across main.py and QML and every output drifted out of sync when one site changed; centralizing math and dispatch means changing the curve is a one-line edit (volume_utils.py docstring, commit d2b047b).
Volume, mute and ducking as separate stateBefore ducking, mute read the output level back as "the volume to restore", so a ducked or muted output could be persisted as the user's volume. Computing the output from three independent values in one function removed that class of bug (5834d9d).
Recovery cap, skip, then stopQt neither reloads nor re-reports an error for a source identical to the current one, so the old "re-set the same URL" recovery left a broken file silently stuck at 0:00 with the pause icon, logging "recovery successful" unconditionally. A library of tag-only stubs must be skipped, not retried forever, and if every track is bad the player must stop rather than cycle the library (2884c65). "Recovered" is only claimed when the player actually reaches LoadedMedia.
Debounced state and store writesSpamming next/previous or scrolling a list must not turn into a disk write per event on an SD card; a 1 s (playback state) and 2 s (tag store) single-shot timer coalesce bursts, and shutdown flushes both explicitly.
Position timer only while playingA 100 ms timer that runs forever keeps an idle head unit waking ten times a second for nothing; tying it to playStateChanged costs nothing while playing (ee5a23e).

How to Modify / Extend

Adding a New Audio Format

  1. Add the extension to s_audioExtensions and the file-local s_audioExts list in mediamanager.cpp, and to AUDIO_EXTENSIONS in media_manager.py
  2. C++ tags already come from TagLib::FileRef; add a picture reader to _extract_art_for() if the container embeds art. Python: add a branch in _read_tags() (tags) and, if the container embeds art, an _extract_album_art_*() reader dispatched from _extract_art_for()
  3. Update the format table above

Adding a New Playback Feature

  1. Add the signal, state variable and slot to both classes with the same names (see the parity rules in CLAUDE.md)
  2. Emit the signal when state changes; grep the QML for the new symbol and confirm both backends define it
  3. If the feature should persist, add a corresponding setting to both SettingsManagers in the same commit
  4. Update Signals & Slots Reference and this page
Parity Notes
The extension list, the per-format tag and cover readers (TagLib / mutagen), the three-phase pre-cache and the extension-stripping fallbacks now match between the backends; the remaining differences are the tag-store eviction order (oldest insertion in Python, QHash::begin() in C++), the Python-only probe-size / analyzeduration player properties, and the mobile C++ paths. The QML never needs to know which backend is running.
