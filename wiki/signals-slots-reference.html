How managers reach QML
Every manager is a QObject subclass instantiated in main.py and registered with engine.rootContext().setContextProperty(...) before frontend/Main.qml loads, so QML reaches it by name: mediaManager.next_track(), settingsManager.themeSetting, obdManager.onRpmChanged. Other context values are screenAutoScale (float: short screen edge / 720, clamped to 0.4–3.0), isAndroid (bool, always False), wikiViewerAvailable (bool: PySide6.QtWebEngineQuick imported) and wikiHomeUrl (QUrl of wiki/index.html). The qmlRegisterType’d OCTAVE.AndroidAuto.EmbeddedDhuItem, the dhuframe image provider and the QML singletons (OBDParameterModel, WidgetCatalog, …) are documented in Components, not here.

Reading this page

  • Properties are PySide6 Property objects (mostly the @Property(type, notify=...) decorator form). Almost all are read-only from QML; call the matching save_* / set* slot to change them. Notify signal is what a QML binding or on<Name>Changed handler listens to; constant properties have none.
  • Slots are methods decorated with @Slot(...), the only Python methods QML can call. The signature shows the Python parameter names with the types passed to @Slot; Returns is the result= type (None when there is none). A plain Python method without @Slot is not callable from QML, even when main.py calls it.
  • Signals are class attributes name = Signal(types...); the column lists the payload types the QML handler receives.
  • Types are written as in the source: Python types (str, int, float, bool, list, dict, bytes, object) or PySide/Qt classes (QObject, QUrl). A quoted type such as "QVariantList", "QVariantMap", "QVariant" or "qint64" is a Qt meta-type name the source passes to PySide as a string; lists and maps arrive in QML as JS arrays and objects.
  • Rows are in source order. Several stacked @Slot decorators on one method are shown as one row with each signature.

SettingsManager — settingsManager

backend/settings_manager.py — QML context property settingsManager

Central settings store. Persists settingsConfigure.json in the app data directory (writes are debounced 500 ms and atomic; flushPendingSave() forces them). Settings with a dedicated property follow a triple: a read-only Property, a <name>Changed signal and a save_<snake_name>() slot. Types, defaults and validation for every key are in the Settings Reference; persistence is described in Settings Manager.
