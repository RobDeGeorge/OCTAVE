Overview

OCTAVE's look is driven by three pragma Singleton QML objects declared in frontend/qmldir and imported everywhere as App.* (import "." as App from frontend/, import ".." as App from frontend/settings/). Files that live in frontend/ itself can also reference them unqualified (SettingsMenu.qml writes Style.assetBase).

 | COLOURS + FONTS      |   | STRUCTURE (one preset) |   | SIZES                |
 | - 17 built-in themes |   | - cardRadius, chip /   |   | - dp(), dpMin()      |
 | - custom themes      |   |   button / switch radii|   | - scaledSize()       |

                                       |
                 Wired at startup by frontend/Main.qml from settingsManager
                 (themeSetting, fontSetting, uiScale, colorTransitionMs, ...)

The backends own persistence only. SettingsManager (both C++ and Python) stores themeSetting, fontSetting, uiScale, colorTransitionMs, songLengthTransition, customThemes and albumArtColors; MediaManager and SpotifyManager produce Album Art Capture palettes. Everything else is QML.

Style.qml — Theme Resolution

frontend/Style.qml (about 1200 lines) holds the built-in palettes, the custom-theme map, the live album-art palette, the font registry, and one reactive colour property per UI token. The activeTheme object is what every token binds to, resolved in priority order:

property var activeTheme: {
    // 1. Album Art Capture with a live palette
    if (currentTheme === "Album Art Capture" && albumArtTheme)
        return albumArtTheme
    // 2. Custom themes saved by the user
    if (customThemes[currentTheme])
        return customThemes[currentTheme]
    // 3. Built-in themes, with a hard fallback
    return themes[currentTheme] || themes["SolarizedLight"]
}

Two setters exist. setTheme(name) validates the name against themes and customThemes, records lastStaticTheme (unless the name is Album Art Capture, in which case it arms _firstAlbumArtUpdate) and assigns currentTheme, letting the Behaviors animate. setThemeInstant(name) does the same but zeroes colorTransitionMs for the duration of the switch and restores it with Qt.callLater. Main.qml uses setThemeInstant for the startup load and for every manual theme change; the Display page's chips call setTheme after persisting through settingsManager.save_theme_setting().

Other public members: getAllThemeNames() (built-ins minus "Album Art Capture", plus custom names), getLightThemeNames() / getDarkThemeNames(), addCustomTheme(name, obj) (emits customThemesUpdated), updateAlbumArtTheme(json), isAlbumArtCaptureActive, lastStaticTheme, and the read-only URL assetBase (Qt.resolvedUrl("assets/")).

Theme Object Structure

Every theme — built-in, custom, or extracted — is a plain object with the same ten top-level keys. MediaManager::_generate_theme_from_colors() in both backends emits exactly this shape as JSON, which is why an extracted palette can be dropped straight into activeTheme:

{
    "base": "#0C0C0C",            // backgroundColor, sidebarColor, rowBackgroundColor
    "baseAlt": "#161616",         // headerBackgroundColor, contentColor, bottom bar gradient
    "accent": "#00FF41",          // accent, clockTextColor, metadataColor, active toggles
    "text":    { "primary": "#CCFFCC", "secondary": "#88CC88" },
    "states":  { "hover": "#202020", "paused": "#1C1C1C", "playing": "#282828" },
    "sliders": { "volume": "#00FF41", "media": "#88CC88", "settings": "#00FF41" },
    "bottombar": {
        "previous", "play", "pause", "next", "volume", "shuffle", "toggleShade",
        "homeButton", "obdButton", "mediaButton", "sensorButton",
        "settingsButton", "androidAutoButton", "phoneMirrorButton"
    },
    "mediaroom": { "previous", "play", "pause", "next", "left", "right", "shuffle", "toggleShade" },
    "mainmenu":  { "mediaContainer": "#005500" },
    "obd":       { "boxBackground": "#161616", "barColor": "#33FF66" }
    // optional: "obd.labelColor", "obd.valueColor", "status": { connected, disconnected, ... }, "albumArt"
}

No shipped theme defines status, obd.labelColor or obd.valueColor; the tokens that read them fall back to fixed colours or to the text colours. bottombar.sensorButton was added in commit 6735de5 ("sensor button now affected by theme colors") to every built-in theme and to both backends' palette generators; Style.bottomBarSensorButton falls back to homeButton so older persisted album-art JSON without the key still tints the icon.

Theme Picker and Swatch Chips

The picker lives in Display → Appearance (frontend/settings/DisplaySettingsPage.qml) and is built from three SettingsChips rows (see Settings UI → Reusable Components):

  • Light and Dark rows use App.Style.getLightThemeNames() / getDarkThemeNames(). Each chip is a square swatch whose chipPalettes[name] is the array [accent, baseAlt, base] drawn as three horizontal bands, top to bottom, by buildThemeChipPalettes().
  • Album Art Theme (visible only when the user has saved one) lists settingsManager.customThemes; a theme that carries an albumArt URL renders as an image chip (chipImages), otherwise it falls back to a palette swatch. These chips are deletableItems: press-and-hold opens the confirmation popup, and deleting the active theme first switches to CosmicVoyager.

The highlighted chip is activeThemeName: when Album Art Capture is on it shows App.Style.lastStaticTheme (the theme "borrowed" behind the live palette, defaulting to CosmicVoyager). Picking any chip calls save_theme_setting(name) + App.Style.setTheme(name), which implicitly turns Album Art Capture off.

Below the chips a SettingSubcategory titled "Album Art Capture" carries the on/off switch (togglable: true, checked when themeSetting === "Album Art Capture"). Turning it on stores the current theme in lastStaticTheme, saves the setting, calls setTheme and immediately asks mediaManager.extract_colors_from_album_art(get_current_file()); turning it off restores lastStaticTheme. Its body holds the "Transition Speed" slider and the "Match Song Length" toggle described under Colour Transitions.

Custom (Saved Album Art) Themes

Custom themes are created from the Media Room: while Album Art Capture is active, the album-art popup's "Save as Theme" button (frontend/MediaRoom.qml) calls

settingsManager.save_custom_theme(themeName, JSON.stringify(App.Style.albumArtTheme), mediaRoom.currentAlbumArt)

using the album name (or the track name, or "Custom Theme") as the key. Both backends copy the cover image into the app data directory, add its file:// URL as the theme's albumArt key, and store the object under customThemes in settingsConfigure.json. get_custom_theme(name) returns the JSON and delete_custom_theme(name) removes it (and its copied art).

Main.qml loads them before applying the saved theme so that a custom theme selected last session passes the setTheme guard:

let customThemes = settingsManager.customThemes
customThemes.forEach(function(themeName) {
    let themeObj = JSON.parse(settingsManager.get_custom_theme(themeName))
    App.Style.addCustomTheme(themeName, themeObj)
})

On settingsManager.customThemesChanged the whole map is rebuilt into a new object and assigned in one shot — the comment explains that clearing and refilling would briefly make activeTheme fall back to SolarizedLight if a custom theme is active. The Display page listens to App.Style.customThemesUpdated to refresh chip options, palettes, images and the deletable list.

Album Art Capture

"Album Art Capture" turns the current cover into a full theme. The work is split between the backends (image analysis, palette generation, persistence) and QML (applying and animating the result).

Triggers

  • Selecting the mode: Main.qml onThemeSettingChanged and the Display-page toggle both call mediaManager.extract_colors_from_album_art(mediaManager.get_current_file()). Inside the backend, _on_theme_changed() also sets m_albumArtCaptureActive / _album_art_capture_active.
  • Track change while active: _on_media_changed_for_theme(filename) (local files) or the Spotify manager's track-changed path, which calls extractColorsFromUrl() / _extract_colors_from_url() and skips an image URL it has already processed.
  • Startup: a one-second timer (_extract_colors_on_startup) re-extracts for the restored track if the mode is active.

Extraction Algorithm (identical in C++ and Python)

  1. Load the cover with QImage, convert to Format_RGBA8888, scale to 50×50 ignoring aspect ratio — 2500 RGB samples.
  2. Run k-means with k = 5, at most 10 iterations, centroids seeded from a random generator fixed at seed 42, stopping early when no centroid moves by more than 1 per channel. (The Python version uses a local random.Random(42); a comment notes that seeding the global module had made every later random.shuffle() in the process deterministic.)
  3. Sort the five centroids by vibrancy (HSV saturation × value), most vibrant first.
  4. Average the luminance (0.299R + 0.587G + 0.114B) of the first 1000 pixels; below 0.5 the image is "dark" and the generated theme uses dark bases.
  5. _generate_theme_from_colors(colors, isDark) derives the accents (primary: saturation ×1.4, brightness ×1.2; secondary ×1.3/×1.15; tertiary ×1.25/×1.1; quaternary ×1.2/×1.05), dimmer nav variants (×0.7 and ×0.75 brightness), picks white or near-black text with WCAG relative-luminance contrast checks, and assembles the ten-key theme object above. Distinct accents are assigned per bottom-bar button (OBD = quaternary, media = secondary, settings = tertiary, sensor = primary) so the bar stays legible.

Threading and Delivery

The C++ manager runs the extraction with QtConcurrent::run and a QFutureWatcher; Python uses a daemon threading.Thread and a queued _colorsReady signal. Both keep a job counter so that a fast skip through several tracks applies only the last palette, and both ignore a repeat request for the same file within 2 s (the restore-playback path and the startup timer ask for the same track). The comment in the Python code gives the cost: about 0.3 s on a desktop, closer to a second on a Raspberry Pi — hence the worker thread.

When the manager has a settings manager attached (always, in both entry points) the result goes to settingsManager.set_album_art_colors(json), which persists it as albumArtColors and emits albumArtColorsChanged. Main.qml's handler reads the albumArtColors property (the comment notes PySide6 signal arguments did not reliably pass through Connections) and calls App.Style.updateAlbumArtTheme(json). The albumColorsExtracted(json) signal on mediaManager / spotifyManager is the fallback when no settings manager is connected; Main.qml handles it too.

Applying in Style.qml

function updateAlbumArtTheme(themeJson) {
    let newTheme = JSON.parse(themeJson)
    albumArtTheme = newTheme
    if (currentTheme === "Album Art Capture") {
        // First paint after entering Album Art mode is instant — only
        // subsequent song changes fade with the configured speed.
        var instantFirst = _firstAlbumArtUpdate
        var savedDuration = colorTransitionMs
        if (instantFirst) colorTransitionMs = 0
        // Force activeTheme to re-evaluate by toggling currentTheme
        let savedTheme = currentTheme
        currentTheme = ""
        currentTheme = savedTheme
        if (instantFirst) {
            _firstAlbumArtUpdate = false
            Qt.callLater(function() { colorTransitionMs = savedDuration })
        }
        albumArtThemeUpdated()
    }
}

Because albumArtTheme is a var holding a fresh object, assigning it does not by itself re-trigger the activeTheme binding; the currentTheme toggle forces it. At startup Main.qml primes albumArtTheme from the persisted settingsManager.albumArtColors before calling setThemeInstant("Album Art Capture"), so the placeholder palette never paints.

Colour Transitions

colorTransitionMs (default 1000, persisted as settingsManager.colorTransitionMs and loaded by Main.qml at startup) is the duration of every token's ColorAnimation. In practice it only governs album-art driven shifts on song change: startup and manual theme picks go through setThemeInstant(), and the first paint after entering Album Art Capture is forced instant by _firstAlbumArtUpdate.

  • Transition Speed slider (Display → Appearance → Album Art Capture): 0–2000 ms in steps of 50, "0 = instant". Moves are debounced 100 ms before save_color_transition_ms() and App.Style.colorTransitionMs are updated.
  • Match Song Length toggle (songLengthTransition): Main.qml's Connections on mediaManager.durationChanged / spotifyManager.durationChanged set colorTransitionMs = durationMs, so the palette drifts across the whole track. Turning it off restores the saved value from settingsManager.colorTransitionMs.
Performance
Each Behavior on is an animation object; with roughly sixty colour tokens a palette change runs sixty ColorAnimations in parallel. This is fine on desktop and acceptable on the Pi-class head units, and a transition speed of 0 makes theme shifts free.

Font System

App.Style.fontFamily is the family used by every Text in the app (the root ApplicationWindow also binds font.family to it):

property string fontFamily: currentFont === "System Default"
    ? systemDefaultFont
    : (fontFamilyMap[currentFont] || systemDefaultFont)

Discovery happens in Main.qml. A FolderListModel scans frontend/assets/fonts/ for *.ttf / *.otf, creates one FontLoader per file, and when all have finished calls App.Style.registerFonts(fontNames, familyMap). Display names are derived from filenames — the extension is stripped and - / _ become spaces — and mapped to the family name Qt reports (loader.name), because the two frequently differ. The shipped files are GoogleSans-Regular.ttf and JetBrainsMono-Regular.ttf, so the picker offers "System Default", "GoogleSans Regular" and "JetBrainsMono Regular". After registration Main.qml applies settingsManager.fontSetting with App.Style.setFont(), which accepts only names present in availableFonts (or "System Default") and otherwise leaves currentFont unchanged.

The Font picker (Display → Appearance → Font) is a SettingsChips row with chipFonts: each chip renders the first word of its own name in that font (fontSizeMode: Text.Fit, minimum dp(8)) so the user sees the typeface before choosing it. Selecting a chip calls save_font_setting() and App.Style.setFont(); the fontChanged signal fires for components that need to react beyond the property binding.

Default Font Name and Migration
Both backends default fontSetting to "GoogleSans Regular", the display name Main.qml derives from GoogleSans-Regular.ttf, and migrate the legacy value "Google Sans" to it when loading settingsConfigure.json (the old name failed the availableFonts check and left the UI in the system font).

EnvironmentTheme.qml — Structural Tokens

Spacing.qml — Layout Scaling

frontend/Spacing.qml turns the window size into pixel values. Main.qml calls App.Spacing.updateDimensions(width, height) at startup and on every resize; applicationWidth / applicationHeight feed dozens of derived int properties.

Scale Factor Chain

property real globalScale: 1.0        // user preference (settingsManager.uiScale)
property real autoScaleFactor: 1.0   // screen detection (screenAutoScale context property)
property real effectiveScale: autoScaleFactor * globalScale   // for dp()
property real baseScale: 0.6 * globalScale                  // for scaledSize()
property real textScale: 1.0          // multiplies overallText only
property real controlScale: 1.0       // declared, unused

Two families of value exist. Hard-coded pixel sizes written for a 720p design (dp(140), dp(8)) use effectiveScale, which includes screen auto-detection. Percentage tokens (0.125 of the window height for the bottom bar) already follow the screen size, so they only receive the original 0.6 design factor and the user's multiplier through baseScale.

Scaling Functions

function dp(size)            { return Math.round(size * effectiveScale) }
function dpMin(size, floor)  { return Math.max(floor, Math.round(size * effectiveScale)) }
function scaledSize(baseSize){ return Math.round(baseSize * baseScale) }
function scalePx(size)       { return Math.round(size * baseScale * (Math.min(applicationWidth, applicationHeight) / 1000)) }
function updateDimensions(width, height) { applicationWidth = width; applicationHeight = height; dimensionsChanged() }
  • dp() converts a 720p reference pixel value. dpMin() adds a floor, used for radii that must never go sub-pixel (dpMin(8, 2)).
  • scaledSize() is applied to the percentage tokens inside Spacing.qml itself.
  • scalePx() scales relative to the shorter edge per 1000 px.
  • dimensionsChanged is a var property holding an empty function, not a QML signal; callers can replace it with a callback.
Why Every File Has Its Own dp()
Almost no QML file calls App.Spacing.dp(). Each declares function dp(size) { return Math.round(size * (App.Spacing.effectiveScale || 1.0)) } locally because singleton functions misbehave on Qt for Android (see the comment in Style.qml next to assetBase). Only singleton properties are read across the boundary.

GUI Scale Slider and Auto-Scale

Auto-scale. Both entry points compute screenAutoScale before QML loads and expose it as a context property; Main.qml copies it into App.Spacing.autoScaleFactor. src/main.cpp divides the shorter edge of primaryScreen()->availableSize() by 720 and clamps to [0.4, 3.0]; the comment explains that Android reports the natural portrait size even when the app is locked landscape, and using the height alone produced a roughly 3× factor there. main.py uses min(available.width(), available.height()) / 720.0 with the same clamp, so both backends produce the same factor for a given display.

User scale. settingsManager.uiScale (default 1.0) is loaded into App.Spacing.globalScale at startup. Both backends migrate a stored value of exactly 0.6 (the old design factor that used to be persisted) to 1.0. The slider lives in Display → Layout → "UI Scaling":

SettingsSlider {
    from: 0.5; to: 2.0; stepSize: 0.05
    value: App.Spacing.globalScale

    // Commit on release only. Updating globalScale mid-drag re-lays out
    // the slider itself (track + handle scale with globalScale), so the
    // handle jumps relative to the finger.
    onPressedChanged: {
        if (!pressed && settingsManager) {
            settingsManager.save_ui_scale(value)
            App.Spacing.globalScale = value
        }
    }
}

Commit fe567f3 ("fix gui scale slider in frontend") replaced a 100 ms debounce with this commit-on-release rule; the ValueDisplay next to it still shows the live percentage as feedback. The hub layouts show the same number as "Scale: 100%".

Translucent surfaces are built from tokens at runtime (primaryTextColor at 5–7 % for cards, accent at 18–25 % for selection) rather than being separate theme keys, which keeps the theme object small and lets Album Art Capture palettes work without extra fields.

Customization Guide

Creating a New Built-in Theme

  1. Add an entry to the themes map in frontend/Style.qml with all ten keys, including bottombar.sensorButton.
  2. Append its name to lightThemeNames or darkThemeNames — the picker rows are built from those arrays, not from Object.keys(themes).
  3. Update Settings Reference if the default changes.

Adding a New Font

  1. Drop a .ttf or .otf file into frontend/assets/fonts/.
  2. Main.qml's FolderListModel discovers it at next launch; the display name is the filename minus extension with -/_ turned into spaces.

Adding a Structural Token

  1. Add the key to the active object in frontend/EnvironmentTheme.qml.
  2. Read it as App.EnvironmentTheme.active.key; there is no runtime switching, so a change is a code change.

Adding a Themed Icon

  1. Draw a 600×600 SVG with a single <g fill="#FFFFFF"> group, centred in the viewBox, and save it in frontend/assets/.
  2. Reference it as App.Style.assetBase + "name.svg" from any directory depth.

Design Decisions

DecisionRationale (from code comments and commit history)
One reactive property color per token, each with a Behavior Components bind to a colour, never to activeTheme.x.y directly, so a palette swap animates everywhere at once and Album Art Capture can change the palette on every track without any component knowing.
setThemeInstant() for startup and manual picks Comment: "the configured colorTransitionMs only applies to album-art-driven color shifts on song change". A user choosing a theme expects it immediately; a fade is only pleasant when it is ambient.
First album-art paint is instant Comment on _firstAlbumArtUpdate: entering the mode (or starting with it on) should snap to the current song's colours; only real song changes honour the transition speed.
Persist the last extracted palette (albumArtColors) Main.qml primes albumArtTheme from it before switching, "so the placeholder Album Art colors never paint". Both backends store the JSON with the comment "persisted for instant restore on startup".
Album Art Capture is a toggle, not a chip Comment on getAllThemeNames(): it is "surfaced as a toggle under the chips, not as a selectable theme"; lastStaticTheme exists so that turning it off restores the prior choice.
Deterministic k-means (seed 42, 50×50 downscale, k = 5, 10 iterations) The same cover always yields the same palette (stable when a track is replayed), and 2500 samples keep the pure-Python path to about 0.3 s on desktop and about a second on a Pi — run on a worker with job supersession so skipping tracks applies only the last result.
Per-button accents in generated palettes The generator deliberately assigns different extracted centroids to OBD, media, settings and sensor buttons "for variety", boosting saturation and brightness so the icons stay visible against the derived base.
Delivery through settingsManager.albumArtColors rather than a signal argument Main.qml comment: "In PySide6, signal arguments may not pass through Connections properly, so we read directly from the property as a workaround". The albumColorsExtracted signal remains as a fallback.
Rebuild the custom-theme map atomically Assigning a new object avoids briefly clearing customThemes, which "would make activeTheme fall back to SolarizedLight if a custom theme is currently active".
assetBase is a property, not a function Comment in Style.qml: singleton functions are unreliable on Android ("same Qt bug the local dp() wrappers work around"), and a URL resolved in frontend/ spares callers from guessing how many ../ they need.
EnvironmentTheme kept as a one-object singleton Comment: the presets "were never finished and the picker was removed", but the singleton stays "so the ~40 existing EnvironmentTheme.active.X bindings keep working unchanged".
Two scale factors (effectiveScale vs baseScale) Comments in Spacing.qml: hard-coded 720p pixel values need screen auto-detection, percentage tokens already adapt to the screen and "only need the original 0.6 design factor times the user's preference multiplier".
Auto-scale from the shorter screen edge (C++) main.cpp comment: Android reports the natural portrait size even when locked landscape; using height alone gave a ~3× factor.
Scale slider commits on release Updating globalScale mid-drag re-lays out the slider under the finger; deferring keeps the geometry steady (commit fe567f3).
Flat white SVGs plus ColorOverlay One asset serves every theme; ThemedIcon's offset second overlay reproduces the drop-shadow weight the old Unicode glyph tiles had, without a blur effect.
