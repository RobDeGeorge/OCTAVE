What a Theme Is

A theme is a set of colours: a background, a second background for panels, an accent, two text colours, and a colour for each button of the bottom bar and the Media Room. Pick one and every screen of OCTAVE changes with it. Sixteen themes are built in, eight light and eight dark.

OCTAVE can also take its colours from the cover of the song that is playing, so the whole app changes with the music. That is Album Art Capture. And you can add themes of your own.

Two more things decide how OCTAVE looks and are on this page too: the font, and the size of everything on screen. This page starts with how to use it and gets more technical as it goes.

Picking a Theme

  1. Open Settings > Display > Appearance.
  2. Under Theme there is a row of Light themes and a row of Dark ones. Each is a small square showing three of its colours: the accent on top, then the panel colour, then the background.
  3. Tap one. The whole app changes at once.

A third row, Album Art Theme, appears when you have themes of your own (below). Press and hold one of those to delete it. If it was the theme in use, OCTAVE goes back to CosmicVoyager.

Colours That Follow the Album Art

Below the theme rows is a switch, Album Art Capture ("Colors from the current song's album art"). Turn it on and OCTAVE builds a complete theme from the cover of whatever is playing, and builds a new one each time the cover changes. A dark cover gives a dark theme, a light cover a light one.

  • For music from your library the cover is the track's own. For another source, such as a mirrored phone, it is the picture that source sends.
  • Two songs with the same cover keep the same colours: nothing changes between tracks of one album.
  • A track with no cover leaves the colours as they were.
  • Tapping a theme in the rows above turns Album Art Capture off. Turning the switch off goes back to the theme you had before.
  • The last colours are saved, so OCTAVE starts in them the next time.

Two controls under the switch decide how the colours move from one song to the next:

ControlWhat it does
Fade TimeHow long the change of colour takes: 0 to 2000 ms. 0 is an instant change. The default is 1000 ms.
Fade Over the Whole SongThe fade lasts as long as the song, so the colours drift slowly towards the new cover. Fade Time is ignored while this is on.

The first colours after you turn the switch on, and the colours at startup, always appear at once. Only the change from one song to the next fades.

The volume knob's LED ring uses the same colours: unless it is set to a fixed colour, it takes the accent of the album-art palette each time a new one is made.

Making Your Own Theme

There is no theme editor in the app. A theme of your own is a block of JSON with the same keys as a built-in theme, kept under customThemes in the settings file (settingsConfigure.json, in the config folder). You can add one in two ways.

A theme of your own does not have to be complete or perfect. A key it leaves out, or one whose value is not a colour, takes the colour SolarizedLight has for it.

By hand

  1. Close OCTAVE. It reads the settings file once at startup and writes it itself while running.
  2. Copy a theme out of frontend/themes.json to start from.
  3. Paste it into customThemes under a name of your own and change the colours.
  4. Start OCTAVE. Your theme is in the Album Art Theme row of the picker, as a three-colour square.

Keep all ten groups. OCTAVE reads every one of them without checking that it is there. Three things are optional:

  • obd.labelColor and obd.valueColor: the text on the reading cards. Without them the two text colours are used.
  • status, with connected, disconnected, error, warning, info, success and danger: the colours of status marks. Give all seven or none. Without it OCTAVE uses fixed greens, reds, an orange and a blue, which is what every built-in theme does.
  • albumArt: the address of a picture. The picker then shows the picture and not the three-colour square.

From a program

A client of the service API can store a theme with settingsManager.save_custom_theme(name, theme, picture) and remove one with delete_custom_theme(name). No screen of the app calls save_custom_theme today. The picture is optional. It is copied into theme_art/ in the config folder as theme_<name>.<ext> (characters other than letters, digits, _ and - in the name become _), and deleting the theme deletes it. Because the caller may be another device, the picture is checked:

  • A file on this device is copied only if it really is a picture, of at most 16 MB.
  • A web address is downloaded in the background, only over http or https, only from an address on the public internet (never this device or its own network), without following redirects, with a limit of 30 seconds and 16 MB, and kept only if what arrives is a picture. It is saved as .jpg. The theme is usable at once; the picture is added when it arrives.
  • The browser demo cannot download a picture.

Fonts

Settings > Display > Appearance > Font shows each font as a sample written in that font. Tap one and all text changes. The choices are:

To add a font, put a .ttf or .otf file in frontend/assets/fonts/ and restart. It is listed under its file name, with the extension removed and - and _ turned into spaces: GoogleSans-Regular.ttf is "GoogleSans Regular". That name is also what the fontSetting setting stores.

Making Everything Bigger or Smaller

OCTAVE sizes itself to the screen when it starts, so it looks the same on a phone, a 7-inch car display and a desktop monitor. If you want it larger or smaller than that, use Settings > Display > Layout > UI Scale: 50 % to 200 %, in steps of 5. The new size is applied when you let go of the slider, not while you drag it.

Writing a Screen That Follows the Theme

From here on the page is for people writing QML for OCTAVE. The rule is short: never write a colour, a font name or a pixel size into a screen. Take colours and fonts from App.Style and sizes from dp() or App.Spacing. A screen written that way follows every theme, album art included, and fits every display, with no further work. 

import QtQuick 2.15
import "." as App          // ".." from a sub-folder such as settings/

Rectangle {
    function dp(size) { return Math.round(size * (App.Spacing.effectiveScale || 1.0)) }

    color: App.Style.contentColor
    radius: dp(12)
    border.color: Qt.rgba(App.Style.accent.r, App.Style.accent.g, App.Style.accent.b, 0.3)

    Text {
        text: "Coolant"
        color: App.Style.primaryTextColor
        font.family: App.Style.fontFamily
        font.pixelSize: App.Spacing.overallText
    }
    Text {
        text: "⚠"                       // a symbol, not a word
        color: App.Style.statusWarning
        font.family: App.Style.symbolFont
        font.pixelSize: dp(20)
    }
}

The tokens that matter

UseFor
App.Style.backgroundColorThe page behind everything.
App.Style.contentColor, headerBackgroundColorPanels, cards and headers: the second background.
App.Style.primaryTextColor, secondaryTextColorText, and less important text.
App.Style.accentAnything highlighted, selected or switched on.
App.Style.hoverColorA row or button under the pointer or finger; also the "off" colour of a switch.
App.Style.statusSuccess, statusWarning, statusError, statusConnected, statusDisconnectedMarks that mean good, careful, bad. Do not use the accent for these.
App.Style.fontFamilyEvery piece of text.
App.Style.symbolFontEvery Text that draws a symbol (✓ ✗ ⚠ ♪ ▶) and not words.
App.Style.assetBaseThe address of frontend/assets/, for icons: App.Style.assetBase + "obd_button.svg" works from any folder.

frontend/Style.qml has the rest: a colour for each button of the bottom bar (bottomBarHomeButton, bottomBarPlayButton and so on) and of the Media Room, the slider colours, the list-row highlights and the reading cards' colours (obdBoxBackground, obdBarColor, obdLabelColor, obdValueColor). Each is one line there and names the theme key it reads.

  • A see-through colour is made on the spot from a token, as the border in the example is. Themes have no separate keys for them, which is why a palette taken from a cover needs nothing extra.
  • Symbols need the symbol font. Android has no fallback font for symbols, so a symbol the text font lacks is drawn as an empty box. symbolFont is a small font shipped with OCTAVE that has them. When you use a symbol that is new to the app, add it to the list in tools/fonts/build_symbol_font.py and run that script again.
  • Do not read the palette itself (App.Style.activeTheme.accent). The tokens animate when the theme changes; the palette does not.

Sizes That Work on Every Screen

There are two kinds of size. Use the one that fits what you are sizing.

KindWriteFollowsUse it for
A fixed sizedp(12)The screen OCTAVE runs on, and UI Scale. Write the number of pixels you would want on a 720-pixel-high screen.Padding, corner radii, line widths, the size of something a finger must hit.
A shared sizeApp.Spacing.overallTextThe window, and UI Scale. Each is a percentage of the window.Text, margins and rows that should agree across pages and grow with the window.

dp(size) multiplies by App.Spacing.effectiveScale and rounds. dpMin(size, floor) is the same with a lower limit, for a radius or a line that must not round down to nothing. Most files declare their own one-line dp(), as in the example above, and do not call the one in App.Spacing: a note in Style.qml records that functions of a QML singleton are unreliable on Android, while its properties are fine.

The shared sizes most screens use, all percentages of the window's shorter side:

TokenSizeFor
overallText4.5 %Body text. Headings are a multiple of it.
overallMargin1 %The gap at the edge of a page or card.
overallSpacing, sectionSpacing5 %Between things in a row; between sections.
rowSpacing, columnSpacing1.5 %, 2 %Between rows and columns of a form.
overallRadius1 %A general corner radius.
isPortraittrue or falseThe window is taller than wide: stack panels that sit side by side.

The percentages are of the design, not of what you see: every shared size is also multiplied by a fixed 0.6 and by UI Scale. frontend/Spacing.qml has the full list, including the sizes of the bottom bar (see Bottom Bar), the Media Room, the music list and the settings pages.

Icons

The icons in frontend/assets/ are SVG files drawn as flat white shapes. On screen, the white is replaced by a theme colour, so one file serves every theme. ThemedIcon does this: give it the file and a colour token. Its properties are on the Components page. 

App.ThemedIcon {
    width: dp(28); height: dp(28)
    source: App.Style.assetBase + "obd_button.svg"
    color: App.Style.accent
}
  • Because the colour is a token, an icon fades with the rest of the app when the theme changes.
  • The picture is drawn at twice the size it is shown and then scaled down, which keeps its edges sharp.
  • A new icon must be one flat colour. A second colour in the file disappears into the tint.

How It Works

From here on the page is about what happens underneath.

The problem is this: a hundred QML files must all change colour together, some of them several times a minute when the colours follow the music, and none of them should know how. So no screen holds a colour. Each binds to a named token, and one object owns all the tokens.

PieceJob
themes.jsonThe built-in themes as data: the palettes, their order, and which are light and which dark.
themeCatalog (C++)Reads that file and serves it. It also works out the palette in force and publishes it as activeTheme, so a frontend other than the QML one can draw the user's theme from a single property.
App.Style (QML)Holds one colour property per token, each bound to a key of the palette in force and each with its own animation. Also holds the font in use.
App.Spacing (QML)Turns the window size and the scale into sizes.
App.EnvironmentTheme (QML)Corner radii of the settings controls.
settingsManagerRemembers the choices: theme, font, scale, fade time, your themes, the last album-art palette.
mediaManager, nowPlayingMake a palette from a cover, and decide when.
fontCatalog (C++)Loads the bundled fonts before any screen exists.

Style, Spacing and EnvironmentTheme are QML singletons: one object each, shared by every file that imports frontend/ as App.

Which Palette Wins

The palette in force is chosen by the first of these that applies:

  1. Album art. The theme is "Album Art Capture" and a palette has been taken from a cover.
  2. A theme of your own with the chosen name.
  3. A built-in theme with the chosen name. For "Album Art Capture" with no palette yet, this is a dark blue placeholder of that name in themes.json.
  4. SolarizedLight, when the name matches nothing.

The rule exists twice, in Style.qml for the QML screens and in ThemeCatalog::resolve() for everyone else, and tst_themecatalog checks the C++ one. A theme of your own that has the name of a built-in one replaces it.

How a Change Reaches the Screen

  1. You tap a theme. The page writes settingsManager.themeSetting.
  2. Main.qml hears the change and calls App.Style.setThemeInstant(name). A name that is neither built in nor yours is ignored.
  3. App.Style.activeTheme is worked out again by the order above.
  4. Every colour token is bound to one key of activeTheme, so every token changes, and every screen bound to a token redraws.
  5. In C++, themeCatalog hears the same change, works out the same palette and announces activeThemeChanged for other frontends. Android Auto's day or night mode is set from it.

Because the change goes through the setting, it does not matter who makes it: the settings page, a service API client setting themeSetting, or a dashboard driver. The font and the scale travel the same way.

Fonts. At startup fontCatalog loads every font file in the fonts folder and lists each as a name (for the picker and the setting) and a family (what a Text needs). The two often differ, which is why screens use App.Style.fontFamily and never the name. It also loads the symbol font from the symbols/ sub-folder, which keeps that font out of the picker. All of this is done before the first screen loads, so the saved font is always there when it is applied. If the symbol font fails to load, symbols are drawn in the text font.

Scale. The size of everything is two numbers multiplied: one worked out at startup from the screen (its shorter side divided by 720, kept between 0.4 and 3.0) and your UI Scale. dp() uses both. The shared sizes are percentages of the window, so they use only UI Scale.

How Colours Are Taken From a Cover

While the theme is "Album Art Capture", nowPlaying asks for new colours whenever the picture of what is playing changes, and once when the theme is switched on. mediaManager then does this, on a worker thread:

  1. Shrink the cover to 50 by 50 pixels. Detail does not matter, only colour.
  2. Find the five main colours by sorting the pixels into five groups of similar colour and taking each group's average. The starting point is fixed, so the same cover always gives the same colours.
  3. Order them by how vivid they are. The most vivid becomes the accent; the next three colour the other buttons, so the bottom bar's buttons do not all look alike.
  4. Decide dark or light from the average brightness of the top part of the picture.
  5. Build the backgrounds from the main colour: darkened to about a sixth of its brightness for a dark theme, or washed out to a pale tint for a light one.
  6. Make it readable. Text is near-white on a dark background and near-black on a light one. Each button colour is brightened or darkened until it stands out from the background (a contrast of at least 3 to 1).
  7. Save the result as a complete palette, with the same keys as a built-in theme, in albumArtColors. From there it reaches the screen like any other change.

If you skip through tracks quickly, only the last cover's colours are applied: a newer request replaces an older one that is still running. A second request for the same track within 2 seconds is ignored.

Animations

Every colour token has its own colour animation, and all of them share one duration, App.Style.colorTransitionMs. When the palette changes, each token glides from its old colour to its new one over that time. The screens do nothing: a colour bound to a token moves with it.

The duration is not always the Fade Time you set:

ChangeDuration
StartupNone.
Picking a theme, or turning Album Art Capture on or offNone. A theme you choose should appear at once.
The first album-art colours after turning it onNone.
A new cover while Album Art Capture is onFade Time, or the length of the song with Fade Over the Whole Song.

A change of palette starts about sixty colour animations at once. On a slow device, set Fade Time to 0 if a song change makes the screen stutter.

EnvironmentTheme: Corner Radii

frontend/EnvironmentTheme.qml holds one fixed object, App.EnvironmentTheme.active, with the shape of the settings controls: mostly corner radii. A control reads its radius from there and scales it, for example radius: dpMin(App.EnvironmentTheme.active.cardRadius, 2).

The object also has about thirty on/off flags, such as cornerBrackets, buttonGlowBorder, scanlineOverlay and cardGlassEffect. They belong to two extra looks ("Spacecraft" and "Deep Sea") that were never finished. All of them are off, except buttonSolidFill, which is on, and nothing can change them while the app runs. The settings controls still contain the drawing code those flags would switch on. To change a radius, edit the file. Do not build on the flags.

Why It Is Built This Way

  • Screens bind to tokens, never to the palette. A change of palette then animates everywhere at once, and Album Art Capture can change it on every track with no screen knowing.
  • The palettes are data, served from C++. Any frontend, not only the QML one, can draw the user's theme, and adding a theme changes no code.
  • Album Art Capture is a switch, not one of the themes. It sits on top of a theme, and turning it off gives that theme back.
  • Themes of your own replace each other in one step. When the list changes, the whole list is swapped at once. Emptying it first would show SolarizedLight for a moment if one of your themes were in use.
  • Two kinds of size. A fixed size must follow the screen it is on; a percentage of the window already does. Scaling both the same way would scale the second kind twice.
  • The scale comes from the screen's shorter side. Android reports the screen as upright even when the app is held sideways; using the height alone made everything three times too big there.
  • UI Scale applies on release. Applying it during the drag resizes the slider under the finger.
