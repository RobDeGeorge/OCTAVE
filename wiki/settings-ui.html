SettingsMenu Orchestrator

frontend/SettingsMenu.qml is the orchestrator that manages settings navigation. It does not render settings content itself; instead it delegates to one of four layout engines based on user preference.

Item {
    id: settingsMenu
    objectName: "settingsMenu"
    required property var stackView
    required property var mainWindow
    required property string initialSection

    property string layoutStyle: settingsManager
        ? settingsManager.settingsLayoutStyle : "Carousel"
}

The layout style determines which component is loaded. The orchestrator provides the hubModel (filtered list of visible pages) and helper functions to each layout.

Page Model

The pageModel is the single source of truth for all settings pages:

readonly property var pageModel: [
    { name: "Display",
      section: "displaySettings",
      source: "settings/DisplaySettingsPage.qml",
      widget: "widgets/DisplayWidget.qml",
      icon: "\u263C",
      iconSource: Style.assetBase + "cat_display.svg",
      group: "Appearance",
      subSections: ["Layout", "Window", "Appearance", "Clock"] },
    { name: "Media",
      section: "mediaSettings",
      source: "settings/MediaSettingsPage.qml",
      widget: "widgets/MediaWidget.qml",
      icon: "\u266B",
      iconSource: Style.assetBase + "media_button.svg",
      group: "Appearance",
      subSections: ["Library", "Playback", "Now Playing", "Spotify"] },
    // ... 5 more pages
]

Each entry defines:

KeyPurpose
nameDisplay name shown in tabs/sidebar
sectionInternal identifier used for navigation and persistence
sourceQML file path (relative to frontend/)
widgetWidget QML file for Dashboard layout (relative to frontend/settings/)
iconLegacy Unicode character; kept only as a fallback
iconSourceTheme-tinted SVG in frontend/assets/, built from Style.assetBase. This is what actually renders.
groupCategory grouping: Appearance, Connectivity, System
subSectionsNamed anchors within the page for sub-navigation. Must match the page's tileModel titles exactly — lookup goes through findChildByObjectName(), and pages set each card's objectName from modelData.title.

Layout Engines

OCTAVE provides four distinct settings layout styles, all rendering the same pages with different navigation paradigms.

Carousel Layout

frontend/SettingsCarouselLayout.qml presents settings pages as a horizontal SwipeView with a tab strip at the top.

Tab Strip

Row {
    id: tabStrip
    anchors.horizontalCenter: parent.horizontalCenter

    // Tabs divide available width equally
    property real tabWidth: hubModel.length > 0
        ? (parent.width - spacing * (hubModel.length - 1)) / hubModel.length
        : App.Spacing.dp(80)

    Repeater {
        model: hubModel.length
        Rectangle {
            color: isCurrent
                ? Qt.rgba(App.Style.accent.r, ..., 0.2)
                : "transparent"
        }
    }
}

Each tab shows an icon + name, with accent-colored highlight for the active tab and an orange dot for update notifications. The SwipeView below allows horizontal swiping between pages or tab clicking.

Sidebar Layout

frontend/SettingsSidebarLayout.qml is a traditional two-panel layout with a sidebar navigation list on the left and content on the right.

RowLayout {
    spacing: 0

    Rectangle { // Left sidebar panel
        Layout.preferredWidth: App.Spacing.settingsNavWidth
        color: App.Style.sidebarColor
    }

    Loader { // Right content area
        Layout.fillWidth: true
        source: sourceForSection(settingsMenu.currentSection)
    }
}

Visual Enhancements

  • Subtle overhead lighting gradient on the sidebar
  • Lit edge highlight along the top
  • Soft drop shadow on the right edge
  • Scroll memory (via ScrollMemory.js) preserves scroll position when switching pages

Hub Layout

frontend/SettingsHubLayout.qml presents a card grid landing page. Clicking a card opens its detail page full-width.

Two-State Navigation

property string viewState: ""  // "hub" or "detail"

The hub state shows a grid of SettingsHubGridCard components, each displaying a summary widget with live info lines (theme name, connection status, etc.). The detail state loads the full settings page in a Loader.

Widget Info Lines

function getWidgetForSection(section) {
    switch (section) {
        case "displaySettings":
            return [
                { label: "Theme", value: settingsManager.themeSetting },
                { label: "Scale", value: Math.round(settingsManager.uiScale * 100) + "%" }
            ]
        // ... similar for each section
    }
}

Dashboard Layout

frontend/SettingsDashboardLayout.qml is an advanced grid layout where each card can load a live widget preview from the widgets/ directory.

Column Spanning

Important sections (Display, Media) get 2 columns in a 3-column grid, while smaller sections get 1:

function getSpanForSection(section) {
    switch (section) {
        case "displaySettings":
        case "mediaSettings":
            return 2
        default:
            return 1
    }
}

Like the Hub layout, it uses a "hub" / "detail" view state. Cards load their widget QML source from pageModel[i].widget.

Reusable Components

All settings components live in frontend/settings/ and import the parent directory as App for access to Style, Spacing, and EnvironmentTheme.

SettingsCard

settings/SettingsCard.qml — A collapsible container card for grouping related settings.

  • Properties: cardId, title, description, expanded
  • Persistence: Expanded/collapsed state is persisted via ExpandedCards.js (a .pragma library singleton loaded at startup). State changes are debounced with a 500ms timer before writing to disk.
  • Theming: Semi-transparent background with primaryTextColor at 7% opacity. Supports environment features: accent borders, corner brackets, top-edge highlights, and frosted glass gradient (Deep Sea).
  • Content: Uses a default property alias so child items are placed inside the card body automatically.

SettingsToggle

settings/SettingsToggle.qml — A toggle switch with two modes.

  • Compact mode: Inline switch with label, suitable for use within cards
  • Full mode: Larger switch with dedicated row layout
  • Properties: checked, compact, text, activeColor
  • Signal: toggled(bool checked)
  • Environment-aware: Switch radius, knob radius, glow effects, and accent borders adapt to the current environment preset

SettingsSlider

settings/SettingsSlider.qml — A themed horizontal slider.

  • Properties: activeColor, visualValue, valueDisplay
  • Environment features: Handle glow (Spacecraft/Deep Sea), tick marks below the track (Spacecraft), configurable handle radius
  • Track: Active fill portion uses the activeColor; background uses secondaryTextColor

SettingsTile

settings/SettingsTile.qml — A large touch target in the settings tile grid. Every top-level settings page is a 2×2-ish grid of these; tapping one opens its content in a SettingsCardPopup.

  • Properties: cardId, title, iconSource (theme-tinted SVG), icon (legacy Unicode glyph fallback), statusColor, statusVisible
  • Signal: tileClicked(string cardId)
  • Icons: Prefer iconSource. Build the path from the Style.assetBase URL, e.g. App.Style.assetBase + "tile_layout.svg" — that resolves correctly from both frontend/ and frontend/settings/.

SettingsButton

settings/SettingsButton.qml — A themed action button.

  • Properties: text, tooltipText, buttonColor, bold
  • Signal: clicked()
  • Environment modes: Standard uses solid color fill; Spacecraft uses semi-transparent fill with glow border and top-edge highlight

SettingsTextField

settings/SettingsTextField.qml — A themed text input field.

  • Styling: Uses hoverColor background with accent border on focus
  • Environment features: Corner marks at all four corners (Spacecraft), configurable border radius

SettingsChips

settings/SettingsChips.qml — A flow layout of selectable chip buttons.

  • Properties: options (array), currentValue, chipColors (per-chip colors), chipImages (album art chips), deletableItems
  • Features: Text chips and image chips are separated into different rows. Deletable chips show a confirmation popup. Environment-aware border radius and accent borders.

Adding a New Settings Page

  1. Create the page QML file in frontend/settings/. Name it MySettingsPage.qml. It receives settingsManager as a context property.

    Follow the tile pattern every settings page uses — declare a tileModel, put each card's body in its own Component, and render the fallback with a Repeater:

    property var tileModel: [
    { cardId: "my_first",  title: "First",
      iconSource: App.Style.assetBase + "tile_first.svg",
      component: firstContent },
    // ... aim for 4 tiles so the grid reads as 2x2
]

Component {
    id: firstContent
    ColumnLayout {
        width: parent ? parent.width : 0
        // ... card body
    }
}

// Default rendering for Carousel/Hub/Dashboard; the Sidebar
// layout hides this and renders the tile grid + popup instead.
Repeater {
    model: pageRoot.tileModel
    SettingsCard {
        Layout.fillWidth: true
        objectName: modelData.title
        cardId: modelData.cardId
        title: modelData.title
        Loader {
            Layout.fillWidth: true
            sourceComponent: modelData.component
        }
    }
}
  2. Draw the tile icons — Add one 600×600 SVG per tile to frontend/assets/, following the house style: a single <g fill="#FFFFFF"> of filled primitives (see tile_layout.svg or sensor_button.svg). They are recoloured at runtime by ThemedIcon, so use one flat fill — a second colour will collapse into the tint. Keep the artwork centred in the viewBox; anything off-centre renders visibly offset in the tile.
  3. Create an optional widget in frontend/settings/widgets/MyWidget.qml for the Dashboard layout preview.
  4. Register in pageModel — Add an entry to the pageModel array in frontend/SettingsMenu.qml. subSections must list the same titles as tileModel: 
    { name: "My Page",
  section: "mySettings",
  source: "settings/MySettingsPage.qml",
  widget: "widgets/MyWidget.qml",
  icon: "\u2605",
  iconSource: Style.assetBase + "cat_mypage.svg",
  group: "System",
  subSections: ["First"] }
  5. Add visibility default — Ensure settingsManager.is_settings_section_visible("mySettings") returns true by default in both backends (C++ and Python).
  6. Test all four layouts — Verify the page appears correctly in Carousel, Sidebar, Hub, and Dashboard modes.
Path Convention: The source path in pageModel is relative to frontend/ (used by layout Loaders in frontend/). The widget path is relative to frontend/settings/ (used by SettingsDashboardCard's internal Loader).

Layout Switching

The layout engine is selected at runtime via a Loader in SettingsMenu.qml:

function layoutSourceForStyle(style) {
    switch (style) {
        case "Carousel":  return "SettingsCarouselLayout.qml"
        case "Sidebar":   return "SettingsSidebarLayout.qml"
        case "Hub":       return "SettingsHubLayout.qml"
        case "Dashboard": return "SettingsDashboardLayout.qml"
        default:          return "SettingsCarouselLayout.qml"
    }
}

Loader {
    id: layoutLoader
    anchors.fill: parent
    source: layoutSourceForStyle(layoutStyle)

    onLoaded: {
        if (item) {
            item.settingsMenu = settingsMenu
            item.hubModel = Qt.binding(function() {
                return settingsMenu.hubModel
            })
        }
    }
}

When the user changes the layout style mid-session, the isInitialLoad flag is set to false so the new layout engine knows to preserve the current section rather than restoring from saved state.

Navigation Functions

The orchestrator provides navigation functions that delegate to the active layout:

function navigateToCategory(section) {
    currentSection = section
    settingsManager.set_last_settings_section(section)

    if (layoutLoader.item) {
        if (layoutStyle === "Carousel")
            layoutLoader.item.currentIndex = indexForSection(section)
        else
            layoutLoader.item.navigateToCategory(section)
    }
}

function navigateToSubSection(section, subSection) {
    // Delegates to layout-specific sub-section scrolling
    layoutLoader.item.navigateToSubSection(section, subSection)
}

Section Visibility

Settings sections can be hidden/shown by the user. The buildHubModel() function filters the pageModel to only include visible sections:

function buildHubModel() {
    var model = []
    for (var i = 0; i < pageModel.length; i++) {
        var page = pageModel[i]
        if (!isVisible(page.section)) continue
        model.push({
            name: page.name,
            section: page.section,
            source: page.source,
            icon: page.icon,
            group: page.group,
            widget: page.widget
        })
    }
    hubModel = model
}

When visibility changes (via the Settings button's visibility popup in the BottomBar), the settingsMenuVisibilityChanged signal triggers a rebuild of the hub model.

Card State Persistence (ExpandedCards.js)

The expanded/collapsed state of SettingsCard components is persisted via a .pragma library JavaScript module:

// Pre-loaded once at app startup in SettingsMenu.onCompleted
ExpandedCards.load(settingsManager)

// In SettingsCard: check cached state (no disk I/O)
property bool expanded: ExpandedCards.isExpanded(cardId)

// On state change: update cache immediately, debounce disk write
onExpandedChanged: {
    ExpandedCards.setExpanded(cardId, expanded)
    _saveTimer.restart()  // 500ms debounce
}

The .pragma library pattern makes this a true singleton across all QML components, ensuring consistent state without per-card disk reads.
