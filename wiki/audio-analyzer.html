Pipeline Overview

backend/audio_analyzer.py (Python) and src/managers/audioanalyzer.{h,cpp} (C++) pre-compute FFT visualization data for an entire audio track, then provide time-indexed levels to QML based on playback position. This avoids real-time FFT computation during playback. Both backends expose the same audioAnalyzer API and produce the same 0-8 levels; the code shown below is the Python version.

Bar Count

The visualizer renders a fixed 96 frequency bars at 60 FPS, the highest-fidelity layout. The waveform is enabled or disabled via the single showWaveformVisualizer setting in MediaRoom — there are no quality tiers.

Audio Decoding

In the Python backend audio files are decoded using the PyAV library (Python bindings for FFmpeg). This supports virtually any audio format: MP3, FLAC, AAC, OGG, WAV, etc. The C++ backend decodes with Qt Multimedia's QAudioDecoder, requesting 8 kHz mono float output directly, so the stereo-to-mono and downsampling steps below happen inside the decoder; it then runs the same Hann window, radix-2 FFT, logarithmic band grouping, 95th-percentile normalisation, and ^0.6 curve.

import av

container = av.open(file_path)
audio_stream = next(
    (s for s in container.streams if s.type == 'audio'), None)

samples = []
sample_rate = audio_stream.rate or 44100

for frame in container.decode(audio_stream):
    frame_data = frame.to_ndarray()

    # Stereo to mono: average channels
    if len(frame_data.shape) > 1:
        frame_data = frame_data.mean(axis=0)

    samples.append(frame_data)

container.close()

Preprocessing Steps

  1. Concatenate — All decoded frames are joined into a single float32 array
  2. Normalize — Divide by the global maximum absolute value to get a [-1, 1] range
  3. Downsample — Reduce to approximately 8 kHz by taking every Nth sample (N = sample_rate // 8000). This dramatically reduces FFT computation while retaining sufficient frequency information for visualization.
# Concatenate and normalize
all_samples = np.concatenate(samples).astype(np.float32)
max_val = np.max(np.abs(all_samples))
if max_val > 0:
    all_samples = all_samples / max_val

# Downsample to ~8kHz
downsample_factor = max(1, sample_rate // 8000)
all_samples = all_samples[::downsample_factor]
effective_rate = sample_rate // downsample_factor

FFT Pipeline

The preprocessed audio is split into 100ms chunks (10 chunks per second). Each chunk is analyzed independently:

chunk_size = int(effective_rate * 0.1)  # 100ms chunks
num_chunks = len(all_samples) // chunk_size
window = np.hanning(chunk_size)  # Pre-compute once

Per-Chunk Processing

  1. Window function — A Hanning window is applied to reduce spectral leakage at chunk boundaries: 
    windowed = chunk * window
  2. FFT computation — Real FFT via NumPy, taking the magnitude and discarding DC (index 0) and the mirror half: 
    fft = np.abs(np.fft.rfft(windowed))
fft = fft[1:len(fft)//2]
  3. Logarithmic frequency bands — The FFT bins are grouped into num_bars bands using logarithmic spacing. This gives more resolution to lower frequencies (which humans are more sensitive to) and groups higher frequencies together: 
    log_indices = np.logspace(
    0, np.log10(len(fft)),
    self._num_bars + 1, dtype=int)
  4. Band averaging — Each band's magnitude is the mean of its FFT bins

Global Normalization (Two-Pass)

After computing raw FFT magnitudes for all chunks, a second pass normalizes and quantizes:

# Find 95th percentile to avoid outlier spikes
all_values = [v for chunk in raw_fft_data for v in chunk if v > 0]
global_max = np.percentile(all_values, 95)

# Normalize, apply power curve, quantize to 0-8
for levels in raw_fft_data:
    for level in levels:
        norm = level / global_max
        norm = min(1.0, norm) ** 0.6   # Power curve for visual balance
        quantized = int(norm * 8)      # 0-8 integer levels
Why 95th percentile? Using the maximum value would compress the entire visualization to accommodate rare peaks. The 95th percentile allows occasional clipping at 8 but keeps the overall visualization dynamic and visually interesting.
Why power curve 0.6? The ** 0.6 exponent compresses the dynamic range, boosting quiet passages and taming loud ones. Without it, most bars would hover near zero with occasional spikes. The 0.6 value was tuned for visual balance.

Data Flow

Once analysis is complete, playback position is mapped to FFT chunks in real time:

@Slot(float)
def update_position(self, position_seconds: float):
    if not self._fft_data or not self._is_active:
        return

    # 10 chunks per second (100ms chunk duration)
    chunk_index = int(position_seconds * 10)
    chunk_index = max(0, min(chunk_index, len(self._fft_data) - 1))

    new_levels = self._fft_data[chunk_index]

    # Only emit if levels actually changed
    if new_levels != self._current_levels:
        self._current_levels = new_levels
        self.fftDataChanged.emit(new_levels)

The position-to-chunk mapping is simple: multiply seconds by 10 (since each chunk is 100ms). The change detection (!= self._current_levels) prevents unnecessary signal emissions when the playback position is within the same chunk.

Threading Model

Audio analysis is CPU-intensive and must not block the Qt event loop. The Python AudioAnalyzer uses a ThreadPoolExecutor with a single worker thread; the C++ port runs analyzeAudio() through QtConcurrent::run() and collects the result on the main thread with a QFutureWatcher.

self._executor = ThreadPoolExecutor(max_workers=1)

# Submit work to background thread
self._pending_future = self._executor.submit(
    self._analyze_audio, file_path)

# Poll for completion from the main thread
self._poll_timer.start()

A QTimer polling at 100ms checks if the future is done. When complete, results are collected on the main thread where it is safe to emit Qt signals:

def _check_analysis_done(self):
    if self._pending_future is None or not self._pending_future.done():
        return

    self._poll_timer.stop()
    future = self._pending_future
    self._pending_future = None

    result = future.result()
    if result is not None:
        self._fft_data = result
        self.analysisComplete.emit()
Thread Safety: The _analyze_audio() method must NOT touch any Qt objects. It receives the file path as an argument and returns the computed FFT data as a plain Python list. All Qt signal emissions happen on the main thread in _check_analysis_done().

Guard Conditions

  • Skip if already analyzed: If the same file is requested, the cached data is reused
  • Skip if analyzing: If analysis is already in progress, the Python backend drops the new request; the C++ backend remembers the latest requested file (m_pendingFile) and analyzes it as soon as the current job finishes, so fast skip sequences do not leave the visualizer on the old track
  • Graceful degradation: If NumPy or PyAV are not installed, the Python analyzer silently disables itself (the C++ analyzer only needs Qt Multimedia)

Performance Considerations

Analysis Time

The 8 kHz downsampling is the primary optimization. A 3-minute song at 44.1 kHz has ~8 million samples. At 8 kHz, this drops to ~1.4 million. FFT computation scales with O(N log N) per chunk, so this reduction is significant.

Memory Usage

A 3-minute song at 96 bars (~1800 chunks) holds 1800 x 96 = 172,800 integers, roughly 1.35 MB of cached FFT data per track.

QML Rendering Impact

Each of the 96 bars is a separate visual element that must be positioned and sized every frame. On low-powered devices this can impact frame rate; on those targets, disable the waveform via showWaveformVisualizer entirely.

Signal Emission Throttling

The change detection in update_position() prevents redundant signal emissions. Since chunks span 100ms, the visualizer emits at most 10 updates per second regardless of how frequently update_position() is called.

QML Integration

The audioAnalyzer is registered as a context property in src/main.cpp / main.py and consumed primarily by the MediaRoom waveform visualizer. The integration pattern:

// In MediaRoom.qml

// When a new track starts playing:
if (audioAnalyzer && mediaManager) {
    var fullPath = mediaManager.get_full_file_path(currentFile)
    audioAnalyzer.analyze_file(fullPath)
}

// Position updates (called from playback timer):
audioAnalyzer.update_position(positionSeconds)

// Receive FFT data:
Connections {
    target: audioAnalyzer
    function onFftDataChanged(levels) {
        // levels is a list of integers (0-8)
        // Update bar heights in the visualizer
        for (var i = 0; i < levels.length; i++) {
            bars[i].height = levels[i] / 8.0 * maxBarHeight
        }
    }
}

Bar Count

The visualizer renders a fixed 96 bars. The component reads the count from the analyzer at startup:

var numBars = audioAnalyzer.get_num_bars()  // always 96

Active/Inactive State

The visualizer can be toggled on/off. When disabled, it emits zero levels to clear the display:

// Disable: clears bars and stops emitting
audioAnalyzer.set_active(false)

// Enable: resumes emitting levels on position updates
audioAnalyzer.set_active(true)

Frequency Band Distribution

The logarithmic frequency band distribution is critical for natural-looking visualization. Linear spacing would dedicate most bars to high frequencies (which are less musically interesting), while logarithmic spacing mirrors how humans perceive pitch:

# Generate logarithmically-spaced band boundaries
log_indices = np.logspace(
    0,                         # Start: 10^0 = 1
    np.log10(len(fft)),        # End: highest FFT bin
    self._num_bars + 1,        # Number of boundaries
    dtype=int                   # Integer indices
)
log_indices = np.clip(log_indices, 0, len(fft))

With an 8 kHz effective sample rate, the FFT covers 0-4 kHz (Nyquist). For a 32-bar visualization, approximate band boundaries would be:

Dependencies and Graceful Degradation

The Python AudioAnalyzer requires two optional dependencies (the C++ backend has none beyond Qt Multimedia):

try:
    import numpy as np
    NUMPY_AVAILABLE = True
except ImportError:
    NUMPY_AVAILABLE = False

try:
    import av
    AV_AVAILABLE = True
except ImportError:
    AV_AVAILABLE = False

If either library is missing, the analyzer silently disables itself. The analyze_file() slot returns immediately with a warning log. The QML visualizer receives no data and remains hidden. This means OCTAVE can run on systems without NumPy or FFmpeg without any errors or degraded experience (the visualizer simply doesn't appear).

Installation: Both numpy and av (PyAV) are listed in requirements.txt and installed automatically by python setup.py. PyAV bundles its own FFmpeg libraries, so no system FFmpeg installation is needed.
