Pipeline Overview

backend/audio_analyzer.py pre-computes FFT visualization data for a whole audio track (up to 3 hours) on a worker thread, then serves time-indexed levels to QML from the playback position. Local-file playback uses this pre-computed data; mirrored-phone audio uses the separate live PCM path. Both produce 96 bars on a 0-8 integer scale from 100 ms windows.

 Audio File (.mp3/.flac/.m4a/...)

       v

Bar Count and the Single Toggle

The visualizer renders a fixed 96 frequency bars (_num_bars = 96, returned by get_num_bars()) and MediaRoom polls every 16 ms. The only setting is showWaveformVisualizer (default true, see Settings Reference); there are no quality tiers. The MediaRoom container hard-codes its look as properties: timerInterval: 16, animDuration: 120, animEasing: Easing.InOutSine, smoothBars: true and pill-shaped fancyBars: true.

Audio Decoding

_analyze_audio(file_path) opens the file with av.open() and takes the first stream whose type is 'audio'; supported inputs depend on the codecs in PyAV's FFmpeg build. The decode is streamed: each frame is converted to an ndarray, mixed to mono and decimated as it arrives, so nothing at the native rate is kept beyond the current frame. Planar frames are (channels, n); packed (interleaved) frames are (1, n × channels) and are reshaped by the layout's channel count before averaging:

container = av.open(file_path)
audio_stream = next((s for s in container.streams if s.type == 'audio'), None)

for frame in container.decode(audio_stream):
    data = frame.to_ndarray()
    channels = len(frame.layout.channels)
    if data.ndim > 1 and data.shape[0] > 1:              # planar (channels, n)
        mono = data.mean(axis=0, dtype=np.float32)
    elif channels > 1:                                     # packed, interleaved
        mono = data.reshape(-1, channels).mean(axis=1, dtype=np.float32)
    else:
        mono = data.reshape(-1).astype(np.float32)

    piece = mono[(-position) % factor::factor]   # decimate, phase kept across frames
    position += len(mono)
    pending.append(piece)                     # FFT'd every ANALYSIS_BATCH_CHUNKS chunks

The FFT is vectorised per batch: every ANALYSIS_BATCH_CHUNKS = 600 chunks (60 s of audio) the pending decimated samples are concatenated, cut to a whole number of chunks, reshaped to (n, chunk_size), Hann-windowed and transformed with one np.fft.rfft(..., axis=1); band means come from np.add.reduceat, and only the resulting band magnitudes are kept. A remainder shorter than a chunk carries over to the next batch and is dropped at the end. Normalisation and quantisation at the end are array operations. This keeps Python-level loops, which hold the GIL, out of the per-sample work; the worker still shares the GIL with the GUI thread, so a very long analysis can be seen in the perf monitor's GIL jitter.

Preprocessing

  1. Mix to mono - per frame, as above, in float32
  2. Decimate - keep every Nth sample with N = max(1, sample_rate // 8000) (sample_rate is the stream's rate, or 44100 if unset), so a 44.1 kHz file becomes 8820 Hz and a 48 kHz file 8000 Hz (effective_rate = sample_rate // N). The phase is carried across frames (position counts native samples so far), so the result is every Nth sample of the whole track. There is no anti-aliasing filter.
  3. Cap - at most MAX_ANALYSIS_SECONDS (3 h) of decimated audio is kept; decoding stops there and an info line "Analysing only the first ... s" is logged
factor = max(1, sample_rate // 8000)
effective_rate = sample_rate // factor
chunk_size = int(effective_rate * self._chunk_duration)
fft_len = chunk_size // 2                 # 0 -> "Sample rate too low for analysis", returns None
max_samples = int(MAX_ANALYSIS_SECONDS * effective_rate)
batch_samples = ANALYSIS_BATCH_CHUNKS * chunk_size

The samples are not peak-normalised. Scaling the samples scales every band magnitude and the 95th-percentile reference by the same factor (see Global Normalization), so the 0-8 levels do not depend on sample scale; the docstring says so explicitly.

FFT Pipeline

The preprocessed audio is split into 100 ms chunks (_chunk_duration = 0.1, 10 chunks per second): chunk_size = int(effective_rate * 0.1), 882 samples for a 44.1 kHz source and 800 for 48 kHz. The window, band edges and band widths are computed once per file, since they depend only on the chunk size:

edges = np.asarray(self._log_band_edges(fft_len, self._num_bars))
widths = np.diff(edges)
starts = np.minimum(edges[:-1], fft_len - 1)
window = np.hanning(chunk_size).astype(np.float32)

Per-Chunk Processing

  1. Window function - a Hann window reduces spectral leakage at chunk boundaries: 
    chunks = samples.reshape(-1, chunk_size) * window
  2. FFT and magnitude - the magnitudes of every positive-frequency bin except DC, i.e. bins 1 .. N/2, which at the ~8 kHz effective rate is 0-4 kHz (0-4.41 kHz at 8820 Hz): 
    fft = np.abs(np.fft.rfft(chunks, axis=1))[:, 1:1 + fft_len]   # skip DC
    That is chunk_size // 2 bins at 10 Hz each (441 for 882 samples, 400 for 800).
  3. Logarithmic frequency bands - the bins are grouped into 96 bands with logarithmic spacing by _log_band_edges(fft_len, num_bars): 
    edges = [0] * (num_bars + 1)
for i in range(1, num_bars + 1):
    idx = int(fft_len ** (i / num_bars))      # the np.logspace(0, log10(N), 97) curve
    idx = max(idx, edges[i - 1] + 1)          # every band at least one bin wide
    edges[i] = min(idx, fft_len)
edges[num_bars] = fft_len
    Edge i is N^(i/96) truncated, but forced to be greater than the previous edge, so the first bands are one bin each until the log curve overtakes them.
  4. Band averaging - np.add.reduceat(fft, starts, axis=1) sums each band and the sum is divided by its width; a band of width 0 (only possible with fewer bins than bars) is 0

Global Normalization (Two-Pass)

After the raw band magnitudes of every chunk are known, a second pass normalizes and quantizes the whole (num_chunks, 96) array:

raw = np.concatenate(raw_batches)
positive = raw[raw > 0]
global_max = np.percentile(positive, 95) if positive.size else 1.0

if global_max > 0:
    return (np.minimum(1.0, raw / global_max) ** 0.6 * 8).astype(np.uint8)
return np.zeros(raw.shape, dtype=np.uint8)

A track too short for a single chunk returns None ("Audio too short for analysis"), and the bars stay flat.

Why 95th percentile? Using the maximum value would compress the entire visualization to accommodate rare peaks. The 95th percentile allows occasional clipping at 8 but keeps the overall visualization dynamic.
Why power curve 0.6? The ** 0.6 exponent compresses the dynamic range, boosting quiet passages and taming loud ones, so most bars do not hover near zero with occasional spikes.

Frequency Band Distribution

Logarithmic spacing gives more bars to low frequencies, where linear spacing would spend most of them on high frequencies. Boundary i of 96 sits at bin N^(i/96) (truncated, then bumped to at least the previous boundary + 1), where N is the number of magnitude bins: 400 for a 48 kHz source, 441 for 44.1 kHz, both 10 Hz per bin. Bar i covers array indices edges[i-1] .. edges[i]-1, and index 0 is the 10 Hz bin. Boundaries for a 48 kHz source (N = 400):

BarUpper edge (N = 400)
1-67one bin each (linear), 10-670 Hz
70edge 78, ~780 Hz
72edge 89, ~890 Hz
80edge 147, ~1.5 kHz
90edge 275, ~2.75 kHz
96edge 400, ~4 kHz
Why the first bands are linear. Truncated to an integer, N^(i/96) stays at 1 for roughly the first dozen boundaries, which (per the _log_band_edges docstring) used to leave those bars permanently at 0. Forcing every band to be at least one bin wide makes the low bars consecutive single bins. With N = 400 that linear stretch lasts until bar 67 (bar 66 for N = 441), so only the upper third of the bars is truly logarithmic.

Data Flow

Once analysis is complete, the playback position is mapped to a chunk on every call:

@Slot(float)
def update_position(self, position_seconds: float):
    if not len(self._fft_data) or not self._is_active:
        return

    chunk_index = int(position_seconds * 10)     # 10 chunks per second
    if chunk_index >= len(self._fft_data):
        new_levels = [0] * self._num_bars            # past the analysed part: flat bars
    else:
        new_levels = self._fft_data[max(0, chunk_index)].tolist()
    if new_levels != self._current_levels:     # only emit on change
        self._current_levels = new_levels
        self.fftDataChanged.emit(new_levels)

The change detection prevents a signal (and 96 QML property writes) while the position is still inside the same chunk. A position past the last analysed chunk (beyond the 3 h cap, or the sub-chunk tail of a track) yields 96 zeros rather than holding the last chunk. set_active(False) emits 96 zeros to clear the display; clear() drops the data, the remembered file and the current levels without emitting.

Live Phone Audio

main.py connects phone_mirror_manager.audioPlayed to audio_analyzer.feed_live_pcm(pcm, buffered_ms). The input is signed 16-bit little-endian PCM at 48 kHz, stereo, that the phone-mirror client has just written to its audio sink (on the GUI thread); buffered_ms is how much the sink still holds ahead of it. set_live(True) selects this mode (only if NumPy is installed); MediaRoom calls update_live() from its 16 ms timer while the phone is the media source.

  • Feed: every 6th frame (LIVE_FACTOR = 48000 // 8000, phase carried across chunks) is mixed to mono as (L + R) / 65536 and written into a one-second ring of 8000 float32 samples.
  • Update: the 100 ms window (800 samples) ending at the sample being heard, i.e. buffered_ms minus the time since the last feed behind the newest one, gets the same Hann window, rfft, DC drop and log bands as a file chunk.
  • Reference: a stream has no whole-track percentile, so the reference is the frame's 95th band value (by sorted index), held with an exponential release of LIVE_RELEASE_SEC = 1.0, floored at LIVE_REF_FLOOR = 1.0 (described in the code as the mean band magnitude of a ~-46 dBFS tone) and scaled by LIVE_REF_SCALE = 0.85 so the bars reach the same heights as a pre-analysed file. Levels are then min(1, band / ref) ** 0.6 * 8.
  • Silence: no PCM for more than LIVE_STALE_MS = 250 ms, or fewer samples than one window, produces zeros.

Only changed levels emit fftDataChanged. Switching live mode on or off clears the displayed levels; set_active(False) also clears them, and update_live() does nothing while inactive. is_analyzed() reports file-analysis data only, not whether the live ring has audio.

Threading Model

Decoding and FFT of a whole track take seconds and must not block the Qt event loop, so _analyze_audio() runs on the executor's single worker thread and must not touch Qt objects; everything else, including signal emission and all live-mode work, happens on the GUI thread.

self._executor = ThreadPoolExecutor(max_workers=1)

# analyze_file(): submit, then poll from the main thread
self._pending_future = self._executor.submit(self._analyze_audio, file_path)
self._poll_timer.start()          # 100 ms QTimer

def _check_analysis_done(self):
    if self._pending_future is None or not self._pending_future.done():
        return
    self._poll_timer.stop()
    future, self._pending_future = self._pending_future, None
    self._analyzing = False
    queued, self._queued_file = self._queued_file, None
    if queued and queued != self._current_file:
        self._fft_data = []                # stale result dropped
        self.analyze_file(queued)
        return
    result = future.result()
    if result is not None:
        self._fft_data = result
        self.analysisComplete.emit()

The worker returns a (num_chunks, 96) uint8 array or None; the poll timer collects it on the GUI thread, where emitting Qt signals is safe. An exception raised by the worker is logged with its traceback and leaves the data empty.

Thread Safety: the worker reads only the fixed _num_bars and _chunk_duration members and returns computed data; it writes no shared state and touches no Qt object. All signal emissions and member writes happen on the GUI thread.

Guard Conditions

  • Missing dependencies: if NumPy or PyAV is not installed, analyze_file() logs a warning and returns
  • Missing file: an empty or non-existent path is rejected with a warning
  • Already analyzed: if the same path is requested and data exists, nothing happens
  • Busy: while an analysis runs, only the newest request is remembered (_queued_file). When the worker finishes, a result for a superseded track is discarded and the queued file is analysed next, so a fast skip sequence does not leave the bars on the previous track. Starting an analysis also clears _fft_data, so the bars sit at zero instead of following the wrong song

QML Integration

The consumer is the waveformContainer item in frontend/MediaRoom.qml, visible when settingsManager.showWaveformVisualizer is on and playlistEmpty is false. Its live property follows mediaRoom.usePhone; a change re-runs initializeWaveform(), which calls set_live(live). The excerpt below is the local-file path:

// Analysis is deferred until the album-art carousel has settled, so decoding
// does not compete with animation frames (called from the carousel's settled signal)
function _doTrackChangeWork() {
    if (audioAnalyzer && mediaManager && !usePhone) {
        var currentFile = mediaManager.get_current_file()
        if (currentFile) {
            var fullPath = mediaManager.get_full_file_path(currentFile)
            if (fullPath) audioAnalyzer.analyze_file(fullPath)
        }
    }
}

// 96 bars, one Rectangle each; the Row is cached as a single texture while the
// card animation runs (layer.live is off then) to collapse 96 draw calls into one blit
Row {
    layer.enabled: true
    Binding { target: waveformBars.layer; property: "live"; value: !mediaRoom._cardAnimBusy }
    property int numBars: audioAnalyzer ? audioAnalyzer.get_num_bars() : 96
    Repeater { model: waveformBars.numBars
        Rectangle { height: Math.max(2, (barLevel / 8) * waveformContainer.height)
                    Behavior on height { NumberAnimation { duration: 120; easing.type: Easing.InOutSine } } }
    }
}

// Levels arrive by signal and are written straight into the bars
Connections {
    target: audioAnalyzer
    enabled: waveformContainer.visible && !mediaRoom._cardAnimBusy
    function onFftDataChanged(levels) {
        for (var i = 0; i < waveformRepeater.count; i++)
            waveformRepeater.itemAt(i).barLevel = (levels && levels[i]) || 0
    }
}

// Position is polled at the visualizer frame rate while playing
Timer {
    interval: 16
    running: waveformContainer.visible && waveformContainer.isPlaying && !mediaRoom._cardAnimBusy
    repeat: true
    onTriggered: if (waveformContainer.live) audioAnalyzer.update_live()
                 else if (audioAnalyzer.is_analyzed() && mediaManager)
                     audioAnalyzer.update_position(mediaManager.get_position() / 1000.0)
}

// Play/pause toggles emission; pausing clears the bars (ignored in live mode)
function onPlayStateChanged(playing) {
    if (waveformContainer.live) return
    waveformContainer.isPlaying = playing
    audioAnalyzer.set_active(playing)
}

In live mode isPlaying and set_active follow mediaRoom.devicePlaying instead of mediaManager.playStateChanged.

Track Changes

On a track change MediaRoom snaps every bar to zero (dropBars(); the Behavior animations are disabled while _cardAnimBusy is true, so the drop is instant) and leaves the visualizer visible. The bars sit at zero until the new analysis lands and then animate up on the next data tick. initializeWaveform() also runs whenever the container becomes visible and on component completion: it re-requests the current file (a no-op if already analyzed) and syncs set_active with mediaManager.is_playing().

Performance Considerations

Analysis Time

Working at ~8 kHz is the main optimization. A 3-minute song at 44.1 kHz has about 7.9 million samples; at 8820 Hz that is about 1.6 million, split into roughly 1800 chunks of 882 samples. The file is decoded at its native rate and each frame is decimated as it arrives, so full-rate audio is never held beyond one decoded frame. Actual time depends on the codec, the machine and the NumPy / PyAV build.

Memory Usage

While decoding, only the per-chunk band magnitudes (96 float32 per 100 ms chunk, about 4 KB per second of audio) plus up to one 60 s batch of decimated samples are held. The docstring records why: decoding whole tracks first "used ~1 MB of RAM per second of audio: a long mix or podcast needed several GB and froze the Orange Pi". The stored result is one byte per bar per chunk: a 3-minute song is about 1800 × 96 = 172,800 bytes. Only the current track's data is kept; a new analysis replaces it.

QML Rendering Impact

Each of the 96 bars is a separate Rectangle with an animated height and opacity and a three-stop gradient. Local-file data changes about 10 times per second; live data up to the 16 ms timer rate. The Row is rendered through a layer that is frozen (layer.live: false) during the card animation, so the 96 gradient draws become one texture blit. If a machine cannot keep up, turn the visualizer off with showWaveformVisualizer.

Signal Emission Throttling

MediaRoom polls every 16 ms, but chunks span 100 ms and update_position() only emits when the levels differ from the last emission, so local-file playback at normal speed produces at most 10 updates per second. A seek can select another chunk immediately.

Dependencies and Graceful Degradation

The analyzer needs two libraries, both in requirements.txt (numpy>=1.26.0, av>=12.0.0) and installed by python setup.py. They are imported lazily through backend/lazy_import.py: available(name) checks importlib.util.find_spec without importing, and lazy_module(name) returns a proxy that imports on first attribute access. The module comment gives the reason: importing them at start-up cost about 0.2 s before the first frame.

from backend.lazy_import import available, lazy_module

NUMPY_AVAILABLE = available("numpy")
if not NUMPY_AVAILABLE:
    logger.warning("NumPy not available - waveform visualization will be disabled")
np = lazy_module("numpy")

AV_AVAILABLE = available("av")
if not AV_AVAILABLE:
    logger.warning("PyAV not available - waveform visualization will be disabled")
av = lazy_module("av")

If either library is missing, analyze_file() logs a warning and returns, so local files get no bars. Live mode needs NumPy only; set_live(True) stays off without it.

Installation: numpy and av come from requirements.txt. PyAV's binary wheels bundle their own FFmpeg libraries, so no system FFmpeg is needed for them.

Design Decisions

ChoiceWhy (from code comments)
Pre-compute local tracksThe class docstring: "Pre-computes FFT for entire track, then provides data based on playback position." Playback then costs one array-row lookup per poll; mirrored-phone audio, which has no file, uses the live PCM feed.
Streamed decode, compact storage, 3 h capDecoding a whole track before analysing it used about 1 MB per second of audio and froze the Orange Pi on long files. Mixing and decimating each frame on arrival and keeping only band magnitudes bounds memory; the levels are stored as bytes; the cap bounds the remaining cost, and past it the bars are flat.
No animation in the backendupdate_position(): "No intermediate animation — QML handles any smoothing it needs." It emits only when the chunk's levels differ, and the QML Behavior animations do the easing on the scene graph.
~8 kHz, 100 ms chunks, 0-8 levelsThe low rate cuts the FFT work; 100 ms chunks give 10 data frames per second, which the 120 ms bar animations bridge; nine integer levels make "did anything change?" a cheap list comparison.
Analysis after the card animationMediaRoom calls analyze_file from the carousel's settled signal so decoding does not compete with animation frames; the bars drop to zero and stay visible meanwhile.
Newest-request queue"Remember only the newest request: its result must not be replaced by the one still running (which used to leave the previous track's levels showing after a quick skip)." Running analyses are not cancelled; their results are discarded.
Poll timer instead of future callbacksA concurrent.futures done-callback would run on the worker thread; the 100 ms QTimer "keeps Qt work on the main thread" with no cross-thread signal plumbing.
Lazy NumPy / PyAV importBoth are only needed once a track is analysed, and a missing library must degrade to "no visualizer", not a crash.
