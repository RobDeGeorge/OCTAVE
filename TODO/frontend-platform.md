# Frontend platform: anyone can build an OCTAVE frontend

**Status:** active (started 2026-10-23)
**Last updated:** 2026-10-23

**Goal:** someone who has never built OCTAVE can download one file, get a simulated car, write a frontend in any language against a published contract that won't break under them, and install it on a head unit where the user picks it as the screen.

## Where this starts

The open backend is done (`TODO/open-backend.md`): every manager is served over the service protocol (`src/service/`), `docs/api/` is generated by `--dump-api` and checked by `tst_apidocs`, `kProtocolVersion` is 2 (pairing), `--headless` runs with no QML engine, `--web-root` serves a web frontend, media streams and `/art` / `/export` exist, and `sdk/python`, `sdk/web` and `sdk/typescript` (types generated from `docs/api/`) are the clients. Five full frontends in five languages proved that every QML feature is reachable; they are kept on the `frontends-experiment` branch, not `main`, because maintaining them is not the goal. Making it easy for other people to write theirs is.

What stops an outside developer today, in order of how much it hurts:

1. (Done, step 2.) The simulated car existed only in developer builds, so a frontend author had to compile OCTAVE and Qt from source.
2. (Done, step 1.) The versioning rule was not enforced.
3. Only the TypeScript SDK is generated; the envelope (ops, errors, events, streams) is described in prose, so a new language means reading `sdk/python` and porting by hand.
4. (Done, step 4.) There was no way to install a frontend or have OCTAVE run and restart one.
5. (Done, step 5.) A paired device got full control.
6. No starter projects; the smallest examples are the SDKs themselves.
7. Unmeasured behaviour with many clients: subscription floods, a slow reader, a client that never reads (`tools/stream/service_load.py` is the baseline).

## Steps

### 1. The contract: stability you can build on
**Done (2026-10-23):** `tools/api/check_compat.py` in CI (`lint`), stability / deprecation annotations (`Q_CLASSINFO`, `src/service/metadescribe.h`) in `describe`, `docs/api/` and the API reference, `docs/api/CHANGELOG.md`. **Left:** surface `deprecated` / `experimental` in the generated SDK types (JSDoc `@deprecated` in `sdk/typescript`; folded into step 3).

### 2. A downloadable simulator
**Done (2026-10-23):** `src/sim/` (the simulated car, ELM327, IMU motion, a compiled-in test video, pairing codes) is built in every configuration and served as the experimental `sim` object; `octave --headless --sim` runs it on a throwaway config seeded with test tracks, `--config DIR` keeps one; `--dev` implies `--sim` on the usual config and keeps the `sim_*` actions as aliases; the browser demo runs on the same simulator. Checked in a Release `-DOCTAVE_DEV_TOOLS=OFF` build (`tst_boot` `headlessSimRunsInEveryBuild`). First step of `wiki/writing-a-frontend.html`. **Left:**
- **Effort:** S. **Device:** the release CI matrix. Run each packaged artifact with `--headless --sim --smoke` next to the existing `--smoke` step (`.github/workflows/build.yml`: the Windows step near line 307, and the AppImage / dmg jobs), so a release whose simulator does not start fails. Not tried yet: only the Linux desktop build was run.
- **Effort:** S. **Device:** desktop. Surface `sim` as experimental in the generated SDK types (folded into step 3 with the step 1 leftover).

### 3. One machine-readable protocol spec, SDKs generated from it
**Effort:** L. **Device:** desktop.
- **Done (2026-10-23):** `docs/api/protocol.json` (ops, errors, events, stream record, HTTP routes, pairing), checked against a headless app by `sdk/python/tests/test_protocol_spec.py` (ctest `sdk_python`); `describe` answers `ops`.
- **Done (2026-10-23):** TypeScript generated from `protocol.json` (`sdk/typescript/src/protocol.ts`: ops, replies, events, errors, record constants, routes; `request` typed per op) and from the object files with `@deprecated` / `@experimental` JSDoc; only the connection logic is hand-written. Go too (`sdk/go`, standard library only: `protocol_gen.go` + `objects_gen.go` from `internal/gen`, hand-written `client.go`, ctest `sdk_go`), which proves the spec isn't TypeScript-shaped. **Left:** Python stays hand-written (its `Client` is 200 lines and `test_protocol_spec.py` already holds it to the spec); generate it only if it drifts.
- A conformance kit for SDK authors: a recorded session plus a fake server they can run their client against.

### 4. Installable frontends
**Done (2026-10-23):** `octave-frontend.json` (`src/managers/frontendmanifest.h`), `FrontendManager` (service object `frontendManager`, scope `system`: install from a folder or zip with no links, no path leaving the folder and size caps, remove, the active screen in `<config>/frontends/ACTIVE`), web frontends served at `GET /`, exec frontends run headless by `FrontendSupervisor` with a session token of the manifest's scopes and loopback trust off for the run, restart with back-off, `USE_QML` / `--qml` and the automatic fall-back to QML, Settings > Device > Frontends. Tests: `tst_frontendmanager`, `tst_frontendsupervisor`, four `tst_boot` cases. **Left:**
- **Effort:** S. **Device:** Windows, macOS. Run an exec frontend there: `terminate()` is WM_CLOSE on Windows (a console program may need `kill()` after the grace period, which the supervisor does), the relaunch uses `applicationFilePath()` inside the `.app`. Only Linux was run.
- **Effort:** M. **Device:** Pi. An exec frontend as the screen on the head unit: start-up time, a crash loop and the fall-back, `USE_QML` from the boot volume.
- **Effort:** M. **Device:** desktop. A web frontend's scopes are shown but not enforced for a browser on the head unit itself (loopback trust); enforcing them means serving it with a session token, or loopback trust off whenever a web frontend is active.
- **Effort:** S. **Device:** desktop. Accepted for now: `QZipReader` inflates a whole entry in memory. Entries whose directory sizes are over 256 MB unpacked or 64 MB packed are refused before inflating, but a zip whose sizes lie can still use a lot of memory before the unpacked-size check refuses it (nothing is written or run, and installing needs the `system` permission or the head unit's own screen). A bounded inflater would close it (official Qt kits don't export zlib).
- **Effort:** M. **Device:** desktop, then Pi. `octave --pair-code`: a pairing code from the running instance without the QML UI (today: `--qml` or `USE_QML` for one start, pair, start again). Design: the running app listens on a `QLocalServer` named from a hash of its config folder, with `QLocalServer::UserAccessOption` (a Unix socket only its user can open; a named pipe with the user's ACL on Windows), never on the network. `octave --pair-code [--config DIR]` connects before building any manager, sends one line `{"op":"pairCode"}`, prints `{code, secondsLeft}` from `ServicePairing::startPairing()` on the GUI thread, and exits; no other ops at first (a later `useQml` could write `USE_QML` and restart). Nothing running: say so and exit 1. Tests: a headless instance and `--pair-code` against it in `tst_boot`, and a refused second user where the platform allows it.

### 5. Permissions per paired device
**Done (2026-10-23):** scopes on paired devices (`src/service/servicescopes.h`), asked for in `pair`, enforced on `set` / `call` / phone streams / `/export` / dev actions with code `forbidden`, every manager annotated (`Q_CLASSINFO("octave.scope...")`, `--dump-api` refuses one without), `scope` in `describe` and `docs/api/`, Settings shows each device's access with a read-only toggle, `check_compat` treats a narrowed scope as breaking. **Left:** an installed frontend's manifest permissions (step 4) map onto the same scopes; the Settings toggle is all-or-read-only, a per-scope editor if users ask for one. **Effort:** S. **Device:** desktop.

### 6. Starter templates
**Effort:** M. **Device:** desktop.
- `templates/` with a "hello car" in plain JavaScript (served with `--web-root`), Python, and one compiled language: connect, pair if needed, show RPM and speed, play/pause, the cover. Under 200 lines each.
- CI runs each against `--headless --sim` (the step 2 build), so they cannot rot.
- Each is copy-and-go: its own README, no path dependencies into the repo.

### 7. Many clients at once
**Effort:** M. **Device:** desktop, then Pi.
- Extend `tools/stream/service_load.py`: 20 clients each subscribed to every PID, one client that never reads, one that floods `call`; measure what the car side and the QML UI lose.
- Per-connection limits (queued bytes, ops a second) with a clear error code, and dropping a reader that stays behind, without slowing the others.
- Results on the Pi, since that is the slowest head unit.
- This is also the groundwork for the process split in `TODO/open-backend.md`.

## Order

1 and 2 first (a contract that holds and a car to build against are the minimum for anyone outside), then 5 (before step 4 makes it easy to install other people's code), 4, 3, 6, 7. Step 6 can start as soon as step 2 lands.
